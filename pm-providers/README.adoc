= `pm-providers`
:nofooter:

`pm-providers` is the aggregator of the provider modules. It holds no code. Its provider adapters connect the engine
to external systems — git, a CI host or a code analysis service — and `pm-provider-http` supplies the shared HTTP
infrastructure they build on. What a provider module may depend on is stated in
the
https://github.com/plan-marshall/plan-marshall-documentation/blob/main/doc/specification/module-structure.adoc[Module Structure Specification].

== Provider Modules

* link:pm-provider-git/README.adoc[`pm-provider-git`]: the git contract and its native variant on JGit.
* link:pm-provider-http/README.adoc[`pm-provider-http`]: the shared HTTP base of the provider modules.
* link:pm-provider-github/README.adoc[`pm-provider-github`]: the native GitHub client.
* link:pm-provider-gitlab/README.adoc[`pm-provider-gitlab`]: the native GitLab client and the `glab` CLI variant.
* link:pm-provider-sonar/README.adoc[`pm-provider-sonar`]: Sonar as a code analysis provider.

== Build and Test

Run from the root of the repository:

* Build: `python3 .plan/execute-script.py plan-marshall:build-maven:maven run --command-args "compile"`
* Tests: the aggregator has no tests of its own. Each provider module documents its test command in its README, linked above. The `modules` section of `pm-providers/pom.xml` is the authoritative list of the provider modules; a module added there gets its link in the list above in the same change.

The commands for the whole repository are in `CLAUDE.md`.

The aggregator has no developer documentation and no ADRs of its own.
