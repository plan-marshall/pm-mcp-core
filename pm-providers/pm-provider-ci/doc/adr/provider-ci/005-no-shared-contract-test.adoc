= ADR 005: No Shared Abstract Contract Test, a Generator-Only Test JAR for the Contract
:nofooter:

NOTE: Amended in place on 2026-11-06 by operator decision (PLAN-V2-92): the contract now publishes a generator-only
test JAR. Number and file name are kept.

== Status

Accepted; amended 2026-11-06 by operator decision (PLAN-V2-92).

== Date

2026-11-01; amended 2026-11-06.

== Context

Two adapters implement `CiProvider`, and a shared abstract test class published in a test JAR would let both prove the
same contract in one place: the registry, the value invariants and the origin check, each asserted once.

The repository publishes six `tests`-classified test JARs — `pm-core`, `pm-provider-http`, `pm-workflow`,
`pm-runtime`, `pm-provider-ci` and `pm-provider-git` — because the generators or fixtures they carry are reused by tests —
a consumer's, or the module's own (CLAUDE.md § Generator Artifacts). When this decision was first taken a test JAR of `pm-provider-ci` would have been
the fifth, and the standing constraint of the plan said a test JAR of this module is a dependency change that needs
the operator's word. The operator gave it on 2026-11-06 (PLAN-V2-92) for a generator-only artifact: a provider module
that needs a generator for its own type in two or more of its own test classes publishes it.

The adapters also differ where the shared test would be weakest: the GitHub token kinds, the App identity, the pull-request
flag, the GitLab bot user — each is adapter-specific and can only be tested against that adapter's mock server.

== Decision

The contract publishes no abstract contract test class, and it publishes a generator-only `tests`-classified test JAR:
`pm-provider-ci:tests`, package `de.planmarshall.provider.ci.testing.generators`, factory `CiGenerators`. Each adapter
tests the contract against its own mock web server (`GitHubCiProviderTest`, `GitLabCiProviderTest`), and the
contract's own grammar, registry and value invariants are tested in `pm-provider-ci` without HTTP (`ForgeUrlTest`,
`CiProvidersTest`, `ValueTypesTest`).

== Alternatives Considered

* *A test JAR with an abstract contract test.* It needs the operator's consent and duplicates the adapter-specific
  cases anyway. Rejected.
* *A test JAR that publishes the generator artifact only.* First rejected, because no adapter test needed a generator
  of a contract type. Adopted by the amendment of 2026-11-06: three test classes of this module build a valid
  `RepositoryRef`, and the rule of the module is that a generator of its own type used in two or more of its own test
  classes is published.
* *Put the shared cases in `pm-core:tests`.* The contract is no foundation type, and the rule keeps provider types out
  of the foundation. Rejected.

== Consequences

* The contract's own invariants are proven once, in its module, at the 80 % coverage bound.
* Each adapter proves the operations it implements, with its own recorded shapes.
* A consumer cannot reuse a contract test base; it reads the guide's mapping instead.
* `pm-provider-ci:tests` is consumable by `pm-provider-github` and `pm-provider-gitlab`; neither declares it in
  PLAN-V2-92.
