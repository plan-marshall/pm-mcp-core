= `pm-provider-ci`
:nofooter:

`pm-provider-ci` is the CI provider contract of the engine. It declares the identity, issue read, issue comment and
pull-request read operations of a forge, the value types of their answers, the URL grammar that resolves a source's URL to its forge,
repository and number, and the explicit provider registry. The forge adapters `pm-provider-github` and
`pm-provider-gitlab` implement it. What the module may depend on is stated in the
https://github.com/plan-marshall/plan-marshall-documentation/blob/main/doc/specification/module-structure.adoc[Module Structure Specification].

== Package

The line is the first sentence of the package's `package-info.java`.

* `de.planmarshall.provider.ci`: the CI provider contract of the engine: the identity of the acting credential, one issue read, one issue comment and one pull-request read (`ci.pr-view`), each answered with the closed `Result` of the shared HTTP base.

== Build and Test

Run from the root of the repository:

* Tests: `python3 .plan/execute-script.py plan-marshall:build-maven:maven run --command-args "test -pl pm-providers/pm-provider-ci -am"`

The commands for the whole repository are in `CLAUDE.md`.

== Test artifact

The test scope is published as the `pm-provider-ci:tests` test JAR (the `tests` classifier, built by `verify` and
deployed with the `SNAPSHOT`). It holds the package `de.planmarshall.provider.ci.testing.generators` with the
`TypedGenerator<T>` of the contract type the test classes build by hand (`RepositoryRef`) and the `CiGenerators`
factory that registers it. The `test-jar` goal includes only this package, so the module's own tests are not
published. `pm-provider-github` and `pm-provider-gitlab` may consume it as a test-scope dependency of type `test-jar`;
the version comes from the root POM's `dependencyManagement`. The artifact is the operator's decision of 2026-11-06
(PLAN-V2-92); its consumers are recorded in link:../../doc/adr/012-generator-artifacts.adoc[ADR 012].

The module publishes no shared abstract contract test: each adapter tests the contract against its own mock web
server (module ADR link:doc/adr/provider-ci/005-no-shared-contract-test.adoc[005], amended 2026-11-06).
