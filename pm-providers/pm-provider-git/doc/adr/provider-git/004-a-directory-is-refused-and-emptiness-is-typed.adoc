= ADR provider-git 004: A Directory Is Refused and Emptiness Is Read From the Index
:nofooter:

== Status

Accepted

== Date

2026-11-20

== Context

`JGitOperations.commit` stages and commits the paths of `CommitInput.paths`. Two properties of JGit make that unsound as
it stood:

* A pathspec is prefix-based. `setOnly("src")` and `addFilepattern("src")` name every path below `src`, so a caller that
  passed a directory committed every change below it, not the one path it named.
* An empty commit is reported by a generic `JGitInternalException` whose message is a translatable `LocalizableText`
  ("No changes"). Matching that text is a locale dependency: on another locale the same condition reads as a failure.

== Decision

* Before anything is staged, `commit` refuses a path that is empty, starts with `:` (git pathspec magic), carries a glob
  (`*`, `?`, `[`, `\`) or resolves to a directory below the root. The refusal is `GitOutcome.PATH_REFUSED` with the path
  as its detail.
* Whether the commit would be empty is read from the worktree and the index before anything is staged: git's status over
  the listed paths (or over the whole worktree for an empty path list) decides whether staging them would change
  `HEAD`. No change is `GitOutcome.NOTHING_TO_COMMIT` with the detail `no changes`, and it leaves the index as it was.
* `CommitInput` fills an empty path list when its builder omits `paths`, so a caller that never sets the member keeps the
  "every change" semantics instead of a `NullPointerException`.

== Alternatives Considered

* *Keep the message match.* Refused: the text is translatable, so the same condition is a failure in another locale.
* *Let the caller guarantee a file path.* Refused as the only guard: the provider is a public contract of the assembly,
  and the bind that refuses a directory is one caller of it.
* *Recompute JGit's own emptiness decision per path with `setOnly`.* Not taken: git's status over the listed paths decides
  the same question before the index is written, with the typed objects JGit exposes.

== Consequences

* A directory, a magic pathspec and a glob are refused before the index is touched, so a refused commit leaves the
  worktree as it was, and the emptiness read that precedes staging leaves the index untouched on `NOTHING_TO_COMMIT`
  (`JGitOperationsTest`, `nothingToCommitLeavesTheIndexUntouched`).
* The three construction sites that build a `CommitInput` without `paths` keep their expectation and no longer can fail
  with a `NullPointerException`.

== Amendment (2026-11-21): A Glob Is Literal and a Link Is a Link

The refusal of `*`, `?` and `[` is withdrawn. JGit's `addFilepattern` and `CommitCommand.setOnly` read no glob, so the
refusal protected nothing and refused legitimate file names such as `app/[slug]/page.tsx`, which Stage 4 requires to be
staged as that file; the bind admits the same characters
(link:../../../../../pm-workflow/doc/adr/workflow-input/006-path-and-commit-body-rules-stated.adoc[ADR
workflow-input/006]). A path that begins with `:` (git pathspec magic) stays refused with `PATH_REFUSED`, naming the
path, as the bind refuses it. Besides an empty path, a magic and a directory, `commit` refuses a path that is absolute,
normalises to outside the root, is not in normal form (an empty, `.` or `..` segment) or carries a control character;
the backslash stays refused. The directory check uses `LinkOption.NOFOLLOW_LINKS`: a symbolic link to a directory is
committed as the link, as git records it, instead of being refused as the directory it points to, so a dirty link
`StagingSets` staged by its own name no longer fails the commit with `PATH_REFUSED`; a dangling link is committed as the
link as well. A real directory is still refused. Three further rules close the gaps of that check:

* The parent of a path is confined against the real root: the parent, or its nearest existing ancestor when it does not
  exist, is resolved with `toRealPath` and must lie inside the real root, so `alias/private.txt` below a link `alias` to
  an outside directory is refused before any listed path is staged.
* A link that replaces a tracked directory (the path is a link in the worktree, read without following it) passes the
  tracked-tree guard and is committed as that link; the entries below the replaced directory leave the tree, while a real
  directory and a deleted one stay refused.
* The index is checked for a directory whether or not `HEAD` resolves, so a directory staged in a repository without
  commits and then removed from the worktree is refused; only the head-tree check needs `HEAD`.

The first bullet of the decision and the first consequence above are read with this amendment.
