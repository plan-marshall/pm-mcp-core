= ADR provider-git-primitive 003: The Staging Set Is Derived from the Scope
:nofooter:

== Status

Accepted

== Date

2026-11-21

== Context

The specification's Stage 4 derives the staging set from the scope, never from whatever the checkout holds: for a plan
the dirty paths inside its worktree, for an epic `.marshall/epics/**` and, while it archives,
`.marshall/archived-epics/**`, for the workspace `.marshall/config/**`, `.gitignore` and
`.marshall/project-architecture/**`. A dirty path outside the set is never staged and is a boundary breach. The set is a
set of files. The confinement check of `pm-core` (`PathConfinement`) returns a refused path as a value. The spec named a
type `ScopeKind`, which does not exist; `core.store.ScopeType` holds `PLAN`, `EPIC`, `WORKSPACE` and `PROJECT`.

== Decision

* `StagingSets.derive(ScopeType, Path worktree, Collection<String> dirtyPaths, boolean archiving)` returns
  `StagingSet(staged, outside)`; every dirty path lands in exactly one of the two.
* A path must also satisfy the rule of a commit path (`CommitPathRefusals`, the textual, the file-system and the
  tracked-tree part); a name that fails it — a pathspec magic, a backslash, a control character, a newline, the `dir/`
  entry of an embedded repository, the name of a modified submodule, which the worktree holds as a directory, and a
  tracked directory a file replaced — is `outside`, so the footprint check names it instead of the commit failing on it
  (link:008-the-staging-set-and-the-commit-share-the-path-rule.adoc[ADR 008]).
* It takes the existing `ScopeType`; no `ScopeKind` is added. `PROJECT` has no staging set: every dirty path is
  `outside`, a value, never an exception.
* The directory that holds each path is confined with `PathConfinement.confine(new WorkspaceRoots(worktree, Set.of()),
  directory)`, so "inside the worktree" is exactly the confinement root; a path whose directory is refused, an absolute
  name and a name that is not in normal form (a `.` or `..` segment) are `outside`. The last name is not followed,
  because git records a symbolic link as a link: a dirty link to outside or a dangling link is staged like any other
  file, while a path through a link to outside stays outside (operator decision of 2026-11-21 on the code review).
* The function is what the assembly's `InputBindingContext` calls for the staging-set bound of a `files` input.

== Alternatives Considered

* *A new `ScopeKind` of three members.* Not taken: it would duplicate `ScopeType` and need a mapping at every caller; the
  fourth member `PROJECT` is answered by an empty staging set.
* *Staging every dirty path of the checkout.* Not taken: the specification forbids it, and a path outside the scope
  would reach a commit.
* *Confining the whole path, its last name followed.* Not taken: a tracked link to outside or a dangling link would be
  refused as outside and block the commit of the whole scope with `footprint_violation`, though git commits only the
  link.

== Consequences

* A dirty path outside the set is a breach of check 1 of the footprint check (link:006-the-primitive-checks-the-boundary-half.adoc[ADR 006]).
* A bound `files` entry outside the set is dropped, not refused: the bind owns the refusal (`input_refused`, the rule
  `path.staging`), so `git.stage-and-commit` narrows only and commits the intersection. A test pins that the primitive
  never refuses a bound entry, so a refusal added here fails it.
* A change of a scope's set changes `StagingSets` and its test; no caller holds a copy of the paths.
