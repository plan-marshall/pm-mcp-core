== Purpose

_Requirements:_ link:{docs}/Requirements.adoc#PM-WF-16[PM-WF-16], link:{req}/06-execution.adoc#PM-EXEC-5[PM-EXEC-5]

Package `de.planmarshall.provider.git.primitive` holds the primitives the sub-workflow `git.commit_and_push` runs for its
commit stages — `git.resolve-message`, `git.template-message`, `git.stage-and-commit` — and the return evaluation
`commit-message.evaluate` of the entity kind `commit-message`, together with the pure rules they apply: the commit
message and its trailer, the staging set of a scope and the footprint check. Everything the primitives need from the
world comes through one port, `CommitSite`, which the assembly implements; the package reads no store and builds no git
command line.

The primitives live in the provider module because they build against the primitive SPI of `pm-core` and call the git
contract of this module, which `pm-workflow` must not see
(link:{adr}/001-the-commit-primitives-live-in-pm-provider-git.adoc[ADR 001]).

[#_the_commit_site]
== The Commit Site

A primitive's `WorkflowExecutionContext` names only the scope. `CommitSite` takes that context in every method, so the
assembly resolves each answer per call from the scope id and one stateless instance serves every scope
(link:{adr}/002-one-port-commit-site-resolved-per-call.adoc[ADR 002]):

[horizontal]
`worktreeRoot`, `scopeType`, `archiving`:: The target checkout (the plan's worktree, the shared epic worktree or the main
checkout), its `ScopeType` and the epic's archive flag.
`dirtyPaths`:: The porcelain list of the checkout, repository-relative, with `.marshall/local/**` left out. The git
contract has no `status` operation, so the site answers it.
`localTrailer`, `machineTrailer`:: The stored `commit_trailer` of the project and of the machine, each a
`CommitTrailer.Stored` whose halves may be absent or invalid; empty when the level stores none.
`commitIdentity`, `agentIdentity`:: The operator's `commit_identity`, the author, and the agent identity resolved from the
provider credential, the committer; each empty while none resolves.
`diffSummary`:: The facts of `git.diff-summary`: changed file count, module scope (`null` across several modules) and
suggested types.
`pinnedFilesChanged`, `mainCheckoutBreaches`:: Checks 2 and 3 of the footprint check (<<_the_staging_set_and_the_footprint_check>>).

*Hand-off.* `pm-provider-git` implements none of it. The implementation per scope — the dirty paths through the git
contract, the `local-config.json` values with their fallbacks to `machine-config.json`, the `agent_identity` of the
derived facts store, `entry_baseline` and the pinned files of the enrolled wrappers — belongs to the engine wiring of the
assembly `plan-marshall-mcp`, which also builds the `PrimitiveRegistry` of the four primitives.

[#_the_commit_message_and_the_trailer]
== The Commit Message and the Trailer

`CommitMessages.validate(String)` returns the violations ordered by line, each a `ContentViolation` with its rule key and
line, empty for a valid message: the rules of `ConventionalCommitValidator` of `pm-core` (a blank message, the header
form, the body separation, a `Co-Authored-By:` line in any case and position), the bound of `commit_message[1..2000]`
counted in code points (`commit.length`) and a lone surrogate, which no UTF-8 commit can carry (`commit.lone-surrogate`).

`CommitMessages.withTrailer(String, CommitTrailer)` is the only writer of the trailer line in the production code of this
module. It returns `Appended` with the message, one blank line, `Co-Authored-By: {name} <{email}>` and one final line feed,
or `Refused` naming the line of a trailer the message already holds — in any case, at any position, whatever it names
(link:{adr}/004-the-trailer-is-appended-by-commit-messages-alone.adoc[ADR 004]).

`CommitTrailer.resolve(local, machine)` resolves the name and the email each on its own: the local value, else the
machine value, else the compiled default `plan-marshall <noreply@cuioss.de>`. A stored value that breaks the constraints
of its half (a name of 1 to 128 characters without `<`, `>`, CR or LF; an email of at most 254 characters of the form
`local@domain` without `<`, `>` or white space) is passed over as absent. Each half reports its `TrailerSource`:
`configured`, `default`, or `invalid_ignored` when a stored value was refused and none later was used. The source is for
the commit's audit record and is never rendered in facts.

[#_the_staging_set_and_the_footprint_check]
== The Staging Set and the Footprint Check

`StagingSets.derive(scope, worktree, dirtyPaths, archiving)` puts every dirty path into `staged` or `outside`
(link:{adr}/003-the-staging-set-is-derived-from-the-scope.adoc[ADR 003]). A path is staged only when
`PathConfinement.confine` admits it with the checkout as the one root, it is relative and in normal form (no `.` or `..`
segment), and it belongs to its scope's set:

[cols="1,3",options="header"]
|===
|`ScopeType` |Staging set

|`PLAN` |Every confined dirty path of the plan's worktree.
|`EPIC` |`.marshall/epics/**`, and `.marshall/archived-epics/**` only while the epic archives.
|`WORKSPACE` |`.marshall/config/**`, `.gitignore` and `.marshall/project-architecture/**`.
|`PROJECT` |None: every dirty path is outside.
|===

`FootprintBoundary.check(stagingSet, pinnedFilesChanged, mainCheckoutBreaches)` judges the three checks of Stage 4:
(1) the `outside` paths of the staging set, (2) the pinned build files that changed and (3) the main-checkout paths a
plan changed. Check 1 is decided here; checks 2 and 3 are the site's answers, treated alike
(link:{adr}/006-the-primitive-checks-the-boundary-half.adoc[ADR 006]). The verdict is `Within`, or `Violated` with the
sorted offending files, at most `OFFENDING_FILES_LIMIT` (50), and the count of all of them.

[#_the_message_primitives]
== The Message Primitives

[cols="2,2,4",options="header"]
|===
|Primitive |Outcomes |Behaviour

|`git.resolve-message`
|`ready` (fact `message`), `needs_interactive`
|By `message_mode`: `auto_deliverable` formats `feat(<module>): complete deliverable <N> - <title>` and goes to
`needs_interactive` when the call names no complete deliverable; `step_or_fallback` takes the bound `message`, else
`chore(finalize): apply <step_id> changes`, or `chore(finalize): settle changes` for a caller that is no step;
`interactive` is always `needs_interactive`; `none_assert_clean` is `ready` without a message on a clean checkout and
`needs_interactive` with dirty files. A bound `message` is read only under `step_or_fallback`. A message
`CommitMessages.validate` refuses is never `ready`; it goes to `needs_interactive`.

|`git.template-message`
|`ready` (fact `message`)
|`render(DiffSummary, subject)`: the suggested type of highest priority in `TYPE_PRIORITY`
(`fix > feat > perf > refactor > docs > style > test > chore > ci`), `chore` when none, the module scope when there is
one, and the caller step's subject. A pure function; it decides nothing
(link:{adr}/007-the-template-message-renders-from-facts.adoc[ADR 007]).

|`commit-message.evaluate`
|`valid` (fact `message`)
|The return evaluation of the kind `commit-message`. The message was validated where the link bound it
(`@FreeParam(minLength = 1, maxLength = 2000)`), so a text that is no Conventional Commit or carries a trailer never
reaches it.
|===

All three declare `awaitedEvent() = NONE` and only outcomes of class `SUCCESS`.

[#_git_stage_and_commit]
== `git.stage-and-commit`

`GitStageAndCommitPrimitive` is constructed with a `GitOperations` and a `CommitSite`; its parameters are the final
message without the trailer and the optional `files`. The order of work is fixed:

. The footprint check over the staging set of the scope and the site's breaches. A breach is `failed` with the reason
  `footprint_violation` before anything is staged and before the message is read.
. The staging set narrowed by `files`; an empty set is `nothing_to_commit` without a git call.
. The message checked by `CommitMessages.validate` and given the resolved trailer by `withTrailer`; a refusal is `failed`
  with the reason `message_refused`.
. One call of `GitOperations.commit` with `CommitInput.paths` set to exactly the files to commit
  (link:../adr/provider-git/003-the-commit-is-the-listed-paths.adoc[ADR provider-git 003]), the operator's
  `commit_identity` as the author and the agent identity, else the compiled `plan-marshall-mcp <noreply@cuioss.de>`, as
  the committer. The operator's git `user.*` settings are never read; a missing `commit_identity` is `failed` with
  `commit_failed`.

The message reaches the repository in memory through the contract (`PM-EXEC-5`); no command line is built from a value.

[cols="2,1,3",options="header"]
|===
|Outcome |Class |Meaning

|`committed` |`SUCCESS` |The files are committed; the fact `commit` names the commit.
|`nothing_to_commit` |`SKIP` |Nothing of the staging set is left to commit.
|`hook_failed` |`FAILURE` |The contract answered `CAPABILITY_MISSING`, a hook the native variant does not run; the fact
`hook_failure` carries the detail.
|`attempts_exhausted` |`FAILURE` |The attempt cap is spent. Declared as the exhaustion outcome of
`CycleMeasure.ATTEMPT_CAP`; the engine returns it, the primitive never does.
|`failed` |`FAILURE` |The commit is refused or failed; the reason says why.
|===

The reasons of `failed` are the closed enum `GitStageAndCommitPrimitive.Reason`
(link:{adr}/005-one-failed-outcome-with-a-closed-reason.adoc[ADR 005]):

[cols="2,2,3",options="header"]
|===
|Reason |Condition |Facts

|`footprint_violation` |`footprint_violation` |`offending_files` (at most 50), `offending_count`
|`message_refused` |none |`rule`, `line` (0 for the whole message)
|`commit_failed` |none |`git_outcome`, `detail`; or `detail` alone when no `commit_identity` is configured
|===

Every `GitOutcome` maps to exactly one outcome: `OK` to `committed`, `NOTHING_TO_COMMIT` to `nothing_to_commit`,
`CAPABILITY_MISSING` to `hook_failed`, every other to `failed` with `commit_failed`.

== Invariants and Failure Modes

* *The trailer is written once.* Only `CommitMessages.withTrailer` writes it, and it refuses a message that already holds
  one; `CoAuthoredBySourceScanTest` fails for any other production source of this module that names the key.
* *The boundary comes first.* `git.stage-and-commit` checks the footprint before it stages anything, for every scope; no
  caller reaches a commit around it.
* *Refusals are values.* A refused path, an invalid stored trailer, a refused message and a breach are returned, never
  thrown; no generic exception is caught or thrown. A constructor of a record throws `IllegalArgumentException` only for
  a value that breaks its own invariant (`CommitTrailer` outside its constraints, `DiffSummary` with a negative count,
  `Violated` with an empty or oversized list).
* *Nothing reaches a command line.* The message and the paths reach the repository through the API of the git contract.

What is not in this package: the mapping of `footprint_violation` to the engine condition, the commit attempt counters,
the `change-ledger.jsonl` row, the `head_at_completion` stamp, `freshness_reconcile`, and the CLI variant of the contract
(`git commit -F -`), the only one that runs repository hooks.

== Extending

* A new value a stage needs is a new `CommitSite` method; the assembly implements it in the same change.
* A new cause of a failed commit is a new `Reason` constant with its facts, not a new outcome: an outcome is named only
  where the graph continues differently.
* A new commit primitive joins this package and the `PrimitiveRegistry` the assembly builds; its wire names must pass
  the registry constructor.

== Testing

The primitives are tested over EasyMock doubles of `CommitSite` and `WorkflowExecutionContext`; test data comes from
`cui-test-generator`, the messages and trailers from `CommitMessageGenerator` and `CommitTrailerGenerator` of the
module's generator artifact.

[horizontal]
link:{test}/CommitMessagesTest.java[`CommitMessagesTest`]:: A message without type, a blank one, one of 2001 characters, a
lone surrogate and a trailer line in any case and position are refused naming the line; the result holds exactly one
trailer.
link:{test}/CommitTrailerTest.java[`CommitTrailerTest`]:: The three trailer sources per half and `invalid_ignored` for an
angle bracket, a line break and an empty value.
link:{test}/StagingSetsTest.java[`StagingSetsTest`]:: The staging set per scope with a path outside, `..`, an absolute
path, a non-normal name, a symbolic link that leads out of the worktree (on Linux and macOS), a name shaped like a link
target, which is staged as a plain name, and `.marshall/archived-epics/x` with and without archiving.
link:{test}/FootprintBoundaryTest.java[`FootprintBoundaryTest`]:: The three checks and the bound of the offending files.
link:{test}/GitResolveMessagePrimitiveTest.java[`GitResolveMessagePrimitiveTest`]:: A case per mode and per presence of
`message`; every `ready` message passes `CommitMessages.validate`.
link:{test}/GitTemplateMessagePrimitiveTest.java[`GitTemplateMessagePrimitiveTest`]:: The type priority over a
generator-driven set of summaries.
link:{test}/CommitMessageEvaluatePrimitiveTest.java[`CommitMessageEvaluatePrimitiveTest`]:: The outcome `valid` with the
submitted message.
link:{test}/GitStageAndCommitPrimitiveTest.java[`GitStageAndCommitPrimitiveTest`]:: Against the real `JGitOperations` on a
temporary repository: a plan commits exactly the listed files and leaves an unrelated dirty file, a path outside the
worktree is a footprint violation before any staging, an epic stages `.marshall/archived-epics/**` only while it
archives, exactly one trailer with author and committer read back through `GitOperations.log`, a trailer line is
`message_refused`, nothing staged is `nothing_to_commit`, and every `GitOutcome` is mapped by a test derived from
`GitOutcome.values()` at run time.
link:{test}/CoAuthoredBySourceScanTest.java[`CoAuthoredBySourceScanTest`]:: The trailer key in no production source but
`CommitMessages.java`, with the control that the scan sees the one occurrence there.

Each primitive test also passes its primitive through the `PrimitiveRegistry` constructor.
