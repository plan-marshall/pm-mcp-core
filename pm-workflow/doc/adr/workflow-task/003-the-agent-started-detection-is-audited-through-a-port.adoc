= ADR 003: The `agent_started` Detection Is Audited Through a Port
:nofooter:

== Status

Accepted.

== Date

2026-10-23

== Context

Model Work § A Worker Off Track makes `agent_started` a signal whose action is always `restart`: a process of the
worker's process tree runs an enrolled harness executable or the operator binary `pm-operator`, so a second agent would
run outside every task, tool set and usage record. The runtime records the supervisor's detection with the attempt, the
measurement and the instant, ends the attempt `off_track`, re-offers the task and stores a `security` audit record
naming the executable.

The audit log needs the base directory, its anchor, a clock and the audit lock, which the workflow module does not own;
the protocol itself has to stay testable without them and must not lose the detection when the audit is unavailable.

== Decision

`SecurityAudit` is the port; `AuditLogSecurityAudit` is the adapter that writes the record into the machine's audit log
under the audit lock. `TaskProtocol.agentStarted` records the signal and the off-track end first and then hands the
detection to the port; the port's default `NONE` records nothing.

== Alternatives Considered

1. *Depend on `AuditLog` directly*.
   _Rejected_: the protocol would need the runtime's base directory, anchor and clock, and every test would need an audit
   log.
2. *Return the audit record for the caller to append*.
   _Rejected_: a caller that forgets it loses the security record, which the specification requires with the detection.

== Consequences

* A production wiring must pass `AuditLogSecurityAudit`; with the default no security record is written. The protocol's
  tests use a recording port and `AuditLogSecurityAuditTest` proves the adapter's record.
* A failed audit append propagates to the supervisor after the queue has already been updated. The detection is not
  repeatable through the same lease: the attempt ended, so a second call is refused `job_scope_mismatch`. A caller that
  must not lose the record appends it before the queue update, or retries the record from its own outbox; the port keeps
  that choice with the runtime.
* The record names the executable, the generation, the task and the attempt; it is one `security`/`agent_started`
  line of the hash-chained log.
