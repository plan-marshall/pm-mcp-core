= ADR 009: A question state declares no link
:nofooter:

== Status

Accepted.

== Date

2026-10-27

== Context

`StateBehavior.QuestionWait` carried an optional list of declared links, which the parser accepted after the question
class and its transitions, and which the verifier and the pruner walked like the links of a resting link state. The
target language gives a question state no link: every question state calls the compiled decision unit, whose operator
states carry the operator's links, and a question state's own body routes only the class's resolution outcomes
(link:../../../../doc/specification/workflow-dsl/02-units-jobs-decisions.adoc#question-states[Workflow DSL § Question
States]; link:../../../../doc/specification/workflow-dsl/04-ast-node-model.adoc#static-verification-rules[Workflow DSL §
Static AST Verification Rules], Rule 10).

== Decision

`StateBehavior.QuestionWait` is `(questionClass, transitions)`. `WorkflowParser.parseQuestion` no longer reads links, so
a `link` clause after a question body is refused `STRUCTURE` ("expected a state but found 'link'"). The printer, the
invariants and the pruner drop the component, and the verifier's Rule 10 keeps no question-link branch.

== Alternatives Considered

Keeping the empty list for source compatibility was refused: a field no model can fill invites a later reader to fill
it. A parser-level silent drop was refused: a link the operator cannot follow must not disappear without a refusal.

== Consequences

A question state that needs an operator link is either a resting link state or the decision unit's own operator state;
the two are not mixed. The question-class registry keeps the class's closed outcome set, and the parser's refusal names
the link so the author sees the mistake.
