= ADR 008: Advisories on the Verification Result, Withdrawn
:nofooter:

== Status

Withdrawn by the work package `static-verifier-residuals`. The advisories channel this record added in PLAN-54 is removed together with the only check that used it, the Rule 3 configuration-reachability check (link:004-rule-3-configuration-reachability.adoc[ADR 004]). `VerificationResult` carries violations only.

== Date

2026-10-14

== Context

PLAN-54 added a second component, `advisories`, to `VerificationResult` to report a state or outcome transition that some configuration combinations do not reach, which the specification (Workflow DSL, § Static AST Verification Rules, Rule 3) reports without failing validation. The only producer of advisories was the configuration-reachability check, and that check judged reachability under an activation rule the specification does not state. With the check removed (ADR 004), no finding of the verifier is reported without refusing the unit.

== Decision

`VerificationResult` is the record of `violations` alone, copied immutably and refusing `null`; `passed()` is "no violation". `WorkflowValidator.verify` returns no second list, and `WorkflowEngine` constructs the empty result as `new VerificationResult(List.of())`. There is no shim (pre-1.0, compatibility `breaking`); `plan-marshall-mcp` has no Java reader of the advisories.

== Alternatives Considered

1. **Keeping the channel empty for a future reported-not-refused finding**:
*Rejected*: an always-empty component is an API without a producer; when the specification's Rule 3 report is implemented against a stated activation rule, the channel is designed with it.

2. **A severity on `Violation`**:
*Rejected*, as in PLAN-54: every consumer would have to filter by severity to decide whether a unit passes, and the name `Violation` would no longer mean a violation.

== Consequences

* The canonical constructor of `VerificationResult` takes one list; the tests of the advisories are removed.
* The report of partial configuration reachability is part of the Rule 3 seam (link:006-rule-3-value-activation-gap.adoc[ADR 006]).
