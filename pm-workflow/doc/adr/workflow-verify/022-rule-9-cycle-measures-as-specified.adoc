= ADR 022: Rule 9 Checks the Cycle Measures STEP_LIST and ARCHIVE_STEPS as Specified
:nofooter:

== Status

Accepted. Refines decision 4 of link:002-rule-9-firing-model.adoc[ADR 002] and closes its named limit on `ARCHIVE_STEPS`.

== Date

2026-10-14

== Context

The specification (Workflow DSL, § Static AST Verification Rules, Rule 9 "Cycle measures", and Rule 11a "Progress measure") states:

* "a `STEP_LIST` measure is admitted only on the dispatch hub of a unit with a step list, which every pass settles one step of"; the hub "fires exactly one step and settles it per pass, measured by the unsettled steps of the instance's step list".
* "an `ARCHIVE_STEPS` measure only on the next-work primitive of an epic unit whose archive path commits, lands, and ends in the terminal"; it "is measured, while the epic archives, by the remaining archive steps (commit, land, archived)".

Until the work package `static-verifier-residuals`, `WorkflowValidator` checked `STEP_LIST` only for a unit with a step list, and `ARCHIVE_STEPS` only for the epic scope and a path to a terminal state; ADR 002 named the commit and the landing of the archive path as not checked.

== Decision

1. *`STEP_LIST`*: besides the unit with a step list, every pass of the hub settles exactly one step. A pass is a path that leaves the hub on one of its outcomes and returns to it; it settles the steps completed on its transitions. A path that enters a terminal state, `finalize.merge-gate` or an implicit-failed state leaves the step list instead, and a path that ends early on an `UNSETTLED` or `STEPPED_OUT` outcome hands its step back; neither is a pass. Each outcome of the hub with a pass that settles no step, or more than one, is refused at the hub's transition as `STEP_COMPLETION`.
2. *`ARCHIVE_STEPS`*: besides the epic scope and a path to a terminal state, the archive path commits and lands. A cycle through the state passes a call of the commit sub-workflow `git.commit_and_push`, the commit, and a cycle through it passes a `job` or `composite_job` state, the landing. Each part that is missing is refused at the state as `STEP_COMPLETION`. The commit sub-workflow is named by its unit identifier, as the compiled invariants name it; no state identifier is named, as ADR 007 decided.
3. *No seam option*. Both checks always run: the specification states both measures completely for the syntax tree, so no part of them is left as a seam, and no configuration switches them off.

== Alternatives Considered

1. **Keeping the coarser checks and naming the rest as seams**:
*Rejected*: the specification's statements are decidable on the syntax tree; a seam would leave a hub that fires two steps per pass, or an archive state that never commits or lands, passing.

2. **Recognising the landing by a primitive identifier**:
*Rejected*: the primitive SPI declares no landing, and a primitive identifier in the verifier would be a rule the specification does not state; the landing is the job state the archive path waits on.

3. **Requiring a separate outcome of the archive state for each archive step**:
*Rejected*: the specification names the steps, not the outcomes that reach them; a commit and a landing on the cycles through the state are what the measure counts.

== Consequences

* The refusing fixtures `cycle-measure-step-list-settle.pmwf` (a pass that settles no step) and `cycle-measure-archive-commit-path.pmwf` (an archive state whose cycles pass no commit) pin the two checks; matched controls pin a hub that settles one step per pass and an archive state on the commit and land path. The fixtures `cycle-measure-step-list.pmwf` and `cycle-measure-archive-path.pmwf` keep pinning the coarser checks.
* The passing fixture `every-construct.pmwf` returns to its hub before it fires the next step.
