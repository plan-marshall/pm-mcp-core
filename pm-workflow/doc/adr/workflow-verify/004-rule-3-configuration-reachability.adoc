= ADR 004: Rule 3 Configuration Reachability Enumeration
:nofooter:

== Status

Accepted

== Date

2026-10-12

== Context

Work package `static-verifier-rule-gaps` (Roadmap Milestone 3, PLAN-44) corrects the Rule 3 slice: reachability must hold under every `depends_on_config` combination, and the check PLAN-41 shipped carried a transition-level loop whose predicate is unsatisfiable.

== Decision

1. **Every-combination enumeration**: `configKeysOf` collects every `depends_on_config` key, `configCombinations` enumerates all 2^N assignments, and the active graph per assignment decides reachability. The enumeration stays lean because the grammar admits only small key sets; the bound is documented where the substrate lives.
2. **State-level report only**: a state unreachable under some combination is refused with the exact failing assignment set. The transition-level not-reachable-under-any-combination loop is removed: the enumeration always includes the all-true assignment, under which every link is active, so every base-reachable transition is reachable under at least that combination.
3. **Dropped transition fixture**: the planned transition refusing fixture is dropped as infeasible under the verify-first clause (no transition can be unreachable under every combination, so the fixture cannot be both planted and refused). The drop is named in the pull request body, not hidden.
4. **Enum-valued enumeration seam**: the substrate enumerates Boolean assignments only. Configuration keys with enum (non-Boolean) values would need a product enumeration over each key's value set; that seam is left open and is out of scope here.

== Alternatives Considered

1. **Keeping the transition-level loop as a backstop**:
A check that can never fire costs nothing and might catch a future regression.
*Rejected*: a check with an unsatisfiable predicate is dead code with a live name; it suggests a guarantee the verifier does not provide and draws fixture effort toward an unplantable defect.

2. **Per-state-per-combination graph rebuilds**:
Rebuilding the active graph inside the per-state loop instead of once per combination.
*Rejected*: the same 2^N enumeration would be built once per state per combination; the single pass feeds every state report.

== Consequences

* `CONFIG_REACHABILITY` fires only at state level with the failing assignments named; the existing `config-unreachable.pmwf` fixture keeps pinning it.
* A future enum-valued `depends_on_config` reopens the enumeration shape through the seam named above; the state-level report shape is unchanged by it.
