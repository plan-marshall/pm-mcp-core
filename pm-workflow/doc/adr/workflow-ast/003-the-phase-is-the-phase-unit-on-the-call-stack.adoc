= ADR 003: The Phase Is the Phase Unit on the Call Stack
:nofooter:

== Status

Accepted

== Date

2026-10-28

== Context

The flat plan unit carried the states of all six phases and marked each state with a `phase` clause; a state of a
sub-workflow declared `phase inherit` and took the phase of its caller. `StateNode` therefore carried an optional
phase, `WorkflowDefinition` carried `partVersions`, `CallFrame` carried `callerPhase`, and the plan unit was merged
from seven phase files (`PlanUnitMerger`). The work package `phase-sub-workflows` splits the plan unit into six phase
sub-workflows, so a state can no longer declare a phase of its own: the phase is the phase sub-workflow on the call
stack, and every sub-workflow called within a phase (the land lane, a remediation unit, a chat) has that phase.

== Decision

* `StateNode`, `WorkflowDefinition` and `CallFrame` carry no phase member; the `phase` clause and `phase inherit`
  are removed from the grammar and the printer.
* `de.planmarshall.workflow.ast.Phase` is the closed list of the six phases, each named by the unit it is carried
  by (`phase-1-init` … `phase-6-finalize`); `Phase.ofUnit` answers the phase a unit carries and `Phase.ofCallState`
  the phase the plan unit's call state `phases.<name>` enters.
* The engine derives the phase of a scope from the phase unit on its call stack, then from the plan unit's call
  state; the verifier derives it from the unit that declares the state (`CallGraphExpansion.carriedPhases`).
* The plan unit calls each phase at the entry its call state names; the phase unit's `start` state is the
  authoritative entry for a loop-back that calls a phase again, and the finalize phase's `reentry` outcome is the
  re-entry into execute.

== Alternatives Considered

1. *Keep a `phase` clause on the phase units' states and delete it elsewhere.* Rejected: the phase unit already
   names its phase, so a clause would restate the frontmatter and could disagree with it.
2. *Let each state carry its phase as a computed default of the merged plan unit.* Rejected: that is the mapping the
   package removes; with separate units there is no merged tree to annotate.

== Consequences

A unit is a phase only through its identity, so a phase unit is renamed only with its call sites. The status store
records the wire name of the phase (`phase-<n>-<name>`), never a state's declaration. A new phase is a new `Phase`
constant, a new unit and a new call state of the plan unit. The `phase` clause is refused by the parser, so no
project unit can reintroduce it.
