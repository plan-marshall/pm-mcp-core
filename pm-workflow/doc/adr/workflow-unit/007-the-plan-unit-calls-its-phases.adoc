= ADR 007: The Plan Unit Calls Its Phases Instead of Merging Them
:nofooter:

== Status

Accepted

== Date

2026-10-28

== Context

`DefaultUnitLoader` and `ProjectUnitLoader` assembled the plan unit from seven phase files through `PlanUnitMerger`
and recorded the parts in `WorkflowDefinition.partVersions`. The merge made the phases storage, not structure: a
phase could not be called, its entries and exits were flattened away, and a state's phase had to be declared. The
package makes each phase a reusable sub-workflow of its own.

== Decision

* `PlanUnitMerger` and `WorkflowDefinition.partVersions` are removed; neither loader merges phase files.
* `plan.pmwf` is one unit that calls `phase-1-init.pmwf` … `phase-6-finalize.pmwf` at the entry its call states
  `phases.<name>` name, and `land.pmwf` is a sub-workflow that `phase-5-execute` calls at its `land` entry.
* `UnitFinding` names no `PlanUnitMerger.PLAN_UNIT`; a project unit replaces the default unit of its own identifier,
  the plan unit included, without a merged-part identity.

== Alternatives Considered

1. *Keep the merge and add call states beside it.* Rejected: two representations of the same phases would have to be
   kept in step and would disagree on the entries and exits.
2. *Compose the phases into one instance file as part of this package.* Moved to PLAN-105 by the operator's decision
   of 2026-10-28: the composer keeps the composition it needs to compile and verify a version over the phase units.

== Consequences

The default-unit corpus is twelve units instead of one merged tree. A project that owns a phase unit replaces that
unit; it cannot re-merge. Verification and the engine reach a phase through a call, so the call depth grows by one
(ADR workflow-engine 014) and the compiled invariants are decided over the call-resolved graph (ADR workflow-verify
033).
