== Overview

This document defines the normative JSON and JSONL storage schemas for *plan-marshall-mcp* (`PM-MCP`). Every persisted file includes an explicit `format_version` integer; before 1.0 a binary accepts exactly the current version of each file kind and refuses any other with a named reason, and nothing is migrated on startup (`PM-IMPL-2`, xref:store-schemas/01-format-and-session-log.adoc#format-versioning[Format Versioning & Atomic Write Discipline]). `PM-MCP` shares no store with `plan-marshall`: its stores live under `.marshall/` and `<PM_MCP_BASE>` (`PM-MIG-2`), and it imports nothing from `plan-marshall`. `plan-marshall` formats are not part of this specification: the legacy -> target mapping of the ported-primitive tests lives in test code and test data only (`PM-TEST-2`).

== Parts

* link:store-schemas/01-format-and-session-log.adoc[Format Versioning & Pending Entry] — format versioning, atomic writes, the transaction journal, and the pending entry: its directory with the source directory, the transcript, and the decision stores, and its record with the bootstrap state
* link:store-schemas/02-workflow-state-store.adoc[Workflow State Store] — the workflow state store `mcp/status.json` of every scope, the machine scope's included (plan outcome, epic terminal reason, instance version, the operator's pause, the queue tasks of the current model state, policy counters, waiver requests, gaps, conditions), the plan's history, titles and names, the start of the current phase, and the merge outcome mapping
* link:store-schemas/03-findings-and-review-records.adoc[Phases, Owed Items, Findings & Review Records] — phases as sub-workflows and the phase value of a record, owed items, the findings ledger, the analysis result record, component assessments, review participation, and the review-bot registry
* link:store-schemas/04-epic-and-change-ledger.adoc[Epic & Change Ledger Records] — epic inbox and plan mailbox (the operator's acts on a plan among the messages), the epic ledger records (header with its sources and mode, queue row, findings and watches registers, landing record, kept landing envelope), the epic's drafts in its machine store (an open decomposition and an open review), and the change ledger
* link:store-schemas/05-metrics-and-quality-report.adoc[Metrics & Quality Report] — the metrics store (task rows with the usage per attempt as the harness reports it, the token figures the operator sees) and the quality report record
* link:store-schemas/06-task-and-references.adoc[Task & References Records] — task records, the references and footprint store (with the recorded unplanned changes), and the plan's intent record
* link:store-schemas/07-project-configuration.adoc[Project Configuration (project.json, workflow.json)] — project configuration overview and the team files `project.json` and `workflow.json`
* link:store-schemas/08-project-configuration-local.adoc[Project Configuration (domains.json, build-map.json, local-config.json)] — the team files `domains.json` and `build-map.json`, the operator `local-config.json`, and the project's values over the machine's values
* link:store-schemas/09-derived-facts-and-build-timings.adoc[Derived Facts & Build Timings] — the derived facts store with its fact kinds and the build timings store
* link:store-schemas/10-job-and-lesson-records.adoc[Job & Lesson Records] — the job record (workers included, with their protocol state and delivery record) and the lesson record
* link:store-schemas/11-enrolment-store.adoc[Project Enrolment Store] — the project enrolment store, the project store identity (display name, unenrolment), and the harness enrolment store
* link:store-schemas/12-machine-stores.adoc[Machine Configuration, Credentials & Audit Stores] — machine configuration, consents, the model catalogue and role assignments, the machine's provider defaults and host tools, harness icons, the operator's projects, the credential store, machine state records (the upgrade record and the login environment among them), runtime token and web access records, the report and cleanup journals, and the audit log
* link:store-schemas/13-leases-integrity-testing.adoc[Leases, Integrity Invariants & Script Disposition] — machine lease stores (build and model slots included) and task leases, data layer integrity and concurrency invariants (plan deletion, the evidence-based removal sweeps), and script disposition and ported-primitive tests
* link:store-schemas/14-plan-instance-waivers-questions.adoc[Plan Instance, Waivers, Questions & Evidence] — the composed plan instance with its bound sub-unit copies, its composition log and rules, the plan's overrides, the waiver record and waiver requests, remediation budget accounting, gap records, question records of the decisions with the answers from the terminal client, and the evidence directory with the failure envelope
* link:store-schemas/15-screening-and-grants.adoc[Screening & Access Grants] — the screen verdict cache of the two-level guard for external text and the access grant record
* link:store-schemas/16-task-queue.adoc[Task Queue & Qualification Records] — the project's task queue: the queue task record (kind, role, entity, status, lease, attempts with their generation, off-track signals, consultations, outcome and reason) and the activity journal of a task; the role qualification record and the decision calibration record of a quorum declaration
* link:store-schemas/17-re-planning.adoc[Re-Planning Records] — the plan's pending re-planning trigger, the re-planning records with their evidence keys, the revisions the operator accepted in a chat, and the follow-up plan records
* link:store-schemas/18-decision-records.adoc[Decision Records] — the append-only decision store of every scope and entry (`decided` and `corrected` lines, the operator's answers among them) and the content-addressed facts snapshots of judgment decisions
