[#endpoint-harness]
== A Model on This Machine
_See Requirements link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-CLIENT-2[PM-CLIENT-2: Data-Driven On-the-Fly Profile Translation], link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-2[PM-ARCH-2: Local-by-Design & Zero External Cloud Dependency], link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-WORK-1[PM-WORK-1: Roles as Configuration]_

A model that a program of the machine serves over HTTP on the loopback interface (an operating system's own model server, or a local model runner) is a harness of its own kind, the *endpoint harness*. It has no tools, no MCP connection, and no session, so it runs exactly one role class, `zero_tool` (the screener and the judge, link:01-profile-schema.adoc#role-classes[Role Classes of a Harness]; the commit message and the change type where an artifact of their roles sets the class, link:../model-work/01-roles-and-configuration.adoc#closed-task-in-band[Model Work Specification, A Closed Task without Tools]), and no other. It is described by an endpoint profile of the same profile sets, verification and override rules as a harness profile. The runtime never starts, stops or configures the serving program, and no task text reaches a program other than the enrolled one. Nothing an endpoint is given leaves the machine, so untrusted text screened on it reaches no model provider. A judgment role, which answers a typed question with a probability per option, is deferred (link:https://github.com/plan-marshall/plan-marshall-documentation/blob/main/doc/later-improvements.adoc#L-39[L-39]).

* *Started by the operator, never by `PM-MCP`*: the serving program runs under the operator's own account and its own
  terms; the runtime only sends requests to it and checks before each request that the program listening on the profile's
  port is the enrolled one.
* *No shipped endpoint profile*: the release ships no endpoint profile. The operator adds one through the onboarding,
  and roles are assigned to it like to any harness (link:../model-work/01-roles-and-configuration.adoc#role-assignment[Model
  Work Specification, Role Assignment]).
* *A judge on an endpoint is the operator's risk*: the assignment is allowed, and the role views of both clients mark a
  `judge` on an endpoint harness as ungraded wherever its assignment is shown.

[#endpoint-request]
=== The Request

A task of a `zero_tool` role on an endpoint harness is one HTTP request, composed by the server:

* *What it sends*: the launch prompt of a `zero_tool` worker (link:../model-work/04-worker-launch.adoc[Model Work Specification, Worker Launch]) as the system message and the task input as the user message; the model of the role's effective configuration; streaming explicitly off; the role's result schema as the response format where `result_schema` is `enforced` or `advisory`. It sends no `tools` member and no tool choice, whatever the endpoint accepts. Every request value the endpoint has a default for is sent explicitly, so no default of the serving program decides how the task runs.
* *What fits*: the role's context budget on an endpoint harness is `context_tokens` less `answer_reserve_tokens`, and the batch of a screening (link:../model-work/07-untrusted-text-screening.adoc#batch-v1[Model Work Specification, Batch Format]) is packed to it like an envelope to its budget. A role artifact whose launch prompt alone does not fit is invalid on that harness and counts as undefined (link:../model-work/01-roles-and-configuration.adoc[Model Work Specification, Roles & Configuration]). Any other task whose in-band input does not fit (a diff, a request, a judge's item) closes before a request with `input_too_large` and is never cut to fit (link:../model-work/01-roles-and-configuration.adoc#model-caller[Model Work Specification, The Model Caller]).
* *What it accepts*: the answer is validated against the result schema by the server, never trusted because the endpoint enforces a schema. An answer that does not validate, a refusal text, an HTTP error, or a timeout ends the attempt like a worker without a valid result, and the task's own rules apply (a screening fails closed and leaves its sources `unscreened`, link:../model-work/07-untrusted-text-screening.adoc#screen-stored[Model Work Specification, Screened Once Stored]). An endpoint that does not answer its readiness check counts as a start failure (link:../model-work/03-supervision-and-recycling.adoc#start-failure-guard[Model Work Specification, Start-Failure Guard]).
* *Usage*: the token counts of the answer's usage object are recorded per task; a count the answer lacks is `unmeasured` (link:01-profile-schema.adoc#token-usage[Tokens, Not Money]).

[#endpoint-enrolment]
=== Enrolment

An endpoint harness is enrolled like a harness started as a process, and before each request
the runtime checks that the process owning the listening socket of `base_url` runs the enrolled executable; another
program on the port refuses the request before it is sent (fate `refused`, reason `harness_not_enrolled`).

[#weights-identity]
=== Weights Identity
_See Requirements link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-WORK-6[PM-WORK-6: Role Qualification], link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-CLIENT-2[PM-CLIENT-2: Data-Driven On-the-Fly Profile Translation]_

Where a profile's `weights_probe` is not `null`, the identity of the weights of every allowed
model is read at enrolment, at every start of the runtime and at every project setup run, and recorded in the harness
enrolment beside the model. It is a member of the qualification digest, so a model whose weights changed is unqualified
until it is graded again, and the change is audited `harness_updated`, naming the model and both identities.

[#endpoint-verification]
=== Verification of an Endpoint

The stages `identity`, `launch`, `classes` and `limits` of `pm-operator profile verify` and of the
onboarding's `harness.verify-profile` are decided from what the runtime observes. A failed `identity` or `launch` stage
refuses the draft; `classes` and `limits` record what they found.
