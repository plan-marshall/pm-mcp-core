[#derived-facts]
== Derived Facts Store (`<PM_MCP_BASE>/projects/<project_id>/derived-facts.json`)
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-EXT-6[PM-EXT-6: Configuration Split by Owner Class (Team, Operator, Server State)]_

A value the server can observe is derived, never configured; an override exists only where a derivation input can be ambiguous (`project.json` `ci_provider`, `merge_method` and `base_branch`, `domains.json`, `local-config.json` `envelope_budget_tokens`). The store is written under its own lock `locks/derived-facts.lock`, which comes late in the total lock order (after the local configuration lock, xref:13-leases-integrity-testing.adoc#lock-free-snapshot-reads[Lock-Free Snapshot Reads, Transaction Locks & Leases (`PM-IMPL-7`)]). A refresh triggered by a read inside a plan, epic, or workspace transaction (a guard evaluation included) takes it in its own transaction after the caller's lock is held; the lock manager asserts the order within one transaction only and does not see the caller's keys.

`derived-facts.json` is a per-project store of owner class *cache*: its entry records are read by a strict codec, and deleting the file only forces re-derivation. Its kinds are a closed enumeration, each bound to its value schema at run time by a registry; a new kind is a specification change, an enum constant and a registration.

A local derivation is recomputed whenever its `input_digest` changes; a network derivation holds for the validity period of link:../timeouts/03-retention-harness-config.adoc#network-derivation-validity[Timeouts & Budgets Specification, Network Derivation Validity] and is additionally refreshed by the project-setup reconcile and at a plan's start (`start.open`); a failed derivation keeps the last value with `state: stale` (or fails with `state: failed` when no value was ever derived) and records its failure, and every gate or guard that depends on a stale or failed fact evaluates `indeterminate` (`COULD_NOT_EVALUATE`, the `guard_indeterminate` condition), never pass; and `agent_identity` is operator-only, shown to the operator in both clients and used server-side (committer identity, setup checks), never in a model-facing representation, resource (including `pm://project/config`) or tool result.

* *Class per entry*: The entry's `source.class` records how its value was obtained. `ci_provider` is `local` when the remote host alone decides it and `network` when a provider probe did; `base_branch_default` is `network` once the provider's default branch confirmed the local `origin/HEAD`. A network entry follows the network validity rule.
* *Provider derivations*: Network kinds are derived through the CI contract's provider integration (the provider module `pm-provider-ci`, link:../../../pm-providers/pm-provider-ci/doc/developer/provider-ci.adoc[`provider.ci`]; the effective variant of the provider, xref:08-project-configuration-local.adoc#local-config[Operator Local Configuration]) with the agent credential; a derivation the credential is not permitted to perform fails (`state: failed`, `failure.reason` naming the missing permission), and the dependent gates evaluate `indeterminate`.

[#derived-fact-kinds-discovery-calibration]
=== Derived fact kinds: `module_discovery`, `cost_calibration`

The value schemas of the two fact kinds `module_discovery` and `cost_calibration`. Both are local derivations, keyed by kind alone (no qualifier), and follow the entry rules above: deleting the store only forces a re-crawl and a recalibration.

*`module_discovery`*: the structural snapshot of link:../domain-extensions/03-module-discovery.adoc#_server_owned_module_discovery_enrolled_discovery_jobs[Domain Extensions Specification, Server-Owned Module Discovery]. `input_digest` is the descriptor tree hash over the live descriptor content of the worktree the discovery ran in, the descriptor set of each build system listing every file its discovery job reads (link:../domain-extensions/03-module-discovery.adoc#_server_owned_module_discovery_enrolled_discovery_jobs[Domain Extensions Specification, In-Process Crawl vs. Lazy Discovery Jobs]); the snapshot is a cache, never the gatekeeper (a module directory present on disk but absent from it is still discovered). Facts that only a build system's discovery job provides (its plugins, source sets, profiles, and inter-module and external dependencies) are added under the module when that job ran, are keyed in addition by the digests of the job's enrolled template, of the captured build environment, and of the build tool's user settings file the job reads, are dropped when the descriptor tree hash or any of these digests changes, and are `unknown` while the job could not run.

The schema of the `module_discovery` value is the file `fact-module-discovery.schema.json` in `pm-core/src/main/resources/de/planmarshall/core/store/`, beside the codec of the derived facts store, `DerivedFactsCodec`:

*`cost_calibration`*: the calibrated size-to-token table of the envelope sizing (link:../model-work/06-envelopes-questions-deadlines.adoc#cost-sizing[Model Work Specification, Cost Sizing]), recomputed by `record-metrics` from the measured `metrics.json` population of the project's completed plans; `input_digest` covers the ids and digests of the metrics stores in that population. Absent or `failed`, the compiled table applies with `basis: uncalibrated`; every figure derived from the table carries the basis of the table it used.

[#build-timings-store]
== Build Timings Store (`<PM_MCP_BASE>/projects/<project_id>/build-timings.json`)

The learned budgets of one project (link:../job-runtime/03-parsers-and-gates.adoc#_adaptive_timeout_learning[Job Runtime Specification, Adaptive Timeout Learning]; allocation in link:../timeouts/01-job-budgets-and-waits.adoc#job-budgets[Timeouts & Budgets Specification, Job Budgets]), keyed by the canonical budget key. It lives in the per-project machine store, so a moved checkout keeps its budgets; there is no machine-level timings store. Written only by the runtime at job fate, under `projects/<project_id>/locks/build-timings.lock` (xref:13-leases-integrity-testing.adoc#lock-free-snapshot-reads[Lock-Free Snapshot Reads, Transaction Locks & Leases (`PM-IMPL-7`)]). A key that module discovery no longer yields is pruned when the discovery snapshot changes.
