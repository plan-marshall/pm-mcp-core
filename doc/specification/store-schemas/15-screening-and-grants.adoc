[#screen-verdict-cache]
== Screen Verdict Cache (`screen-verdicts.jsonl`)
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-SEC-1[PM-SEC-1: Two-Boundary Security Model & Untrusted Content Containment]_
_Implementation watch: link:../../implementation-watch/model-work.adoc#PM-WATCH-DISP-35[PM-WATCH-DISP-35]_

External text, content from outside the machine (issue and pull request titles and bodies, review comments and bot findings, analysis-provider messages, upstream MCP results entering a store), passes two guards before it reaches a model as content; what the operator wrote in a client and what is on this machine (the checkout, documents the operator chose) is trusted and never screened (link:../model-work/07-untrusted-text-screening.adoc#local-trusted[Model Work Specification, What Is on This Machine Is Trusted]). The two guards are the server's deterministic level-1 validator, which cleans it and reports every change, and the level-2 screener, a fresh worker of the `zero_tool` role `screener` that returns a closed verdict per item (link:../model-work/07-untrusted-text-screening.adoc#screener[Model Work Specification, Screener Job]). The screener can only restrict: an item whose verdict is missing, extra, or unparseable counts as `suspicious`. Screened text is still delivered marked untrusted.

* *One Batch per Firing*: Every source unit and every gather firing that ingests external text builds one screening batch (named schema `batch-v1`, link:../model-work/07-untrusted-text-screening.adoc#batch-v1[Model Work Specification, Batch Format]) over its new items. A source of a start is screened only once it is stored: it is fetched by a bounded job, passed through the level-1 validator, stored in the source directory marked unscreened, and its batch is built from the stored files (link:../model-work/07-untrusted-text-screening.adoc#screen-stored[Model Work Specification, Screened Once Stored]; link:../filesystem-layout/03-project-store.adoc#source-directory[Filesystem Layout Specification, The Source Directory]). The batch is persisted with the records it came from (the finding records with their `batch_id`; for a source, its verdict in the source manifest `sources/sources.json`) and is not stored separately; `batch_id` is a per-scope counter (`BT-<n>`) recorded on each finding record of the batch and in this cache.
* *Cache*: One append-only file per scope, `screen-verdicts.jsonl` in the plan directory, in `epics/<epic_id>/`, and in `workspace/` (which also serves the pending entries of the project), written in the transaction that settles the screener task. Before a batch is sent, every item whose SHA-256 has a verdict in the scope's cache takes it and is left out; only uncached items are screened, split into several screener tasks above the screening split bound (link:../timeouts/03-retention-host-config.adoc#screening-split-bound[Timeouts & Budgets Specification, Screening split bound]). Only verdicts the screener returned are cached; an item without a returned verdict (worker failed, timed out, or answered without the item) is not cached and is screened again by the next firing. The `start.create-scope` transaction of a start writes the verdicts of its sources into the new plan's or epic's cache as part of the new scope.
* *Effect on a source of a start*: its verdict is written into the source manifest, and no model but the screener reads the source before the verdict is `clean` or the operator accepted it. A `suspicious` source is shown with its flagged spans in an operator wait (`source-<kind>.flagged`), where the operator accepts it (used still marked untrusted, recorded with the operator's reason and audited `screen_accepted`) or removes it. A screener that fails, or a role `screener` with no qualified configuration, leaves the source *unscreened* with the cause, never `suspicious` in its place (`source-<kind>.unscreened`): the operator tries again, removes it, or accepts it explicitly as untrusted, recorded and audited like an accepted flagged source (link:../state-catalogue/09-bootstrap-and-lessons.adoc#state-catalogue-source[State Catalogue Specification, Source States]).
* *Effect inside a scope*: a `suspicious` item, and an item counted `suspicious` because the screener returned no verdict for it, is withheld: only its structured fields and `withheld: flagged by screener` are delivered, a withheld finding stays `pending`, and the unit ends through its budget and fallback unless a `met` waiver of its gate lets the plan proceed (xref:03-findings-and-review-records.adoc#_findings_ledger_record_findings_jsonl[Findings Ledger Record]).
* *Integrity*: The cache is covered by its scope's digest sidecar (xref:13-leases-integrity-testing.adoc#store-digest-verification[Store Digest Verification Against Out-of-Band Edits]); flagged spans are operator and audit data, shown to the operator in both clients and never rendered to a model.

[source,json]
----
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://cuioss.de/plan-marshall-mcp/schemas/screen-verdict.json",
  "title": "ScreenVerdictRecord",
  "type": "object",
  "required": ["format_version", "sha256", "verdict", "spans", "batch_id", "queue_task_id", "screened_at"],
  "additionalProperties": false,
  "properties": {
    "format_version": { "type": "integer", "const": 1 },
    "sha256": { "type": "string", "pattern": "^[0-9a-f]{64}$", "description": "SHA-256 of the level-1-cleaned text; the cache key within the scope." },
    "verdict": { "type": "string", "enum": ["clean", "suspicious"] },
    "spans": {
      "type": "array",
      "description": "suspicious only: the flagged spans of the cleaned text; empty for clean.",
      "items": { "type": "object", "required": ["start", "end", "reason"], "additionalProperties": false, "properties": { "start": { "type": "integer", "minimum": 0 }, "end": { "type": "integer", "minimum": 0 }, "reason": { "type": "string", "maxLength": 200 } } }
    },
    "batch_id": { "type": "string", "pattern": "^BT-[0-9]+$" },
    "queue_task_id": { "type": "string", "pattern": "^qt-[0-9a-f]{16}$", "description": "The screener task (role screener) that returned the verdict." },
    "screened_at": { "type": "string", "format": "date-time" }
  }
}
----

[#grant-record]
== Access Grant Record (`grants.jsonl`)
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-SEC-2[PM-SEC-2: Workspace Confinement & Path Traversal Prevention]_

A plan reads or writes only its own project. Access to another enrolled project (its checkout, or its archived plans), the read-only provider reads of an organisation, group, or repository outside the project (link:../credentials-and-enrolment/01-provider-credentials.adoc#cross-repository-reads[CLI, Coordination & Security Specification, Cross-Repository Reads]), and the read of an issue or a pull request of another repository named as a source of a start (link:../state-catalogue/09-bootstrap-and-lessons.adoc#issues[State Catalogue Specification, Issues by Number or URL]) exist only through an operator grant. A grant is an operator act of either client, given on the operator's own initiative or as the act of the hold that an access without a grant raises (`pm-operator grant-access <plan_id> <project_id> read|read-write --reason <text>`, or `pm-operator grant-access <plan_id> --org <owner>|--repo <owner>/<name> read --reason <text>` in the terminal; link:../../../../plan-marshall-documentation/doc/specification/cli-and-security/02-operator-channel.adoc#operator-channel-isolation[CLI, Coordination & Security Specification, Operator Channel Isolation]). The runtime appends one line to the append-only `grants.jsonl` of the store the grant belongs to: a plan's grant to `plans/<plan_id>/grants.jsonl`; a source's grant given once, for that start, to the pending entry's `pending/<entry_id>/grants.jsonl`, which moves into the plan's store at `start.create-scope`; a source's grant given for the project to `workspace/grants.jsonl`, which every later start of the project reads. The runtime executing the act is its only writer, no link or primitive writes it, and every line is mirrored into the audit log (`access_granted`, xref:12-machine-stores.adoc#audit-log[Audit Log]). The model never requests a grant: an access to another project or repository without a grant for the needed access raises the `precondition_unmet` condition (reason `grant_missing`), held for the operator with the grant as its act (link:../state-catalogue/01-conventions-generic-conditions.adoc#holds[State Catalogue Specification, Holds and Their Acts]), whose bounded `retry` re-checks the grants before the phase's fallback. A grant holds until the plan ends, a start's grant until its start ends, and a project's until the project is released or unenrolled: there is no revocation verb and no revoking record, and ending the plan is the only way to stop a plan's grant. It is refused for the plan's own project, an unenrolled project, an ended plan (`plan_ended`), and a provider target with another access than `read`. A record names exactly one target: `project_id`, `org`, or `repo`, a repository of another forge with its `host`. A read under a grant uses the credential of that forge where the operator has one, else none for a public issue. The store is covered by the digest sidecar of its scope.

[source,json]
----
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "https://cuioss.de/plan-marshall-mcp/schemas/grant-record.json",
  "title": "AccessGrantRecord",
  "type": "object",
  "required": ["format_version", "access", "reason", "operator", "at"],
  "oneOf": [
    { "required": ["project_id"], "not": { "anyOf": [ { "required": ["org"] }, { "required": ["repo"] }, { "required": ["host"] } ] } },
    { "required": ["org"], "properties": { "access": { "const": "read" } }, "not": { "anyOf": [ { "required": ["project_id"] }, { "required": ["repo"] }, { "required": ["host"] } ] } },
    { "required": ["repo"], "properties": { "access": { "const": "read" } }, "not": { "anyOf": [ { "required": ["project_id"] }, { "required": ["org"] } ] } }
  ],
  "additionalProperties": false,
  "properties": {
    "format_version": { "type": "integer", "const": 1 },
    "project_id": { "type": "string", "pattern": "^[a-z0-9][a-z0-9-]{1,62}[a-z0-9]$", "description": "The other enrolled project the plan may access." },
    "org": { "type": "string", "pattern": "^[A-Za-z0-9][A-Za-z0-9._/-]{0,254}$", "description": "The organisation (GitHub) or group path (GitLab) at the plan's provider whose repository list and code search the plan may read (ci.org-repos, ci.code-search)." },
    "repo": { "type": "string", "pattern": "^[A-Za-z0-9][A-Za-z0-9._/-]{0,253}/[A-Za-z0-9._-]{1,100}$", "description": "The repository <owner>/<name> whose files, labels, issues, and pull requests the plan or start may read (ci.repo-file, ci.labels, ci.issue-view)." },
    "host": { "type": "string", "pattern": "^[a-z0-9.-]{1,253}(:[0-9]{1,5})?$", "description": "repo only: the forge's host when it is not the project's provider, resolved from a source's URL." },
    "access": { "type": "string", "enum": ["read", "read-write"] },
    "reason": { "type": "string", "minLength": 1, "maxLength": 2000 },
    "operator": {
      "type": "object",
      "required": ["channel", "os_principal"],
      "additionalProperties": false,
      "properties": {
        "channel": { "type": "string", "enum": ["cli", "web"] },
        "device_id": { "type": ["string", "null"], "pattern": "^dev-[0-9a-f]{12}$" },
        "os_principal": { "type": "string" }
      }
    },
    "at": { "type": "string", "format": "date-time" }
  }
}
----
