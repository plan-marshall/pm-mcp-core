[#state-catalogue-decomposition]
== Decomposition: `decomposition`
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-WF-15[PM-WF-15: Epic Creation, Server-Started Plans & Cross-Plan Merge Mutex]_

Declared in `decomposition.pmwf` (`scope subworkflow`, compiled only), called by `epic.decompose` (xref:06-setup-epic-other.adoc#state-catalogue-epic[Epic Workflow]) for the epic's first decomposition, for the operator's _decompose again_ with its instruction, and for a re-cut that adds, drops, or re-scopes a plan, with the re-cut's proposal; exits `done` (the decomposition committed) and `held` (its drafting role failed). Its states have the phase value `epic`. The draft and the operator's decisions on it are kept in the epic's machine store (`epics/<epic_id>/decomposition.json`) until committed, so leaving and a restart resume the review where it stopped, in either client; nothing is committed before the operator agrees and every check passes, and the epic starts no plan before its first decomposition is committed. A later run keeps what shipped, what runs, and what is paused: it changes only staged rows and shows each change against the staged row it replaces. Every change a model proposes reaches the draft only through the operator's read-back (link:../model-work/08-epic-coordination.adoc#decomposition-review[Model Work Specification, The Decomposition Is Reviewed]).

[#state-catalogue-review]
== Review: `review`
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-WF-15[PM-WF-15: Epic Creation, Server-Started Plans & Cross-Plan Merge Mutex]_

Declared in `review.pmwf` (`scope subworkflow`, compiled only), called by `epic.review` over one of the epic's registers, findings (a problem no plan owns yet) or watches (an observation to check again, with its trigger) (link:../model-work/08-epic-coordination.adoc#findings-watches[Model Work Specification, An Epic's Findings and Watches]); exit `done`. Its states have the phase value `epic`. Its tasks are those of the epic's planning role `decompose`; every change a model proposes reaches the register only through the operator's read-back, and the planning role reads the items as data, an item that came from outside the machine still marked untrusted. The dispositions made so far are kept in the epic's machine store (`epics/<epic_id>/review.json`) until committed, so leaving resumes the review where it stopped, in either client; they are written to the ledger in one write, and a promoted item stages a row under the same surface checks as the decomposition (link:../model-work/08-epic-coordination.adoc#epic-review[Model Work Specification, The Review]).
