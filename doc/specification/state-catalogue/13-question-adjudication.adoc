[#state-catalogue-adjudicate]
== Unit `adjudicate.decisions`
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-WF-18[PM-WF-18: Question Recommendation Score & Decision Quorum]_

The adjudication, its decision declarations, the blind input, the decision rule, and the record are specified in link:../model-work/10-decision-quorum.adoc#adjudication[Model Work Specification, Ask or Quorum]; the unit and its binding in link:../workflow-dsl/02-units-jobs-decisions.adoc#question-adjudicate-unit[Workflow DSL Specification, Adjudication Unit]. The unit (`adjudicate-decisions.pmwf`, designable; its `decide` lines declare per decision kind `ask` or a quorum, link:../model-work/10-decision-quorum.adoc#decision-declarations[Model Work Specification, Decision Declarations]) is run by every question state of every scope (a plan's question states run the unit the project resolves by level, the question states of the epic, the setup, and the starts the default unit) for the scope's new question set before the question state's call of `decision` delivers it (xref:01-conventions-generic-conditions.adoc#_state_kinds[State Kinds, question state]): `init.sibling-collision`, `init.domain-choice`, `refine.awaiting_answers`, `outline.awaiting_answers`, `outline.review`, `execute.task-question`, every `<state>.asked`, and the question states of the project setup. Its states have the phase of their caller and are named `adjudicate.<state>`; no state of the unit waits for the operator. Exit contract: `decided` and `escalated`; the engine routes `stepped_out` like `escalated`.

|[[state-adjudicate.check]]`adjudicate.check`
|inherit
|`auto`
|Entering a question state (start state, the new question set bound).
|`adjudicate.check`: for every question of the set its kind is declared `quorum`, the declaration passes the validation and is calibrated, every listed role is available and qualified, and a listed asking role's confidence reaches the score. A set whose kinds are declared `ask` ends `escalated` and records nothing.
|`eligible` -> `adjudicate.vote`; `ineligible` (reason `kind_ask`, `quorum_invalid`, `calibration_failed`, `role_unavailable`, `role_unqualified`, or `below_score`) -> `adjudicate.escalated`.
|link:../model-work/10-decision-quorum.adoc#adjudication[Model Work Specification, The Adjudication]

|[[state-adjudicate.vote]]`adjudicate.vote`
|inherit
|`job`
|`adjudicate.check` (`eligible`).
|`job llm vote role each adjudicate.vote-roles`: one fresh task per listed role of the set's quorum declarations other than the asking role, each on its own entity `vote-<question_set>-<role>` with the blind facts of the questions whose declaration lists it and one closing link `submit:vote`, recording a vote per option of each part (the runtime derives each option's support from them). The declared vote wait is the vote tasks' own deadline: a task still open when it passes closes `lost`, so the state awaits only the end of its tasks (`TASK_SETTLED`). The return evaluation records each answer; a task without a valid answer, a `lost` one included, is a missing vote. An empty list settles `collected` at once.
|`collected` -> `adjudicate.decide`; `lost` (no task of the list could be served) -> `adjudicate.escalated`.
|link:../model-work/10-decision-quorum.adoc#blind-input[Model Work Specification, Blind Input]; link:../timeouts/01-job-budgets-and-waits.adoc#vote-wait[Timeouts & Budgets Specification, Vote Wait]

|[[state-adjudicate.decide]]`adjudicate.decide`
|inherit
|`auto`
|`adjudicate.vote` (`collected`).
|`adjudicate.decide-agreement`: the decision rule per question of the set, over the votes of its declaration's listed roles (the asking role's recommendation where it is listed).
|`agreed` (every question decided) -> `adjudicate.decided`; `not_agreed` (reason `role_unavailable`, `disagreement`, or `below_score`) -> `adjudicate.escalated`.
|link:../model-work/10-decision-quorum.adoc#decision-rule[Model Work Specification, Decision Rule]

|[[state-adjudicate.decided]]`adjudicate.decided`
|inherit
|`terminal`
|`adjudicate.decide` (`agreed`).
|Terminal `decided` (class `success`): its transaction writes one `question.adjudicate` decision record per question (reason `agreement`, every vote), the set's `adjudicated` lines naming them, and answers every question with its agreed option, `channel: quorum`; the question state's call resolves `answered` without delivering the decision.
|Returns `decided` to the question state.
|link:../model-work/10-decision-quorum.adoc#adjudication-record[Model Work Specification, Record, Delivery & Audit]

|[[state-adjudicate.escalated]]`adjudicate.escalated`
|inherit
|`terminal`
|`adjudicate.check` (`ineligible`); `adjudicate.vote` (`lost`); `adjudicate.decide` (`not_agreed`).
|Terminal `escalated` (class `success`): where a quorum voted, its transaction writes one `question.adjudicate` decision record per question with the reason and the votes taken, the set's `adjudicated` lines naming them; the decision then carries the support of each option.
|Returns `escalated` to the question state, whose call of `decision` delivers the set to the operator as one decision (xref:16-decision.adoc#state-catalogue-decision[Decision]).
|link:../model-work/06-envelopes-questions-deadlines.adoc#decision-structure[Model Work Specification, The Decision Structure]
