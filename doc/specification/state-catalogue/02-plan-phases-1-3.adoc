== Plan Workflow

The plan unit (`plan.pmwf`) is a workflow of the six phase sub-workflows `phase-1-init.pmwf`, `phase-2-refine.pmwf`, `phase-3-outline.pmwf`, `phase-4-plan.pmwf`, `phase-5-execute.pmwf` (which calls the land lane's `land.pmwf`), and `phase-6-finalize.pmwf`, called `init` … `finalize` for short; it calls `init` first, and each phase's outcome decides its next call (xref:18-plan-unit-axes-short-landings.adoc#state-catalogue-plan-unit[Plan Unit]; link:../workflow-dsl/02-units-jobs-decisions.adoc#workflow-definition-units[Workflow DSL Specification, Workflow Definition Units]). The start state of `init` is `init.classify`. Each plan executes its own composed, versioned plan instance of these templates, each resolved by level (link:../store-schemas/14-plan-instance-waivers-questions.adoc#plan-instance[Store Schemas Specification, Plan Instance]); version 1 is composed when its start creates the plan (`start.create`, xref:09-bootstrap-and-lessons.adoc#state-catalogue-bootstrap[Starts]), with the variants of the plan behaviour axes the plan, the project, or the machine sets bound and the others pruned with the reason `plan_default` (link:../workflow-dsl/09-plan-instance.adoc#plan-axes[Workflow DSL Specification, Plan Behaviour Axes]). Every model state names a role of the default role set; the role per state and its fallback while unqualified are listed in link:../phase-workflows/01-planning-phases-1-2.adoc#phase-roles[Phase Workflows Specification, Model Work per State]. The lane topology is specified in link:../phase-workflows/01-planning-phases-1-2.adoc#_lifecycle_topology_phases_14[Phase Workflows Specification, Lifecycle Topology]. Every source is gathered, stored in the entry's source directory, and, if it comes from outside the machine, screened over the stored copy by its source unit before the plan exists (xref:09-bootstrap-and-lessons.adoc#state-catalogue-source[Source Units]), so no plan state waits for a source; the models of the plan read the sources in the plan's source directory. A recipe's plan runs the recipe's own workflow (link:../domain-extensions/05-recipes-and-extension-points.adoc#recipe-workflow[Domain Extensions Specification, A Recipe Is a Workflow]).

[#state-catalogue-init]
=== Phase 1: `init`

The init questions are server-raised question records of class `init`, asked as decisions by question states (xref:01-conventions-generic-conditions.adoc#_state_kinds[State Kinds, question state]). Every answer returns to the re-entrant `init.classify`, which reads it and decides; an option whose effect is the `returned` route leaves it through its outcome `returned` into `plan.return`. Every other option of the plan that no level sets is asked where the plan first needs it, in `init.options` (link:../phase-workflows/01-planning-phases-1-2.adoc#_plan_source_contracts[Phase Workflows Specification, Plan Source Contracts]).
