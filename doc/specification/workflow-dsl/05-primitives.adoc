== Typed Java `Primitive<P, R>` Interface & Transition Validation
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-WF-6[PM-WF-6: Independent Server-Side Transition & Parameter Validation]_

[#primitive-spi-contract]
=== `Primitive<P, R>` SPI Contract

Every deterministic server operation is encapsulated as a stateless Java `Primitive<P, R>`; the SPI lives in `pm-core`, the plan-domain primitives in `pm-workflow`, and the `git.*` and `ci.*` primitives in the provider modules (link:../../../../plan-marshall-documentation/doc/specification/module-structure.adoc#modules[Module Structure]):

[source,java]
----
package de.planmarshall.core.spi;

import java.util.Map;
import java.util.Optional;
import java.util.Set;

public enum OutcomeClass { SUCCESS, SKIP, FAILURE, INDETERMINATE, UNSETTLED, STEPPED_OUT }

/**
 * The external event a primitive waits for before its outcome can change (Rule 11b).
 * OPERATOR_WAIVER: an operator-written waiver record or the operator's decline (the waiver wait);
 * OPERATOR_ACT: an act of the operator through an operator link of an operator wait;
 * EXTERNAL_STATE: a re-observation of a provider, a remote, or the checkout;
 * QUESTION_ANSWER: an answer to a decision from either client of the operator, or a quorum's;
 * TASK_SETTLED: the end of a task of a job llm state (its closed task outcome).
 */
public enum AwaitedEvent {
    NONE, JOB_SETTLED, TASK_SETTLED, OPERATOR_WAIVER, OPERATOR_ACT, MODEL_SUBMIT, TIME, EXTERNAL_STATE, QUESTION_ANSWER
}

public interface OutcomeReason {
    Set<String> MAPPABLE_CONDITION_KINDS = Set.of("footprint_violation", "precondition_unmet");
    String wireName();
    default Optional<String> conditionKind() { return Optional.empty(); }
}

public interface PrimitiveOutcome {
    String wireName();

    /**
     * Class of the outcome; decides which step record the engine writes (see Outcome Classes).
     */
    OutcomeClass outcomeClass();

    /**
     * True for a declared job-starting outcome of an enqueuesJob() primitive (e.g. "started",
     * "rerun_started", "concurrent_restarted"); its transition targets a job or composite_job state (Rule 1).
     */
    default boolean startsJob() { return false; }

    /**
     * Closed enum of the reasons an outcome of this primitive may carry; empty when it carries none
     * (see Outcomes and Reasons).
     */
    default Optional<Class<? extends OutcomeReason>> reasonType() { return Optional.empty(); }
}

public record PrimitiveResult<R extends Enum<R> & PrimitiveOutcome>(
    R outcome,
    Map<String, Object> updatedFacts,
    Optional<String> spawnedJobId,
    Optional<OutcomeReason> reason
) {}

public interface Primitive<P extends Record, R extends Enum<R> & PrimitiveOutcome> {

    /**
     * Canonical dotted primitive identifier (e.g., "git.stage-and-commit", "git.push", "findings.triage").
     */
    String id();

    /**
     * Record class defining the free and state-resolved parameters.
     */
    Class<P> parameterType();

    /**
     * Closed enum class of all possible deterministic outcomes.
     */
    Class<R> outcomeType();

    /**
     * Execute the operation within the locked scope context and return one of the closed outcomes.
     */
    PrimitiveResult<R> execute(WorkflowExecutionContext context, P parameters);

    /**
     * Artifacts this primitive produces as side effects (Rule 8), e.g. "pr_title".
     */
    default Set<String> producedArtifacts() { return Set.of(); }

    /**
     * Artifacts this primitive requires before it can pass (Rule 8), e.g. a gate requiring "pr_title".
     */
    default Set<String> requiredArtifacts() { return Set.of(); }

    /**
     * External event this primitive waits for (Rule 11b); NONE for a primitive whose outcome
     * depends only on state it reads in the same transaction, EXTERNAL_STATE for one that
     * re-observes a provider, a remote, or the checkout (e.g. ci.pr-observe, finalize.archive-plan,
     * finalize.retry-emit-landing, finalize.adopt-pr, merge.sync-base). A server retry after a failed
     * re-observation waits in a composite_job state (TIME, EXTERNAL_STATE), never in an engine-chained cycle (Rule 11a).
     */
    AwaitedEvent awaitedEvent();

    /**
     * Closed gate identifiers (waiver record, e.g. "ci_check:*", "analysis_gate:*") this primitive may
     * pass to the read-only WorkflowExecutionContext.waiver().lookup(gate), which appends a consumption.
     * Every declared identifier must be on the closed gate list (INV-GEN-2); no primitive can write a waiver.
     */
    default Set<String> waivableGates() { return Set.of(); }

    /**
     * True for a primitive that enqueues a job for the following job state and returns its id
     * in PrimitiveResult.spawnedJobId with one of its declared job-starting outcomes, each targeting
     * a job or composite_job state (Rule 1, Job State Entry & Binding).
     */
    default boolean enqueuesJob() { return false; }

    /**
     * The finite measure that strictly decreases on every pass of an engine-chained cycle through this
     * primitive's state, the only way such a cycle passes Rule 11a (checked by Rule 9): NONE;
     * STEP_LIST for the dispatch hub finalize.next-step (the unsettled steps of the instance's step list,
     * every pass fires and settles exactly one step); ARCHIVE_STEPS for epic.next-work while the epic
     * archives (the remaining archive steps: commit, land, archived); ATTEMPT_CAP for a primitive with a
     * compiled attempt cap (git.rebase-onto-upstream: the sync attempt cap; setup.verify-credentials: one
     * re-probe per setup run), which returns exhaustionOutcome() once the cap is spent.
     */
    default CycleMeasure cycleMeasure() { return CycleMeasure.NONE; }

    /**
     * The outcome an ATTEMPT_CAP primitive returns when its cap is spent (class FAILURE, leaving every
     * cycle through its state), e.g. "attempts_exhausted", "reprobe_exhausted".
     */
    default Optional<String> exhaustionOutcome() { return Optional.empty(); }
}
----

[#primitive-outcome-classes]
==== Outcome Classes & Step Records
_Implementation watch: link:../../implementation-watch/workflow-dsl.adoc#PM-WATCH-DSL-9[PM-WATCH-DSL-9]_

Every outcome constant declares one `OutcomeClass`, and the engine derives the step record from it, never from the outcome name:

* *`SUCCESS`*: The step completed with its work; the engine records `done`.
* *`SKIP`*: The step had nothing to do. A primitive with an optional input declares the outcome `skipped` of this class with a reason for the absent-input case, instead of a `skipped_<reason>` constant per cause; the step record stores `skipped`, `work_performed: false`, and the reason, and downstream steps treat it as neither a failure nor produced content (xref:#outcomes-and-reasons[Outcomes and Reasons]).
* *`FAILURE`* and *`INDETERMINATE`*: The step record stores `failed`; neither is ever recorded as `done`. An `INDETERMINATE` outcome keeps its class on the outcome itself (the job record and the decision trail name it), so it is never folded into success or reported as a refuted verdict (`PM-EXEC-4`).
* *`UNSETTLED`*: Outcomes that hand the step back without settling it: a remediation unit's `fix_requested` (the `loop_back` form of `fix`), the re-planning terminals `replan.reentered` and `replan.reauthor`, and a task's `task.asked`. The engine writes no completion record, so a re-fired step never produces two completions.
* *`STEPPED_OUT`*: The control outcome `stepped_out` of a sub-workflow: the unit stepped out by itself (a terminal of class `stepped_out`, for example after exhausted commit attempts), the engine unwound every frame after a condition's self-remedy budget was spent or a task state without a declared `lost` route lost its task (`cause: condition` or `cause: lost`, which enter the phase's fallback directly), or, in a sub-workflow a workspace, machine, or entry unit calls, the operator followed the implicit `step_out` of one of its operator waits. Like `UNSETTLED` it writes no completion record: the caller routes the outcome once (Rule 6), typically to the plan's fallback, whose entry records the open firing `failed`, never to a state that continues the flow as if the operation had succeeded, and never completes a step `done`, `skipped`, or `waived` on it (xref:01-grammar.adoc#sub-workflow-exits[Sub-Workflow Exit Contract]).

A remediation unit's `waived` outcome has class `SUCCESS`, but only its transition may complete a step `waived` (Rule 9).

[#outcomes-and-reasons]
==== Outcomes and Reasons
_Implementation watch: link:../../implementation-watch/workflow-dsl.adoc#PM-WATCH-DSL-15[PM-WATCH-DSL-15], link:../../implementation-watch/workflow-dsl.adoc#PM-WATCH-DSL-22[PM-WATCH-DSL-22]_

A name is an outcome only where the graph continues differently. Every other failure, skip or indeterminacy is one outcome of its class plus a reason carried as data: the outcome declares the reasons through `PrimitiveOutcome.reasonType()` as a closed enum of `OutcomeReason`, and the reason travels in `PrimitiveResult.reason()`. A unit that must route on a cause promotes that cause to a named outcome; that is the rule, not an exception to it. Nothing routes on a reason: no grammar production, guard or verifier reads it (`PM-WATCH-DSL-15` and `PM-WATCH-DSL-22` keep their text, and they state exactly that).

Only an outcome of class `FAILURE`, `INDETERMINATE` or `SKIP` admits a reason: the three explain "why not". `SUCCESS` has nothing to explain, and `UNSETTLED` and `STEPPED_OUT` are engine control. The registry refuses a reason type on any other class, a reason enum that is not a closed enum of `OutcomeReason`, a wire name that is malformed or not unique within its enum, and a condition kind outside the closed table below.

A reason maps to at most one engine condition. The table is total and closed: every constant answers `conditionKind()` (empty is an answer), and a present answer is one of the two conditions a primitive can originate.

[cols="2,3",options="header"]
|===
|Condition kind |Where it arises

|`footprint_violation` |A primitive found a change outside the boundary it was called to make.
|`precondition_unmet` |A primitive found a condition its call requires unfulfilled.
|===

The other condition kinds are not mappable: `guard_indeterminate` arises from the engine's guard evaluation, `job_incomplete` from its task attempts, `config_drift` from its re-composition, and `integrity_breach` names the store it breached. `OutcomeReason.MAPPABLE_CONDITION_KINDS` states the set, and a test pins it to the kinds the status store persists.

For example, the `failed` outcome of `git.stage-and-commit` declares the reasons `footprint_violation`, `message_refused` and `commit_failed` in one closed enum. The workflow routes the outcome `failed` once, whatever the reason, and a log, a diagnostic or a diagram prints the reason. This specification states the rule in prose; the concrete example of that primitive belongs to `PLAN-V2-20`.

=== Concrete Primitive Example (`GitStageAndCommitPrimitive`)

The example is the primitive behind the `git.stage-and-commit` state of the `git.commit_and_push` sub-workflow (xref:06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Six-Stage Execution Contract of `git.commit_and_push`], Stage 4); its outcome wire names are the ones that state routes on.

[source,java]
----
public final class GitStageAndCommitPrimitive
        implements Primitive<GitStageAndCommitPrimitive.Params, GitStageAndCommitPrimitive.Outcome> {

    public record Params(@FreeParam(minLength = 1, maxLength = 2000) String message) {}

    public enum Outcome implements PrimitiveOutcome {
        COMMITTED("committed", OutcomeClass.SUCCESS),
        NOTHING_TO_COMMIT("nothing_to_commit", OutcomeClass.SKIP),
        HOOK_FAILED("hook_failed", OutcomeClass.FAILURE),
        ATTEMPTS_EXHAUSTED("attempts_exhausted", OutcomeClass.FAILURE);  // commit attempt cap spent

        private final String wireName;
        private final OutcomeClass outcomeClass;
        Outcome(String wireName, OutcomeClass outcomeClass) {
            this.wireName = wireName;
            this.outcomeClass = outcomeClass;
        }
        @Override public String wireName() { return wireName; }
        @Override public OutcomeClass outcomeClass() { return outcomeClass; }
    }

    @Override public String id() { return "git.stage-and-commit"; }
    @Override public Class<Params> parameterType() { return Params.class; }
    @Override public Class<Outcome> outcomeType() { return Outcome.class; }
    @Override public AwaitedEvent awaitedEvent() { return AwaitedEvent.NONE; }

    @Override
    public PrimitiveResult<Outcome> execute(WorkflowExecutionContext ctx, Params params) {
        // Runs the footprint check, stages the derived staging set, appends the resolved
        // Co-Authored-By trailer (refusing one in the model-supplied message),
        // and streams the UTF-8 message via stdin to `git -C <worktree> commit -F -`
        ...
    }
}

[#independent-transition-validation]
=== Independent Server-Side Transition & Parameter Validation (`PM-WF-6`)

[[_independent_server_side_transition_parameter_validation_pm_wf_6]]
When `pm_do(scope_id, entity?, link, args)` arrives, the workflow engine executes a single atomic transaction under the scope's exclusive lock (acquired through the lock manager in the total lock order, link:../store-schemas/13-leases-integrity-testing.adoc#lock-free-snapshot-reads[Store Schemas Specification]); all of its store writes form one journaled transaction (link:../store-schemas/01-format-and-session-log.adoc#transaction-journal[Store Schemas Specification, Transaction Journal]):

1. *Load Authoritative State*: Read `mcp/status.json` for `scope_id` (applying any `migrate` mapping if `status.json` references a renamed released state) and resolve the addressed `StateNode`: for a task entity the state of its task (`task.offered`, or the state of its entity unit) from the queue task record, otherwise the scope's active state (within the top `CallFrame.subWorkflowId()` if `call_stack` is non-empty, or the root workflow otherwise).
2. *Verify Caller Binding*: A worker's request carries its job token and generation, set by its relay (link:../model-work/04-worker-launch.adoc[Model Work Specification, Worker Launch]). A call of a fenced generation is refused `generation_fenced`, a worker's call after its job ended `job_ended`, and a call on an entity not leased to the caller's generation `job_scope_mismatch` (link:../model-work/02-task-protocol.adoc#execute-submit[Model Work Specification, Execute & Submit]). A worker reaches only the links of the task entities leased to its generation (Rule 4); every other `pm_do` is refused `link_not_available`, because a view offers a model no transition and an operator link is never reachable through `pm_do`.
3. *Re-Compute Active Links & Guards*: Evaluate all `LinkSpec` entries on the addressed `StateNode` (for a task entity, the entity kind's links, evaluated in the call frame of the task state that created the task, of the plan instance version in force), add the state's implicit links (xref:02-units-jobs-decisions.adoc#implicit-job-links[Implicit Links]), expand entity placeholders (for example `submit:<task_id>`) against current persisted stores (`tasks/TASK-*.json`, `findings.jsonl`), and evaluate each link's `GuardExpr` to a `GuardResult` (xref:04-ast-node-model.adoc#guard-results[Three-Valued Guard Results]): only `HELD` links are active, and a `COULD_NOT_EVALUATE` result raises the `guard_indeterminate` condition instead of dropping the link. While `pending_condition` is an `integrity_breach`, every `pm_do` of the scope is rejected with `integrity_paused` before any other step (xref:04-ast-node-model.adoc#condition-overlays[Condition Overlays (Engine-Owned)]).
4. *Verify Link Offering*: Confirm that `link` exactly matches one of the currently active, guard-satisfied `LinkSpec` instances. If `link` is not in the active set, return `isError: false` with the current representation and a `rejected.reason` from the closed enumeration (link:../../../../plan-marshall-documentation/doc/specification/mcp-tools/04-errors-and-testing.adoc#rejection-reasons[MCP Tool & Resource Surface Specification]): `operator_only` for an operator act (waivers, the operator's scope-wide acts, integrity resolutions, the links of an operator wait), which is never offered to a model; `stale_entity` for an entity-addressed link whose entity is no longer in an accepting state; `link_not_available` for any other identifier, including invented or paraphrased ones.
5. *Validate & Bind Free Parameters (`P`)*: Validate the raw `args` map against the `LinkSpec.freeParams` constraints (`additionalProperties: false`, required keys, enum membership, string length bounds, integer ranges) and execute any attached content validator (`OutlineValidator`, `AsciiDocValidator`, `ConventionalCommitValidator`) in-process on submitted text payloads. If validation fails, return `isError: false` with the current representation and `rejected.reason` `undeclared_param` (a key the link does not declare), `missing_param` (a required key is absent), or `invalid_link_args` (type, range, or content-validator violation); `detail` names the offending parameter.
6. *Verify Task Footprint (`submit:TASK-*` only)*: For a task `submit:<task_id>` link, verify the task's contribution against the boundary: that no files outside the plan's worktree (the main checkout included) were dirtied by the worker and that no enrolled wrapper's `pinned_files` (link:../job-runtime/01-pipeline-and-subprocesses.adoc#_verify_not_resolve_execution_pipeline[Job Runtime Specification, Verify-Not-Resolve]) changed inside it. Paths inside the worktree beyond the declared footprint are accepted and recorded as unplanned changes with the task as provenance (listed in the PR body and the landing record), never refused. On a boundary violation, the link's primitive is not executed and the `footprint_violation` condition is raised on the current state (xref:04-ast-node-model.adoc#condition-overlays[Condition Overlays (Engine-Owned)]), naming the offending files; `state` and `call_stack` are unchanged. Commits are not checked here: every commit, whatever its caller and whichever link or state leads to it, is guarded by the footprint check that `git.stage-and-commit` runs as its first step (xref:06-reusable-sub-workflows.adoc#_six_stage_execution_contract_of_git_commit_and_push[Six-Stage Execution Contract of `git.commit_and_push`], Stage 4).
7. *Execute Primitive & Advance State*: Instantiate `P`, invoke `primitive.execute(context, params)`, look up the returned `R.wireName()` in `LinkSpec.transitions` (for a call return, the transition whose result guard holds), persist the new `state` (and updated `call_stack` if entering or exiting a `SubWorkflowCall`) in `mcp/status.json`, append the transition event to `audit.jsonl`, and render the next state's TOON representation (executing chained `auto` and `call` steps until an operator wait, a job or task state, or a root terminal state is reached). An instance version composed in this transaction by a server event (`outline`, `plan`, `fallback`, `empty_harvest`, `replan`, xref:09-plan-instance.adoc#plan-instance[Plan Instance]) is in force from the transition that enters its target state, so the rest of the chain runs on it; a version composed by an operator or configuration event takes effect from the next transition.

[#operator-act-validation]
==== Operator Acts on the Same Path
_See Requirement link:../../../../plan-marshall-documentation/doc/Requirements.adoc#PM-WF-20[PM-WF-20: Waiting for the Operator]_

An act of the operator through a link of an operator wait arrives over the local API from either client (xref:02-units-jobs-decisions.adoc#operator-wait[Waiting for the Operator]) and runs the same transaction as a `pm_do`: steps 1, 3, 5, and 7 apply unchanged, step 2 is replaced by the verification of the operator's channel and device (link:../../../../plan-marshall-documentation/doc/specification/cli-and-security/01-cli-and-installer.adoc#two-channels[CLI, Coordination & Security Specification, Operator Choices in the Web App and the Terminal]), and step 4 matches the act against the operator links the wait offers in its current state, so an act of a second client on a state that has moved on is refused with the current representation. The act records its channel and device in the transition event of `audit.jsonl`.
