== Reference Workflow DSL Excerpt (`phase-6-finalize.pmwf`)
_Implementation watch: link:../../implementation-watch/phase-workflows.adoc#PM-WATCH-PHASE-31[PM-WATCH-PHASE-31], link:../../implementation-watch/workflow-dsl.adoc#PM-WATCH-DSL-22[PM-WATCH-DSL-22]_

The excerpt shows the finalize phase, the sub-workflow `phase-6-finalize` (file `phase-6-finalize.pmwf`), with the states of its default landing variant `landing.pull-request` (the push barrier, the wait region, and the merge gate) at their orders, as the plan instance composes them (xref:09-plan-instance.adoc#plan-axes[Plan Behaviour Axes]). Every state the excerpt defines is catalogued in the link:../state-catalogue/04-plan-finalize-terminal.adoc#state-catalogue-finalize[State Catalogue, Phase 6: `finalize`]. The excerpt is a template: a plan executes its composed instance, in which the composition may prune steps, links, and policy actions and binds the effective budgets (xref:09-plan-instance.adoc#plan-instance[Plan Instance]). The remediation units it calls are specified in xref:08-remediation-units.adoc#remediation-units[Remediation Policy Units].

----
---
name: Finalize
description: Settles and reviews the plan's change, lands it through the landing variant, then runs the post-run band and archives the plan.
type: subworkflow
entry: start
entry_description: The execute phase ended, or a fix was committed; settle_trigger is order 0.
entry: adopt
entry_description: A plan of source pr: the pull request's head branch is adopted.
entry: hand_back
entry_description: The execute phase took the fallback, or a returned plan has commits beyond the base; the plan is handed back.
entry: post_run
entry_description: A returned plan or a recipe's empty harvest; the post-run band runs, then the plan is archived.
exit: merged
exit_description: The work landed on the base branch and the plan is archived.
exit: no_change
exit_description: A recipe's empty harvest; the plan is archived without a change.
exit: handed_back
exit_description: The work is delivered without a merge and the plan is archived.
exit: returned
exit_description: The plan is archived without a commit beyond the base.
exit: reenter_execute
exit_description: Remediation tasks are allocated; the execute phase runs them.
exit: loop_back_outline
exit_description: A re-planning re-authors the outline.
modification_date: 2026-10-14
version: 1.0.0
author: plan-marshall
---
workflow phase-6-finalize version 1 format 1
scope subworkflow
entry start -> finalize.settle-commit
entry adopt -> finalize.adopt-pr
entry hand_back -> finalize.hand-back
entry post_run -> finalize.next-step

state finalize.settle-commit
  call git.commit_and_push (message_mode=step_or_fallback, push_mode=post_pr_conditional)
    done                     -> finalize.review-cap-check
      guard result.pushed
    done                     -> finalize.next-step
      guard not result.pushed
    stepped_out              -> finalize.hand-back

state finalize.sync-baseline
  composite_job finalize.sync-baseline          # fetch, re-planning triggers, overlap check, rebase attempt
    replan                   -> finalize.replan
    up_to_date               -> finalize.next-step
      completes default:finalize-step-sync-baseline as skipped
    rebased                  -> finalize.next-step
      completes default:finalize-step-sync-baseline as done
    conflict                 -> finalize.remediate-sync-conflict
    fetch_failed             -> finalize.step-failed
      completes default:finalize-step-sync-baseline as failed
    cancelled                -> finalize.step-failed
      completes default:finalize-step-sync-baseline as failed

state finalize.remediate-sync-conflict
  call remediation.merge-conflict (retry_budget=0, fix_budget=2, actions=[fix])
    resolved                 -> finalize.settle-commit
      completes default:finalize-step-sync-baseline as done
    exhausted                -> finalize.replan       # trigger ceiling
    stepped_out              -> finalize.hand-back

state finalize.pre-push-quality-gate
  composite_job build.quality-gate              # the build and, on red, the baseline comparison
    passed                   -> finalize.settle-commit
      completes default:pre-push-quality-gate as done
    baseline_red             -> finalize.settle-commit
      completes default:pre-push-quality-gate as done
    red                      -> finalize.remediate-build
    no_verdict               -> finalize.remediate-build
    cancelled                -> finalize.remediate-build

state finalize.remediate-build
  call remediation.build-failure (retry_budget=1, fix_budget=3, actions=[retry,fix])
    resolved                 -> finalize.settle-commit
      completes default:pre-push-quality-gate as done
    fix_requested            -> finalize.allocate-remediation
    exhausted                -> finalize.replan
    stepped_out              -> finalize.hand-back

state finalize.allocate-remediation
  auto plan.allocate-remediation-tasks
    allocated                -> finalize.reenter-execute

state finalize.push-barrier
  call git.commit_and_push (message_mode=none_assert_clean, push_mode=if_push_remote)
    done                     -> finalize.merge-gate       # the branch already landed
      guard result.landed
      completes default:push as skipped
    done                     -> finalize.next-step        # the remote branch holds HEAD
      guard not result.landed
      completes default:push as done
    stepped_out              -> finalize.hand-back

state finalize.review-cap-check
  auto review.check-structural-caps
    within_caps              -> finalize.concurrent-wait
    replan                   -> finalize.replan       # required bot's cap, HEAD not yet judged
    cap_exceeded             -> finalize.remediate-review

state finalize.concurrent-wait
  composite_job finalize.watch-ci-and-bots
    all_green                -> finalize.merge-gate
      completes default:ci-verify as done
      completes default:automatic-review as done
      completes default:analysis-roundtrip as done
    ci_failed                -> finalize.remediate-ci
    analysis_failed          -> finalize.remediate-analysis
    findings_open            -> finalize.remediate-review
    bot_refused_structural   -> finalize.remediate-review
    review_evidence_missing  -> finalize.remediate-review
    bot_refused_awaitable    -> finalize.review-window-wait
    bot_no_unreviewed_commit -> finalize.review-full-trigger
    watch_interrupted        -> finalize.restart-watch
    cancelled                -> finalize.restart-watch

state finalize.restart-watch
  auto finalize.restart-watch
    concurrent_restarted     -> finalize.concurrent-wait
    evidence_restarted       -> finalize.merge-evidence-wait
    exhausted                -> finalize.hand-back

state finalize.remediate-ci
  call remediation.ci-failure (retry_budget=2, fix_budget=3, actions=[retry,fix,loop_back])
    resolved                 -> finalize.next-step
      completes default:ci-verify as done
    waived                   -> finalize.next-step
      completes default:ci-verify as waived
    fix_requested            -> finalize.allocate-remediation
    exhausted                -> finalize.replan
    stepped_out              -> finalize.hand-back

state finalize.remediate-analysis
  call remediation.analysis (retry_budget=1, fix_budget=3, actions=[retry,fix])
    resolved                 -> finalize.next-step
      completes default:analysis-roundtrip as done
    waived                   -> finalize.next-step
      completes default:analysis-roundtrip as waived
    exhausted                -> finalize.replan
    stepped_out              -> finalize.hand-back

state finalize.remediate-review
  call remediation.review-findings (retry_budget=1, fix_budget=3, actions=[retry,fix,loop_back])
    resolved                 -> finalize.next-step
      completes default:automatic-review as done
    waived                   -> finalize.next-step
      completes default:automatic-review as waived
    fix_requested            -> finalize.allocate-remediation
    exhausted                -> finalize.replan
    stepped_out              -> finalize.hand-back

state finalize.remediate-security-audit
  call remediation.review-findings (retry_budget=0, fix_budget=3, actions=[loop_back])
    resolved                 -> finalize.next-step
      completes default:finalize-step-security-audit as done
    waived                   -> finalize.next-step
      completes default:finalize-step-security-audit as waived
    fix_requested            -> finalize.allocate-remediation
    exhausted                -> finalize.replan
    stepped_out              -> finalize.hand-back

state finalize.remediate-self-review
  call remediation.review-findings (retry_budget=0, fix_budget=3, actions=[loop_back])
    resolved                 -> finalize.next-step
      completes default:pre-submission-self-review as done
    waived                   -> finalize.next-step
      completes default:pre-submission-self-review as waived
    fix_requested            -> finalize.allocate-remediation
    exhausted                -> finalize.replan
    stepped_out              -> finalize.hand-back

state finalize.replan
  call replan                                   # reads replan_pending (phase-workflows/08)
    done                     -> finalize.next-step
    reentered                -> finalize.reenter-execute
    reauthor                 -> finalize.loop-back-outline
    hand_back                -> finalize.hand-back
    stepped_out              -> finalize.hand-back

state finalize.review-window-wait
  facts review.window-status
  job review.await-rate-window
    succeeded                -> finalize.review-retrigger
    failed                   -> finalize.remediate-review
    refused                  -> finalize.remediate-review
    cancelled                -> finalize.remediate-review
    timed_out                -> finalize.remediate-review
    killed                   -> finalize.remediate-review
    indeterminate            -> finalize.remediate-review

state finalize.review-retrigger
  auto review.retrigger-unproven
    triggered                -> finalize.review-cap-check
    window_closed            -> finalize.review-window-wait

state finalize.review-full-trigger
  auto review.post-full-trigger
    triggered                -> finalize.review-cap-check
    already_triggered        -> finalize.remediate-review
    window_closed            -> finalize.review-window-wait

state finalize.adr-author
  skill pm/finalize/adr-propose
  facts finalize.adr-signal
  job llm adr role adr-author                   # links: adr (the ADR, written by the server) or decline
    recorded                 -> finalize.settle-commit
      completes default:adr-propose as done
    declined                 -> finalize.next-step    # work_performed=false
      completes default:adr-propose as done
    infeasible               -> finalize.next-step    # work_performed=false, gap recorded
      completes default:adr-propose as skipped
    lost                     -> finalize.next-step    # conservative: no ADR, work_performed=false, gap recorded
      completes default:adr-propose as skipped

state finalize.merge-gate
  auto merge.gate-entry
    ready                    -> finalize.merge-lease
    incomplete               -> finalize.next-step
    local_only               -> finalize.hand-back
      completes default:branch-cleanup as done
    terminus_review_owed     -> finalize.self-review      # terminus mode, returns to the gate

state finalize.step-failed
  auto finalize.refire-failed-step
    refire                   -> finalize.next-step
    before_merge             -> finalize.hand-back
    after_merge              -> finalize.next-step

state finalize.hand-back
  auto finalize.hand-back
    handed_back              -> finalize.next-step
    returned                 -> finalize.next-step

state finalize.emit-landing
  auto finalize.emit-landing
    verified                 -> finalize.next-step        # read back and valid: landing_delivery verified
      completes default:emit-landing as done
    not_orchestrated         -> finalize.next-step        # also a detached epic linkage: landing_delivery null
      completes default:emit-landing as done
    pending                  -> finalize.next-step        # indeterminate epic linkage: envelope kept
      completes default:emit-landing as done
    append_failed            -> finalize.emit-landing-failed
    incomplete               -> finalize.emit-landing-failed   # read back incomplete
    failed                   -> finalize.emit-landing-failed   # read back, validation failed

state finalize.emit-landing-failed
  facts finalize.landing-status
  auto finalize.retry-emit-landing              # server retry within the compiled retry budget, then pending
    verified                 -> finalize.next-step
      completes default:emit-landing as done
    pending                  -> finalize.next-step
      completes default:emit-landing as done

state finalize.archive-plan
  auto finalize.archive-plan
    merged                   -> finalize.merged
      completes default:archive-plan as done
    no_change                -> finalize.no-change
      completes default:archive-plan as done
    handed_back              -> finalize.handed-back
      completes default:archive-plan as done
    returned                 -> finalize.returned
      completes default:archive-plan as done
    observation_failed       -> finalize.archive-unobserved   # budget left; spent: archives with merge_state unknown

state finalize.merged terminal merged success

state finalize.no-change terminal no_change success

state finalize.handed-back terminal handed_back failure

state finalize.returned terminal returned failure

state finalize.reenter-execute terminal reenter_execute unsettled

state finalize.loop-back-outline terminal loop_back_outline unsettled
----

* *Settle commit and `settle_trigger` (`PM-WF-16`)*: `finalize.settle-commit` is the one commit point of Phase 6. Its call routes the exit contract of `git.commit_and_push` (xref:06-reusable-sub-workflows.adoc#_bound_parameter_contract[Bound Parameter Contract]): `done` with `result.pushed` re-enters the wait region through `finalize.review-cap-check`, so CI and review bots re-evaluate the new `HEAD`; `done` without a push continues with `finalize.next-step`; `stepped_out` enters `finalize.hand-back`. The transition that enters the state persists `settle_trigger {step_id, order}` in `mcp/status.json`: the step whose firing is open, or order `0` (never a push) when it is entered through the phase's entry `settle` (after the execute phase's or the `land` lane's exit barrier) or from `finalize.adopt-pr`. `push_mode=post_pr_conditional` reads that order, so a loop-back never pushes before the Settle band re-runs.
* *Step states*: Every default step has one declared template state that the composition includes or prunes (link:../phase-workflows/04-finalize-step-bands.adoc#_normative_step_catalogue_across_ordering_bands[Phase Workflows Specification, Step Catalogue]); the excerpt shows `finalize.sync-baseline` (a `composite_job`: the fetch, the overlap check, and the rebase attempt run as one observed job, so a failed fetch re-fired through `finalize.step-failed` never forms an engine-chained cycle, Rule 11a), `finalize.pre-push-quality-gate`, `finalize.push-barrier`, the wait region, `finalize.remediate-security-audit` and `finalize.remediate-self-review` (the Settle-band findings of `security-audit` and `pre-submission-self-review`, one call state per step, each completing its own step), `finalize.adr-author` (a task state of the role `adr-author`), `finalize.merge-gate`, `finalize.emit-landing`, and `finalize.archive-plan`. A step state that completes a source-mutating step enters `finalize.settle-commit` with the completion on that transition. `sync-baseline` rebases also over overlapping upstream changes: a clean rebase completes `done` (the plan's gates re-verify later), a conflict calls `remediation.merge-conflict` before the pull request and CI exist.
* *Shared failure state*: `finalize.step-failed` serves the job failures of Settle-band and project steps. The transition that enters it completes the failed firing `failed`; `refire` (one automatic re-fire per step) lets `finalize.next-step` open a new firing, `before_merge` takes the fallback, and `after_merge` records an owed item and continues: after the merge there is no fallback, and the plan stays `merged`.
* *Baseline-red is a server rule*: `build.quality-gate` compares every failing diagnostic's fingerprint with the base (the provider's CI result of the base first, a local build of the merge base as fallback); when every failure is baseline-only it writes a `baseline_red` build row bound to `worktree_sha` and settles `baseline_red` (class `SUCCESS`), and the step completes `done` with `assurance_verdict: degraded`. Every other red calls `remediation.build-failure`.
* *Remediation calls*: Every blocking failure calls its remediation unit, whose decision task may request a waiver of the operator: CI (`remediation.ci-failure`), code analysis over every configured provider (`remediation.analysis`), review findings, structural refusals, and missing review evidence (`remediation.review-findings`), a red quality gate (`remediation.build-failure`), and a sync-baseline conflict (`remediation.merge-conflict`). Each unit's `decide` is server logic where the call site's bound actions and budgets leave one remedy, and otherwise a task of the unit's triage role (xref:08-remediation-units.adoc#remediation-units[Remediation Policy Units]). Each call site routes the unit's reachable domain outcomes and `stepped_out` (Rule 6): `resolved` completes the class's step `done`, `waived` completes it `waived` with the waiver id (Rule 9), `fix_requested` enters `finalize.allocate-remediation`, which allocates Phase 5 remediation tasks (the `loop_back` form of `fix`, xref:07-loop-back-diagrams-verification.adoc#loop-back-bounds[Worktree-Constrained Loop-Back & Iteration Bounds]) and ends the phase with `reenter_execute`, `exhausted` enters `finalize.replan` (trigger `ceiling`, link:../phase-workflows/08-dynamic-re-planning.adoc#replan-existing-mechanisms[Phase Workflows Specification, Relation to the Remediation Policies]; in the `land` lane it enters `finalize.hand-back`), and `stepped_out` enters `finalize.hand-back`. The two Settle-band call sites `finalize.remediate-security-audit` and `finalize.remediate-self-review` bind `actions=[loop_back]` with `retry_budget=0`: no pull request exists yet, so a fix runs only in the `loop_back` form, and its commit is the exit-barrier commit of Phase 5 (`settle_trigger` order `0`), never pushed before the push barrier (`INV-FIN-4`); the in-branch `fix` with its `push_mode=always` commit is bound only at call sites after the pull request exists. The budgets written at the call sites are the template values; the instance carries the effective ceilings with their source, and a `land` plan's composition binds `actions=[retry]` at every call site, so its `decide` takes the retry without a task (at the two Settle-band call sites, whose `retry_budget` is `0`, the unit ends `exhausted` at once).
* *Wait-region order and re-entry*: `finalize.watch-ci-and-bots` hands one failing class at a time to its unit in the fixed order CI -> analysis -> review findings (link:../hypermedia-format/03-composite-wait-and-encoder.adoc#policy-unit-returns[Hypermedia Format Specification, Policy Unit Returns]); a unit's own await state watches only its class at the new `HEAD`. After `resolved` or `waived`, `finalize.next-step` re-enters the region: the steps whose firing is still open continue it, and verdict currency re-fires every class that is stale at the new `HEAD` (Rule 9, completion per firing).
* *Pre-wait cap gate*: Before `finalize.concurrent-wait` is entered, `finalize.review-cap-check` measures the diff against the structural caps each required review bot declares in the review-bot registry (link:../phase-workflows.adoc[Phase Workflows Specification]). An exceeded cap of a required bot at a `HEAD` not yet judged raises the re-planning trigger `downstream_limit` (link:../phase-workflows/08-dynamic-re-planning.adoc#replan-triggers[Phase Workflows Specification, Dynamic Re-Planning]); otherwise an exceeded cap records the bot as `refused` with mode `size` pre-emptively and files the refusal as a finding, which the review unit's triage job dispositions (`ACCEPT` accepts the refusal, `SUPPRESS` disables the bot for this pull request).
* *Review-bot rate windows*: `bot_refused_awaitable` enters `finalize.review-window-wait`, a job that waits for the bot's rate window (link:../timeouts/01-job-budgets-and-waits.adoc#review-bot-windows[Timeouts & Budgets Specification, Review-Bot Rate Windows]; a published ETA is a floor that is re-checked, never skipped) and then re-triggers the unproven bots automatically; a trigger is never posted inside a closed window. `bot_no_unreviewed_commit` enters `finalize.review-full-trigger`, which posts the registry's full-review trigger verb once per bot and `HEAD`. Every way the wait cannot produce evidence (hard quota, unproven bot, unestablished roster, a failed window wait, a repeated notice) reaches `remediation.review-findings` with the failure kind `evidence_missing`, whose only ends besides a window-gated re-trigger are a `review_evidence[:<bot_kind>]` waiver or the fallback.
* *Interrupted watches*: A constituent job of the watch that ends with any fate other than success, and a cancellation of the composite by the engine, settle the composite as `watch_interrupted {constituent, fate}` or `cancelled`; `finalize.restart-watch` restarts the watch explicitly (an `enqueuesJob()` primitive whose outcome `concurrent_restarted` or `evidence_restarted` names the interrupted wait and binds the new composite job) within the compiled restart budget of `2` per wait-region firing and takes the fallback when it is spent. The engine never restarts a job on its own (xref:02-units-jobs-decisions.adoc#job-state-binding[Job State Entry & Binding]).
* *Fallback end (`handed_back`)*: `finalize.hand-back` is the one fallback state of Phase 5, the `land` lane, and Phase 6 before the merge. In the transaction that enters it the engine records every begun, unsettled step `failed` (the on-entry rule) and composes the post-run-only instance version (composition event `fallback`, the pruned steps with reason `handed_back` or `returned`), which is in force for the rest of that chain, so `finalize.next-step` selects from it (xref:09-plan-instance.adoc#_versions_composition_events[Versions & Composition Events]). Its primitive settles uncommitted work (commit only, footprint-checked), pushes the branch when a push remote exists, opens the pull request as a draft or marks the existing one, posts the idempotent gap comment and the label `pm-mcp:handed-back`, and removes the worktree; it settles `returned` when the branch holds no commit beyond the base. In its local form (the outcome `local_only` of `finalize.merge-gate`) it keeps the plan branch as the product, records `merge_outcome: local_only`, and carries open findings out as late findings. In its ready form (the pre-merge barrier's outcome `pass_hand_back`, which the barrier returns instead of `pass` when the instance prunes the merge execution with reason `merge_by_operator`, because the plan's asking variant leaves the merge to the operator) it marks the existing pull request ready for review and records `merge_outcome: awaiting_human_merge`. The post-run band then runs, and `finalize.archive-plan` ends the plan in `handed_back` or `returned`.
* *Model task in a plan*: `finalize.adr-author` shows a task state inside a plan: the server creates a task of the role `adr-author`, whose worker submits the ADR or declines through the links of its task entity; the plan's view offers no link. No model ends or hands back a plan: a task ends only in its closed outcomes, and `lost` takes the state's declared conservative route, here the continuation without an ADR: `declined` completes `default:adr-propose` as `done` with `work_performed=false`, and `infeasible` and `lost` complete it `skipped` with `work_performed=false` and the gap recorded (Rule 9) (link:../state-catalogue/07-plan-finalize-merge-post-run.adoc#state-finalize.adr-author[State Catalogue, `finalize.adr-author`]).
* *Review chain terminus*: `terminus_review_owed` (a consumed `review_evidence` waiver covers a `HEAD` no bot reviewed) runs `finalize.self-review` once in terminus mode, which returns to `finalize.merge-gate` through `finalize.self-review-code`'s `terminus_submitted`, carrying `completes default:pre-submission-self-review as done` (link:../phase-workflows/04-finalize-step-bands.adoc#_normative_step_catalogue_across_ordering_bands[Phase Workflows Specification, Step Catalogue row `8`]).
* *Local only*: `local_only` of `merge.gate-entry` (no push remote) completes `default:branch-cleanup` `done` and enters the local form of `finalize.hand-back`.
* *Merge path*: The merge-path states after `finalize.merge-gate` are not part of the excerpt; they are catalogued in the link:../state-catalogue/07-plan-finalize-merge-post-run.adoc#state-catalogue-finalize-merge[State Catalogue, Merge Path]. Open findings at the pre-merge barrier call `remediation.review-findings`, merge conflicts `remediation.merge-conflict`; `finalize.merge-refused` routes a provider refusal by its reason (`behind`, `conflict`, `checks_*` re-enter `finalize.merge-gate` within the retry budget; a refusal by the protection rules is not waivable and ends `handed_back`); where the plan's asking variant leaves the merge to the operator, the merge execution is pruned and the barrier settles `pass_hand_back` instead of `pass`, which enters the ready form of `finalize.hand-back` (a fact the primitive reads, never a second target of one outcome); both `merged` transitions complete `default:branch-cleanup` as `done`.
* *Landing delivery*: An indeterminate epic linkage settles `emit-landing` `pending` at once: the envelope is composed and kept in the plan directory with `landing_delivery: pending` for the epic's shipped-without-landing reconciliation, and the step completes `done`; a `not_orchestrated` or `detached` linkage emits nothing and stores `landing_delivery: null`. An I/O failure of the `emit-landing` append, and a read-back that finds the envelope `incomplete` or `failed` (its validation), enter `finalize.emit-landing-failed`, a server retry: its `auto` primitive re-appends, reads back, and re-verifies the envelope up to the compiled retry budget `2`; once the budget is spent it settles `pending` (class `SUCCESS`, `landing_delivery: pending`), keeping the envelope in the plan directory for the epic's shipped-without-landing reconciliation. The state never refuses or strands the plan (link:../phase-workflows.adoc[Phase Workflows Specification], validator rule 7).
* *Unobservable pull request*: `observation_failed` archives nothing and enters `finalize.archive-unobserved`, a `composite_job` that waits the retry backoff (`TIME`) and settles `retry`, so the server re-enters `finalize.archive-plan` within the compiled condition budget and the retry never forms an engine-chained cycle (Rule 11a); once the budget is spent, a failed observation archives the plan with the `merge_outcome` the plan's own records determine and `merge_state: unknown` (counted in the landing's `missing_facts`) and settles the recorded plan `outcome`, so the state never strands the plan (link:../phase-workflows/04-finalize-step-bands.adoc#_normative_step_catalogue_across_ordering_bands[Phase Workflows Specification, Step Catalogue row `1100`]).
* *Ends*: `finalize.archive-plan` is the only path to the phase's four delivery exits `merged`, `no_change` (an empty recipe harvest), `handed_back`, and `returned`, on which the plan unit enters its terminals `completed` (for `merged` and `no_change`), `handed_back`, and `returned` (xref:01-grammar.adoc#_formal_ebnf_grammar_for_the_workflow_dsl[Formal EBNF Grammar], Ends of a scope); the status and landing record's `outcome` field tells them apart. The exits `reenter_execute` and `loop_back_outline` (class `unsettled`) hand the plan back to its plan unit, which calls the execute phase through its entry `reentry` or the outline phase through its entry `rework` (link:../state-catalogue/18-plan-unit-axes-short-landings.adoc#state-catalogue-plan-unit[State Catalogue, Plan Unit]). The phase declares no step-out terminal and has its fallback `finalize.hand-back` inside it, so it never returns `stepped_out`. `plan.aborted` is a state of the plan unit, entered only by the engine-owned operator transitions (xref:02-units-jobs-decisions.adoc#waivers-and-integrity[Waivers, Waiver Requests & the Integrity Pause]).
* *Step completion*: The `completes` clauses name the finalize steps each transition settles, one completion per firing (Rule 9): `default:push` in `finalize.push-barrier` (`done` when the remote branch holds `HEAD` after the call, which continues at `finalize.next-step`, so a step the instance prunes, such as `create-pr` of an `adopt` plan, is never entered; `skipped` when the branch already landed, `result.landed`, which continues at `finalize.merge-gate`; a local-only plan prunes the step), the two Settle-band remediation calls completing `security-audit` and `pre-submission-self-review` by their own `resolved` or `waived`, the terminus-mode `terminus_submitted` completing `pre-submission-self-review` as `done`, the three wait-region steps `default:ci-verify`, `default:automatic-review`, and `default:analysis-roundtrip` (entered through `finalize.review-cap-check`) as `done` on `all_green` and each by its own unit's `resolved` (`done`) or `waived` (`waived`), `default:branch-cleanup` on `local_only`, and `default:emit-landing` and `default:archive-plan` in the post-run band. A `fix_requested` or `stepped_out` outcome completes nothing (classes `UNSETTLED` and `STEPPED_OUT`, xref:05-primitives.adoc#primitive-outcome-classes[Outcome Classes & Step Records]); a firing still open when `finalize.hand-back` is entered is recorded `failed` on entry.
* *No waits as links*: `finalize.concurrent-wait` is a `composite_job` state; its completion is an engine event, and the plan's view shows the progress of the watch without a link (xref:02-units-jobs-decisions.adoc#implicit-job-links[Implicit Links]).
* *Routing by fact*: The DSL routes an outcome to one target (or twice with complementary result guards at a call site). Where the continuation depends on a plan fact, a lane, or configuration, the primitive returns a distinct outcome per case, and a call or job whose outcome must branch enters a small `auto` router state that reads the persisted fact, as `execute.route-build-cause` reads the persisted `remediation_cause`.
* *No cross-phase targets*: `finalize.next-step`, `finalize.self-review`, `finalize.merge-lease`, `finalize.merge-evidence-wait`, and `finalize.archive-unobserved` are declared elsewhere in the phase or in its landing variant composed into it; no transition of the phase targets a state of another phase, and the execute and outline phases are reached only through the phase's exits and the plan unit's calls (xref:02-units-jobs-decisions.adoc#workflow-definition-units[Workflow Definition Units]).
