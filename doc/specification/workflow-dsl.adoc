== Overview

This document specifies the declarative Workflow Domain-Specific Language (DSL), Abstract Syntax Tree (AST) model, typed Java `Primitive<P, R>` execution contract, loop-back guard semantics, automated diagram generation, and the verification harnesses (including the out-of-band behavioural conformance harness for model-facing content) for *plan-marshall-mcp* (`PM-MCP`). The workflow engine and DSL reside in the plain-Java module `pm-workflow` on top of `pm-core`, with zero runtime framework dependencies, and are assembled into the native daemon by `pm-mcp-server` (link:../../../plan-marshall-documentation/doc/specification/module-structure.adoc[Module Structure Specification]).

== Parts

* link:workflow-dsl/01-grammar.adoc[Grammar] — the formal EBNF grammar of the workflow DSL, including result guards, question clauses, the `job llm` task clause with its freely named role, its fan-out (`each`) and its `consult role` clauses, operator links, the sub-workflow exit contract, the phase of a state, the ends of a scope, the unit frontmatter with the unit types and the interface of entries and exits, and the machine scope with its onboarding unit
* link:workflow-dsl/02-units-jobs-decisions.adoc[Workflow Units, Operator Waits, Implicit Links, Questions & Waivers] — workflow definition units (the plan unit as a workflow of six phase sub-workflows, the entity, bootstrap, and project onboarding units), waiting for the operator (the one definition of an operator wait, consent states), all interaction in the operator's two clients, the implicit links (`ack`, `consult:<role>`, `infeasible`, the operator's `step_out`), job state binding, task states with the conservative `lost` route, the compiled task protocol unit `worker-task`, question states and the decision unit, the designable adjudication unit, unit declarations (decision parameters within compiled bounds), and waivers, waiver requests, the operator's ends of a scope, and the integrity pause
* link:workflow-dsl/03-reference-excerpt.adoc[Reference Workflow Excerpt] — the reference DSL excerpt of the finalize phase `phase-6-finalize.pmwf` with its default landing variant: entries and exits, settle commit, step states, a task state, remediation calls, restart of the watch, and the `handed_back` fallback
* link:workflow-dsl/04-ast-node-model.adoc[AST Node Model] — the constraints on the implemented AST node model, guard results, condition overlays with their server self-remedies, static verification rules (operator links and model links apart, every named role exists), the designable units with their levels (project, machine, compiled default) and the compiled invariants, and designing a process (catalogue, validation with its dry run, placing and removing)
* link:workflow-dsl/05-primitives.adoc[Primitive Interface & Transition Validation] — the `Primitive<P, R>` SPI contract (outcome classes, awaited events, waiver lookup), a concrete primitive example, and independent transition validation of a worker's call and of an operator's act
* link:workflow-dsl/06-reusable-sub-workflows.adoc[Reusable Sub-Workflows] — call-stack execution, step-out and guided step-in, the canonical `git.commit_and_push` sub-workflow with its task states and exit contract, and the short landings `git.land-removal` and `git.land-unit`
* link:workflow-dsl/07-loop-back-diagrams-verification.adoc[Loop-Back, Diagram Generation & Verification] — budget-bounded loop-backs, generated diagrams and the drift gate, property verification (task protocol included), scenario replay with fixture workers and worker faults, the conformance harness with the grading of role configurations, and state-name migration
* link:workflow-dsl/08-remediation-units.adoc[Remediation Policy Units] — the `remediation.*` sub-workflow units: evidence, closed action set, decision roles, call sites and default budgets, the unit template (server `decide`, decision task, conservative fallback, the waiver wait as an operator wait), the `remediation.ci-failure` sketch, and the `INV-REM-*` invariants
* link:workflow-dsl/09-plan-instance.adoc[Plan Instance] — the composed, versioned plan instance: composition events, position rule, instance header grammar, composition rules, the plan behaviour axes (landing, method, asking) with their three levels, the plan's overrides, and display
