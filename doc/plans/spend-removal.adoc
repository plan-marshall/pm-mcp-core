== What

The specification counts tokens and limits none of a plan's use: it has no policy class `spend`, no remediation unit `remediation.spend`, no outcome `spend_overrun` of the pre-merge barrier, and no spend waiver (link:../specification/model-work/09-completion-usage-and-spend.adoc#spend-accounting-budget-anchors[Model Work § Usage Reporting & Spend Classes]). This package removes the code that link:https://github.com/plan-marshall/pm-mcp-core/blob/603d4f7/doc/plans/store-substrate.adoc[`store-substrate`] and link:https://github.com/plan-marshall/pm-mcp-core/blob/603d4f7/doc/plans/workflow-engine.adoc[`workflow-engine`] built for them, without a deprecation (pre-1.0) and without reopening those packages. The recording of the usage in tokens is link:token-usage.adoc[`token-usage`]'s.

* *The policy class*: `spend` leaves `WorkflowStatus.POLICY_CLASSES`, so `policy_counters` keyed `spend` are refused by the status codec as by the schema, and `LoopBackBudget` refuses a policy class `spend`; a workflow state naming it is refused.
* *The remediation unit*: `RemediationInvariants.SPEND_UNIT` and every exemption that names `remediation.spend` go (the parameter set of `INV-REM-1` with `waiver_wait_seconds` only, the call routing of `INV-REM-5`, the state set of `INV-REM-7`), and the unit leaves the list of remediation units; a unit named `remediation.spend` is no remediation unit.
* *The pre-merge barrier*: `INV-FIN-5` checks only that `finalize.merge-gate` lies on every path to the merge; `FinalizeInvariants.SPEND_OVERRUN` and `SPEND_REMEDIATION` and the clause "an overrun calls `remediation.spend`" of `InvariantId.INV_FIN_5` go.
* *The header*: `HeaderSchemaCheck` admits as policy call units the six remediation units of the header schema and refuses `remediation.spend`.
* *The package `workflow.spend`*: keeps the completion of a task and its usage only, its Javadoc and the module's README saying so; the spend classes, which report waste, stay.
* *Tests and documents*: the fixtures and expectations that name the spend unit, the spend class, or the spend overrun (among them `HeaderSchemaCheckTest`) are changed to the six classes; the developer guides of `workflow.verify` and `workflow.engine` and ADR `workflow-verify/024` without the spend unit; in `plan-marshall-documentation` the roadmap item checked and the removal no longer stated as remaining in `token-usage`'s roadmap item.

== Done When

No class, test, or developer guide of pm-core or pm-workflow names `remediation.spend`, `spend_overrun`, or the policy class `spend` as a limit; a workflow state with `policy_counters.spend` is refused by the codec and by `LoopBackBudget`; a header binding `remediation.spend` is refused; a plan unit whose `finalize.merge-gate` routes no `spend_overrun` passes `INV-FIN-5`, and a remediation unit set without `remediation.spend` passes the remediation invariants; `workflow.spend` states completion and usage only; `verify`, `verify -Ppre-commit`, `verify -Pcoverage`, and `verify -Pintegration-tests` are green.
