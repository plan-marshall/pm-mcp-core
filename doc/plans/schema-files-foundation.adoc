== Tasks

The first package of the transition; the packages that move the schema blocks, the numbers and the lists depend on it.

. *ADR*: the next free ADR number at the start of the package (the last on `main` is 015, the docs-only skip with a code include list). It states that the JSON schemas of the specification are files of the module that implements them, that the specification includes the file, and that a test reads inputs of its own repository only. It supersedes the sentence of link:../adr/007-specifications-of-the-engine-in-this-repository.adoc[ADR 007] that has the parity tests read the specification (`pm.specification.root`); the premise of ADR 009 and the include list of ADR 015 are retired by `adoc-reading-retired`.
. *Layout*: a schema file lies in `src/main/resources` of the module that owns its codec, in the resource package of that codec, named `<record>.schema.json` (precedent: the corpus schemas of `pm-core`, `core/role/corpus/`). One file per block; the text is the block's text, byte for byte, so its `$id`, `$defs` and member order are unchanged.
. *Include convention*: the block in the specification becomes `[source,json]` over `----` with one line `include::<relative path to the file>[]`; the heading and the anchor stay, so every link into the section keeps resolving. A block that is an example, not a schema, stays inline. GitHub does not expand an `include::`; it shows a link to the file. The paragraph above the include names the file and its path, so a reader on GitHub follows one link.
. *Test helper*: `SchemaResource` beside `SpecificationDocument` in the test sources of `pm-core` (ADR 012 artifact): loads a schema from the class path by resource path and parses it with the parser `SpecificationDocument` has; an absent resource or invalid JSON fails the test, never skips it. `SpecificationDocument` stays until `adoc-reading-retired`.
. *Documents here*, in the pull request beside this one (link:../../../plan-marshall-documentation/CLAUDE.md[CLAUDE.md], _A change that spans code and documents_): the sentence of link:../../../plan-marshall-documentation/doc/developer/project-setup.adoc#_planning_the_work[Project Setup § Planning the Work] that keeps the schema blocks "that a test reads as its contract" and the sentence of § Repositories and Checkouts that has a test read a document from the sibling checkout are replaced by the rule of the ADR; the project skill `traced-implementation` says the same; `trace.py` checks that every `include::` target exists (also an include into a sibling checkout) and reports an inline schema block of a specification (a block with `$schema`, or `properties` under `"type": "object"`, or `items` under `"type": "array"`; the test of the check holds an inline example of each shape and one permitted example that is not a schema), failing for the specifications below `pm-mcp-core/doc/specification` and only reporting those of specifications nothing implements yet (`harness-integration/02-bundle-manifest.adoc`).
. *Developer documentation*: the developer document of the build names where a schema file lies and how a test loads it.
. *Not part of the transition*: validating a stored record against its schema file at run time. `networknt` is a test-scope dependency of `pm-core`; a compile-scope validator is a new dependency and waits for the operator (link:../../../plan-marshall-documentation/doc/discussions/open-questions.adoc#runtime-schema-validation[Open Questions, `runtime-schema-validation`]).

== Done When

* Tests: `SchemaResource` loads a present schema (matched positive control), fails on an absent resource and on invalid JSON (negative controls); `verify`, `verify -Ppre-commit` and `verify -Pcoverage` green in `pm-core`.
* `trace.py` reports `BROKEN LINKS 0`; run on a specification with an inline schema block it reports the block, and on `main` of `pm-mcp-core` after the last schema package it reports none.
