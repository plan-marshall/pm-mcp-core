== What

* The daemon composes the write and read sets of each job and records the confinement level and the Landlock ABI that `pm-exec` reports.
* The job environment table built from scratch per job type, the rows of the CLI variant included; the `enrolment` rows come from the project's `build_environment`, which the terminal client captured from the operator's login environment and sent with the onboarding or `pm-operator enrol`, and no row is taken from the runtime's own environment.
* The per-project build daemon store, so that no build daemon serves jobs of two write sets.
* The enrolment opt-in `container_engine: docker`, set at the project's enrolment (its onboarding or `pm-operator enrol --container-engine docker`); without it the engine's sockets are withheld and the failure envelope names the opt-in.
* *Probe jobs*: the working directory (the checkout root, or `cwd/` of the probe's job-private directory); the read set of every job plus its own job-private directory, read-only; the write set of the system temporary directory and device nodes, for a harness probe also its `headless.writable_paths` and data home, for a checkout's script the build write set of that checkout; the environment of the all-job rows, the `enrolment` rows from the login environment the terminal client sent, and `PATH` limited to the directories of the probed executable and its interpreter; no job token, MCP connection, credential variable, or session bus.
* No session bus for any job; the runtime socket as an own read rule of every worker.
* *The worker read set*: a worker's read set listed instead of enumerated, from the compiled system locations, the installations of the harness and of the enrolled host tools and interpreters, the bundle-managed files of the harness, its `headless.readable_paths`, and the roots of granted projects; no grant and no entry of a worker's write set that is the home directory or holds a credential location of the compiled list; profile validation and the `paths` stage of the profile verification extended to `readable_paths` and to the credential rule; `pm-exec`'s listed mode comes from link:../../../pm-mcp-clients/doc/plans/exec-listed-read-set.adoc[`pm-mcp-clients` / `exec-listed-read-set`].
* *The concept `Job Confinement`*: a new document in link:../../../plan-marshall-documentation/doc/concepts/[`doc/concepts/`] of `plan-marshall-documentation` (agreed by the operator), written with this package from the specification and the code: why a job is confined as it is, the network kept apart from execution (the worker egress proxy), the listed read set of a worker, why `build` and `project_script` jobs keep the open network for now (link:../../../plan-marshall-documentation/doc/later-improvements.adoc#L-23[Later Improvements, L-23]), and why the confinement of the platform instead of containers; the attack chain of a backdoored model is its worked example and its reasoning is in the analysis link:../../../plan-marshall-documentation/doc/articles/abliterated-models-backdoor.adoc[How Abliterated Models Can Get You Pwned].
* *macOS confinement (Seatbelt) and the worker egress proxy*: on macOS the `pm-exec` launcher confines every job before `execve` with a sandbox profile of the platform that every descendant inherits and no job can remove; the profile denies by default and allows reading the whole filesystem except `<PM_MCP_BASE>` (its own job-private directory excepted) and writing exactly the write set of the Linux ruleset, computed from the same enrolment at job start, and, since `PR_SET_NO_NEW_PRIVS` has no macOS counterpart, it denies `process-exec` of setuid and setgid files instead. For a worker the profile admits outbound connections to its egress proxy's loopback port and to the runtime socket only; the other job kinds keep the network. The release verifies the profile on every supported macOS version with the confinement tests of the Linux ruleset (a write outside the set, a read of `<PM_MCP_BASE>`, a connection that bypasses the proxy, each refused); a version on which the profile cannot be applied runs jobs unconfined and records `confinement: unavailable` in every job record and the runtime status, and a confined job records `confinement: seatbelt`. The worker egress proxy is the runtime's HTTP `CONNECT` proxy on a loopback port, one per worker generation, admitting a tunnel only to a host and port of the profile's `headless.endpoints` and refusing every other one; the worker's `HTTPS_PROXY` and `HTTP_PROXY` name it and `NO_PROXY` is empty; enforcement is the platform's (the macOS profile, a Linux network namespace whose only route is the proxy's loopback forward over a Unix socket), every job record states `egress: enforced`, and a platform that cannot enforce it runs no worker unless the operator accepted unenforced egress, which the runtime status shows for as long as it holds and every job record states `egress: unenforced`. A refused destination is an activity entry of the worker and counts toward the audit record `egress_refused` per worker generation, and a harness whose profile verification did not measure that it works through the proxy is not eligible as a worker host (link:../specification/job-runtime/02-confinement-and-environment.adoc#macos-confinement[Job Runtime § macOS Confinement]; link:../specification/job-runtime/02-confinement-and-environment.adoc#worker-egress[§ Worker Egress Proxy]; link:../specification/client-profiles/01-profile-schema.adoc#profile-verification[Client Profiles § Profile Verification]).
* *Hardened confinement, the runtime's side*: the job record's `confinement` with `partial(abi=2)` for a kernel that offers Landlock ABI 2 only, and the fields `seccomp` and `egress` in `JobRecord`, taken from the launch report; the egress proxy matches a `CONNECT` host by name before it resolves anything, never resolves a refused name, and refuses an admitted name whose address is not public (`address_not_public`); the confinement self-check once per runtime start before the first worker, its effect on the recorded confinement, seccomp and egress, its result in the runtime status and the audit records `confinement_self_check` and `confinement_check_failed`; the `egress` stage of the profile verification extended to a harness that works without a name lookup of its own. `pm-exec`'s part (the Landlock scopes, the system call filter, the truncation report, the parent watch of a worker, the macOS resolver and signal rules, and the check mode) comes from link:../../../pm-mcp-clients/doc/plans/exec-hardening.adoc[`pm-mcp-clients` / `exec-hardening`] (link:../specification/job-runtime/02-confinement-and-environment.adoc#abi-floor[Job Runtime § ABI Floor]; link:../specification/job-runtime/02-confinement-and-environment.adoc#worker-name-resolution[§ Name Resolution]; link:../specification/job-runtime/02-confinement-and-environment.adoc#confinement-self-check[§ Confinement Self-Check]; link:../specification/store-schemas/10-job-and-lesson-records.adoc#job-record[Store Schemas § Job Record]).
* *The git identity check*: every operation of the git contract that the runtime runs, in the native variant over JGit and the CLI variant over `git`, treats a pinned commit as an identity that is checked, never as a name that is looked up: a commit the server pins (the entry baseline and the capture snapshot, the `head_sha` of a pull request, the merge base, an epic's landing, `head_at_completion`) is passed and compared as its full 40-character object id, never abbreviated and never as a ref name; a branch is addressed as `refs/heads/<name>`, a ref of the runtime as `refs/pm-mcp/<…>` and a remote branch as `refs/remotes/<remote>/<name>`, and the CLI variant passes `--end-of-options` where `git` would also accept a commit; a name that resolves both as a ref and as an object id, or as two refs, is refused `git_identity_ambiguous`, naming the name. After every fetch, checkout, reset, rebase and worktree creation the commit reached is compared with the pin the operation was meant to reach, and a mismatch refuses the operation `git_identity_mismatch` with both ids before anything runs on the result; the CLI variant passes a commit as `<id>^{commit}` where a ref is not accepted. A test creates a branch named like the pinned commit in a fixture remote and asserts the refusal in both variants (link:../specification/job-runtime/01-pipeline-and-subprocesses.adoc#git-identities[Job Runtime § Git Identities]; link:../../../plan-marshall-documentation/doc/implementation-watch/cross-cutting.adoc#PM-WATCH-GEN-59[PM-WATCH-GEN-59]).

== Done When

Linux tests under Landlock: a write outside the write set and a read of `<PM_MCP_BASE>` are refused; a worker reads only its listed read set and no credential location (PM-WATCH-JOB-38); a confined Gradle build proves the registry option; the Docker socket is unreachable without the opt-in; the job record carries level and ABI; a probe job cannot read `<PM_MCP_BASE>` beyond its own job-private directory, writes nothing outside its write set, and receives no job token, no credential variable, and no bus variable, its `PATH` holding only the probed executable's directories. The macOS run records `unavailable`. On macOS a job is confined by Seatbelt to the Linux write set, records `confinement: seatbelt`, and has no route out but its worker egress proxy, one per worker generation, a read of `<PM_MCP_BASE>` and an execution of a setuid or setgid file are refused, and a supported macOS version on which the profile cannot be applied records `confinement: unavailable` in every job record and in the runtime status; a worker whose egress is unenforced is refused unless the operator accepted it for the machine, its `HTTPS_PROXY` and `HTTP_PROXY` name its proxy and `NO_PROXY` is empty, an egress connection to a host outside `headless.endpoints` is refused, recorded as an activity entry and audited `egress_refused`, and every job record states `egress: enforced` or `egress: unenforced`; a branch named like a pinned commit in a fixture remote is refused `git_identity_ambiguous`, an abbreviated commit id is refused, a name that resolves as two refs is refused alike, and a commit that differs from its pin after a fetch, a checkout, a reset, a rebase or a worktree creation is refused `git_identity_mismatch` with both ids, in the JGit and the CLI variant alike, the CLI variant passing `--end-of-options` and `^{commit}` where a ref is not accepted; a harness whose profile verification did not measure that it works through the proxy is not eligible as a worker host, and the runtime status shows unenforced egress for as long as the operator's acceptance holds. The proxy test of PM-WATCH-JOB-40 passes (no query for a refused name, `address_not_public` for `127.0.0.1`, `169.254.169.254` and `10.0.0.1`); a job on a Landlock ABI 2 kernel records `partial(abi=2)` and one on ABI 3 or later `confined`; every job record carries `seccomp` and `egress`; the self-check tests of PM-WATCH-JOB-45 pass, a failed refusal downgrading the recorded mechanism and a failed positive control refusing every worker start.
