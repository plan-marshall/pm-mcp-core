Roadmap item:: the protected-path decision at the commit check and the main-checkout clause of the commit boundary (link:../../../plan-marshall-documentation/doc/roadmap.adoc[Roadmap]); the code of the two parts is the plans of the cut, and this package owns the decision
Where:: pm-core (`core.store`: `ProtectedPaths`, `FootprintBoundary`); pm-provider-git (the commit primitive's `CommitSite`)
Status, milestone and dependencies:: in the link:README.adoc#packages[index], the only place that states them

== Tasks

The specification sections named are the single statement of what each task builds.

. *The protected-path decision at the commit check*: the server asks the operator one question over the diff of exactly the touched protected paths, `accept` or `refuse`, and a `refuse` leads to a `fix` task; the family of protected paths is unchanged: link:../specification/phase-workflows/03-q-gate-and-execute.adoc#protected-paths[Phase Workflows § Protected Paths].
. *The main-checkout clause conditional on confinement*: the main-checkout check holds only under `confinement: unavailable`; under confinement the main checkout is no concern of a plan, and the operator's own edits there never concern one: link:../specification/job-runtime/02-confinement-and-environment.adoc#_linux_filesystem_confinement_landlock[Job Runtime § Linux Filesystem Confinement]; link:../specification/store-schemas/02-workflow-state-store.adoc#_workflow_state_store_mcpstatus_json[Store Schemas § Workflow State Store], `entry_baseline`.
. *The lift removal*: `ProtectedPaths` drops the `declared_files` lift, and the family stays what it was; the `unplanned_changes` breach sentence names the protected path it reports: link:../specification/phase-workflows/03-q-gate-and-execute.adoc#protected-paths[Phase Workflows § Protected Paths]; link:../specification/store-schemas/06-task-and-references.adoc[Store Schemas § Task and References].

Left out: the code of the protected-path matcher and of the main-checkout guard themselves, which the plans of the cut own; this package owns the decision they implement.
