== Tasks

The specification sections named are the single statement of what each task builds.

. *The protected-path decision at the commit check*: the server asks the operator one question over the diff of exactly the touched protected paths, `accept` or `refuse`, and a `refuse` leads to a `fix` task; the family of protected paths is unchanged: link:../specification/phase-workflows/03-q-gate-and-execute.adoc#protected-paths[Phase Workflows § Protected Paths].
. *The lift removal*: a path the outline declares lifts no protection, so a declared protected path is decided at the commit check like any other, and the family stays what it was. The matcher `ProtectedPaths` still drops a path named in `declaredFiles` from its result; the change removes that lift from the matcher and its test `ProtectedPathsTest`, from the link:../../pm-core/doc/developer/core-store.adoc#_protected_paths[Scope Stores Developer Guide § Protected Paths] and from link:../../pm-core/doc/adr/core-store/071-the-protected-path-matcher-is-a-pure-core-class.adoc[ADR core-store/071]: link:../specification/phase-workflows/03-q-gate-and-execute.adoc#protected-paths[Phase Workflows § Protected Paths]. This task also owns the description of `unplanned_changes` in `pm-core/src/main/resources/de/planmarshall/core/store/references.schema.json`, which says a change of a protected path is "refused by the non-waivable guards": the change reaches the operator's decision at the commit check, and the description says so. The rows of `doc/Traceability.adoc` that name `ProtectedPaths` name the matcher and its test, not the lift, and stay as they are.

Left out: the main-checkout clause made conditional on confinement (link:../specification/job-runtime/02-confinement-and-environment.adoc#_linux_filesystem_confinement_landlock[Job Runtime § Linux Filesystem Confinement]). The main-checkout guard of the commit primitive in `pm-provider-git` does not implement that condition: `FootprintBoundary.check` refuses every path `CommitSite.mainCheckoutBreaches` reports, neither takes a confinement input, and `git.stage-and-commit` runs the check for every scope before anything is staged, so today any main-checkout change a plan made since its entry baseline refuses its commit unconditionally (documented in `provider-git-primitive.adoc` and `pm-provider-git` ADR `provider-git-primitive/006`). Making that check conditional on confinement is owed work that no package of this index carries.
