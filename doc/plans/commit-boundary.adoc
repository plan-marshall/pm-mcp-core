== Tasks

The specification sections named are the single statement of what each task builds.

. *The protected-path decision at the commit check*: the server asks the operator one question over the diff of exactly the touched protected paths, `accept` or `refuse`, and a `refuse` leads to a `fix` task; the family of protected paths is unchanged: link:../specification/phase-workflows/03-q-gate-and-execute.adoc#protected-paths[Phase Workflows § Protected Paths].
. *The main-checkout clause made conditional on confinement*: the guard's check holds only under `confinement: unavailable`, and under confinement the main checkout is no concern of a plan, so the operator's own edits there never concern one; the guard's code is `worker-write-set-and-main-checkout-guard` (PLAN-V2-193, staged), and this package decides the clause and the wording every reader relies on: link:../specification/job-runtime/02-confinement-and-environment.adoc#_linux_filesystem_confinement_landlock[Job Runtime § Linux Filesystem Confinement]; link:../specification/store-schemas/02-workflow-state-store.adoc#_workflow_state_store_mcpstatus_json[Store Schemas § Workflow State Store], `entry_baseline`.
. *The lift removal*: a path the plan declares no longer lifts a protected path, and the family stays what it was; the matcher's code is `lane-entries-and-realized-composition` (PLAN-V2-190, staged), and this package owns the decision and the `unplanned_changes` wording: link:../specification/phase-workflows/03-q-gate-and-execute.adoc#protected-paths[Phase Workflows § Protected Paths]; link:../specification/store-schemas/06-task-and-references.adoc[Store Schemas § Task and References].

Left out: the code of the protected-path matcher (`lane-entries-and-realized-composition`, PLAN-V2-190) and of the main-checkout guard (`worker-write-set-and-main-checkout-guard`, PLAN-V2-193), which the plans of the cut own; this package owns the decisions they implement and the wording they report.
