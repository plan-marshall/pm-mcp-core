== What

The checks of the static verification rules that link:static-verifier-and-fuzzer.adoc[`static-verifier-and-fuzzer`] left out, each as a further `VerificationRule` constant of `WorkflowValidator`:

* Rule 1, the rest: every `job llm` entity kind resolves to a registered entity kind with its entity unit and return-evaluation primitive; every `each` primitive is a registered read-only list primitive; `role each` is admitted only in `adjudicate.decisions`, with a registered read-only primitive that returns role names; `ask` is refused on a `role each` state and on a state whose entity kind has no entity unit; every role name of a `job llm` state and of a `consult role` clause matches the role-name grammar; every `schema[...]` names a registered schema; every question clause names a registered question class; a primitive that declares `enqueuesJob()` declares its job-starting outcomes, and only their transitions target a `job` or `composite_job` state.
* Rule 2, the rest: the transitions of a `job llm` state form the bijection with the outcomes of its return-evaluation primitive plus `lost`, which stays undeclared only where the rule admits it; `asked` is covered by the engine-made transition and refused when declared; the transitions of a question clause form the bijection with the closed resolution outcomes of its class.
* Rule 3, the rest: state identifiers are unique across the files of the definition unit, the engine-made `<state>.asked` included; `startState` and every transition target exist; reachability under every combination of the `depends_on_config` values; the abort-terminal targeting rules (`plan.aborted` never targeted, `epic.aborted` only by `abort_landed` of `epic.next-work`); the implicit link identifiers `ack`, `consult:<role>` and `answer:<question_id>` in the uniqueness check; a condition kind or a reserved state id refused as a target.
* Rule 4 (single-level leaf tasks), Rule 6 (sub-workflow exit contract and parameter binding), Rule 7 (acyclic call graph, depth at most 4), Rule 8 (gate artifact producer coverage), Rule 9 (step completion once per firing, outcome classes, cycle measures), Rule 10 (links only where a model acts), Rule 11 (no cycle without an awaited event, 11a and 11b) and Rule 12 (link relation and form compatibility).

Not in this package, so no scope is duplicated:

* link:project-units-and-invariants.adoc[`project-units-and-invariants`] owns the loader of project units, the merged plan workflow unit, the format refusals, `project_step_unbound`, `FinalizePipelineValidator` and the compiled invariants `INV-*` and `INV-REM-*`. It calls the verifier with Rules 1 to 12; none of them is its own. An invariant that cites a rule (the condition overlays of Rule 3, the completion once per firing of Rule 9, no resting link state of Rule 10) stays an invariant there; this package implements only the rule check it cites.
* Role existence and class fit (Rule 13, with the `zero_tool` consult check of Rules 1 and 4) join with the role sets of Milestone 4; skill resolution (Rule 14 and the `skill` clause of Rule 3) joins with the skill checks of Milestones 7 and 14. The package leaves the seam.
* Rule 5, the rest (the content of the `released-states.txt` baseline, the default-unit gate and the engine's state rewrite) lives in `plan-marshall-mcp` and link:workflow-engine.adoc[`workflow-engine`].
