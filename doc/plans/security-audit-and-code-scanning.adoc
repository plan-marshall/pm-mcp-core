== What

* *The finding record.* `submitted_severity` and the nested `security` record (`ingress`, `attacker_position`, `privileges_required`, `evidence_level`, `cap_rule`) in `Finding` and its codec, required for `security_audit` and null for every other source; `FindingSchemaParityTest.componentsInSchemaOrder` re-enabled.
* *Located finding grounding.* The refusal at filing of a model-filed finding whose file does not exist at `raised_at_head` or whose line lies beyond that file's end, read from the git object of that commit, a `security.ingress` checked the same way.
* *The security audit calibration.* `test_reproduced` accepted only with a build job of the plan's run; the cap from the declaration `security_severity_caps` of `phase-6-finalize` with its compiled bounds; the threat model `.marshall/config/threat-model.adoc` and the security history (bounded, remainder counted, an unreadable archive named) in the task's facts; the `security_guard_removed` finding from a removed-guard candidate whose lines an earlier security fix added.
* *The code scanning provider.* `github-code-scanning` behind the code-analysis contract of `pm-core`: the configured `tools`, the status rules (a configured tool without an analysis of the head commit `undecidable`, never `not_run`), the issues the pull request adds with their severity mapping and screening, and dismissals only for alerts the plan's pull request raised.
