== What

* *The nine build output parsers.* Maven, Gradle, npm errors, TypeScript, ESLint, Jest, TAP, pyproject (pytest, ruff, mypy) and the OpenRewrite log, each compiled from the `plan-marshall` module it ports and verified by Java tests whose data and expected values derive from that module and its pytest suite: the file, line, column, message, category and severity of a diagnostic, the failing task or test, and the test counts (link:../specification/job-runtime/03-parsers-and-gates.adoc#_native_build_output_parsers[Job Runtime § Native Build Output Parsers]).
* *The counts that may not be guessed.* Test counts aggregated over every summary block of a multi-module run; `tests_population: unmeasured` where a successful build's summaries cannot be aggregated, never `tests_run: 0`; a `no_tests_ran` verdict only from a positive marker; the Maven failure-trailer advice lines dropped whole against a compiled pattern table; an unrecognised `[ERROR]` line categorised `unrecognized`, never a real category; the OpenRewrite parser run only when the build reached `rewrite:run` and the java-cui domain is active, with the fail-closed verdicts `observed`, `not_observed`, `domain_inactive`, `parse_error` (link:../specification/job-runtime/03-parsers-and-gates.adoc#_native_build_output_parsers[Job Runtime § Native Build Output Parsers]).
* *`failed_unparsed`.* A non-zero exit whose output yields no structured diagnostic is `failed_unparsed`, never folded into `failed`, with the raw log kept beside the job record, one failure envelope of class `build` and kind `unparsed` whose excerpt is the bounded redacted log tail (last 50 lines, at most 4 KB) and whose resource is `pm://plan/{plan_id}/builds/{job_id}/log`, and no invented diagnostic (link:../specification/job-runtime/03-parsers-and-gates.adoc#_unparseable_output_fallback_failed_unparsed[Job Runtime § Unparseable Output Fallback]).
* *The coverage report parsers.* JaCoCo, Cobertura, LCOV and Istanbul, parsed natively after the tests: the overall and per-class line percentages and the missed-method detail, the threshold verdict on the overall *line* percentage with the low-coverage list per item, and every other metric parsed and rendered but never feeding a threshold (link:../specification/job-runtime/03-parsers-and-gates.adoc#_native_coverage_report_parsers[Job Runtime § Native Coverage Report Parsers]).
* *Gate honesty.* The four checks before a gate is `fresh` in `change-ledger.jsonl`: the examined population non-empty and covering every module of the realized footprint; the gate coverage computed from the `module` argument, with `gate_coverage` (`COMPLETE`/`PARTIAL`/`UNKNOWN`, `empty_scope` neither a pass nor a gap), `structural_limits`, `uncovered` (`not_at_this_scope`/`not_by_this_gate`/`undeclared`) and the non-empty `parity_population`, persisted in the job record's `gate_facts` and rendered only as `gate_coverage` with the degraded dimensions and `uncovered`; the test-scope divergence detection with the `skipped_tests` of the modules of the realized footprint, each with the reason the parser reads, recorded and never rendered and blocking nothing; and the baseline separation, proved by the provider's result of the same check on the merge base or, as the fallback, by a local build of the merge base in the baseline scratch worktree, with `baseline` and `baseline_debt` verdicts, the `baseline_red` ledger row bound to the gate's `worktree_sha`, and fail-closed attribution where neither proof can be obtained (link:../specification/job-runtime/03-parsers-and-gates.adoc#_gate_honesty_verification[Job Runtime § Gate Honesty Verification]).
* *The adaptive timeout and the failure evidence.* Which runs feed the learned baseline `L` (finished runs, never `killed`, `cancelled` or `timed_out`; a worker only with successful work), the `poisoned` and `cold` filters and the hygiene figures of the build timings store, `budget_derivation` in the job record and never in the representation, the seeded CI wait budget, and the failure evidence per class (`build`, `ci`, `review`, `analysis`, `merge_conflict`, `qgate`) through the ingestion validator and the screening batch of externally authored text (link:../specification/job-runtime/03-parsers-and-gates.adoc#_adaptive_timeout_learning[Job Runtime § Adaptive Timeout Learning]; link:../specification/job-runtime/03-parsers-and-gates.adoc#evidence-gathering[§ Evidence Gathering per Failure Class]).
* *Kept, delivered by `job-runner` and the ingestion work.* `worktree_sha` and its ported tests (`WorktreeShaDigest`, `WorktreeShaPortedTest`) and the ingestion validator (`IngestionValidator`, `IngestionValidatorTest`) are implemented and stay as they are; the provenance provider's snippet matching is a code analysis provider and belongs to the analysis contract.

== Done When

Each of the nine parsers is a JUnit test per diagnostic form of its ported module with the ported module's own expected values, its own fixture for a deliberate change (`unrecognized`, the positive marker of `no_tests_ran`, the trailer table, the OpenRewrite verdicts), and a multi-module log aggregated over every summary block; a successful build with unusable summaries reports `tests_population: unmeasured`, and a `no_tests_ran` verdict arises only with its positive marker.

A non-zero exit with no parseable diagnostic yields `failed_unparsed` with the raw log kept and one `unparsed` envelope whose excerpt is the bounded redacted tail; a signal-ended build is `killed`, never `failed_unparsed`; the representation carries no invented diagnostic.

Each of the four coverage formats parses its fixture into the overall and per-class figures, the threshold verdict follows the overall line percentage only, and a metric outside the line never changes it.

A gate result carries `gate_coverage`, `structural_limits`, `uncovered` and `parity_population` in its job record with the split of `uncovered`; a module-scoped run never satisfies a whole-tree gate; a run that filtered out tests of a modified module is detected; a skipped test appears in `skipped_tests` with its reason where the log gives one and `null` where it does not, and blocks nothing; a failure present on the base is `baseline` or, for coverage, one `baseline_debt` finding per module, the all-baseline red writes its `baseline_red` row for the same `worktree_sha` only and completes `done` with `assurance_verdict: degraded`, a red that is not provably baseline-only is plan-caused, and a base run or result that cannot be obtained attributes every diagnostic to the plan and says so.

A `timed_out` run feeds no baseline and sets the one-shot escalation; a `poisoned` and a `cold` run are stored as such and not blended while warm observations exist; `budget_derivation` appears in the job record and in no representation; a seeded CI wait records its expected duration and never a failure deadline.
