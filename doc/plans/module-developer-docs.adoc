== What

* *One file per package*: every package with production code and no developer file gets one below its module's `doc/developer/` (link:../adr/004-module-documentation-layout.adoc[ADR 004]), named after the package below its namespace `de.planmarshall` with dots replaced by dashes (`de.planmarshall.core.service` is `core-service.adoc`). The file states what the package is for, its main types and how they work together, how to use and extend it, its invariants and failure modes, and links to the specification sections it implements and to the package's ADRs; it does not repeat the Javadoc type by type.
* *The guides that move here*: the package guides still below `plan-marshall-documentation`'s `doc/developer/` — link:../../../plan-marshall-documentation/doc/developer/store-substrate.adoc[`store-substrate`], link:../../../plan-marshall-documentation/doc/developer/enrolment-store.adoc[`enrolment-store`], link:../../../plan-marshall-documentation/doc/developer/locks-and-leases.adoc[`locks-and-leases`], link:../../../plan-marshall-documentation/doc/developer/primitive-spi.adoc[`primitive-spi`], link:../../../plan-marshall-documentation/doc/developer/findings-and-analysis.adoc[`findings-and-analysis`], link:../../../plan-marshall-documentation/doc/developer/runtime-lifecycle.adoc[`runtime-lifecycle`], link:../../../plan-marshall-documentation/doc/developer/workflow-dsl.adoc[`workflow-dsl`] — are folded into the module files of the packages they describe. `project-setup.adoc` and `registry-setup.adoc` stay process documents; `assembly-boundary.adoc` describes `plan-marshall-mcp` code and is not taken over. The deletion there and the pointer from its `DeveloperGuide.adoc` are made by the documentation-repository session, not by this package.
* *Existing files are extended, never overwritten*: the developer files that already exist are extended where they do not cover the package, and their ADR references are corrected against the current ADR directories.
* *Write from `main`*: a statement the code contradicts is corrected, not copied from an older guide; the module listing and the dependency rules of the link:../../../plan-marshall-documentation/doc/specification/module-structure.adoc[Module Structure Specification] are linked, never copied.

== Trace

The package has no requirement of its own. The developer documentation of a package is the operator decision of 2026-10-11, recorded in link:../adr/004-module-documentation-layout.adoc[ADR 004] and amended by link:../adr/007-specifications-of-the-engine-in-this-repository.adoc[ADR 007]: the documentation that belongs to the code lives beside it. Each file links the specification sections its package implements and the package's ADRs, and those stay the trace of the package (link:README.adoc#how[How to Work a Package]).

== Done When

Every package with production code has its developer file below its module's `doc/developer/`; the seven guides are folded into the module files of the packages they describe; every relative link of a developer file and of this package file resolves when opened; and `trace.py` reports `BROKEN LINKS 0`.
