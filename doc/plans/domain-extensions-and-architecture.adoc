== What

* *The four axes and the descriptor.* Axis A (the applicability of a domain to a module, with its `when` predicates and the promotion of optionals), Axis B (the build-system routes and the canonical build verbs), Axis C (the directed dependency-edge derivation with its explicit resolver identity) and Axis D (the path-prefix ownership claims) as sealed interfaces, and the declarative domain descriptor `<domain_id>.json` with its closed schema: the profile skill lists, `additive_to`, `always_on`, `applies_to_module` and `promote_optional_skills_to_default`, `domain_id` as the axis identity, and the validation that fails closed on an unknown key, an unknown resolver or an unparsable descriptor (link:../specification/domain-extensions/01-four-axis-architecture.adoc#_declarative_domain_descriptor_schema_domain_id_json[Domain Extensions § Declarative Domain Descriptor Schema]).
* *The provenance-preserving merges.* `DerivationMerge` over the Axis-C resolvers and the path-attribution merge over the Axis-D attributors in `core.architecture`: the failing-resolver and failing-attributor isolation (status `ERROR`, zero edges or claims, the sanitized `merge: ` note, never a stack trace), registration in `attributorId` order, the surviving report of a dropped duplicate, ordered maps throughout, and every contribution and report stamped with the resolver or attributor ID that produced it (link:../specification/domain-extensions/02-merge-algorithms.adoc[Domain Extensions § Provenance-Preserving Merge Algorithms]).
* *The resolver dispatch and its machine-local binding.* Which discovered resolver runs is the operator's `derivation_resolvers.<resolver_id>.enabled` of the project's `local-config.json` — an absent entry means enabled, only an explicit `false` disables it, a disabled resolver is still reported (`NOT_DISPATCHED`, reason `DISABLED`, zero edges) — and the `project-script` resolver runs the enrolled `edge_resolver` scripts of the project as `project_script` jobs, `NOT_RUN`/`ABSENT` where a project has none (link:../specification/domain-extensions/01-four-axis-architecture.adoc#four-axis-architecture[Domain Extensions § Four-Axis Domain Architecture], Machine-Local Resolver Enablement).
* *Module discovery and the build map.* The server-owned discovery of the modules of a project per build system (Maven, Gradle, npm, pyproject), their kinds and packaging, each build domain's build-file dependency parser (its claimed `pom.xml`, `build.gradle(.kts)` and `settings.gradle(.kts)`, `package.json` and `pyproject.toml` and the ecosystem-qualified coordinates they declare with their scope, or a parse diagnostic, which the change map and the pre-merge Dependency Delta Check read), and the `derive-verification` build map: the route precedence of the longest matching glob, the classification of changed paths into `(role, build_class)`, the canonical command and discovery argument templates, and the `derive-verification` entry of the machine store that records what was derived and what was verified (link:../specification/domain-extensions/03-module-discovery.adoc[Domain Extensions § Module Discovery, Build Map & Architecture Queries]).
* *The architecture query resources.* `pm://architecture/*`: the discovered modules with their facts, the derived edges with their resolver provenance, the attribution table with its attributor notes, and the build map, each a read-only representation over the project's derived facts, plus the LSP edge resolver that reports `NOT_RUN` with its reason until Milestone 13 and the project-script resolver that runs (link:../../../plan-marshall-documentation/doc/specification/mcp-tools.adoc[MCP Tools Specification]).
* *The `documentation` domain verbs.* `asciidoc.validate` as a confined job of the enrolled `asciidoctor` with its diagnostics parsed into findings, the compiled `asciidoc.verify-links` and `asciidoc.format`, and the documentation review as a role task (link:../specification/domain-extensions/01-four-axis-architecture.adoc#documentation-domain-verbs[Domain Extensions § Documentation Domain Verbs]; watch link:../implementation-watch/domain-extensions.adoc#PM-WATCH-EXT-37[PM-WATCH-EXT-37]).
* *Left out*: the recipes and extension points (link:../specification/domain-extensions/05-recipes-and-extension-points.adoc[Domain Extensions § Recipes, Extension Points & Project Scripts], package link:recipe-workflows.adoc[`recipe-workflows`]); the configuration split (link:../specification/domain-extensions/06-configuration.adoc[Domain Extensions § Configuration Split & Upgrades], the packages of the configuration); the setup state machine and the architecture enrichment as the setup's tasks (link:../specification/domain-extensions/04-setup-state-machine.adoc[Domain Extensions § Architecture Enrichment & Project Setup State Machine], package link:project-onboarding-unit.adoc[`project-onboarding-unit`]); the change map that reads the module crawl (link:change-map.adoc[`change-map`]); the build output parsers of `core.build` (package link:build-parsers-and-gate-honesty.adoc[`build-parsers-and-gate-honesty`]).

== Done When

The descriptor of every shipped domain validates against the closed schema, and a descriptor with an unknown key, an unknown axis or an unresolvable `domain_id` is refused with the key and the file, never partially applied; Axis A selects the same modules for a fixture tree as the shipped `applies_to_module` rules state, an optional skill promoted by `promote_optional_skills_to_default` appears in the rendered set, and a `when` predicate naming an unknown build system refuses the descriptor.

The two merges are shown by fixtures with two resolvers and two attributors: a resolver and an attributor that throw are reported `ERROR` with their sanitized note and contribute nothing while their siblings do; the reports are ordered by their resolver or attributor ID and the merged edges by `(from, to)`, whatever order the caller passes; a duplicate attributor ID keeps the first and notes the drop; every edge carries the ID of the resolver that found it and an edge found by two resolvers carries both.

The discovery of a fixture repository of each build system yields its modules, kinds and packaging; the build map classifies a changed production, test and configuration path into the expected `(role, build_class)` and honours the longest global precedence; each build domain's dependency parser reads its claimed build files and returns the ecosystem-qualified coordinates with their scope, a file no parser claims or one that fails to parse yields its diagnostic, and a parsed coordinate set is the same over two reads of one revision; a resolver disabled in `local-config.json` is reported `NOT_DISPATCHED` with `DISABLED` and contributes no edge while the others run; a project with no enrolled `edge_resolver` script reports the `project-script` resolver `NOT_RUN` with `ABSENT`; a malformed `derivation_resolvers` entry fails the closed schema of `local-config.json` and is reported, never read as a setting.

Each `pm://architecture/*` resource answers a fixture project and names its facts' provenance, the LSP resolver answers `NOT_RUN` with its reason, and a read of a project that is not enrolled is refused with the closed outcome.

`asciidoc.validate` runs the enrolled `asciidoctor` as a confined job and files its diagnostics as findings with file and line; `asciidoc.verify-links` and `asciidoc.format` are compiled, and the documentation review runs as a role task; the whole check fails closed where the enrolled `asciidoctor` is missing.
