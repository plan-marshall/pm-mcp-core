= The model slot of an ended job is released in recovery
:nofooter:

link:README.adoc[Work packages of `pm-mcp-core`] » `model-slot-release`

[horizontal]
Roadmap item:: none of its own: the release in recovery completes the model slots of the workers (link:../../../plan-marshall-documentation/doc/roadmap.adoc[Roadmap], Milestone 4)
Where:: pm-runtime package `runtime.start` (the per-project recovery: `JobRecoveryStep`, `LeaseRecoveryStep`) over `ModelSlotScheduler` of `runtime.launch`; pm-core package `core.store` (`ModelSlotStore`, `model-slots.json`) and `core.service` (the audit record)
Status, milestone and dependencies:: in the link:README.adoc#packages[index], the only place that states them

== Tasks

The specification sections named are the single statement of what each task builds. Built today: the model slots are persisted (`ModelSlotStore`, `model-slots.json`), and a settled worker's slot is released through `ModelSlotScheduler.release` behind the port `ModelSlots`. The worker end writes in the order job record, queue task record, model slot. Not built: `JobRecoveryStep` skips every settled job (`if (job.status().isSettled()) continue;`), and `LeaseRecoveryStep` sweeps the lease stores only, so a stop between the recorded fate and the release leaves the slot held until a later admission reaps it as the slot of a dead runtime (`ModelSlotScheduler.java:339`, the reaping in the admission transaction; pm-runtime ADR `runtime-launch/005`), while PM-WATCH-STORE-63's hazard says that no evidence releases it: a model slot has no time expiry, the job was not recorded `killed` at the restart and the owning scope may still be live (link:../implementation-watch/store-schemas.adoc#PM-WATCH-STORE-63[PM-WATCH-STORE-63]); the two readings are reconciled by the build of task 1; the release in recovery adds that the slot is released on the evidence of the recorded fate, at the next start and with an audit record, without waiting for an admission. The Javadoc of `SettlementStep`, which says a worker's model slot is no lease-store slot and is released through `ModelSlotScheduler.release`, is accurate and stays.

. *The release on the evidence of an end fate*: in the per-project recovery, a model slot whose job record already carries an end fate is released at once, the fate being the positive evidence, with an audit record naming the fate, and the next queued worker is admitted; a slot whose job has no fate is kept: link:../specification/store-schemas/13-leases-integrity-testing.adoc#machine-lease-stores[Store Schemas § Machine Lease Stores], _Ownership vs Liveness_; link:../specification/store-schemas/01-format-and-session-log.adoc#transaction-journal[§ Transaction Journal], _Worker end_; link:../specification/runtime-lifecycle/01-startup-recovery-drain.adoc#per-project-recovery[Runtime Lifecycle § Per-Project Recovery], step 4. Module `pm-runtime`, paths `pm-runtime/src/main/java/de/planmarshall/runtime/start/JobRecoveryStep.java`, `pm-runtime/src/main/java/de/planmarshall/runtime/start/LeaseRecoveryStep.java`, `pm-runtime/src/main/java/de/planmarshall/runtime/launch/ModelSlotScheduler.java`; extends `JobRecoveryStepTest`, `JobRecoveryStepRecordsTest`, `LeaseRecoveryStepTest`, `ModelSlotSchedulerTest` and `RecoveryStepsKilledRuntimeIT`. Open: the name of the audit event of the release, which the specification does not give; the plan that builds it writes the name into the specification in its own pull request.

Left out: the slot admission and its FIFO (built, `ModelSlotScheduler`); the build slot's twin of this release, which has no owner: the build slots are lease-store slots, but `LeaseRecoveryStep` sweeps them as orphaned and never releases them — it releases only on a caller-supplied `AbandonmentEvidence`, whose default `NONE` finds none ("so the step never releases", `LeaseRecoveryStep.java:28`, `:51`), and its Javadoc leaves the releases of slots and task leases to `JOBS_AND_WORKERS` (`:33`), where `JobRecoveryStep.java:238` skips every settled job. The specification applies the end-fate release to "a build or model slot" (`store-schemas/13-leases-integrity-testing.adoc:17`; Runtime Lifecycle § Per-Project Recovery, step 4), while PM-WATCH-STORE-63 covers the model slot only, so the build slot's twin stays owner-open here.
