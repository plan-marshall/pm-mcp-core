== What

This package implements link:../specification/model-work/08-epic-coordination.adoc#epic-actions[Model Work § An Epic's Actions], link:../../../plan-marshall-documentation/doc/specification/runtime-model/01-processes-and-transport.adoc#epic-resource[Runtime Model § The Epic as a Resource], and link:../specification/credentials-and-enrolment/02-enrolment-and-project-lifecycle.adoc#project-release[Credentials & Enrolment § Releasing Ends Work as the Operator Ends It] (`PM-WF-23`, `PM-MIG-5`). The step names the use cases give these flows (`epic.actions`, `epic.raise-scope`, `epic.confirm-cancel`, `epic.cancel`) are operator acts over the local API, never workflow states (link:../specification/state-catalogue/01-conventions-generic-conditions.adoc#operator-flows[State Catalogue § Operator Flows That Are Not Workflow Units]). It builds on the plan's activity, the ends of a plan, and the holds of link:plan-and-epic-control.adoc[`plan-and-epic-control`].

* *The epic as a resource* (UC-PLN-5): `GET /api/v1/epics/{epic_id}` with its rows, sources, landings, registers' counts, the draft while one is open, the archive check, its history; the operator's acts as its endpoints.
* *Chat*: not built here. The action Chat among the actions of a plan and of an epic in every state, read-only on an ended plan or epic, its endpoint, and the conversation itself, also its follow-up plan from ended work, are link:chat.adoc[`chat`]'s, which adds the action to the lists of actions this package builds; this package leaves its place in them and does not wait for it.
* *An epic's actions* (UC-CTL-2): next plan, decompose again, the reviews, archive, cancel, chat, and the toggle _Automatic: on/off_ with the overlap limit, each an operator endpoint of the epic's resource, validated, answered with the epic's new state, audited, and re-entering `epic.next-work` as an `operator_action`; what the epic starts and does by itself is link:epic-auto.adoc[`epic-auto`]'s, the review and decompose again link:epic-decomposition.adoc[`epic-decomposition`]'s.
* *Next plan*: `epic.next-work` starts the next launchable row now under the same admission tests; with no launchable row it answers why per row (`dependency`, `lock`, `scope`, `overlap`, `stale`, `held`); with `parallelization_scope` full it offers to raise it by one, a ledger write of the header.
* *Archive*: `epic.review-completion` first where it has not run since the epic was through, then the archive check `epic.archive-check` (no plan running, pausing, or paused, every row shipped or ended, no `open` finding, the ledger landed, the completion review done), archiving through `epic.archive` only when it passes and otherwise answering what is open; kept findings and watches are listed as carried and archived with the epic; `terminal_reason` `completed`.
* *Cancel*: with the operator's reason (`pm-operator abort epic` its shell form) and the choice for its plans (cancel them, each `cancelled`, or let them run on detached); the epic ends through `epic.aborted` with `terminal_reason` `cancelled`, the value `abandoned` of the code renamed (pre-1.0, no shim). This cancel is also the resolution _abort_ of an integrity pause of an epic, a hold of link:plan-and-epic-control.adoc[`plan-and-epic-control`] (its bullet _Holds and their acts_), which offers it as the hold's act.
* *The release of a project* (UC-PRJ-3, an act of both clients, `POST /api/v1/projects/{project_id}/release`, `pm-operator project release` its terminal form, confirmed with what it ends): a running short landing of the project (`git.land-removal`, `git.land-unit`) finishes first within `release.landing_wait_seconds`, no new start or short landing admitted meanwhile (`lifecycle_closed`), and when it does not, the release is refused `release_landing_pending` and ends nothing; then `released_at` is written into the enrolment with an `operator` audit record; every plan that has not ended, whatever its state, ends through `plan.aborted` with the outcome `released` (never `cancelled` or `abandoned`) and is archived, its open decisions and waiver requests closed `cancelled` and its lesson claims released; every epic ends with the `terminal_reason` `released` by an engine-owned transition into `epic.aborted` that bypasses `epic.archive`, its open tasks withdrawn and its machine scope archived in the project's machine store only, its ledger left in `.marshall/epics/<epic_id>/` untouched, with no ledger commit and no epic landing; the outcome `released` changes no queue row; the pending entries are deleted with their sources, each entry ended as a scope first so that whatever stands on its call stack ends with it (a running task withdrawn with the reason `withdrawn`), and a running onboarding or setup run is ended; the report `project.released`; the release touches no repository. While `released_at` is set, a start is refused `lifecycle_closed`; enrolling again clears it. Unenrol stays refused while work runs, `scope_active` naming it.

== Done When

A test per act of an epic shows what it does and what it refuses, also an epic whose ledger has not landed failing the archive check; next plan with the raise of `parallelization_scope`, the archive check (an open finding holds it, kept findings and watches carried), and cancel behave as specified, also with no launchable row, and an epic ends `completed`, `cancelled`, or `released`, never `abandoned`; a release waits for a running short landing and is refused `release_landing_pending` when it does not finish, deletes the pending entries, a task running in one withdrawn, ends a running onboarding, ends every plan `released` and every epic `released`, archives the epics machine-side only with their ledgers untouched, changes no queue row, and makes no commit in any repository. A release refuses new starts and short landings of its project while it runs, and a released project refuses a start until it is enrolled again, after which a start is accepted.
