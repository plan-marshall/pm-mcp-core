== What

* *The renderer and the placeholder table.* `ClientProfileRenderer` renders the vocabulary skill templates, the launch prompts of workers and the model-facing guidance strings of representations from the canonical placeholder notation, with the normative resolution table for `claude`, `opencode`, `antigravity` and `codex`: the seven tool placeholders and `{{skill_load:<uri>}}`, rendered from the profile of the harness of the role's effective configuration, recorded in the job record (link:../specification/client-profiles/02-placeholders.adoc#_on_the_fly_placeholder_rendering_rules[Client Profiles § On-the-Fly Placeholder Rendering Rules]).
* *`{{tool:ask_user}}` and the worker.* It renders only where a skill tells a worker not to use it: a worker asks only through its task's `ask` links, the server delivers the decision to the operator's clients, and the host's own question tool is never in a worker's tool set (`tool_not_permitted`; link:../specification/model-work/01-roles-and-configuration.adoc#role-validation[Model Work § Role Validation]).
* *The rendering invariants.* Zero unresolved placeholders (a token that does not resolve fails closed and is logged as a template defect, never emitted raw); the per-variant SHA-256 digest of the rendered bytes `_meta["de.planmarshall.mcp/sha256"]`, stable while those bytes are unchanged; no worker without an eligible harness (rendering never replaces a worker by inline work); vocabulary-only translation (byte-identical outside resolved placeholders, never emphasis, scaffolding, structure or format); profile completeness for every canonical placeholder in every built-in and operator-installed profile, checked at build time; and the technique precondition rendered per project as "available technique, not adopted in this project" (link:../specification/client-profiles/02-placeholders.adoc#_rendering_invariants[Client Profiles § Rendering Invariants]).
* *The calibration decision.* Model-facing content is written once and rendered vocabulary-only; whether it is adequate for a model is what role qualification measures. A calibration axis is keyed by the model of the role artifact, never by `client_id`, and one multiplies the rendered digests, so it needs per-model content and a qualification of every role on each model it distinguishes before it ships (link:../specification/client-profiles/02-placeholders.adoc#calibration-decision[Client Profiles § Calibration Decision]).
* *The host-resident surface inventory.* Per built-in profile, the bytes the harness injects into every turn of a worker — the tool schemas and descriptions of the role's tool set when `schema_residency: resident`, the shim skill's description where the bundle installed it, and the `pm_skills` catalogue entries once loaded — per component and in total with the population it measured; the derived length and shape bounds and their derivation, enforced by a build-time test; the named runtimes and models a description shape rule was reasoned about (link:../specification/client-profiles/02-placeholders.adoc#host-resident-surface-inventory[Client Profiles § Host-Resident Surface Inventory]).
* Left out: the profile schema, the harness scan, the login probe and the profile verification stages (link:../specification/client-profiles/01-profile-schema.adoc[Client Profiles § Client Profile Schema], package `profile-loader`, shipped); the launch vector, the job record and the launch refusals (link:worker-launch.adoc[`worker-launch`]); the served-bytes side of `pm_skills` and `pm_skill` (link:../../../plan-marshall-mcp/doc/plans/worker-surface-tools.adoc[`plan-marshall-mcp` / `worker-surface-tools`]); the preview and user documentation of the client profiles (`pm-mcp-clients`, the documentation repository).

== Done When

Every canonical placeholder and `{{skill_load:<uri>}}` resolves in each of the four built-in profiles and in an operator-installed profile, and a template with a token no profile resolves fails closed with the template named in a template-defect log line and no raw `{{…}}` reaching the rendered bytes; two renders of one template under two profiles differ only inside the resolved placeholders.

The digest of the rendered bytes is stable over two renders of unchanged bytes and changes when a resolved value changes, and neither a configuration change nor a version change that leaves the rendered bytes unchanged changes it; `{{tool:ask_user}}` renders where a skill tells a worker not to use the host's question tool and the tool is in no worker's tool set.

A build-time test renders every template for every built-in profile and fails on an unresolved or missing form; an optional technique whose precondition is unmet renders with the "available technique, not adopted in this project" marker in place of binding wording, and the precondition result enters the digest.

The host-resident surface inventory is derived per built-in profile with its population, its per-component and total bytes match the fixture's rendered surface, a bound derived from the measured distribution is enforced by a build-time test, and a description shape rule names the runtimes and models it was reasoned about.
