== Tasks

The code is the source of these lists, so the direction of the check turns: the document takes the list from the code, or does not state it.

. *The log message tables are generated*: for every holder table of `doc/LogMessages.adoc` a committed file below `doc/` lists the identifier and the template of every record of the holder, generated from the holder; the document includes the file in place of the table rows. The Component and Description columns go: what a record is for stays the Javadoc of the record, which the document links per holder. Before a column goes, every sentence of a Description that the Javadoc of its record does not say (for example the reason a guard closes tasks with, or the component that logs the record) moves into that Javadoc. The generated files are the only files below a `doc/` tree that a test still reads.
. *The check of the generated files*: a test per module compares the committed file with a fresh generation byte for byte and parses nothing; its matched positive control is the current file, its negative control a file with one identifier or template changed.
. *The protocol lists are dropped*: the enumerations of the `TaskRefusal` values, the `WaitAgain` reasons and the `End` reasons in `pm-workflow/doc/developer/workflow-task.adoc` are replaced by a link to the Javadoc of the enum or the type that holds them; the prose around them stays. Before a list goes, the Javadoc of `TaskRefusal`, `WaitAnswer.WaitAgain` and `WaitAnswer.End` names every value or reason the list names, so a reader of the link finds them.
. *Remove the checks that parse a document*: `everyRecordDocumented` and `undocumentedRecordsAreFound` of `RuntimeLogMessagesTest` are replaced by task 2, and `ProtocolVocabularyParityTest` is deleted.
. *The other holders*: a holder of `doc/LogMessages.adoc` whose rows no test checks follows the same form (ADR link:../adr/005-one-log-message-holder-per-module.adoc[005]).
