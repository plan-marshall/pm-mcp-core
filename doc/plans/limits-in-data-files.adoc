Roadmap item:: none: two tests read a number out of the sentences of a specification with a regular expression, `StalledScopeDetectorTest` and `UnitFrontmatterReaderTest`; rewording the sentence breaks them
Where:: pm-runtime (`StalledScopeDetector`), pm-workflow (`ProjectUnitLoader`, `UnitFrontmatterReader`)
Status, milestone and dependencies:: in the link:README.adoc#packages[index], the only place that states them

== Tasks

The value of each limit lies in one file of the module; the code reads it from there and the specification includes it. No second copy and no prose that a test has to parse.

. *Stalled threshold*: the value of `StalledScopeDetector.THRESHOLD` (`timeouts/02-runtime-leases-operator-web.adoc`, anchor `stalled-threshold`) goes into a properties resource of pm-runtime between `# tag::stalled-threshold[]` and `# end::stalled-threshold[]`; the constant is read from it when the class loads and fails fast when the resource or the key is absent.
. *Unit frontmatter limits*: `MAX_UNIT_FILE_BYTES`, `MAX_FRONTMATTER_LINES` and `MAX_ECHO_LENGTH` (`workflow-dsl/01-grammar.adoc`) likewise, in a properties resource of pm-workflow, one tag per limit.
. *The specification includes the tagged lines* (`include::<path>[tag=…]`) where it states the value; the sentence around it names the key and no longer repeats the number. A limit that cannot be stated that way is carried by the file alone.
. *Tests*: the two tests that match a number in the prose are replaced by a test of the load (the present resource is read; the absent resource and a non-numeric value fail, never default) and of the behaviour at the limit, which `UnitFrontmatterReaderTest` and `StalledScopeDetectorTest` already hold.
. *The other values of the `timeouts` registry* have no test that reads them and are left as they are; they follow the same form when a test needs one.
