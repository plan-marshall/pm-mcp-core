== What

* The loader reads the whole profile documents that are resources of `pm-api` and validates them against the profile schema (with the `headless` members `install_locations`, `install_hint`, `auth_probe`, `models_probe`, `model_tiers`, `events`, and `resumability`, and the top-level `icon`); a failing profile is refused as a whole. The usage block and its rule that `input_tokens` and `output_tokens` are never `not_applicable` are link:token-usage.adoc[`token-usage`]'s.
* *The installed profile sets*: the machine set `<PM_MCP_BASE>/profiles/` and the project set `<PM_MCP_BASE>/projects/<project_id>/profiles/` beside the shipped one, the nearest set winning as a whole document and never merged; a project profile only for a `client_id` the machine or shipped set defines, with equal `detection`, `identity`, and `headless.executable`. A machine or project profile counts only with its verification record: `profile_digest` equal to the SHA-256 of the canonical JSON (RFC 8785) of the document and the HMAC sidecar verified with the key of the enrolment store; otherwise it is refused `profile_unverified` and the next set stays in force. A record whose harness version or digest differs from the enrolled harness within the supported range marks the profile `verified_on_other_build` and launches go on. Writing the sets is the onboarding's (link:machine-onboarding-unit.adoc[`machine-onboarding-unit`]); this package reads them and reports the state it found.
* Build test: every shipped profile validates.

== Done When

Every shipped profile loads and validates; for each hardening rule that concerns the parts read here, and for each pattern-constrained new member (`install_locations`, `install_hint`, `icon.source` with https and SVG or PNG only, `resumability.resume.argv` with its session-id slot exactly once), there is a fixture profile that the loader refuses as a whole, with the document and the JSON Pointer of the failing value asserted; a machine profile of a `client_id` the release does not ship is loaded; a machine or project profile without a record, edited after its record, or with a failing HMAC is refused `profile_unverified` and the next set's profile is in force; a project profile whose `detection` differs from the machine one is refused; a record of another harness build yields `verified_on_other_build`; a build test fails when a class of the loader names a harness, proven by a control fixture.
