== What

* *Specification first*: the package writes the change Reports to the Operator into `plan-marshall-documentation` as part of its own work, once it and UC-PLN-6 are agreed (link:../../../plan-marshall-documentation/doc/discussions/client-specification-changes.adoc#slicing[Specification Changes for the Clients, Packages]): the new requirement the change drafts, in `doc/requirements/02-workflow.adoc` under the next free PM-WF id; and the specification sections it names: the report journal (Store Schemas, Filesystem Layout of the machine scope), the endpoints and the event stream (Runtime Model § Local API), the representation with its `detail` link (Hypermedia Format), the report id `rep-NNNN` (Identifiers), the event sources (which server transition writes which kind), the catalogue's texts, and a plan's completion report with its Tokens section beside the completion and usage records.
* *A report*: a record the runtime writes for the operator when something happened that the operator should know without having to act; it never asks anything, and what blocks stays what it is (decisions, waits, holds: `needs_operator`). Its fields: id (`rep-NNNN`); `from` (the project, and the epic and the plan where there are, each with its link); `kind`; `subject` (one line, a text of the catalogue with its parameters, in the client's language); a short body; `created_at` (when it happened) and `sent_at` (when the clients could see it, later than `created_at` where it was written after a restart); `read_at` with the channel and device that read it; `detail`, the link to the detailed report where there is one.
* *The catalogue*: closed, first version `plan.started` (by the operator, an epic, or a recipe; a plan an epic starts gives this one report, its `from` naming the epic), `plan.ended` (with its outcome, one of the closed list of plan outcomes of the terminal-state catalogue as link:plan-and-epic-control.adoc[`plan-and-epic-control`] extends it), `plan.revised` (a re-planning or a chat's revision), `plan.hold_released`, `epic.launchable` (automatic off, a row became launchable), `epic.waits_overlap`, `epic.overlap_found`, `epic.recut_applied`, `epic.through`, `epic.ended`, `project.onboarded`, `project.released`, `source.flagged`, `decision.closed_elsewhere`, and `system.cleanup_due`, which link:cleanup.adoc[`cleanup`] adds with its source; each kind with its subject text in English and German and its `detail`.
* *The sources*: each kind written by the server transition that makes it true, once, in the same step: the start and the end of a plan and its outcomes and holds (link:plan-and-epic-control.adoc[`plan-and-epic-control`]), a revision (re-planning and link:chat.adoc[`chat`]), a row launchable with automatic off, its overlap wait and the overlap found, an applied recut, and the epic through (link:epic-auto.adoc[`epic-auto`]), the end of an epic and the release of a project (link:plan-and-epic-control.adoc[`plan-and-epic-control`]), a project onboarded (link:project-onboarding-unit.adoc[`project-onboarding-unit`]), a screened source flagged (link:start-from-clients.adoc[`start-from-clients`]), a decision closed in another channel (link:decision-engine.adoc[`decision-engine`]); no report is written outside the catalogue.
* *The store*: one journal of the machine scope (link:operator-wait-and-machine-scope.adoc[`operator-wait-and-machine-scope`]), `<PM_MCP_BASE>/state/reports.jsonl`, with the events `report` (a new report) and `read` (its `read_at`, channel, and device), the current state of a report folded from them; unread reports never expire; read ones are kept until the cleanup of the machine deletes them (link:../../../plan-marshall-documentation/doc/use-cases/07-system.adoc#UC-SYS-3[UC-SYS-3], built by link:cleanup.adoc[`cleanup`]).
* *Read*: a report is read when the operator marks it read (one, or all shown) or opens its detail; read is per machine, so a report read on one device is read on all, with the channel and device recorded; marking a report read twice changes nothing.
* *The endpoints*: `GET /api/v1/reports?state=unread` (unread only, newest first, grouped by project, then epic and plan; the count of unread reports), `POST /api/v1/reports/{report_id}/read`, `POST /api/v1/reports/read` with the ids the client showed (only those, never one that arrived since), the event stream `GET /api/v1/reports/events` that announces a new report and a read one to every open client; the representation with `from`'s links and the `detail` link, addressed through link:entity-addressing.adoc[`entity-addressing`]; the same acts as operator verbs.
* *The details*: a plan's completion report `GET /api/v1/plans/{plan_id}/completion`, new as a view of an ended plan built on its archive entry and its records (outcome, reason, its pull request, deliverables done, re-planning records, decisions taken, its tokens, duration); the epic's completion review and the landing record as they are; a subject that has been archived opens from the archive; opening a detail through a report's `detail` link marks the report read.
* *The completion report's Tokens section* (link:../../../plan-marshall-documentation/doc/use-cases/03-plans.adoc#change-token-usage[Tokens, Not Money]): usage only, every figure the unified one of link:token-usage.adoc[`token-usage`] with its split (input, output) and from its one derivation: the plan's total with the wall time; by phase; by role (a role pins harness, model, and effort); by model and harness; the waste, the tokens of the tasks of spend class `no_product` and of the retries and remediations by cause class; the coverage, the tasks unmeasured with their reasons and a total over them shown as a floor. No cost (recorded, never shown), no limit, no budget line, no projection, and no comparison with one: the plan has none (link:token-usage.adoc[`token-usage`] removes them).

== Done When

The requirement and the specification of the change are merged in `plan-marshall-documentation`; a test per kind of the catalogue shows its source transition writing exactly one report with `from`, subject, `created_at`, `sent_at`, and `detail`, and no transition writing a kind outside it; a report written after a restart carries a later `sent_at`; the list returns unread reports only, newest first and grouped, with their count; marking one read, marking the ids shown read (not one that arrived since), and opening the detail each set `read_at` with channel and device, once, and the read state is the same on every device; the journal folds to the same state after a restart; the event stream announces a new and a read report; a plan's completion report shows outcome, reason, pull request, deliverables, re-planning records, decisions, and duration for each outcome, also for an archived plan, with its Tokens section by phase, role, model and harness, waste, and coverage, a total over unmeasured tasks shown as a floor and no cost, limit, or budget comparison in it; no report ever waits for the operator.
