== What

* *Specification first*: the package writes the changes Phases as Sub-Workflows and The Plan's History into `plan-marshall-documentation` as part of its own work, once UC-PLN-1 is agreed (link:../../../plan-marshall-documentation/doc/discussions/client-specification-changes.adoc#slicing[Specification Changes for the Clients, Packages]).
* *Phases as sub-workflows*: the plan unit becomes a workflow of phases, each phase (`init`, `refine`, `outline`, `plan`, `execute`, `land`, `finalize`) a sub-workflow it calls; a lane is the choice of the phases it calls, a loop-back a call of a phase again, a re-entry from finalize into execute an outcome of finalize. The `phase` clause and the phase value table go; a plan's phase is the phase on its call stack; the call depth grows by one; the plan instance composes the phases and prunes a phase as a call.
* *The plan's history*: an append-only history per plan of states entered and left, sub-workflows called and returned, with their outcomes, the instance version in force, and the time; archived with the plan; the runtime derives each node's state from it.
* Where `workflow-engine`, `plan-instance`, or `project-units-and-invariants` have already implemented the flat plan unit, this package restructures them.

== Done When

The specification of both changes is merged in `plan-marshall-documentation`; every phase is a sub-workflow the plan unit calls, and the static verifier and the fuzzer pass over the default units; a test per lane shows the phases it calls and prunes; a loop-back calls a phase again and the history records both runs; a plan's history reproduces the node states of its process after a runtime restart.
