== What

* The one implementation that turns the corpus's own part into a complete corpus: it reads the source manifests (a public dataset's repository, a pinned commit, every file used with its SHA-256, the licence) and the overlays (which rows, the item framing, written replies, rubrics, review status) that the model verification corpus holds (link:../../../plan-marshall-mcp/doc/plans/question-corpus-public-datasets.adoc[`plan-marshall-mcp` / `question-corpus-public-datasets`]), fetches each source at its pin, checks every file against its hash, and generates the items into a cache outside the repository.
* The fetch goes through two service interfaces in `pm-core`: the git part is implemented with the cache repository operations of the git contract of `pm-provider-git` (plain JGit), which read a file stored with Git LFS as its pointer; the LFS part, in `pm-runtime`, downloads the pointer's object from the repository's LFS batch endpoint through `cui-http`; the object is checked against the pointer's SHA-256. `pm-mcp-server` composes the two.
* A source that cannot be fetched is reported by name and its items are left out: the result names the sources it covers and those it misses, so that a qualification on a partial corpus is recorded as such. A file that does not verify fails the run.
* The same code serves both uses: our development, through a JUnit test of `plan-marshall-mcp` in its own Maven profile (it needs the network), and `pm-operator roles qualify` on a user's machine, through link:role-qualification.adoc[`role-qualification`].
* The item validation of the corpus (the rules of `test/model/verification/validate.py`: schema, id equals path, canary, closed answers among the choices, rubric items, context files, no transient names) as a Java validator over the corpus's own and the generated items, so that the build validates the corpus without Python.

== Done When

Against a local fixture repository (a plain file and an LFS object, served without network): a pinned source is fetched, verified, and its overlay generated into valid items; a changed file fails its hash; an unreachable source yields the remaining items and names the missing source; the Java validator accepts the corpus's own items of `plan-marshall-mcp` as present at its current main and rejects each rule's negative fixture; its acceptance of generated items is proven against the local fixture.
