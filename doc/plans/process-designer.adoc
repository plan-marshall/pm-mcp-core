== What

* *Implements* link:../../../plan-marshall-documentation/doc/specification/workflow-dsl/04-ast-node-model.adoc#process-designer[Workflow DSL § Designing a Process] and the levels of link:../../../plan-marshall-documentation/doc/specification/workflow-dsl/04-ast-node-model.adoc#project-owned-units[§ Designable Workflow Units, Levels & Compiled Invariants] (items 1, 2, 4, and 5), with the short landing `git.land-unit` of link:../../../plan-marshall-documentation/doc/specification/state-catalogue/18-plan-unit-axes-short-landings.adoc#state-catalogue-short-landings[State Catalogue § Short Landings] and the recipes' places of link:../../../plan-marshall-documentation/doc/specification/domain-extensions/05-recipes-and-extension-points.adoc#recipe-workflow[Domain Extensions § A Recipe Is a Workflow] (`PM-WF-22`, `PM-IMPL-5`).
* *What can be designed*: the closed set of designable units: the phase sub-workflows `phase-1-init.pmwf` to `phase-6-finalize.pmwf` and `land.pmwf`, `git-commit-and-push.pmwf`, `remediation-*.pmwf`, `replan.pmwf`, `adjudicate-decisions.pmwf`, the variants of the plan behaviour axes (`landing.*`, `method.*`, `ask.*`), each held to the compiled invariants of the part of the process it takes over (`INV-AXIS-1`), and the recipes' workflows (type `recipe`). An axis's variants are a closed list: a variant is changed, never added. A compiled-only unit (the plan unit, the epic, setup, onboarding, bootstrap, source units, `chat`, …) is served read-only as a building block.
* *The levels*: the compiled default, the machine's copy (`<PM_MCP_BASE>/workflows/<unit>.pmwf`, a recipe's at `<PM_MCP_BASE>/recipes/<id>.pmwf`, the operator's, never committed), and the project's copy (`.marshall/config/<unit>.pmwf`, a recipe's at `.marshall/recipes/<id>.pmwf`). *This package builds the unit resolver*, in the loader of link:project-units-and-invariants.adoc[`project-units-and-invariants`] and in the composition of the plan instance alike: a unit resolves project copy › machine copy › compiled default, and only an absent unit defers to the next level; a unit present but invalid never falls back: a refused machine unit refuses the plan lifecycle of every project it reaches, a refused project unit that project's, naming file and line. A machine recipe is offered in every project on the machine, and a project's recipe of the same key takes its place there.
* *No first copy*: the setup copies no default unit into `.marshall/config/`; a project holds only the units it changes, and the code where the setup unit or the loader of link:project-units-and-invariants.adoc[`project-units-and-invariants`] assumed a first copy is changed accordingly. A changed machine or project unit raises `config_drift` at the next phase handshake of every plan it reaches and is adopted (event `config_adopted`) only when it verifies and still contains the plan's position.
* *The installed units* (`GET /api/v1/projects/{project_id}/workflows`, `GET /api/v1/workflows`): for a project the designable units with, per level, whether a copy exists, its text and digest, and which level is in force; for the machine the machine level's units with the compiled defaults, so a machine-level unit is designed with no project chosen.
* *The catalogue of building blocks, in two scopes* (`GET /api/v1/projects/{project_id}/workflows/catalogue`, `GET /api/v1/workflows/catalogue`): for a project as it resolves them (its copies over the machine's over the compiled defaults, its effective role set), for the machine the compiled and machine-level units and the machine's role set. It is complete (the primitives of `do`, `auto`, `job`, and `guard` with their parameter records and outcomes; the guards and their condition kinds; the link relations and forms; the reusable and compiled sub-workflows with their parameters, entries, and exits, the phases among them; the roles with their class; the declarable parameters with their compiled bounds; the keywords and clauses with a template each), each unit shown by the name and description of its frontmatter; it is generated from the registries the parser, the static verification, and the composition use, never from a list kept apart, and carries the runtime's version and a digest that changes after an upgrade or a placing.
* *Validation* (`POST /api/v1/workflows/validate`: text, kind, name, and the target, a project or the machine): exactly as the units of that level load: the frontmatter's format, fields, and interface, the parse, Rules 1–12, the compiled invariants, and a dry-run composition against the project's effective configuration, roles, skills, and providers (Rules 13 and 14), for a machine target against every enrolled project the unit would reach, each finding naming its project; with no enrolled project the dry run is reported `not_run` with the reason `no_project`. The answer lists the findings with rule or invariant, line, and column, and for a valid unit the composed process in the form of the plan's process resource. The dry run starts and stores nothing.
* *Placing and removing* (`PUT` and `DELETE /api/v1/workflows/{unit}` at machine level, `PUT` and `DELETE /api/v1/projects/{project_id}/workflows/{unit}` at project level, a recipe's workflow under the recipe's key): operator acts that re-validate in the same request, at machine level against every enrolled project the unit would reach (a removal validating the unit of the next level), refused with `unit_invalid` and each failing project's findings, and with `no_project_to_compose` while no project is enrolled; carrying the digest of the unit they replace, refused with `conflict` when it changed meanwhile; refused with `unit_not_designable` for a compiled-only or non-designable unit, a variant name its axis does not list, and the key of a built-in or domain recipe; refused with `unit_invalid` when the unit fails validation, among them when its author is `plan-marshall` or its type, entries, or exits differ from those of the unit it replaces (`INV-GEN-1`).
* *Project level as a short landing*: a unit placed or removed at project level is written to `.marshall/config/` (a recipe's to `.marshall/recipes/`) and landed by one commit through `git.land-unit`, by the project's landing (`landing.pull-request` or `landing.main`; with `landing.files` it stays uncommitted in the working tree); until it has landed it shows in the project's running work, and a failed landing waits for the operator (the hold `landing_failed`, `git-land-unit.failed`). A new plan takes a project unit once it has landed on the base branch, a running plan through `config_drift` at its next sync with the base; with `landing.files` no plan takes it until it is committed. A machine unit is in force from its placing.
* *Path confinement*: every route that names a unit accepts only a name of the canonical unit-name grammar (the `state_id` of the link:../../../plan-marshall-documentation/doc/specification/identifiers/01-general-rules-and-registry.adoc#id-state-id[Identifier Registry]: no path separator, no `..`, no absolute path) that the catalogue lists as designable for that level, and writes or deletes only after checking that the resolved path lies inside its target directory (`<PM_MCP_BASE>/workflows/`, `<PM_MCP_BASE>/recipes/`, `.marshall/config/`, `.marshall/recipes/`) after normalisation and the resolution of links; otherwise `unit_name_invalid` (`400`), before anything is read, written, or removed.
* *The web listeners, no audit record*: every designer endpoint is on the runtime's own `/api/v1/`, none `cli_only`, reached by the web app through the loopback or the LAN listener with its device secret, so a paired device and the loopback browser read, validate, place, and remove. Placing and removing write no audit record: the origin of a unit is its frontmatter (author, modification date, release). Downloading needs no endpoint: the client writes the text it holds.
* Out of this package: a unit designed for one plan only and its promotion, and a model's help in designing.

== Done When

A fixture unit at each level shows the precedence project copy › machine copy › compiled default in the loader and in the composition alike, only an absent unit defers, and removing a copy returns to the next level; a unit name with a separator, `..`, or an absolute path, a name the catalogue does not list as designable, and a name whose path resolves outside its target directory (through a link) are each refused with `unit_name_invalid` on the machine and the project routes, for placing and for removing, and nothing is read, written, or deleted; a set-up project holds no copied default unit; an unparsable and a violating unit at project and at machine level each refuse the lifecycle with file and line and never fall back to the next level; a changed machine unit is adopted by a running plan through `config_drift`; the validation of a fixture with a frontmatter error, a parse error, a rule violation, and an invariant violation returns each with its rule or invariant, line, and column, and for a valid one its composed process without starting or storing anything, the dry run `not_run` with `no_project` while no project is enrolled; a machine placing and a machine removal that fail for one enrolled project are refused `unit_invalid` naming it, and every placing while no project is enrolled `no_project_to_compose`; a new axis variant, a compiled-only unit, and the key of a built-in recipe are refused `unit_not_designable`, a unit whose type, entries, or exits differ from the replaced one `unit_invalid`, and a placing over a unit whose digest changed meanwhile `conflict`; a changed variant is held to the invariants of its part of the process; a machine recipe is offered in every project and a project's recipe of the same key takes its place; a new plan takes a project unit only once it is on the base branch, a running plan at its next sync with the base, and with `landing.files` no plan until it is committed; a project-level placing lands as one commit through `git.land-unit` by `landing.pull-request` and `landing.main`, stays uncommitted with `landing.files`, and a failed landing shows as the hold `landing_failed`; no placing or removing writes an audit record; the catalogue of the machine scope and of a project each lists every primitive of the SPI registry, every role of the respective role set, every sub-workflow of the unit loader, and every keyword of the grammar, a test comparing it with those registries, and every block it offers inserted into a fixture unit passes validation; its digest changes after a placing and after a version change; every designer endpoint answers on the web listeners to a paired device and to the loopback browser, none `cli_only`.
