== Scope

Modules of this repository in the milestone: `pm-core`, `pm-runtime`.

The milestone delivers the always-on daemon on its Unix socket, the session relay, the operator CLI, process coordination, and the security foundation. What it means and requires is stated in the documentation repository and only referenced here: the requirements the milestone names, the specifications and their watch documents. This plan holds the tasks: what this repository does for the milestone, in which module and package, in which order, and how each task is proven.

The other two plans: link:../../../pm-mcp-clients/doc/plans/milestone-02-runtime-relay-operator.adoc[`pm-mcp-clients`] and link:../../../plan-marshall-mcp/doc/plans/milestone-02-runtime-relay-operator.adoc[`plan-marshall-mcp`].

== How to Work a Task

* *Trace first.* The tasks are cut from the roadmap items, with the requirements, sections, and watch documents the roadmap names. Before code, the implementing session builds the trace matrix of the project skill `traced-implementation` (`../plan-marshall-documentation/.claude/skills/traced-implementation/SKILL.md`) for the task: every requirement bullet, every specification section, and every watch item anchored to them, each with its destinations. A task is split or extended where the matrix shows it; a row left out is recorded `out of slice` with its reason.
* *Present and remaining.* Each roadmap item of the milestone states what the code of Milestone 0 already covers. Read it before a task: a task delivers the remainder, never a second form of what exists.
* *Order.* Second. It builds against the `SNAPSHOT` of `pm-mcp-clients`; `plan-marshall-mcp` wires what this plan delivers.
* *Done.* A task is done with its guarding tests, `verify`, `verify -Ppre-commit` (its rewrites reviewed and committed), `verify -Pcoverage`, and `verify -Pintegration-tests` green, and the native build where the task touches a binary.
* *Documents.* A statement of a requirement or specification that a task proves wrong is corrected in the documentation repository, never worked around in code. The concept, developer, and user documentation of a task, the deletion of the implemented specification sections and watch items, and the ticks in the roadmap go into one pull request in `plan-marshall-documentation` that names the code pull request and merges after it.

[[M2-CO-1]]
=== M2-CO-1: Runtime lock manager, lease records, and the stale lease sweep

Where:: pm-core packages `core.service`, `core.store`; pm-runtime package `runtime.lock`
What::
* One lock manager for every acquisition: one in-process lock per key and at most one OS `FileChannel.lock()` per lock file; the one total lock order asserted on every acquisition, an out-of-order acquisition refused as `internal_fault` with an audit record.
* Sibling lock files for every store replaced by atomic rename; lock paths outside the directories they protect.
* Lease records for the long-lived claims, claimed and released under a short transaction lock; the stale lease sweep.
* Lock-free snapshot reads of the stores.
Trace::
* Requirements: link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-IMPL-7[PM-IMPL-7]
* Specification: link:../../../plan-marshall-documentation/doc/specification/store-schemas/13-leases-integrity-testing.adoc#lock-free-snapshot-reads[Store Schemas § Lock-Free Snapshot Reads, Transaction Locks & Leases]; link:../../../plan-marshall-documentation/doc/specification/store-schemas/13-leases-integrity-testing.adoc#machine-lease-stores[§ Machine Lease Stores]; link:../../../plan-marshall-documentation/doc/specification/filesystem-layout/02-machine-runtime.adoc[Filesystem Layout § Machine & Runtime]
* Watch: link:../../../plan-marshall-documentation/doc/implementation-watch/store-schemas.adoc[Store Schemas]; link:../../../plan-marshall-documentation/doc/implementation-watch/cross-cutting.adoc[Cross-Cutting]
Depends on:: —
Done when:: A unit test per rule of the lock order, with the refusal of an out-of-order acquisition; a two-process test of the OS lock.

[[M2-CO-2]]
=== M2-CO-2: Runtime lifecycle: bounded verification, drain, recovery, sweep, version mismatch

Where:: pm-runtime package `runtime.start`
What::
* The bounded verification step of the startup order.
* Drain: the runtime ends only after its drain, bounded by the drain timeout of the machine configuration.
* Per-project crash recovery, run lazily per project and in a background pass after the bind.
* The periodic sweep, and the detection of a runtime whose version differs from the installed binaries.
* Jobs and workers join each of these in Milestone 4; this task leaves the seams they need.
Trace::
* Requirements: link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-7[PM-ARCH-7], link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-ARCH-1[PM-ARCH-1], link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-TECH-3[PM-TECH-3]
* Specification: link:../../../plan-marshall-documentation/doc/specification/runtime-model/02-startup-recovery-drain.adoc[Runtime Model § Startup, Recovery & Drain]; link:../../../plan-marshall-documentation/doc/specification/runtime-model/02-startup-recovery-drain.adoc#per-project-recovery[§ Per-Project Recovery]; link:../../../plan-marshall-documentation/doc/specification/runtime-model/02-startup-recovery-drain.adoc#periodic-sweep[§ Periodic Sweep]; link:../../../plan-marshall-documentation/doc/specification/timeouts/02-runtime-leases-operator-web.adoc#runtime-lifecycle[Timeouts § Runtime Lifecycle]
* Watch: link:../../../plan-marshall-documentation/doc/implementation-watch/runtime-model.adoc[Runtime Model]
Depends on:: M2-CO-1
Done when:: Tests of each step with a killed-runtime fixture; the cold start bound of PM-TECH-3 is measured again after the change.

[[M2-CO-3]]
=== M2-CO-3: Anchored audit trail

Where:: pm-core package `core.store` (records, chain); pm-runtime (head, rotation, verification)
What::
* The append-only audit log as a hash chain with its HMAC head, keyed from the keyring primitive that exists.
* Rotation with the audit index, and the incremental verification at runtime start.
* The verification that `pm-operator audit verify` requests.
Trace::
* Requirements: link:../../../plan-marshall-documentation/doc/Requirements.adoc#PM-SEC-6[PM-SEC-6]
* Specification: link:../../../plan-marshall-documentation/doc/specification/cli-and-security/02-credentials-and-operator.adoc#_security_audit_trail_three_tier_identity_verification[CLI & Security § Security Audit Trail]; link:../../../plan-marshall-documentation/doc/specification/store-schemas/12-machine-stores.adoc#audit-log[Store Schemas § Audit Log]; link:../../../plan-marshall-documentation/doc/specification/store-schemas/12-machine-stores.adoc#audit-head[§ Audit Head]; link:../../../plan-marshall-documentation/doc/specification/store-schemas/12-machine-stores.adoc#audit-index[§ Audit Index]
* Watch: link:../../../plan-marshall-documentation/doc/implementation-watch/cli-and-security.adoc[CLI & Security]; link:../../../plan-marshall-documentation/doc/implementation-watch/store-schemas.adoc[Store Schemas]
Depends on:: M2-CO-1
Done when:: Fixtures with a removed, a reordered, and an edited record, and with a replaced head, each detected; a rotation in the middle of a verification.
