== What

* *Implements* link:../specification/credentials-and-enrolment/01-provider-credentials.adoc#credential-store-choice[CLI, Coordination & Security § Credential Store as an Operator Choice] with link:../specification/credentials-and-enrolment/01-provider-credentials.adoc#credential-store-move[§ The move] and the store rules of link:../specification/credentials-and-enrolment/01-provider-credentials.adoc#os-keyring-backends[§ Credential Stores] (`PM-CRED-2`, `PM-CRED-3`). Present: the three stores behind `SecretStore` (`KeychainSecretStore`, `SecretServiceStore`, `FileSecretStore`) with the service name per instance and the project entry before the global entry, the enrolment integrity key in the keyring or the key file (`EnrolmentKey`), and `SecretStoreSelector`, which chooses the one active store at start by itself and falls back to the file store; that automatic choice is what this package replaces.
* *The recorded store*: the runtime reads `credentials.store` of `machine-config.json` (`os` or `file`) and uses that store and no other; `SecretStoreSelector` and its fallback go. Before the store is recorded no credential is entered (`onboarding_incomplete`, naming the store step); a recorded OS store that is unavailable at start or later makes the credentials unavailable with its cause, a step that needs one held with `credential_store_unavailable`, a write refused with `credential_store_locked`, and nothing written to the file store in its place.
* *Recording the choice*: an operation that writes `credentials.store` under `locks/machine-config.lock`, called by the credential-store aspect of the machine's onboarding and by the move, and refused for every other writer (`aspect_owned`); before an OS store is recorded, the check of that store writes, reads back, and deletes one test entry, each step a check line; asking the consent `check_credential_store` before it and the states `store.*` are link:machine-onboarding-unit.adoc[`machine-onboarding-unit`]'s.
* *The integrity key before the choice*: until `credentials.store` is recorded the key is created where the runtime finds a store, in the OS store where one is available, else in the key file `<PM_MCP_BASE>/state/enrolment-hmac.key`; `EnrolmentKey` reads it from the recorded store once there is one, and the choice moves it like every other entry, nothing re-signed.
* *The move* in either direction (OS to files, files to OS), an operator act of the aspect or of `pm-operator credentials migrate os|file`: recorded with from, to, and start; every Token Lane entry copied into the target and read back; the integrity key copied last and every HMAC sidecar (the enrolment files, `harnesses.json`, `logs/audit.head`) verified under it in the target; `credentials.store` switched in one write; every entry deleted from the old store; the record ended. A failed copy or read-back before the switch ends the move with nothing switched and the copies deleted from the target (`credential_store_failed`); a move cut by a stop resumes after the next start from its record, before the switch from the first entry, after it with the deletion; no store but the recorded one is read while it runs; the move is audited.
* *Tests per OS*: the Keychain and Secret Service paths run with `@EnabledOnOs`, the Secret Service also against the session keyring like `SecretServiceIT`; the file store and the move between a fake OS store and the file store run everywhere.
* *The assembly*: the producer of the active store in `plan-marshall-mcp` (`SecretStoreProducer`) follows in a pull request there.

== Done When

With no store recorded, entering a credential is refused with `onboarding_incomplete` and the integrity key is created in the store the runtime finds; with `os` recorded and the OS store unavailable, no file is written, the cause is reported, and a step needing a credential is held with `credential_store_unavailable`; no code path chooses a store by itself; a move in each direction copies and reads back every entry, moves the integrity key last after the sidecars verify, switches once, and empties the old store; a failed read-back leaves the old store in force and the target without copies (`credential_store_failed`); a move cut before and after the switch completes after a restart; the OS paths are tested on their OS; `verify`, `verify -Ppre-commit`, `verify -Pcoverage`, and `verify -Pintegration-tests` are green.
