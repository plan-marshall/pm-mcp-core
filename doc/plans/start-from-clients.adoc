== What

* *Specification first*: the package writes the changes All Interaction in the Operator's Clients, Starting from the Clients, The Source Directory, Documents as a Source, What Is on This Machine Is Trusted, Screened Once Stored, Issues by Number or URL, and Asked When Needed into `plan-marshall-documentation` as part of its own work, once UC-STA-1 to UC-STA-4 and UC-STA-7 to UC-STA-9 are agreed (link:../../../plan-marshall-documentation/doc/discussions/client-specification-changes.adoc#slicing[Specification Changes for the Clients, Packages]).
* *The operator's clients only*: the bootstraps of a plan and an epic run as units of operator waits that the clients drive; the session-driven units, the entry session, and the channel `session` of answers go, with the static verification rule that allowed links-only states in them.
* *Sources as a list*: `start.sources` and `start-epic.sources`; the description stored by the main workflow; the source units `source-documents` (copy or move, the machine's default; a move removes a file git tracks from git through the short landing `git.land-removal`), `source-issue` (number or URL, always stored as its URL, another repository on the operator's grant, the structured fields), and the existing ones of lesson, local changes, pull request, and epic row, each writing into the source directory.
* *The source directory*: created with the entry, moved into the plan or the epic's machine store at creation; the manifest; `origin` naming the sources; the epic header listing them; `request.md` composed from them; `epic.decompose` reading them.
* *Screened once stored*: fetch, level-1 validator, store, screener over the stored copy, the verdict in the manifest; nothing but the screener reads an external source before a clean verdict or the operator's acceptance; the operator's text and the documents on the machine are never screened.
* *The other sources* (UC-STA-7 to UC-STA-9): pull request, lesson, and local changes as sub-workflows storing into the source directory; an issue's and a pull request's URL stored.
* *An epic's sources in its ledger* (`.marshall/epics/<epic_id>/sources/`, committed and landed), so that adoption and every decomposition read them.
* *Chat while starting*: `start.sources` and `start-epic.sources` leave room for the choice Chat that link:chat.adoc[`chat`] adds on top of this package, and the source directory keeps its transcript (moved at the creation, deleted with an abandoned entry, never a source the plan reads); the chat itself and its one change, the description through `start.store-description`, are that package's.
* *Loopback only*: the listing of files, a move, and documents outside the checkout only from the terminal client and the loopback listener; `POST /api/v1/entries` goes.
* *Asked when needed*: posture, base branch, outline review, and `parallelization_scope` (a project key now) leave the start and become operator waits where they are first needed, skipped where the project or the machine sets them.
* Where `entity-addressing`, `plan-instance`, or `project-units-and-invariants` have already implemented the session-driven bootstrap, this package restructures them.

== Done When

The specification of the changes is merged in `plan-marshall-documentation`; no unit is driven by a session and the static verifier refuses one; a test per source kind stores it in the source directory with its manifest entry; a plan and an epic start from several sources and keep them after creation; no model but the screener reads an external source before its verdict, shown by a test that fails the screening; each option of the start is asked where it is first needed and not at all when the project or the machine sets it.
