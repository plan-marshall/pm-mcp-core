== What

* *Specification first*: the package writes the changes All Interaction in the Operator's Clients, Starting from the Clients, The Source Directory, Documents as a Source, What Is on This Machine Is Trusted, Screened Once Stored, Issues by Number or URL, Asked When Needed, and A Claimed Lesson Ends with the Landing into `plan-marshall-documentation` as part of its own work, once UC-STA-1 to UC-STA-4 and UC-STA-7 to UC-STA-9 are agreed (link:../../../plan-marshall-documentation/doc/discussions/client-specification-changes.adoc#slicing[Specification Changes for the Clients, Packages]).
* *The operator's clients only*: the bootstraps of a plan and an epic run as units of operator waits that the clients drive; the session-driven units, the entry session, and the channel `session` of answers go, with the static verification rule that allowed links-only states in them.
* *Sources as a list*: `start.sources` and `start-epic.sources`, offering only the kinds that combine with those already listed (a pull request or the local changes only with descriptions and documents, never both); the description stored by the main workflow; the source units `source-documents`, `source-issue` (number or URL, always stored as its URL, the structured fields; another repository on the operator's grant, whose _no_ goes to `source-issue.failed`; without a credential for the forge a public issue is read and another fails naming the credential), and the existing ones of lesson, local changes, pull request, and epic row, each writing into the source directory.
* *Rate limits*: a fetch of an issue or a pull request that the forge refuses for its rate limit, with or without a credential, fails the source with the cause `rate_limited` and `resets_at` from the forge's answer; it is not retried by itself, and the operator tries again or adds a credential for the forge.
* *Documents, copy or move*: the machine key `sources.documents_mode` (`copy`, `move`, or `ask`, the default); with `ask` the operator wait `source-documents.mode` with _copy_ preselected, where _always_ stores `copy` or `move` as the machine's value; otherwise straight to `source-documents.store`. A move removes a file git tracks from git through the short landing `git.land-removal`, landed by the project's landing (`landing.pull-request` or `landing.main`); with `landing.files` the removal stays uncommitted in the working tree.
* *An entry never expires*: a pending entry has no time limit; it stays among the project's open entries, offered to continue in both clients, until it is started or abandoned, or deleted with the release of its project. The pending entry record's maximum age (24 hours, `PENDING_ENTRY_MAX_AGE` of `PeriodicSweep`) and the removal of older records by the project recovery and the periodic sweep go, in the specification and in the code.
* *The source directory*: created with the entry, moved into the plan or the epic's machine store at creation; the manifest; `origin` naming the sources; the epic header listing them; `request.md` composed from them; `epic.decompose` reading them.
* *Screened once stored*: fetch, level-1 validator, store, screener over the stored copy, the verdict in the manifest; nothing but the screener reads an external source before a clean verdict or the operator's acceptance; the operator's text and the documents on the machine are never screened.
* *Fail closed*: a screener that fails, or a role `screener` with no qualified configuration, leaves the source unscreened with the cause in the operator wait `source-<kind>.unscreened` (`source-issue.unscreened`, `source-pr.unscreened`): try again, remove it, or accept it explicitly as untrusted, recorded with its reason like an accepted flagged source; a failure is never shown as `suspicious`.
* *The other sources* (UC-STA-7 to UC-STA-9): pull request, lesson, and local changes as sub-workflows storing into the source directory; an issue's and a pull request's URL stored. A pull request's changed files are stored as its head and marked untrusted unless the operator authored it, never read by a model as instructions, the plan's own gates applying to them; its title and body screened as an issue's. A lesson: `source-lesson.resolve` with the premise check; a lesson claimed meanwhile, retired, or in a damaged store back to `source-lesson.choose` with the cause; a premise that no longer holds to the operator wait `source-lesson.premise` with the evidence, where _use it anyway_ stores the lesson with the evidence for the plan, _retire_ retires it in the lesson store, and _remove_ leaves it as it is, both adding nothing. The local changes: `source-local-changes.confirm` with _not now_ back to `start.sources`, a checkout without changes failing the source with that cause; the plan takes the land lane and lands them by the project's landing.
* *The start's end*: `start.ready` refuses a landing that does not fit the sources or the project, with the reason: `landing.files` for a plan from local changes, and a machine default that does not fit the project (the landing variants are link:machine-onboarding-unit.adoc[`machine-onboarding-unit`]'s); `start.create` re-checks what creation needs and returns to `start.ready` with the cause where something changed meanwhile.
* *A claimed lesson ends with the landing*: the lesson of a source is claimed at the plan's creation and retired when the plan lands its changes (the merge of `landing.pull-request`, the push of `landing.main`; verdict `applied`, `by` the plan), released when it ends without landing them (handed back with `landing.files`, cancelled, abandoned, released, aborted, deleted), the lesson staying `active`.
* *An epic's sources in its ledger* (`.marshall/epics/<epic_id>/sources/`, committed and landed), so that adoption and every decomposition read them.
* *Chat while starting*: `start.sources` and `start-epic.sources` leave room for the choice Chat that link:chat.adoc[`chat`] adds on top of this package, and the source directory keeps its transcript (moved at the creation, deleted with an abandoned entry, never a source the plan reads); the chat itself and its one change, the description through `start.store-description`, are that package's.
* *Entries addressed like plans and epics*: created under their project (`POST /api/v1/projects/{project_id}/entries`, the kind `plan` or `epic`), addressed at the top level by id (`/api/v1/entries/{entry_id}`, its events at `/api/v1/entries/{entry_id}/events`); `POST /api/v1/entries` goes.
* *Loopback only*: the listing of files, a move, and documents outside the checkout only from the terminal client and the loopback listener.
* *Asked when needed*: posture, base branch, and outline review leave the start and become operator waits where they are first needed, skipped where the project or the machine sets them. `parallelization_scope` becomes the project key `epic.parallelization_scope` (machine default 1), which a new epic takes and which is never asked; it is raised through _Next plan_ (link:plan-and-epic-control.adoc[`plan-and-epic-control`]) or the project's settings.
* Where `entity-addressing`, `plan-instance`, or `project-units-and-invariants` have already implemented the session-driven bootstrap, this package restructures them.

== Done When

The specification of the changes is merged in `plan-marshall-documentation`; no unit is driven by a session and the static verifier refuses one; a test per source kind stores it in the source directory with its manifest entry; a plan and an epic start from several sources and keep them after creation; no model but the screener reads an external source before its verdict, shown by a test that fails the screening and one whose screener fails or has no qualified configuration, leaving the source unscreened until tried again, removed, or accepted as untrusted; a pull request's changed files are never read as instructions; a rate-limited fetch of an issue and of a pull request fails with `rate_limited` and `resets_at` and is not retried; a pending entry older than a day is still offered and no sweep removes it; each branch of a lesson, unavailable and a premise that no longer holds, ends as specified; each option of the start is asked where it is first needed and not at all when the project or the machine sets it, and `parallelization_scope` never; `start.ready` refuses `landing.files` for local changes; documents are asked copy or move only with `ask`; a claimed lesson is retired on a merge and on a push to the base branch and released on every other end.
