== What

* *Specification first*: the package writes the change The Runtime's Metrics into `plan-marshall-documentation` as part of its own work, once it and UC-SYS-2 are agreed: the new requirement the change drafts, under the next free id of the requirements domain it names (link:../../../plan-marshall-documentation/doc/requirements/01-architecture.adoc[PM-ARCH]); the metrics catalogue as a closed list in the specification; the endpoints and the stream (Runtime Model § Local API); the representation; and, where the change takes it, the exposition on loopback.
* *The requirement*: the runtime keeps the figures of what it is doing as metrics, a registry of named counters, gauges, and timers maintained where things happen, never computed by scanning stores on a request; a figure the platform cannot give is reported unavailable with its reason, never as `0`.
* *The catalogue*, closed, first version as the change fixes it: the runtime's identity (version, build, started at, uptime, the open listeners, loopback and network); the process (heap and resident memory, CPU where the OS gives it, the disk use of `<PM_MCP_BASE>`); the work (plans and epics by state, running, waiting, held, paused, across projects and per project; tasks queued and running; workers by role, harness, and model, busy and idle; jobs running and queued by kind, with the build and model slots; locks held); the models (calls, tokens, and cost per model and per role, errors and retries, over the windows now, today, and the last seven days). No metric is recorded outside the catalogue, and none carries content of a plan, a task, or a secret.
* *Maintained where things happen*: each figure is recorded by the code that makes it true, in the same step: a plan's or epic's transition, a task offered, leased, and ended, a worker started, idle, recycled, and ended, a job admitted and settled, a slot and a lock claimed and released, a model call's usage row written (link:slots-usage-and-budgets.adoc[`slots-usage-and-budgets`]). The windows of the model figures are rebuilt once at startup from the usage records and then kept by the same increments; the counts of plans and epics by state once from the stores after recovery.
* *The endpoints*: `GET /api/v1/system` (the identity, the process, and the totals) and `GET /api/v1/system/metrics` (the catalogue's metrics with their labels, values, and units, an unavailable one with its reason); an event stream of changed values for live views, the interval and the stream's name as the change fixes them; each figure with the link to what it counts where there is one (the running plans, the jobs, the workers), addressed through link:entity-addressing.adoc[`entity-addressing`]. Both are read endpoints for both channels, from a paired web device as from `pm-operator`. A standard exposition (OpenMetrics text on loopback) for outside tools is delivered only if the change takes it.
* *The library is not chosen here*: which library implements the registry (a metrics library, or none and a registry of the product's own) is a dependency decision for the operator (CLAUDE.md: no dependency without asking). The package blocks on it and never decides it; the seam of pm-core names no library type.

== Done When

The requirement and the specification of the change are merged in `plan-marshall-documentation`, and the operator has chosen the library; a test per metric of the catalogue shows the code that makes it true recording it in the same step, and no metric outside the catalogue; no request reads a store to answer a figure; after a restart the model windows and the counts by state equal those rebuilt from the stores; a figure the OS does not give is reported unavailable with its reason, never `0`; the snapshot endpoints and the stream answer both channels, the stream announcing a changed value; no metric carries content or a secret.
