== What

* *Implements* link:../../../plan-marshall-documentation/doc/specification/runtime-model/01-processes-and-transport.adoc#runtime-metrics[Runtime Model § The Runtime's Metrics] (`PM-ARCH-9`), with the disk-use step of link:../../../plan-marshall-documentation/doc/specification/runtime-model/02-startup-recovery-drain.adoc#periodic-sweep[§ Periodic Sweep] and the metrics event interval of link:../../../plan-marshall-documentation/doc/specification/timeouts/02-runtime-leases-operator-web.adoc#metrics-event-interval[Timeouts § Metrics Event Interval].
* *The registry*: one registry of named counters, gauges, and timers; each metric has one writer, its unit, and its labels from the closed set `project`, `role`, `harness`, `model`, `kind`, `state`, and a name distinct from the names of the metrics store; no figure is computed by reading the stores on a request, none leaves the machine, and a figure the platform does not give is `unavailable` with its reason, never `0`.
* *The catalogue*, closed, as the specification lists it: `runtime.version` (with its build), `runtime.started_at`, `runtime.uptime`; `runtime.memory.heap`, `runtime.memory.resident`, `runtime.cpu` (read at a snapshot from `/proc` on Linux and the task information on macOS); `runtime.disk.machine_store` (kept by the periodic sweep with when it was measured); `runtime.listeners`; `work.scopes`, `work.tasks`, `work.workers`, `work.jobs`, `work.slots`, `work.locks`, `work.leases`; `models.calls`, `models.tokens_in`, `models.tokens_out`, `models.total_tokens` (per hour with the coverage of the hour, each token figure the unified one of link:token-usage.adoc[`token-usage`]), `models.errors`, `models.retries`. No metric is recorded outside the catalogue, and none carries content of a plan, a task, or a secret, or a cost.
* *Maintained where things happen*: each figure is recorded by the code that makes it true (a plan's or epic's transition, the task queue, the supervisor, the job runner, the slot scheduler, the lock manager and the lease stores, the transaction that writes a task row or ends an attempt); the work's gauges are set from the recovered state at every start, and the models' hourly figures filled at the start from the task rows of the metrics stores and the machine's usage aggregate `state/usage-aggregate.jsonl` of link:cleanup.adoc[`cleanup`], which stay the truth; unmeasured usage counted as unmeasured.
* *The endpoints*: `GET /api/v1/system` (the snapshot of the system view, with the window `hour`, `today`, or `7d` and the project as parameters) and `GET /api/v1/system/metrics` (every metric with its labels), both never waiting for a project's recovery and marking a recovering project; the runtime-wide stream carries `system.metrics` with the figures that changed, at most once per metrics event interval; each figure with the link to what it counts where there is one, addressed through link:entity-addressing.adoc[`entity-addressing`]; read by a paired device like every resource and by `pm-operator system`.
* *The library is not chosen here*: which library implements the registry is an open question of the documentation repository (link:../../../plan-marshall-documentation/doc/discussions/open-questions.adoc#metrics-library[Open Questions, metrics library]) and a dependency decision for the operator (CLAUDE.md: no dependency without asking). The package blocks on it and never decides it; the seam of pm-core names no library type.

== Done When

The operator has chosen the library; a test per metric of the catalogue shows the code that makes it true recording it in the same step, and no metric outside the catalogue; no request reads a store to answer a figure; after a restart the model windows and the counts by state equal those rebuilt from the stores; a figure the OS does not give is reported unavailable with its reason, never `0`; the snapshot endpoints and the stream answer both channels, the stream announcing a changed value; no metric carries content, a secret, or a cost, and every token metric carries its split and its coverage.
