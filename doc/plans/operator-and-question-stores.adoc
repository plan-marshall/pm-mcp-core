== What

* The append-only stores of waivers and waiver consumptions of a plan (`waivers.jsonl`, `waiver-consumptions.jsonl`), and of question records of the plan, epic, and workspace scopes and of an entry (`pending/<entry_id>/questions.jsonl`, moved into the new scope at its creation).
* Waiver requests are no store of their own: they are read and written as `waiver_requests[]` of the scope's `mcp/status.json` through the workflow state store, with the closed outcomes `waived`, `raised`, `declined`, and `cancelled` and the `answered` act; no request has a time limit or an `expired` outcome.
* The question record: a decision is a set of questions named by its first `question_id`; the events `asked`, `revised`, `adjudicated`, `delivered`, `answered`, `withdrawn`, and `cancelled`; the `decision` member on the first question of the set; a `revised` line per question of the set for a change, each line naming its revision; the channels `web`, `cli`, and `quorum`; no deadline and no expiry member. The store holds the record's own invariants: a question is closed by exactly one `answered`, `withdrawn`, or `cancelled` line, a further answer is refused `already_answered`, and an answer to an older revision `conflict`; the validation of an answer's content against its part is the engine's.
* The module of the question store is settled in the trace matrix: this package names pm-core `core.store`, the Javadoc of the engine port `QuestionRecordReader` names pm-runtime, and the module structure places the question records in pm-workflow `workflow.question`.
* The per-project machine store below `<PM_MCP_BASE>/projects/<project_id>/` and the state-free repository directory `.marshall/local/`.
* The project resolution rule every request of a client that names a checkout path rests on.

== Done When

Round-trip and append-only tests per store; a changed record is a new line and the last readable line of its key is current; a revision appends a `revised` line for every question of its set; a second closing line is refused `already_answered` and an answer to an older revision `conflict`; an entry's question file is moved into the new scope at its creation and read there; a waiver request round-trips through `waiver_requests[]` with each outcome. Resolution fixtures: a worktree, a nested checkout, a moved checkout and an unenrolled directory each resolve as specified; nothing with state is written below the repository.
