== Tasks

The specification sections named are the single statement of what each task builds; the values come from the runs of `plan-marshall-mcp` / `question-loop-follow-up`.

. *The `headless.resumability` values* of the measured profiles, and the stage `resumability` with its expectation for a missing session: link:../specification/client-profiles/01-profile-schema.adoc#headless-resumability[Client Profiles § Resumability]; link:../specification/client-profiles/01-profile-schema.adoc#profile-verification[§ Profile Verification].
. *The member `headless.inline_settings`* validated by `core.profile` and merged by the launch, with its checked OpenCode 2.x values: link:../specification/client-profiles/01-profile-schema.adoc#headless-inline-settings[Client Profiles § Inline settings].
. *A place in the schema*, or a recorded reason for none, for each finding of the follow-up the profile schema has no member for: link:../specification/client-profiles/01-profile-schema.adoc#headless-block[Client Profiles § Headless Block].
. *The `questions` values of the shipped roles and the question bound*: link:../specification/model-work/01-roles-and-configuration.adoc#roles[Model Work § Roles as Configuration Artifacts]; link:../specification/model-work/06-envelopes-questions-deadlines.adoc#question-bound[Model Work § Question Bound].
. *The values handed to `pm-api`* of `pm-mcp-clients` as the owed change.

Left out: the code of the stage `resumability` (link:question-continuation.adoc[`question-continuation`]); the supported version range, launch, version probe, `events` mapping and tool names of the OpenCode 2.x profile (its own roadmap item); the measurement itself (`plan-marshall-mcp` / `question-loop-follow-up`).
