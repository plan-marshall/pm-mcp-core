== What

* *The division of the measurement.* `plan-marshall-mcp` / `question-loop-follow-up` measures and keeps its own repository's work and the documents in `plan-marshall-documentation`; this package owns every engine value the measurement settles and every statement of the specification it writes those values into. The follow-up names this package as the owner of the engine's part.
* *The `headless.resumability` values.* The measured candidates of link:../specification/client-profiles/01-profile-schema.adoc#headless-resumability[Client Profiles § Resumability] become the shipped values of the profiles the follow-up measured, per shipped profile, with a form it did not measure staying `false` or `null`; the follow-up's driver settled them from its own runs, and the stage repeats the measurement. The rule there that every value comes from the stage is reconciled with that order: the follow-up settles, the stage repeats. The stage or its expectation — a resume of a missing session fails at once — takes the form the follow-up's task 12 decided, so that it agrees with the hosts that start a new session instead (`opencode`, `antigravity`).
* *The `headless.inline_settings` member.* The member stays in the `required` list of the profile schema and `null` where a harness has none, and `core.profile` validates it and the launch composition merges it — the specification's rule is not left as text alone. Its provisional `opencode` 2.x values of link:../specification/client-profiles/01-profile-schema.adoc#headless-inline-settings[Client Profiles § Inline settings] become the values the follow-up checked the effect of, one key at a time, never its acceptance alone (link:../implementation-watch/client-profiles.adoc#PM-WATCH-CLIENT-17[PM-WATCH-CLIENT-17]). Where Milestone 14's item that verifies and ships the OpenCode 2.x profile has not landed when the values are ready, the OpenCode profile keeps its provisional object, the measured ones stay in the evaluation reference, and the other profiles' `resumability` values ship regardless; that item keeps the supported version range, the launch, the version probe, the `events` mapping and the tool names, and this package takes only what the question-loop measurement settles.
* *The places of the findings.* The four findings the profile schema had no place for — whether a model reaches the tools, a missing session that starts a new one, a cut call the worker survives, and the OpenCode tool-catalog refusal — get a place in the schema, or a recorded reason why the schema stays as it is.
* *The `questions` values and the question bound.* The `questions` values of the shipped roles (link:../specification/model-work/01-roles-and-configuration.adoc#roles[Model Work § Roles as Configuration Artifacts]) and the question bound (link:../specification/model-work/06-envelopes-questions-deadlines.adoc#question-bound[Model Work § Question Bound]) take the values the follow-up's R4 measurement and its bound variants settle, with the event-log evidence per variant; both stay open, not guessed, until those runs exist.

== Done When

The shipped `headless.resumability` values per profile are the measured ones, or — where Milestone 14's 2.x profile has not landed — the measured candidates for the OpenCode profile are in the evaluation reference and that profile keeps `false` and `null`, while the other profiles ship theirs; the stage or its expectation agrees with the measured hosts in the form the follow-up decided; the `headless.inline_settings` values of the OpenCode 2.x profile are the checked ones, or stand as the recorded provisional values with the evaluation reference carrying the measured ones, and the member is validated by `core.profile` and merged by the launch; each finding has a place in the schema or a recorded reason for none; the session-id pointer, the Antigravity `mcp_config` form and the model choice per role that the follow-up hands over are in the schema or recorded with a reason; the `questions` values of the shipped roles and the question bound are written from the follow-up's runs, or recorded as deliberately open with the run they wait for; no statement of the corrected specification contradicts a result of the follow-up.
