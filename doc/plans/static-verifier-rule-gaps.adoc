== What

The rule slices link:static-verifier-remaining-rules.adoc[`static-verifier-remaining-rules`] (PLAN-41) left with gaps, corrected to the specification (Workflow DSL § Static AST Verification Rules). The work order is the one of PLAN-44, deliverables 2 to 7, quoted here:

* *Rule 9, completion once per firing.* "Model the firing as the specification states (opening at the beginning or region-entry state; end at the next opening, at `finalize.merge-gate` or a terminal; early end at UNSETTLED or STEPPED_OUT outcomes; implicit `failed` on `plan.aborted`, `plan.return`, `finalize.hand-back`) and refuse a path with no completion as well as a duplicate. Class admission must not fail open: no SUCCESS fallback in `outcomeClassOf` for question outcomes or unresolved outcomes; `skipped` only on the declared conservative route of an optional step; `waived` only on a remediation call. The cycle-measure checks (STEP_LIST, ARCHIVE_STEPS, ATTEMPT_CAP with a FAILURE-class exhaustion outcome) follow the specification instead of hard-coded state ids, and each has a test."
* *Rule 11b.* "The per-link rule (a `noop` or link step counts through its primitive's `awaitedEvent()`), so a resting cycle without an awaited event is refused; `stepAwaitsEvent` no longer answers `true` for every resting state. A refusing fixture and a matched control; Rule 11a gets a positive control (a measured engine-chained cycle)." Question-state links are judged by their primitive's awaited event like other links.
* *Rule 3, configuration reachability.* "Fail only when no combination reaches a state or transition, report the reaching combinations otherwise; fix the stale class Javadoc; address the 2^N rebuild per state if the merged plan unit makes it slow."
* *Rule 6 and the registries.* "The `stepped_out` target rules and the 'declared only by a terminal of class `stepped_out`' rule; refuse a single guarded `done`; the guarded field is a boolean or optional field of the callee's result schema. Production defaults carry no test identifiers (`EntityKindRegistry` maps `change` to `test.evaluate-change`); entity-unit existence is resolved against the catalog. Where the SPI cannot express read-only / list-returning / role-name-returning primitives (Rule 1 `each`, `role each`), an ADR says so and leaves the seam." `stepped_out` is part of every sub-workflow's exit contract implicitly (Rule 6).
* *Tests to the Done-When.* One refusing fixture per atomic check, asserting its `VerificationRule`, state and line, with no duplicate fixtures; the fixture coverage is counted against an enumerated checklist of atomic checks, not against the enum constants. `every-construct.pmwf` restored and extended to every construct the rules reach. A matched control per exemption. Every weakened assertion restored: the transition fuzzer asserts `passed()` unfiltered, the PLAN-41 switches from `plan` to `workspace` scope and the EXIT_PATH filters are undone, and inline tests assert the exact violation set.
* *Documentation honesty.* The ADRs of `pm-workflow/doc/adr/workflow-verify/` and `pm-workflow/doc/developer/workflow-verify.adoc` state what the code checks and nothing more.

Left as a seam, each named by an ADR of `pm-workflow/doc/adr/workflow-verify/`:

* Rule 3: the enumeration of the values of an enum `depends_on_config` key, the rule by which a configuration value makes a guard true, and the refusal of a state or transition no combination reaches, with its refusing fixture (a link needing `mode=strict` followed by a link needing `mode=lenient`). The specification gives the keys' enum and boolean domains but no activation rule, and the DSL names keys only; the verifier keeps the Boolean enumeration with all-keys-true activation, under which the all-true combination reaches everything the unconditional graph reaches, so partial reachability is reported as an advisory and nothing is refused (ADR 004, ADR 006). Superseded by link:static-verifier-residuals.adoc[`static-verifier-residuals`]: the all-keys-true activation, the check and its advisories are removed, and Rule 3 configuration reachability as a whole is the seam.
* Rule 9: whether a `lost` or `infeasible` route that completes a step `skipped` is the declared conservative route of an optional step. The AST declares no optional step and no conservative route, so the verifier admits `skipped` on `lost` and `infeasible` by outcome name and class (ADR 002).
* Rule 1: `each` over a read-only, list-returning primitive and `role each` over a primitive returning role names. The primitive SPI cannot express either, so neither is checked (ADR 010).
* Rule 6: the guarded field of a result guard is a boolean or optional field of the callee's result schema. `SchemaRegistry` registers schema names only, so the field type is not checked (ADR 010).
* Rule 6: inside a remediation unit, `stepped_out` may target the unit's budget re-check, which the language does not mark; there only a target of class `SUCCESS` is refused (ADR 010). Superseded by link:static-verifier-residuals.adoc[`static-verifier-residuals`]: `stepped_out` of a remediation unit is admitted only to its `remediation-<class>.budget-check` state running `remediation.check-budgets` (ADR 024).

Not in this package, so no scope is duplicated:

* link:project-units-and-invariants.adoc[`project-units-and-invariants`] owns the loader of project units, the merged plan workflow unit, the format refusals, `project_step_unbound`, `FinalizePipelineValidator` and the compiled invariants `INV-*` and `INV-REM-*`. It calls the verifier with Rules 1 to 12; none of them is its own. An invariant that cites a rule stays an invariant there; this package implements only the rule check it cites.
* Role existence and class fit (Rule 13, with the `zero_tool` consult check of Rules 1 and 4) join with the role sets of Milestone 4; skill resolution (Rule 14 and the `skill` clause of Rule 3) joins with the skill checks of Milestones 7 and 14. The package leaves the seam.
* Rule 5, the rest (the content of the `released-states.txt` baseline, the default-unit gate and the engine's state rewrite) lives in `plan-marshall-mcp` and link:workflow-engine.adoc[`workflow-engine`].
