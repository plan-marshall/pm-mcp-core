= Architectural Decision Records of `pm-mcp-core`
:nofooter:

An ADR records one design decision: the situation, what was decided, the alternatives and what follows. The ADRs of
this repository live in two kinds of directory:

* `doc/adr/`: the decisions that concern the whole repository.
* `{module}/doc/adr/{package}/`: the decisions of one package of a module.

== Numbering

ADRs are numbered per directory, with three digits: `NNN-{slug}.adoc`. A new ADR takes the next free number of its
directory. A number is never reused, not even for a superseded ADR. Two plans that write into the same directory at
the same time can take the same number; the plan that merges later renumbers its own ADR before the push.

== Writing an ADR

A new ADR follows the template link:template.adoc[`doc/adr/template.adoc`]. The template states the sections and what
each one holds. The layout of the module documentation is ADR
link:004-module-documentation-layout.adoc[004 The Module Documentation Layout]; where the specifications of this repository live is ADR
link:007-specifications-of-the-engine-in-this-repository.adoc[007 The Specifications of the Engine in This Repository].

** link:015-the-docs-only-build-skip-with-a-code-include-list.adoc[015 The Docs-Only Build Skip with a Code Include List]: the docs-only skip is on again, and `maven-build.paths-code-extra` keeps every `doc/` and `src/` tree building, so only `.plan/`, `.claude/`, README and configuration changes skip.
** link:016-schemas-are-files-of-the-implementing-module.adoc[016 Schemas Are Files of the Implementing Module]: a JSON schema of the specification is a file `<record>.schema.json` in the resources of the module that owns its codec, the specification includes it, and a test reads it from the class path through `SchemaResource` of `pm-core:tests`.
** link:017-http-tests-through-mock-response-config-and-module-dispatcher.adoc[017 HTTP Tests Through `@MockResponseConfig` and `@ModuleDispatcher`]: every HTTP test serves its canned responses through `@MockResponseConfig` or a `ModuleDispatcherElement` under `@ModuleDispatcher`, with the base URI from the injected `URIBuilder` and no hand-written `Dispatcher`; supersedes ADR 002, whose `cui-http` and two-origin rules it keeps.
** link:018-placement-of-schema-files-without-a-codec-of-their-own.adoc[018 Placement of Schema Files Without a Codec of Their Own]: a record without a codec of its own goes with the codec of the store that holds it, a schema whose codec lies in `pm-workflow` lies in `pm-workflow`, with the placement of the 27 files of `schema-files-tested-records` as the source.
** link:019-generated-log-message-listings.adoc[019 The Log Message Listings Are Generated from the Holders]: the identifier and template of every record are generated from its holder into `doc/log-messages/<module>.adoc`, included by `doc/LogMessages.adoc`, and compared byte for byte by each module's holder test; the Component and Description columns move to the record's Javadoc.
** link:021-optional-fields-parameters-and-record-components-are-nullable-states.adoc[021 `Optional` Fields, Parameters and Record Components Are Nullable States]: the conversion rule of `pm-core`, the container that keeps an `Optional` element, and the unchanged stored formats.
** link:022-the-effective-idle-wakeups-are-an-optionalint.adoc[022 The Effective Idle Wakeups Are an `OptionalInt`]: the absence of the effective idle wakeups is a value type, not a null-boxed `Integer`.
** link:023-the-outbound-call-guard-lives-in-pm-runtime.adoc[023 The Outbound-Call Guard Lives in `pm-runtime`]: the closed list of outbound calls is held by an ArchUnit rule in `pm-runtime` (a primitive rule and a destination list, each with its controls), the exemption map is by class with a reason, listening sockets are not connections, the integration test behind a recording network stays owed, and the decision settles what ADR `runtime-endpoint/006` (deleted by `deferred-code-removal`) called "owed … reported to the milestone exit".
** link:024-verify-duration-measured-and-cut.adoc[024 The Duration of the Full Verify, Measured and Cut]: the measured baseline of the full verify per module and phase with the host load of every run (the idle `verify -Ppre-commit` takes about 650 s, the reported 22 minutes are the coverage lane), the quality baseline per module, the ranked cost table with a cause and a decision per item above 5 s, and the build-level and test-level changes taken from it.
** link:025-test-design-layering-base-classes-and-fixtures.adoc[025 The Test Design: Layering, Base Classes and Fixtures]: proposed; the findings per module before the rework — the layers the suite mixes in one lane, the fixtures and base classes that cost time or hide duplication (`JobEnrolmentFixture`, `TestBases`, the published fakes, the abstract fixtures of `pm-core`), the tests that duplicate each other by construction (one builder test per record, one test per generator and per schema), and the structure the reworked design needs.
