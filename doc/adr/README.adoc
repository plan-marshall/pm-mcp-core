= Architectural Decision Records of `pm-mcp-core`
:nofooter:

An ADR records one design decision: the situation, what was decided, the alternatives and what follows. The ADRs of
this repository live in two kinds of directory:

* `doc/adr/`: the decisions that concern the whole repository.
* `{module}/doc/adr/{package}/`: the decisions of one package of a module.

== Numbering

ADRs are numbered per directory, with three digits: `NNN-{slug}.adoc`. A new ADR takes the next free number of its
directory. A number is never reused, not even for a superseded ADR. Two plans that write into the same directory at
the same time can take the same number; the plan that merges later renumbers its own ADR before the push.

== Writing an ADR

A new ADR follows the template link:template.adoc[`doc/adr/template.adoc`]. The template states the sections and what
each one holds. The layout of the module documentation is ADR
link:004-module-documentation-layout.adoc[004 The Module Documentation Layout]; where the specifications of this repository live is ADR
link:007-specifications-of-the-engine-in-this-repository.adoc[007 The Specifications of the Engine in This Repository].

== Directories

The repository:

* link:./[`doc/adr/`]: the decisions that concern the whole repository.
** link:009-no-build-skip-for-a-specification-only-pull-request.adoc[009 No Build Skip for a Specification-Only Pull Request]: every pull request runs the full build, including one that changes only the specification.
** link:010-the-coding-skills-and-the-accepted-exception.adoc[010 The Coding Skills and the Accepted Exception]: the marketplace coding skills bind every plan that touches Java, the six dependencies they need are allowed, and tests follow behaviour (the one accepted exception).
** link:011-ignore-s4449-for-jspecify-null-safety.adoc[011 Ignore java:S4449 for the JSpecify Null Contract]: the Sonar rule that asks for `javax.annotation.Nullable` is ignored for Java sources, because the repository's nullable marker is JSpecify's.
** link:012-generator-artifacts.adoc[012 Generator Artifacts per Module]: each module that provides reusable generators publishes them as a `tests`-classified test JAR, with the consumption matrix and the rule that a generator for another module's type comes from that module's artifact.
** link:013-the-null-contract-of-the-null-marked-packages.adoc[013 The Null Contract of the `@NullMarked` Packages]: the three classes a null-contract site belongs to, the evidence each needs, the rule that absence a method returns is `Optional`, and the rejection of the ignore and of waiting for the conformance family.
** link:014-the-ci-contract-is-the-module-pm-provider-ci.adoc[014 The CI Contract Is the Module `pm-provider-ci`]: the operator's choice of the module over a `pm-core` port, the three dependency rules (the `provider` include, `provider-contract`, and the new `provider-analysis` for Sonar), and what they mean for a consumer in `pm-runtime` or `pm-workflow`.
