= ADR 025: The Test Design: Layering, Base Classes and Fixtures
:nofooter:

== Status

Proposed

== Date

Proposed 2026-11-12. The decision takes effect on the merge date of the pull request that carries it.

== Context

ADR link:024-verify-duration-measured-and-cut.adoc[024] measured the full verify and removed its largest cost, the
fresh test JVM per class, in the build configuration. Three of its ranked rows were handed on as findings of the test
design rather than fixed in a test: the volume of small classes in `pm-core` (row 2), the tests that wait out a
specified budget in real time (row 9, `ProbeJobTest`), and the question which tests duplicate each other by
construction. The operator decided at refine that the rework of the test design is part of this plan. This section
records what the suite looks like before that rework starts; the rework itself is the Decision below.

The findings were taken on the rebased tree (`main` at `e07bf737` plus the commits of this plan) by a structured
content and path search over `src/test/java` of every module and by reading the shared fixtures and a sample of each
kind of test named below. A count is the number of test source files the search matched; a statement about what a
kind of test asserts rests on the classes named as read. The test and class counts per module are those of
<<024-verify-duration-measured-and-cut.adoc#baseline-tests,ADR 024 § Tests per Module>>, taken before about 20
classes of `pm-core` and `pm-runtime` were deleted on `main`.

[#layers]
=== The Layers the Suite Runs

Every module runs its tests in one Surefire lane of `verify -Ppre-commit`, one JVM per module (ADR 024, change A); only
the classes named `*IT` run in the separate lane `-Pintegration-tests`. Within the one lane the suite mixes five layers
that the class names do not tell apart:

. *Unit*: one class or record, in memory, no file and no process.
. *Component with real files*: a store, loader or log over a `@TempDir` or a `TestBases` directory.
. *Component with real processes*: a launcher, a job runner, a language server or a probe started as an operating-system
  process, with real process groups and signals.
. *Component with a server*: a mock web server (`@EnableMockWebServer`) or a fake message bus on a Unix domain socket.
. *Architecture check*: an ArchUnit import of the main classes of a module and rules over it.

Two further layers run only in the integration-test lane and keep it: the *nested build* (`BuildGuardsIT`, a Maven
build per fixture project below `src/guard-controls`) and the *killed runtime* (the seven `*KilledRuntimeIT` classes
and `StartupColdStartIT` of `pm-runtime`, which start the runtime as a child process and kill it).

[#findings]
=== The Findings

[[f1]]*F1 — One class per record that proves the generated builder.* The rule that a record of four or more components
carries Lombok's `@Builder` brought with it a test per record that builds the value once through the canonical
constructor and once through the builder, asserts that both are equal, and that both refuse an absent component with
the same message. The same check carries two names: 79 `*BuilderContractTest` classes in `pm-core` and
`ProviderDefaultBuilderContractTest` in `pm-runtime`, and the `*RecordsTest` classes elsewhere (55 in `pm-workflow`,
44 in `pm-runtime`, one in each of `pm-provider-http`, `-git`, `-github` and `-gitlab`). Read: `LeaseOwnerBuilderContractTest`,
`WaiverRecordsTest`, `JobEvidenceRecordsTest`, `GitOperationsRecordsTest`. They duplicate each other by construction:
each asserts the behaviour of generated code, written out by hand once per record, and a defect in Lombok's builder or
in a constructor's null check is caught the same way in every class. Under the fresh JVM per class they were the
largest share of the "volume of small classes" (ADR 024, row 2); since change A they cost little time but about 180
classes of maintenance.

[[f2]]*F2 — Tests of the record semantics of the language.* `AbsenceContractsTest` of `pm-provider-http` (read),
`-git`, `-github` and `-gitlab`, and `OptionalAbsenceContractsTest` of `pm-runtime` construct a record with `null`
components and assert that the accessors return `null`. They were written when a conversion replaced `Optional`
components by nullable ones (the rule ADR
link:021-optional-fields-parameters-and-record-components-are-nullable-states.adoc[021] states for `pm-core`);
what they assert is what a record does by definition, so they duplicate the language rather than another test.

[[f3]]*F3 — One test class per generator.* Each generator of the generator artifacts (ADR
link:012-generator-artifacts.adoc[012]) has its own `*GeneratorTest`: 4 in `pm-core`, 3 in `pm-workflow`, 10 in
`pm-runtime`, 3 in `pm-provider-http`, 1 each in `pm-provider-ci` and `pm-provider-git`. They prove that a generator
yields values of its grammar; the factory is the one registration point of an artifact, so the same check runs once per
generator instead of once per factory.

[[f4]]*F4 — One parity test class per schema, written by hand.* 18 `*SchemaParityTest` classes in `pm-core` and 2 in
`pm-runtime` compare a codec's written members with its schema file (ADR
link:016-schemas-are-files-of-the-implementing-module.adoc[016]). The one read (`LeaseOwnerSchemaParityTest`) asserts
member order, the required set and the enumerated values; the classes share that shape by name and purpose, which the
rework confirms class by class before it merges any of them. Each class is a real check of its own schema, so they are
duplicates of form, not of behaviour.

[[f5]]*F5 — One unit split over many classes by an abstract fixture.* `QuestionLogFixture` carries the question-log
tests in seven subclasses, `ProjectResolverFixture` the project-resolution tests in eight, and `ParsedBuildPortedTest`
the ported parser tests in seven; `pm-runtime` splits `QuestionLogRecordReader` over three classes. The inheritance
hides which fixture state a subclass relies on, and the split is what `@Nested` classes in one test class would say
(the repository's test rule, `CLAUDE.md` § Code Standards). `ParsedBuildPortedTest` differs: it is a template over
seven parsers with one contract, which a parameterised test would carry.

[[f6]]*F6 — Four separate ArchUnit imports.* `AnalysisBoundaryArchTest` (3.39 s in the coverage lane),
`ProviderNeutralityArchTest` (3.09 s) and `JobRunnerTest` (2.73 s) of `pm-core` each import the main classes of
`pm-core` themselves, and `OutboundCallsArchTest` of `pm-runtime` (7.5 s) imports those of `pm-runtime` and `pm-core`
again. `JobRunnerTest` mixes the value-type tests of the job-runner interface with an architecture guard in one class.
ADR 024 (row 14) kept the import of `OutboundCallsArchTest` whole for the evidence of its rule; the finding here is the
repetition and the mixed class, not the import's scope.

[[f7]]*F7 — `JobEnrolmentFixture`: the whole real enrolment for every test of the job package.*
link:../../pm-runtime/src/test/java/de/planmarshall/runtime/job/JobEnrolmentFixture.java[`JobEnrolmentFixture`] builds,
per test (`@BeforeEach` in all nine classes that use it), an enrolment store, an enrolment key over a file secret store
with key material from a `SecureRandom`, a file lock manager, the enrolment check, the operator writes, a project tree
with wrappers, pinned files, a script and one binary per host tool, whose SHA-256 digests it computes, and a linked
worktree. Its users are the runner tests that need all of it (`SubprocessJobRunnerTest`, `SubprocessJobRunnerPidReuseTest`,
`ProbeJobTest`, `WorkerJobTest`) and the stage tests of the verification pipeline, whose logic needs only an enrolment
value and the files a stage reads (`ArgumentCheckTest`, `ExecutableCheckTest`, `WrapperVerificationTest`,
`VerifyNotResolvePipelineTest`, `VerifyNotResolveAdversarialTest`); for the argument check, a stage that reads no file,
the whole build is setup the assertion does not depend on. The fixture writes four `with…` helpers that each repeat
the fifteen-component constructor of `ProjectEnrolment` to change one component, and it takes its base from
`TestBases` (<<f10>>) although the fixture itself binds no socket.

[[f8]]*F8 — The same compositions written more than once.* `start/EnrolmentFixture` of `pm-runtime` composes the same
store, key file, lock manager, check and operator writes as `JobEnrolmentFixture`, with an audit sink that records,
refuses or stops. `ProjectResolverFixture` of `pm-core` and `JobEnrolmentFixture` of `pm-runtime` each write the plain
pointer files git writes for a linked worktree by hand. `pm-core:tests` publishes only its generator package and
`SchemaResource` (ADR 012), so a fixture of `pm-core` cannot be shared with `pm-runtime` without changing what that
artifact publishes.

[[f9]]*F9 — Hand-written recording doubles, two of them twins.* `RecordingAuditSink` exists in `pm-core`
(`core.store`) and in `pm-runtime` (`runtime.lock`); `pm-core` also has `RecordingLockManager`, `pm-runtime`
`RecordingProcessCall`, and several fixtures record audit events into a list (`events::add`). The repository's rule is
that test doubles are EasyMock and no new hand-written fake is added (`CLAUDE.md` § Code Standards); these predate it.
The twin exists because of the same artifact boundary as <<f8>>.

[[f10]]*F10 — `TestBases` outside `@TempDir`.*
link:../../pm-runtime/src/test/java/de/planmarshall/runtime/test/TestBases.java[`TestBases`] hands out
`/tmp/<prefix>-<8 hex>`, short enough for a Unix socket path below the `sun_path` limit, which `@TempDir` below
`java.io.tmpdir` does not guarantee; each user deletes the base itself in `@AfterEach` or `close()`. It is used by
fifteen test classes and one fixture: the eight integration tests of the `start` package, which start a runtime with its
socket, and seven classes of the unit lane (`JobDrainParticipantTest`, `RuntimeDrainTest`, `StartupSequenceTest`, `WebTlsTest`, the three
`QuestionLogRecordReader*Test` classes) besides `JobEnrolmentFixture`. Which of the seven bind a socket and so need the
short path is not established; for the others it is a `@TempDir` with a manual delete. The class is part of the
published surface (<<f11>>).

[[f11]]*F11 — The published test surface is the whole test scope of `pm-runtime`.* `pm-runtime:tests` carries the
whole test scope (ADR 012), so every public type of it is published to the assembly `plan-marshall-mcp`: `TestBases`,
link:../../pm-runtime/src/test/java/de/planmarshall/runtime/credentials/dbus/FakeBus.java[`FakeBus`],
link:../../pm-runtime/src/test/java/de/planmarshall/runtime/credentials/FakeSecretService.java[`FakeSecretService`],
and also link:../../pm-runtime/src/test/java/de/planmarshall/runtime/job/FakePmExec.java[`FakePmExec`], whose Javadoc
states it is shared through the test JAR, and the generator package. `FakeBus` is a protocol fake: it answers SASL
`EXTERNAL`, `Hello` and the method calls over a real Unix domain socket, so it is the evidence of the D-Bus wire codec
and no EasyMock double can stand in for it (two users, `DbusConnectionTest` and `SecretServiceStoreTest`).
`FakeSecretService` is a public, non-final class whose behaviour switches (`collectionLocked`, `itemsLocked`,
`promptOnCreate`, `noDefaultCollection`, `serviceUnknown`) and stored items are package-private fields, so outside its
package only its default behaviour is usable. `FakePmExec` writes a `/bin/sh` launcher, runs on Linux only and is used
by seven classes. ADR 012 names PLAN-V2-106 as the plan that replaces the fakes by EasyMock doubles; the three are still
in place. A change of any public signature among them can break the assembly (the operator's floor for this plan).

[[f12]]*F12 — Real time in the unit lane.* Every class that starts a real process or waits out a bound runs in the same
lane as the unit tests. After ADR 024 the remaining waits are specified bounds: `ProbeJobTest` waits out the 15 s
version-probe budget (`ProbeBudget.VERSION_SECONDS`, no clock seam; ADR 024, row 9), `TerminationProtocolTest` the
compiled grace period of one real process group (row 17), `LspClientTest` its 2 s bounds (row 10). No test of the
suite calls `Thread.sleep`; the waits are bounds of the production code.

[[f13]]*F13 — Engine tests over the parser and the validator.* `EngineFixtures` of `pm-workflow` assembles the engine of
each test over units parsed from DSL text and validated by `WorkflowValidator`, with scripted primitives and a manual
clock. Every engine test therefore also runs the parser and the validator: a defect there fails engine tests as well as
the parser's and validator's own, and the engine is never tested over a definition built without the DSL.

[[f14]]*F14 — The CI contract proved once per adapter, by decision.* `GitHubCiProviderTest` and `GitLabCiProviderTest`
each prove the operations of the CI contract against their own mock web server. ADR
link:../../pm-providers/pm-provider-ci/doc/adr/provider-ci/005-no-shared-contract-test.adoc[`provider-ci/005`] decided
against a shared abstract contract test, because the adapter-specific cases dominate; the provider-neutral cases they
share are therefore duplicates by decision, and ADR 024 (row 11) found the two page-cap walks of the GitLab class to be
no duplicates. A rework that merges them supersedes that ADR.

[#needed-structure]
=== The Structure the Reworked Design Needs

Each element names the findings it answers. It states what the design has to provide, not yet how; the Decision
chooses the form.

[cols="1,5,2",options="header"]
|===
|# |Element |Findings

|S1
|*A declared layer per test class.* A test class belongs to one layer of <<layers>>, so that a unit test carries no real
process, file tree or server, and the tests of one unit that need a real resource sit in a class of their own beside
the unit tests. The integration lane keeps the nested build and the killed runtime; no test leaves the lanes
`verify -Ppre-commit` runs, except that existing lane.
|<<f6>>, <<f7>>, <<f12>>, <<f13>>

|S2
|*One check for the generated builders, and no tests of the language.* The builder-equals-constructor check is carried
once per module, over every record that has a builder, instead of once per record by hand; the absence tests of record
accessors are removed, each with its retention row.
|<<f1>>, <<f2>>

|S3
|*One generator test per factory and one parity harness per kind of schema check*, parameterised over the generators of
an artifact and over the schemas, so that a new generator or schema is a new row, not a new class; a schema whose
check differs keeps its own class.
|<<f3>>, <<f4>>

|S4
|*Fixtures by composition and sized to the layer.* A fixture builds only what its layer needs: an enrolment value and
the files a stage reads for the stage tests, the whole real enrolment for the runner tests. An abstract fixture class
gives way to a composed fixture or to `@Nested` classes of one test class; an expensive immutable part is built once
per class. A record is changed through its builder (`toBuilder`) or a generator, not through a helper that repeats its
constructor.
|<<f5>>, <<f7>>, <<f8>>

|S5
|*One home per shared fixture or double, and EasyMock for the rest.* A composition written twice (the enrolment, the
git layout of a worktree, the recording audit sink) has one home in the module that owns the types; where that home is
another module's test scope, the change of what `pm-core:tests` publishes is a decision of the operator and is recorded
as a lead, not made. A recording double that EasyMock can replace is replaced when its classes are touched.
|<<f8>>, <<f9>>

|S6
|*One import per module for the architecture checks*, shared by the classes that check rules over the same classes,
with the guard of `JobRunnerTest` moved to the architecture checks of `pm-core`, and the import of
`OutboundCallsArchTest` kept whole (ADR 024, row 14).
|<<f6>>

|S7
|*`@TempDir` unless a socket needs the short path.* `TestBases` is used where a Unix socket is bound below the base; a
class that binds none takes a `@TempDir`.
|<<f10>>

|S8
|*A stable published surface.* The public types of `pm-runtime:tests` — `TestBases`, `FakeBus`, `FakeSecretService`,
`FakePmExec` and the generators — keep their public signatures for the assembly; `FakeBus` stays, because it is the
wire evidence; a change that would break any of them is an operator lead in this ADR, not a change.
|<<f11>>

|S9
|*The CI contract cases stay with their adapter* unless ADR `provider-ci/005` is superseded by a decision of its own;
the rework does not merge them on its own authority.
|<<f14>>
|===

== Decision

Owed: Deliverable 6 of the plan records the target design taken from the findings above — the layers and where each
runs, the base classes and fixtures per module, the retention table for every removed, merged or re-layered test — and
sets the status to Accepted.
