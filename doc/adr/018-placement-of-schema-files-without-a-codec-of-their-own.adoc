= ADR 018: Placement of Schema Files Without a Codec of Their Own
:nofooter:

== Status

Accepted

== Date

2026-11-07

== Context

ADR link:016-schemas-are-files-of-the-implementing-module.adoc[016] places a JSON schema of the specification in the
resources of the module that owns its codec, in `src/main/resources/<resource package of the codec>/<record>.schema.json`.
The work package `schema-files-tested-records` moves the 27 schema blocks of the store-schema documents 01, 02, 03, 09,
10, 14 and 16 into such files. Checked against the code of `main`, two kinds of block do not fit the rule as ADR 016
states it:

* Eleven blocks have no codec of their own. They describe a member of another record (`owed[]`, `policy_counters`,
  `gaps[]` of `status`), the value schema of a fact kind, a record of the findings and review family that no codec
  writes yet, a sibling of the qualification records, or a store of the plan (the plan overrides and the failure
  envelope).
* Two blocks belong to records whose codec lies in `pm-workflow`, not in `pm-core`: the plan instance header
  (`PlanInstanceHeader`, written by `HeaderJson`) and the line of the composition log (`CompositionRecord`). The work
  package placed every file below `pm-core`.

== Decision

* *A record without a codec of its own goes with the codec of the store that holds it.* A member of `status` lies
  beside `WorkflowStatusCodec`, a record of the findings and review family beside the findings ledger, a value schema
  of a fact kind beside `DerivedFactsCodec`, a sibling of the qualification records beside `QualificationRecordCodec`,
  and a record of a plan store beside the plan stores of `de/planmarshall/core/store/`. A package that builds the codec
  of such a record later moves nothing.
* *A schema whose codec lies in `pm-workflow` lies in `pm-workflow`.* `plan-instance-header.schema.json` and
  `composition-record.schema.json` lie in `pm-workflow/src/main/resources/de/planmarshall/workflow/plan/`, beside
  `PlanInstanceHeader` and `CompositionRecord`; this follows ADR 016 over the wording of the work package (operator
  decision of 2026-11-07).
* *The file name* is the last path segment of the block's `$id` without `.json`. The `AnalysisResult` block has no
  `$id`; its file is named after its anchor, `analysis-result.schema.json`.

== Alternatives Considered

1. *Every file below `pm-core`, as the work package states.* Rejected for the two plan-instance records: it would
   separate the schema from the codec that writes the record, which ADR 016 rules out.
2. *A shared directory for the schemas without a codec.* Rejected: a record without a codec is still held by a store
   that has one, and the schema belongs beside that store's codec, where a later codec of its own finds it.

== Consequences

* The work packages that move the schema blocks of the remaining documents (`schema-files-machine-stores`,
  `schema-files-other-specifications`) place a codec-less block by the same rule.
* `pm-workflow` carries schema files of its own; a test of `pm-workflow` reads them through `SchemaResource` of
  `pm-core:tests`, as ADR 016 provides.
* When a later package builds a codec for a record of the table, it writes the codec in the package the file already
  lies in, and the file stays.
