= ADR 003: Log Identifiers in Three Digits, One Block per Workstream
:nofooter:

== Status

Superseded by link:005-one-log-message-holder-per-module.adoc[ADR 005]

== Date

2026-10-09

== Context

Every INFO, WARN and ERROR message is a `LogRecord` constant in the single log-message holder of `pm-core`, in the
identifier ranges INFO 001-099, WARN 100-199 and ERROR 200-299. Nearly every work package adds log messages there.
When the plans first declared that holder as shared surface, the gate that checks whether two plans touch the same
files asked the operator on 553 of 666 plan pairs.

== Decision

The operator decided on 2026-10-09 that log identifiers stay in the three-digit scheme and are allocated per
workstream, with the same offset in each level:

[cols="1,2"]
|===
|Workstream |Identifiers

|WS-01 |x50-x59
|WS-02 |x60-x69
|WS-03 |x70-x79
|WS-04 |x80-x89
|WS-05 |x90-x99
|WS-07 |x02-x09
|===

WS-06 and WS-08 get no block. The holder is no longer declared as shared surface of a plan. An identifier
already in use is never renumbered.

Rationale not recorded.

== Alternatives Considered

1. *Four digits with a block per plan.* Recommended to the operator; declined.
2. *No allocation.* Declined.

== Consequences

* The plans of one workstream still share a block, and two of them can take the same identifier: #19 and #20 both took WARN 150 of the WS-01 block, and #20 moved to WARN 151.
* The test of the holder is the guard: it refuses an identifier used twice.
* The blocks are marked by comments in the holder. On 2026-10-13 the WS-01 block holds INFO 050-057, WARN 150-159 and ERROR 250-253, the WS-02 block INFO 060-064, WARN 160-167 and ERROR 260, and the WS-04 block starts at WARN 180.
