= ADR 002: `cui-http` for HTTP Calls, the Mock Web Server for HTTP Tests
:nofooter:

== Status

Accepted

== Date

2026-10-11

== Context

The operator set two HTTP rules on 2026-10-09: every HTTP call goes through `cui-http`, and every test that involves
HTTP runs against `cui-test-mockwebserver-junit5`. The code did not meet the second rule: `pm-provider-ci`,
`pm-provider-github` and `pm-provider-gitlab` each carried a hand-made `FakeServer` on `com.sun.net.httpserver`.
`CiHttpClient` of `pm-provider-ci` already sent every request through the `HttpHandler` of `cui-http`; its
`java.net.http` imports are exchange types only.

== Decision

* Every HTTP call goes through `cui-http`. Because `CiHttpClient` already does so, the rule is pinned by a guard test (`sendsThroughCuiHttp` in `CiHttpClientTest`), not by a production change.
* Every HTTP test runs against `cui-test-mockwebserver-junit5`. Each test class carries `@EnableMockWebServer` and serves its canned responses from its own dispatcher, with no shared helper class.
* The hand-made `FakeServer` doubles are deleted. The library is a test-scope dependency of the three provider modules, its version managed by the parent chain.
* Cross-origin tests address the one mock web server as the literal of the address it bound (`127.0.0.1` or `[::1]`) and as `localhost`, two origins on one machine.

Rationale not recorded.

== Alternatives Considered

Alternatives not recorded.

== Consequences

* No class named `FakeServer` and no import of `com.sun.net.httpserver` remain in the repository.
* A new provider module that calls HTTP uses `cui-http` and tests on the mock web server from its first test.
* `pm-provider-sonar`, `pm-provider-git` and `pm-runtime` hold no HTTP test server; `FakeBus` of `pm-runtime` is a D-Bus fake, not HTTP, and is outside the rule.
