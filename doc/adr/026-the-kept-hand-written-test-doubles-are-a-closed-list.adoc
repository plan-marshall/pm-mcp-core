= ADR 026: The Kept Hand-Written Test Doubles Are a Closed List
:nofooter:

== Status

Accepted

== Date

2026-11-13, the day of the merge; the decision takes effect with the merge of the pull request that carries it.

== Context

PLAN-V2-106 (#355) was to replace the hand-written test doubles by EasyMock doubles. It converted nine classes and
kept twenty-nine, because its deliverable allowed every "real in-memory implementation that many tests share" to stay
with a stated reason, and its Done-when scan was satisfied by any stated reason. The analysis of that landing
(`landings/PLAN-V2-106.md`) read the kept classes and found that about half are pure or scripted recorders of the kind
the pull request itself converted: a list of appended records, a numbered answer, a captured argument. ADR
link:025-test-design-layering-base-classes-and-fixtures.adoc[025] records the same population as finding F9 and leaves
the replacement to "a plan that takes the classes up for a reason of their own"; its element S5 asks for one home per
shared fixture or double and EasyMock for the rest. The operator's decision of 2026-10-30 ("replace the fakes") stands.

PLAN-V2-136 is that plan. It closes the keep vocabulary, converts every other class the scan finds and every
fixture-resident double the scan missed that is not kept below, and makes its Done-when a scan whose result is the
closed list and nothing else. The scan matches names, so it cannot prove a conversion by itself: a class renamed out of
the pattern would leave the scan even if its hand-written body stayed. That limitation is the reason the decision is a
list rather than a name pattern: each converted declaration is named in the table below, and a reviewer checks the
declaration, not the scan's silence.

== Decision

=== What a hand-written double is

A hand-written double is a class, record, enum, anonymous class or lambda that implements a production interface or
abstract class by hand and keeps state or records calls. A static factory that returns an EasyMock mock is not a
hand-written double: `de.planmarshall.core.store.AuditSinkDoubles` and `de.planmarshall.runtime.test.AuditSinkDoubles`
are the precedent. A helper class that builds EasyMock expectations, including `ProcessCallDoubles` of `pm-runtime`,
is not one either.

=== The scan and its exclusion

The population is found by:

[source,text]
----
git grep -n -E '(class|record|interface|enum) (Fake|Stub|Recording|Failing)' -- '*/src/test/java/*.java' ':!*/testing/generators/*'
----

At `6937efe4` (the merge commit of PLAN-V2-106) it found 36 declarations with the exclusion and 38 without it. The two
extra are `FailingExitCodeGenerator` and `FailingExitCodeGeneratorTest` under `pm-runtime/.../testing/generators/`:
`TypedGenerator<Integer>` test data, not a double of a production interface. The path `*/testing/generators/*` is
therefore excluded from the scan, and only that path.

At the branch base of PLAN-V2-136 the scan-matched keeps of the closed list below hold thirteen declarations, not the
fourteen the plan's spec expected: `ProcessTreeTrackerTest.RecordingSignals` was already replaced by an EasyMock mock of
`ProcessGroupSignals` before that base (#390, `1283710f`). The plan's verify-first clause re-runs the counts at the
head, so the closed list below names two `RecordingSignals`; the fixture-resident F1 to F3 are not matched by the scan
and are kept by inspection.

=== The closed list of sound keeps

A hand-written double stays only for one of three reasons: **(S1)** it is a protocol or process stand-in that an
interface double cannot restate (a socket bus, a shell launcher); **(S2)** it is a stateful in-memory implementation
whose answers follow from its history across calls, so a mock would reimplement that state in `andAnswer`; **(S3)** it
is a simulation of an OS or time source that advances with the calls. A recorder of arguments, a scripted answer, a
numbered answer or a flag a test sets before the call does not qualify: `Capture`, `andReturn`, `andAnswer` and
`andStubReturn` express those.

=== The converted population

Every other class the scan finds, and every fixture-resident double it misses that is not F1 to F3, is an EasyMock
double. In PLAN-V2-136 that is: `pm-core` `core.store.RecordingAuditSink` and `AuditLogTest.RecordingAnchor` and
`FailingPredecessorAnchor`; `pm-workflow` the four port doubles of `EngineFixtures`, the three of
`ScenarioFixtures`, `ModelFixtures.Qualifications` and `Guard`, and `TaskFixtures.Paused`; `pm-runtime`
`lock.RecordingAuditSink`, `RecoveryStepFixtures.RecordingAuditSink`, `SupervisorTestFixture.FakeStarter`,
`FakeSlots`, `RecordingProtocol` and `RecordingStateWriter`, the three per-test `RecordingProtocol` classes,
`NoSignals`, `SilentProtocol`, `RecordingTimers`, `RecordingGuard`, both `RecordingStep` records,
`start.RecordingProcessCall`, `SubprocessJobRunnerTest.StubProcess` and `CredentialStoreMoveTest.FakeKeyrings`.

`StubProcess` was the one class gated by a hypothesis: whether the managed EasyMock can create a class mock of
`java.lang.Process` on Java 25. The first `createMock(Process.class)` of the conversion compiled and its tests ran, so
the hypothesis is confirmed and the class is converted; there is no K10.

=== The published surface

The doubles that are published to the assembly keep their public signatures: `FakeBus`, `FakeSecretService` and
`FakePmExec` are K1 to K3 and stay, and `TestBases` is untouched. The conversion added one public type to
`pm-runtime:tests`: `de.planmarshall.runtime.test.AuditSinkDoubles`, the EasyMock audit-sink factory. Every converted
hand-written double is package-private (`SupervisorTestFixture`, `RecordingProcessCall`, `lock.RecordingAuditSink` and
`RecoveryStepFixtures` are `final class` without `public`), so a consumer can name one only from the same package: the
`pm-runtime:tests` test jar has no `includes` and packages them, and a same-package test of a consumer could reference
them. **Owed outside this repository: none on the converted doubles.** The assembly checkout `plan-marshall-mcp` was not
searched for a same-package reference to one of the four; that check is an open item, and a breaking change of one would
need it first (2026-11-14: the assembly checkout was checked by reading for `AuditSinkDoubles`; see the amendment
below).

=== The 2026-11-14 amendment

A read-only landing analysis of PLAN-V2-136 of 2026-11-14 found the residue this amendment records (PR #416).

* *Converted, not kept:* the scripted primitive doubles the name scan missed — `EngineFixtures.Scripted`,
  `EngineFixtures.NoteStep` and `DefaultPlanPrimitives.Scripted` — are EasyMock doubles now. The class of each name is a
  holder that builds the mock's expectations and keeps the script a test feeds; the double the registry holds is the
  mock, so the shape stays outside this ADR's definition of a hand-written double.
* *Scan enforced by a test:* one `HandWrittenDoubleScanTest` per module (`pm-core`, `pm-workflow`, `pm-runtime`) scans
  the test sources for a class, record or enum that implements or extends a production interface, for an anonymous
  class over one, and for a lambda or method reference assigned to one, and compares the result with
  `src/test/resources/hand-written-doubles.txt`. The baseline is this closed list plus the population outside the old
  name scan, which PLAN-V2-125 (`pm-core`, `pm-workflow`) and PLAN-V2-126 (`pm-runtime`) convert; a new double adds a
  line and fails the build. A lambda passed straight to a constructor or a method has no declared type at the call site;
  it stays a reviewer's check, as the scan test says.
* *Statements corrected (only the sentences that had become false; the documents otherwise record history):*
  `workflow-engine/006` (the tests read the port through `EngineFixtures.answerEntry`), `runtime-start/003` (the
  service-manager tests run against the EasyMock call of `ProcessCallDoubles`) and `012-generator-artifacts`
  (PLAN-V2-136 completes the replacement and keeps K1 to K3).
* *Published surface:* `pm-runtime:tests` gained the public `de.planmarshall.runtime.test.AuditSinkDoubles` factory. The
  assembly checkout `plan-marshall-mcp` was read for that name on 2026-11-14 and does not use it.
* *Calls that must happen:* where a converted mock's call is not proved by an assertion on a recorded list, the test
  pins it or the mock is documented as a nice stub; `AuditLogTest.failingPredecessor` throws on every predecessor read.

== Alternatives Considered

* *Keep the open vocabulary with a stated reason per class.* Not taken: that is PLAN-V2-106's rule, and the analysis
  showed a reason was accepted for recorders the pull request itself converted.
* *Add `StubProcess` as K10 for the Java-25 class-mock risk.* Not taken: the risk is refuted by the first
  `createMock(Process.class)`.
* *Keep one lock-manager implementation shared across the module packages.* Not taken: no artifact publishes fixtures;
  the generator artifacts carry generators only (ADR link:012-generator-artifacts.adoc[012]).
* *Replace `FakeBus` and `FakeSecretService` by EasyMock doubles.* Not taken: `FakeBus` is the evidence of the D-Bus
  wire codec and both are published (ADR link:025-test-design-layering-base-classes-and-fixtures.adoc[025], S8).

== Consequences

* A new hand-written double is refused by the repository rule (`CLAUDE.md` § Code Standards); a test that needs a
  double uses EasyMock or a factory that returns one.
* The list K1 to K9 and F1 to F3 is closed. A class that does not qualify for S1, S2 or S3 is converted; a class the
  operator wants to keep needs a new ADR that supersedes this one and names the reason.
* The scan is the Done-when of a conversion plan: it returns the declarations of the closed list's scan-matched keeps
  at the branch base and no other line (thirteen at the base of PLAN-V2-136, because the process-table
  `RecordingSignals` was converted with EasyMock before it; F1 to F3 are fixture-resident and not matched by the scan),
  so a conversion cannot be claimed without removing the class from the scan.
* A consumer of the `pm-runtime:tests` jar sees no change: the converted classes were package-private and the
  published fakes keep their signatures.
* The unscanned population is out of scope by decision: about forty hand-written implementations whose names do not
  match the scan (`HoldingEverything`, `OneLock`, `InMemoryLockManager`, the clocks, the keyrings) stay until a plan
  widens the scan by role (`implements <production interface>`) or touches them.
