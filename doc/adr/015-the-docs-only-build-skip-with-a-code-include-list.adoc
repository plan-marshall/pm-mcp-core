= ADR 015: The Docs-Only Build Skip with a Code Include List
:nofooter:

== Status

Accepted

== Date

2026-11-05

== Context

ADR link:009-no-build-skip-for-a-specification-only-pull-request.adoc[009] turned the docs-only skip of the reusable
workflows off (`maven-build.skip-on-docs-only: false`), because the organisation's ignore list could only grow
(`paths-ignore-extra`) and `**/*.adoc` and `doc/**` hid the specification the schema parity tests read. The price was a
full build, about eight minutes, for every pull request, also for one that changes only `.plan/`, an ADR or developer
documentation.

`cuioss/cuioss-organization` v0.44.0
(`5a641e5da90ae209472419a541b7566bf7f4172e`, the pin of `.github/workflows/maven.yml` and
`.github/workflows/integration-tests.yml`) adds `maven-build.paths-code-extra`: globs that count as code even when the
default ignore list or `paths-ignore-extra` matches them. Both the build and the integration-test workflow read it.

The tests of this repository read these files the default ignore list matches:

* `doc/specification/**`: the schema parity tests through `pm.specification.root` (ADR
  link:007-specifications-of-the-engine-in-this-repository.adoc[007]), among them `FindingSchemaParityTest`,
  `CredentialStoreMoveRecordParityTest`, `StalledScopeDetectorTest` and `UnitFrontmatterReaderTest`.
* `doc/LogMessages.adoc`: `RuntimeLogMessagesTest` (`Path.of("..", "doc", "LogMessages.adoc")` from `pm-runtime`).
* `pm-workflow/doc/developer/workflow-task.adoc`: `ProtocolVocabularyParityTest`.
* `.md` and `.adoc` fixtures below `src/test/resources` of `pm-core` and `pm-workflow`.

== Decision

The docs-only skip is on again: `skip-on-docs-only` is removed from `.github/project.yml`, so its default `true`
applies. `maven-build.paths-code-extra` lists `**/doc/**` and `**/src/**`: every documentation tree (the root `doc/`
and each `{module}/doc/`) and every source tree counts as code. A pull request that changes any file below one of them
builds; a pull request whose every file is matched by the ignore list and lies outside both trees skips. That leaves
`.plan/`, `.claude/`, the `README`/`CLAUDE.md` files and `.github/project.yml` as the changes that skip.

The rule names trees, not the files the tests read, so it does not mirror the readers: a new test that reads another
specification part, guide or fixture below `doc/` or `src/` is covered without a change of the list.

== Alternatives Considered

1. *Keep `skip-on-docs-only: false` (ADR 009).* Rejected: it builds every `.plan/` pull request, which no test reads.
2. *List exactly the files the tests read* (`doc/specification/**`, `doc/LogMessages.adoc`,
   `pm-workflow/doc/developer/workflow-task.adoc`). Rejected: the list mirrors the readers by hand. Its first version
   missed `ProtocolVocabularyParityTest`'s guide, and every missed path reopens the hole ADR 009 closed.
3. *The exact list plus a test that scans the test sources for documentation paths and fails on an uncovered one.*
   Rejected: the scan is a heuristic over string literals, and the ADR- and guide-only pull requests it would keep
   skipping are few.

== Consequences

A pull request that changes only `.plan/`, `.claude/`, the `README`/`CLAUDE.md` files or `.github/project.yml` skips
the build again; one that changes only an ADR or a developer guide builds, about eight minutes. A new test that reads a
file the ignore list matches outside `doc/` and `src/` (a `README`, say) must add its path to `paths-code-extra`;
otherwise a change of only that file is reported green without the test having run.

This pull request changes `doc/adr/`, so its own build runs under the new setting. That a
specification-only pull request builds can only be observed by the next such pull request.
