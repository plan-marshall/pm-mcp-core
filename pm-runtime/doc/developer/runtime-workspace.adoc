== Purpose
_Requirements: link:{docs}/Requirements.adoc#PM-SEC-2[PM-SEC-2]_

Package `de.planmarshall.runtime.workspace` of `pm-runtime` holds the entry through which the file, git and build
operations of the daemon obtain a confined path of a project: the enrolled repository root and the live linked worktrees
of it. The rule it implements is a decision of the store side of the product: the confinement types live in `core.store`
(link:../../../pm-core/doc/developer/core-store.adoc[Scope Stores § Path Confinement]), and this package is the runtime
adapter that logs a refusal and hands the outcome on.

A refused path is a value, not an exception: the outcome is `ConfinementOutcome.Rejected` with the code
`path_traversal_rejected`, and no checked exception type exists or is added.

|Type |What it is

|Its constructor takes the `WorkspaceRoots` of one project; `confine(rawPath)` answers a `ConfinementOutcome`.

|`WorkspaceRoots` of `core.store`
|The enrolled root and the live linked worktrees of the project.

|`PathConfinement` of `core.store`
|The decision: whether a path lies inside the given roots, and the canonical path when it does.

|`ConfinementOutcome` of `core.store`
|`Confined(canonicalPath)` or `Rejected(reason)`; `Rejected.code()` is `path_traversal_rejected` for every reason.

|`LinkedWorktreeConfinementTest` of `core.store`
|The test that proves which linked worktrees count as roots of the workspace; the decision itself is `PathConfinement`'s.

== Using the Confinement

[source,java]
----
var outcome = confinement.confine(rawPath);
switch (outcome) {
    case ConfinementOutcome.Confined confined -> operate(confined.path());
    case ConfinementOutcome.Rejected rejected -> refuse(rejected.reason());
}
----

An operation uses the canonical path of a `Confined` outcome, never the text it was given. Canonicalization resolves the
symbolic links that exist during the check; it does not prevent a directory or a symbolic link from being replaced before
the operation. A relative path is resolved against the enrolled root.

`WorkspaceConfinement.confine` logs a refusal at WARN as `PM_RUNTIME-106` (`PROJECT_PATH_REFUSED`) with the outcome code
and the reason, never with the path: the path may name a location the operator did not intend to disclose, and the
record's diagnostic is enough to tell the kinds of refusal apart.

== Invariants and Failure Modes

* *A refusal is a value.* `Rejected` carries a `Reason` and the closed outcome code; a caller distinguishes the reasons,
  and neither an exception nor a `null` stands for a refusal.
* *The operation uses the canonical path.* The returned `Confined.path()` is the only path an operation may use. Reusing
  the raw text re-opens the window between the check and the use.
* *The roots are the enrolled root and the live worktrees.* A worktree that is not live is not a root; a linked worktree
  that was removed after the roots were read is refused by the following file operation, and the roots are read afresh for
  a new operation.
* *The check is a library.* No file, git or build consumer calls it yet (epic standing rule R09, and
  `doc/Traceability.adoc` records the same); each consumer calls `confine(rawPath)` before its project-path operation and
  passes `Confined.path()` on, never the text. Until then a path that reaches the runtime through another entry point is
  not confined there.
* *No path in a message.* The WARN record names the outcome code and the reason. A caller that reports a refusal to an
  API caller gives the code and the reason, not the rejected path either.

== Adding a Consumer

. Obtain the `WorkspaceRoots` of the project from the same source that resolves the enrolment and the project store.
2. Call `confine(rawPath)` before the first file-system or repository operation on the path.
3. Carry `Confined.path()` through the operation; return `Rejected` to the caller as its refusal value.
4. Test both arms: a path inside the root and inside a live worktree is confined to its canonical form, and a `..` path, an
   absolute path outside the roots and a symbolic link that leaves them are refused with the same outcome code.

== Testing

link:{test}/WorkspaceConfinementTest.java[`WorkspaceConfinementTest`]:: a path inside the enrolled root is confined to
its canonical form; a relative path resolves against the root; a path inside a live linked worktree is confined; a path
outside the roots, a `..` traversal and a symbolic link that leaves the workspace are refused with `path_traversal_rejected`;
every reason carries the same code; and the refusal is logged with the outcome code and the reason, never with the path.
