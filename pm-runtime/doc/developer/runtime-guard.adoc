== Purpose

_Requirements:_ link:{docs}/Requirements.adoc#PM-ARCH-2[PM-ARCH-2], link:{req}/12-testing.adoc#PM-TEST-5[PM-TEST-5], link:{docs}/Requirements.adoc#PM-TECH-2[PM-TECH-2]

The package `de.planmarshall.runtime.guard` of `pm-runtime` holds no production class.
It is the test package of the architecture guard that keeps the closed list of Credentials & Enrolment § Closed List of Outbound Calls (link:{spec}/credentials-and-enrolment/03-audit-and-outbound-https.adoc#closed-outbound-list[`03-audit-and-outbound-https.adoc`]) true in the code: "local, no telemetry" (`PM-ARCH-2`) holds only while every connection the runtime opens is one the specification names, and no review would catch a new one.

The guard is link:{test}/OutboundCallsArchTest.java[`OutboundCallsArchTest`], an ArchUnit test in the pattern of `pm-core`'s `AnalysisBoundaryArchTest`.
It imports the main classes of `de.planmarshall.runtime` and of `de.planmarshall.core` — the two modules on the test classpath of `pm-runtime` — and applies two rules to them.
It is a plain JUnit 5 test on the JVM: the controls are classes compiled in the test tree and evaluated by the same rules.

== Rule A: no class opens a connection

A class of `pm-runtime` or `pm-core` may not depend on a connection-opening type or call a connection-opening method.
The set is the one the specification names, and the class Javadoc of the test writes it out:

[cols="1,3",options="header"]
|===
|Group |Types and calls

|The JDK's HTTP client and web socket
|`java.net.http.HttpClient`, `java.net.http.WebSocket`

|Client sockets
|`java.net.Socket`, `java.net.DatagramSocket`, `java.net.MulticastSocket`

|URL connections
|`java.net.URLConnection` and its subtypes `java.net.HttpURLConnection`, `java.net.JarURLConnection`, `javax.net.ssl.HttpsURLConnection`; the calls `URL.openConnection` and `URL.openStream`

|Socket factories
|`javax.net.SocketFactory` and its SSL subtype `javax.net.ssl.SSLSocketFactory`

|Client channels of NIO
|`java.nio.channels.SocketChannel`, `java.nio.channels.DatagramChannel`, `java.nio.channels.AsynchronousSocketChannel`
|===

Listening types are not connections: `ServerSocket`, `ServerSocketChannel`, `AsynchronousServerSocketChannel` and `com.sun.net.httpserver.HttpServer` accept connections and open none, so they are not in the set (the worker's `DecoyServers` listens on a loopback address and needs no exemption).
The data types of the client's API — `java.net.http.HttpRequest`, `HttpResponse`, `HttpTimeoutException`, `BodyHandlers`, `BodyPublishers` — open nothing and are not in the set either.

== Rule B: only the destination classes use the `cui-http` client

No class of `pm-runtime` may depend on `de.cuioss.http.client..` except the destination classes of the closed list, one entry per class, each with the sentence of the specification it implements:

[cols="2,3",options="header"]
|===
|Destination class |Sentence it implements

|`de.planmarshall.runtime.endpoint.JudgmentClient`
|the remote judgment endpoint the operator enrolled (Client Profiles § Judgment Endpoint)

|`de.planmarshall.runtime.endpoint.EndpointClient`
|the loopback endpoint of a client profile (Client Profiles § The Request)

|`de.planmarshall.runtime.corpus.HuggingFaceSourceRepository`
|the fetch of the corpus sources over HTTPS (Credentials & Enrolment § Closed List of Outbound Calls)

|`de.planmarshall.runtime.corpus.LfsBatchClient`
|the Git LFS batch request and the object download of the corpus fetch (Credentials & Enrolment § Closed List of Outbound Calls)
|===

`de.cuioss.http.security..` — the validation pipelines of `IngestionValidator` — stays free: a pipeline validates a URL or a header and opens no connection.
Rule B does not look at `pm-core`: the build already forbids `cui-http` there.

== The exemption map of rule A

The exemptions are a closed map from one top-level class to the reason the specification gives it; nested and anonymous classes of an entry are exempt with it, and nothing is exempt by package.
The map holds the four classes the sweep of the head finds, and the specification names each of them in § Closed List of Outbound Calls:

[cols="2,3",options="header"]
|===
|Top-level class |Why it is not an outbound call

|`runtime.job.WorkerEgressProxy`
|opens a `Socket` to the destination of a model job; a model job's own traffic is the egress proxy's (`PM-SEC-5`) and is not part of the list

|`runtime.credentials.dbus.DbusConnection`
|opens a `SocketChannel` on a Unix-domain socket, the session bus of the Secret Service: local IPC that leaves no machine

|`core.role.ShippedRoles`
|reads a `jar:` classpath resource through `URL.openConnection()` and a `JarURLConnection`: the JAR, never a network

|`core.profile.ShippedProfiles`
|reads a `jar:` classpath resource through `URL.openConnection()` and a `JarURLConnection`: the JAR, never a network
|===

Both maps are proved load-bearing in both directions.
A test evaluates rule A without its exemptions over the same import and asserts that the violating top-level classes are exactly the keys of the map, so an entry that no longer violates fails as stale and a violation without an entry fails as unlisted; rule B asserts the same equality between the classes that depend on `de.cuioss.http.client..` and the allow-list.
The import is asserted non-vacuous (it contains `HuggingFaceSourceRepository`, `WorkerEgressProxy` and `ShippedRoles`), so a changed import path cannot make either rule pass on nothing.

== How to add an outbound call

1. Add the call's destination class to the allow-list of rule B **and** the destination to the closed list of the specification, in the same pull request. Rule B holds a failing test until the class is on the list, and a list entry with no specification sentence is what the guide forbids.
2. If the class opens a socket or a URL connection of its own instead of going through `cui-http`, it needs an exemption of rule A with the reason the specification gives it — and the specification gains the destination. Prefer `cui-http`: an exemption is the exception, not the rule.
3. A class that only listens (a server socket, an HTTP server) needs no entry; check the set above before adding a fixture.
4. Run the test of the module; the failure report names the class, the dependency or the call, and the rule that refused it.

A provider module's calls are not seen by this rule: `pm-runtime` may not depend on `pm-provider-*`, so a provider's HTTP client, the JGit transport and the calls of `pm-workflow` are outside the import.
Extending the rule to a provider module needs an ArchUnit test dependency in that module, which is the operator's decision.

== How to read a failure

The failure report of ArchUnit names the violating class and the dependency or call, for example `Method <de.planmarshall.runtime.job.WorkerEgressProxy.tunnel(...)> calls constructor <java.net.Socket.<init>()>`.
Rule A's message names the type or the call of the set; rule B's names the `de.cuioss.http.client` type the class used without being on the allow-list.
The two symmetry tests fail without naming a dependency when the list and the code drift apart: the message names the class that violates without an entry, or the entry that no longer violates.

== The controls

`de.planmarshall.runtime.guard.fixtures` holds one class per hazard, each a class the rule must fail on, in the pattern of `de.planmarshall.core.guard.fixtures`:

[cols="2,3",options="header"]
|===
|Fixture |The hazard it proves

|`HttpClientFixture`
|`java.net.http.HttpClient`

|`ClientSocketFixture`
|`java.net.Socket` and its `connect`

|`DatagramFixture`
|`java.net.DatagramSocket`

|`ChannelFixture`
|`SocketChannel`, `DatagramChannel`, `AsynchronousSocketChannel`

|`UrlConnectionFixture`
|`URL.openConnection()` and `URL.openStream()`

|`SocketFactoryFixture`
|`SSLSocketFactory.getDefault().createSocket(...)`

|`CuiHttpFixture`
|a class that builds an `HttpHandler`, which rule B refuses because it is on no list
|===

Two positive controls must hold: `ListeningOnlyFixture` (a `ServerSocket` and an `HttpServer` on loopback, no client) and `DataTypesFixture` (`URI`, `HttpRequest`, `HttpResponse`, `HttpTimeoutException`, no client).
A parameterised test pairs each hazard fixture with the forbidden target its failure report must name, so a rule that stopped naming its target fails too.
