== Purpose

A field, parameter or record component whose value may be absent is written `@Nullable T` since the null-contract conversion; `Optional<T>` is returned for absence only.

_Requirements: link:{req}/15-extensions-and-recipes.adoc#PM-EXT-6[PM-EXT-6], link:{req}/07-credentials.adoc#PM-CRED-1[PM-CRED-1]_

Package `de.planmarshall.runtime.config` of `pm-runtime` owns three members of the machine's operator document:
`providers` (link:{spec}/store-schemas/12-machine-stores.adoc#provider-defaults[Store Schemas § Machine Provider Defaults]),
`sources.documents_mode` (link:{spec}/state-catalogue/09-bootstrap-and-lessons.adoc#documents-source[State Catalogue §
Documents as a Source]) and `cleanup` (link:{spec}/timeouts/03-retention-harness-config.adoc#cleanup[Timeouts & Budgets §
One Cleanup]) of `machine-config.json` (link:{spec}/store-schemas/12-machine-stores.adoc#machine-config[Store Schemas §
Machine Configuration Store]). The provider step of the machine's onboarding and its later runs write the defaults; the
machine's settings write the documents mode and the cleanup durations
(link:{spec}/state-catalogue/14-machine-onboarding.adoc#state-catalogue-settings[State Catalogue § The Machine's
Settings]). Every project takes a machine default unless its own operator values set another.

The package lies in the runtime, not in `pm-core`'s `core.config`, because the closed list of providers names them and the
foundation is provider-neutral by its architecture guard
(link:../adr/runtime-config/001-the-provider-defaults-are-written-in-the-runtime.adoc[ADR 001]). The document's
other writer — `credentials.store` — is the runtime's `CredentialStoreChoice`, so one module now holds both writers,
coordinated by `locks/machine-config.lock`.

== The Model

* `Provider` is the closed list `git`, `github`, `gitlab`, `forgejo`, `sonar`; only the first three have a CLI variant,
  which `hasCliVariant()` states once.
* `ProviderVariant` is `native` or `cli`.
* `ProviderDefault` is one provider's default: whether it is available, the variant a project that sets none takes, the
  credential key it uses where a project names none, and the last `VerificationResult`. A credential key must match the
  identifier grammar. A default recorded available must carry a passed result, and the record refuses to be constructed
  otherwise; `verified(result, variant)` and `unavailable(variant)` are the two forms the rule leaves, and
  `withCredentialKey(key)` adds the key.
* `VerificationResult` is `{passed, at, checks[{check, ok}]}`: the check names and their outcomes only, never the
  provider's answers, so nothing a provider said is stored.
* `ProviderDefaults` is the closed object: per provider its default. A provider the machine does not serve is absent, not
  recorded as unavailable; a `cli` variant for a provider without one is refused, and so is an omitted variant for a
  provider with one (`git`, `github`, `gitlab` name it, `forgejo` and `sonar` omit it).
* `DocumentsMode` is `copy`, `move` or `ask`; `ASK` is the schema default while the key is absent. The store reads and
  writes it; the start that reads it and records an "always" answer is the onboarding's, which this half does not deliver.
* `CleanupDuration` is whole days (at least 7, so no window of the system view loses data) or `never`;
  `CleanupDurations` is the six values the cleanup reads — the five item kinds and the reminder's days — and
  `CleanupDurations.defaults()` is what the schema applies while the member is absent (30 days, a 3-day reminder).
  A `cleanup` member that sets only some of them reads with each explicit member kept and only the absent ones at the
  schema default; the codec writes the members back as they were read, so a partial member is never lost.

A provider is recorded available only after its verification passed
(link:runtime-credentials.adoc#_provider_verification[`runtime.credentials` § Provider Verification]); one whose checks
failed is recorded only on the operator's word, and then as not available.

== The Store

`MachineConfigurationStore` reads and writes `machine-config.json` under `locks/machine-config.lock`. Its constructor
refuses a store file that is not `machine-config.json` below the base the lock key lies under, so a document can never be
written at another path under the lock's name.

* `read()` answers the defaults, the documents mode and the cleanup durations at their recorded value — or at the schema
  default where the document records none — and the document's `revision`, or the defaults of an absent document at
  revision `0` when the file does not exist.
* `writeProviders(defaults, revision)` reads the document again under the lock, checks the caller's revision, replaces
  `providers` alone, writes the next revision and keeps every other member — `credentials`, the concurrency limits, the
  languages, `project_defaults` — copied through untouched.
* `writeDocumentsMode(mode, revision)` and `writeCleanupDurations(durations, revision)` write their one member the same
  way: the other members of the operator's document survive; a member the document did not hold yet is appended after the
  members it holds.
* A change against an older revision is refused with `core.config.SettingsConflict`: the code `conflict`, the status
  `409`, the current revision and the current value of the member the change names (the defaults, the mode, or the
  durations), so the first change wins and nothing is merged.
* A document that does not exist is created with `format_version` `1`, `revision` `1` and the two required members at
  their schema defaults (`max_build_slots` 2, `lsp_idle_timeout_seconds` 900).

The codec reads `format_version` first, so a document of another version is refused as outdated or newer rather than as
unreadable for a field that version changed. It refuses an unknown provider, an unknown variant, an unknown member of a
provider's object, a negative revision, and content after the root object (a second object, a number, any token). It
validates the two settings it requires against the schema before it reads or preserves them — `max_build_slots` an
integer 1 to 16, `lsp_idle_timeout_seconds` an integer of at least 60 — so a `null`, a string or an out-of-range value is
refused while every other member is still copied through unchanged.

== The Machine's Own Check of its Plan Defaults

`MachineDefaultsValidation` is `defaults.validate` of the plan-defaults aspect, as far as the machine alone can decide
it: a `landing.pull-request` needs a forge the machine serves (`github`, `gitlab` or `forgejo` — not the `git`
transport, which opens no pull request), `landing.main` and `landing.files` need none, and an unknown variant is refused.
The check reads the machine's provider defaults only; it never reads a repository, and whether a base branch is
protected, or a landing variant fits a project, is the project's own check where the project is known.

[#_the_machine_s_plan_defaults]
== The Machine's Plan Defaults

`PlanDefaults` is the typed value of `plan_defaults`: the machine's variant of each plan behaviour axis (`landing`,
`method`, `asking`) and its optional posture. Each value is checked against the schema's closed list, and
`MachineConfigurationSchemaParityTest` reads those lists out of `machine-config.schema.json`, so the two cannot drift.
`MachineConfigurationStore.writePlanDefaults(defaults, revision)` records the member under the machine configuration lock
and the revision rule the other writers follow: the first change wins, and a change against an older revision is refused
with `conflict` and the current defaults.

A member the document does not set reads at the schema default; a *partial* member — only `posture`, for example — keeps
the one value it sets, reads the rest at their defaults, and survives another setting's write unchanged. The
`posture` is optional in the schema and has no default: while no level sets it, a plan asks it in `init.options`.

The composition's reader is `PlanAxisLevels` of `workflow.plan`: it maps the raw members of this document, the project's
values and the plan's overrides onto the axes, refuses a key or a value the axes do not admit with the level named, and
resolves the posture by the same levels
(link:../../../pm-workflow/doc/developer/workflow-plan.adoc#_the_plan_behaviour_axes[`workflow.plan` § The Plan Behaviour
Axes]). The store never imports the workflow module: the values travel as plain strings.

== The Machine's Settings States

`MachineSettingsStates` is the engine half of the settings states of the machine's onboarding (State Catalogue § The
Machine's Settings), in the shape of `CredentialStoreAspect`: one method per state that has an engine half, each answering
a `Transition` with the next state and, where it refuses, the reason. The operator wait `settings.credential` has none —
choosing rotate or replace is the operator's act — and the engine half starts at `settings.store-credential`.

[cols="2,4"]
|===
|State |What the method does

|`settings.choose`
|`facts()` reads the recorded documents mode, cleanup durations and plan defaults, the provider defaults with their last
verification and the remembered consents, and builds the links the state offers (`reconfigure:<aspect>`,
`withdraw:<kind>` — `withdraw:<kind>/<project>` for a project-scoped kind — `documents_mode`, `cleanup_durations`,
`credential:<key>`, `verify_providers`, `done`).

|`settings.withdraw`, `settings.remove-consent`
|`withdrawOffer` answers the remembered consent of a scope; `removeConsent` removes it through `ConsentStore.withdraw`, so
the removal is audited and its revision is the store's. The action asks again afterwards because the store no longer
remembers it; nothing recorded with the consent changes.

|`settings.credential`, `settings.store-credential`
|`storeCredential` writes the secret into the recorded store and then drops every token derived from the old one through
the registered `DerivedTokenCache` seams. A store that refuses the write throws before any drop, and the state is refused
with `credential_store_unavailable`.

|`settings.verify-providers`
|`verifyProviders` runs `ProviderVerification` over every recorded provider — the on-request form — and `verifyProvidersUsing`
over the providers of one credential key, the form the rotation opens; both write the results against the change's
revision. A declined consent records nothing and leaves the providers as they were; the consent each verification answers
with is the caller's to record.

|===

Each state above has an engine half except the operator wait `settings.credential`, which is the operator's act: choosing
rotate or replace. The settings' own audit record — the channel and the paired device of a change — is the local API's, which serves the
operator: this package writes only what the consent store audits. The hold of a plan that goes on after a rotation is the
job subsystem's; what this package guarantees is that no consumer keeps a token of the replaced secret
(link:../adr/runtime-config/006-the-settings-states-run-in-the-runtime-and-drop-derived-tokens-through-a-seam.adoc[ADR
runtime-config/006]).

== Pitfalls

1. **The document has several writers.** The provider step writes `providers`; the credential-store aspect writes
   `credentials.store`; the machine's settings write `sources.documents_mode`, `cleanup` and `plan_defaults`. No writer may
   rewrite the whole document from its own model: a writer that did would delete the others' members. Copying every member
   through is what keeps them apart, and each writer's test asserts the others' members survive.
2. **The revision is the caller's.** A write that names the revision it read refuses a concurrent change instead of
   overwriting it; a caller that writes `revision + 1` it computed itself defeats that.
3. **A provider without a credential key is not a provider with no credential.** `providers` records where the credential
   is found; whether one exists is the credential store's answer.
4. **Two revision protocols share the document.** `MachineConfigurationStore` and the consent, catalogue and assignment
   stores of `core.config` take the caller's revision through `SettingsConflict`; `CredentialStoreChoice.record`
   increments the revision under its own protocol (link:../adr/runtime-credentials/001-the-recorded-store-replaces-the-automatic-choice.adoc[ADR
   runtime-credentials/001], link:../adr/runtime-credentials/002-credentials-store-written-only-through-credential-store-choice.adoc[002])
   and takes none from a caller. A writer that mixes the two would answer a conflict that no caller can resolve.
