== Purpose

_Requirements:_ link:{req}/07-credentials.adoc#PM-CRED-2[PM-CRED-2], link:{req}/07-credentials.adoc#PM-CRED-3[PM-CRED-3], link:{req}/07-credentials.adoc#PM-CRED-4[PM-CRED-4]

Package `de.planmarshall.runtime.credentials` of `pm-runtime` holds the credential stores of the runtime. The machine
uses exactly one store, the one the operator recorded in `credentials.store` of `machine-config.json`: `os`, the
macOS login Keychain or the Linux Secret Service, or `file`, the permission-guarded file store below
`<PM_MCP_BASE>/credentials/`. The runtime makes no automatic choice and has no fallback: before a store is recorded no
credential is entered, and an unavailable recorded OS store makes the credentials unavailable without a file being
written in its place (link:../adr/runtime-credentials/001-the-recorded-store-replaces-the-automatic-choice.adoc[ADR
001]).

Changing the store is a move of every entry, in either direction, which a stop can cut and the next start resumes.
The work package `credential-store-choice` (PLAN-74) replaced the former `SecretStoreSelector`, which chose a store at
start and fell back to the file store, by this recorded choice.

== Core Types

_Requirements:_ link:{req}/07-credentials.adoc#PM-CRED-2[PM-CRED-2]

[horizontal]
`SecretStore`:: One store: `name()` (`keychain`, `secret-service` or `file`), `put`, `get`, `delete`, `entries()` and
the resolution of a project entry before its global entry (`resolve`).
`CredentialAccount`:: The account of an entry: `<credential_key>` (global) or `<project>/<credential_key>`.
`CredentialStoreChoice`:: The recorded store: reads and writes `credentials.store`, gives the active store, either
store for the move, and the store of the integrity key before the choice.
`CredentialStoreChoice.Store`:: `OS` (`os`) or `FILE` (`file`).
`CredentialStoreChoice.Writer`:: The closed set of writers of the machine configuration: `CREDENTIAL_STORE_ASPECT`,
`STORE_MOVE`, `OTHER_CONFIGURATION`; only the first two own `credentials.store`.
`CredentialStoreChoice.Refusal`:: A request refused although no store failed: `onboarding_incomplete` or
`aspect_owned`.
`SecretStoreException`:: A store that failed: `credential_store_locked`, `credential_store_unavailable`,
`credentials_file_insecure`, `credentials_file_invalid`, `credential_store_failed`.
`CredentialStoreCheck`:: The check of the OS store before it is recorded.
`CredentialStoreMove`:: The move of every entry between the two stores, and its resume.
`CredentialStoreMoveRecord`:: The codec of the record `state/credential-store-move.json` of an open move.
`FileSecretStore`, `KeychainSecretStore`, `SecretServiceStore`:: The three stores.

=== Component Interaction

[source]
----
credential-store aspect (assembly) ──► CredentialStoreChoice.record(tx, store, CREDENTIAL_STORE_ASPECT)
                                         locks/machine-config.lock: re-read, set credentials.store,
                                         revision + 1, one atomic write                   (PM_RUNTIME-26)
caller of a credential ───────────────► CredentialStoreChoice.activeStore()
                                         no store recorded ─► Refusal onboarding_incomplete
                                         os   ─► Keychain | Secret Service, probed per operation
                                                 unavailable ─► credential_store_unavailable (read)
                                                                credential_store_locked      (write)
                                         file ─► FileSecretStore(<base>/credentials)
operator move (assembly) ─────────────► CredentialStoreMove.move(to)        locks/credentials.lock
                                         record ─► copy + read back ─► key last + sidecars
                                         ─► switch (machine-config.lock) ─► delete old ─► end record
start, after the bind ────────────────► CredentialStoreMoveResume.run() ─► CredentialStoreMove.resume()
----

== The Recorded Store

_Requirements:_ link:{req}/07-credentials.adoc#PM-CRED-2[PM-CRED-2], link:{req}/07-credentials.adoc#PM-CRED-4[PM-CRED-4]

`CredentialStoreChoice.recorded()` reads `credentials.store` of `<PM_MCP_BASE>/machine-config.json` without a lock:
the file is replaced by one atomic rename, so a read sees it before or after a write. An absent file or an absent key
means that no store is recorded; any other value than `os` or `file`, another format version, or an unreadable
document is a `StoreRefusal`.

`record(transaction, store, writer)` is the only write of the key
(link:../adr/runtime-credentials/002-credentials-store-written-only-through-credential-store-choice.adoc[ADR 002]).
A writer that does not own the key is refused with `aspect_owned` before anything is acquired. Otherwise the call
acquires `locks/machine-config.lock` in the given transaction, re-reads the document inside the lock, keeps every
other member verbatim, increments `revision` and replaces the file in one atomic write, so two writers never
interleave and no check-then-act window opens outside the lock. An absent document is created with
`format_version` 1, `revision` 1 and the other required keys at their schema defaults (`max_build_slots` 2,
`lsp_idle_timeout_seconds` 900). Every write logs `PM_RUNTIME-26` with the store, the writer and the revision.

== The Active Store

_Requirements:_ link:{req}/07-credentials.adoc#PM-CRED-2[PM-CRED-2], link:{req}/07-credentials.adoc#PM-CRED-4[PM-CRED-4]

`activeStore()` reads the recorded store at every call, so the switch of a move takes effect for the next operation:

* No store recorded: `Refusal` with `onboarding_incomplete`, naming the store step `store` of the onboarding.
* `file`: the `FileSecretStore` below `<PM_MCP_BASE>/credentials`.
* `os`: the OS store of the platform, the Keychain on macOS and the Secret Service on Linux, behind a wrapper that
  probes it before every operation. An OS store unavailable at start or later fails a read with
  `credential_store_unavailable` and a write with `credential_store_locked`, logged as `PM_RUNTIME-128`; a locked
  collection or item met by a read is unavailable as well. No other store serves in its place.

`store(Store)` (package-private) gives either store whether it is recorded or not; only the move uses it.
`integrityKeyStore()` gives the store of the enrolment integrity key: the active store once a store is recorded, and
before that the OS store where one is available, else the file store, for which the key is the key file below
`state/` (link:runtime-enrolment.adoc[`runtime.enrolment`]). The store before the choice is found at the first call
and kept for the lifetime of the instance, as the former selector chose once per process: a later probe never moves
the key from the OS store to the key file or back, so a transient outage of the OS store fails an operation on the key
and never creates a second key in the other store.

The OS keyrings are reached through the package-private seam `CredentialStoreChoice.Keyrings`, which the tests
replace; `CredentialStoreChoice.of(MachinePaths)` uses the real ones. The Secret Service is bounded by
`SecretServiceStore.BUS_TIMEOUT` (2 seconds).

=== The Two Kinds of Refusal

`SecretStoreException.Reason` names failures of a store only. The two refusals that are not store failures, no store
recorded yet and a writer that does not own the key, are the nested `CredentialStoreChoice.Refusal` with its own
`Reason` (`ONBOARDING_INCOMPLETE`, `ASPECT_OWNED`), so that a caller that maps a store failure to its error code never
meets them there (link:../adr/runtime-credentials/002-credentials-store-written-only-through-credential-store-choice.adoc[ADR
002]).

== The Check of the OS Store

_Requirements:_ link:{req}/07-credentials.adoc#PM-CRED-2[PM-CRED-2]

Before the OS store is recorded, `CredentialStoreCheck.check(choice)` writes one test entry under the fixed global
account `credential-store-check`, reads it back and compares it, and deletes it. Each step is one `CheckLine`: the
step (`write`, `read_back`, `delete`), `ok` or `failed`, the message key `credential_store_check.<step>.<what>` with
the store and the account as arguments, and the store's own answer where there is one (its reason code and message).
A failed step ends the check, deletes what was written, and the check records nothing. An unavailable OS store fails
the write step. The test value is random and never logged or put into a line. The consent `check_credential_store`
and the states of the store step stay with the onboarding in the assembly.

== Enumeration

_Requirements:_ link:{req}/07-credentials.adoc#PM-CRED-2[PM-CRED-2], link:{req}/07-credentials.adoc#PM-CRED-3[PM-CRED-3]

Every store lists its entries through `SecretStore.entries()`: every account of `PM-MCP` it holds, global and project
entries, the account `enrolment-integrity-key` included where the key lives in the store, ordered by account; entries
of another service name are never listed (link:../adr/runtime-credentials/003-every-store-enumerates-its-entries.adoc[ADR
003]).

[horizontal]
`FileSecretStore`:: Lists `<dir>/<key>.json` and `<dir>/<project>/<key>.json` without following a link and skips the
temporary files `~tmp-*` of an atomic write, also one a crash left behind. `~` is outside the alphabet of an account,
so no legal name is skipped: an entry or a project named `.tmp-ci` is listed and moved. An absent directory is an
empty store. A directory that fails the
private-mode check or a symbolic link is `credentials_file_insecure`; an entry whose name is no account is
`credentials_file_invalid`.
`KeychainSecretStore`:: `SecItemCopyMatching` with `kSecReturnAttributes` and `kSecMatchLimitAll` under the service
name, reading `kSecAttrAccount` of each result dictionary (`MacSecurity`: `CFArrayGetCount`,
`CFArrayGetValueAtIndex`, `CFDictionaryGetValue`, `CFStringGetCString`). `errSecItemNotFound` is an empty store.
The new downcalls are registered in
`META-INF/native-image/de.planmarshall/pm-runtime-credentials/reachability-metadata.json`; the native build of
`pm-mcpd` in plan-marshall-mcp verifies them.
`SecretServiceStore`:: `SearchItems` on `service=<service name>` alone and the `Attributes` property of each item
(`credential_key`, optional `project`). A locked matching item is `credential_store_locked`; an item without
`credential_key` is no entry and is not listed.

== The Move Between the Stores

_Requirements:_ link:{req}/07-credentials.adoc#PM-CRED-2[PM-CRED-2], link:{req}/07-credentials.adoc#PM-CRED-3[PM-CRED-3], link:{req}/08-security.adoc#PM-SEC-5[PM-SEC-5]

`CredentialStoreMove.move(to)` moves every entry from the recorded store into the other one under
`locks/credentials.lock`, the lock every credential write takes, held for the whole move, and re-reads its record
inside the lock before every phase
(link:../adr/runtime-credentials/004-move-copies-the-key-last-and-switches-once.adoc[ADR 004]):

. Write the record `state/credential-store-move.json` in phase `copying` (`PM_RUNTIME-27`).
. Copy every Token Lane entry the old store enumerates into the target and read each back.
. Copy the enrolment integrity key last, into the keyring entry of the target or the key file below `state/`, read it
  back from the target, and verify every HMAC sidecar under the key read back: the enrolment files, `harnesses.json`
  and `logs/audit.head` (`EnrolmentSidecars` of link:runtime-enrolment.adoc[`runtime.enrolment`];
  link:../adr/runtime-credentials/005-the-move-verifies-every-sidecar-in-the-runtime.adoc[ADR 005]). Where the old store
  holds no key there is nothing signed and nothing to verify.
. Switch `credentials.store` in one write through `CredentialStoreChoice` (writer `STORE_MOVE`), then rewrite the
  record in phase `switched`.
. Delete every entry and the key from the old store.
. Delete the record, log `PM_RUNTIME-28` and append the `operator` audit record `credential_store_moved` with the
  details `from`, `to` and `entries` (the number of Token Lane entries in the new store).

A failed copy, read-back or sidecar verification before the switch logs `PM_RUNTIME-129`, deletes the copies from the
target and the record, and fails with `credential_store_failed`; the old store stays recorded. The clean-up never
deletes from the recorded store: it deletes the copies only while `credentials.store` names the old store, and keeps
them where another writer recorded the target or the machine configuration cannot be read. Until the switch the
recorded store is the old one, so the active store reads no other store while the move runs. A move is refused
before anything is written when no store is recorded (`onboarding_incomplete`), when the target is the recorded store,
or when a move is open already.

=== Lock Order

The move holds `locks/credentials.lock` and takes `locks/machine-config.lock` inside it for the switch, which sorts
after it. The sidecars are verified in a transaction of their own while the move's transaction holds the credentials
lock: the verification takes the enrolment locks, `locks/harnesses.lock` and the audit leaf lock last, after which a
transaction may acquire nothing, and the move still has to take the machine configuration lock for the switch.

=== The Record and the Resume

`CredentialStoreMoveRecord` is the strict codec of `{"format_version": 1, "from", "to", "started_at", "phase"}`
(mode `0600`, one atomic rename, every field once, no other field, the two stores different; every refusal a
`StoreRefusal` naming the file). It names stores only and holds nothing secret.

`credentials.store` is switched before the record is marked `switched`, and only after every entry and the key were
copied and verified. A stop between the two leaves a record in phase `copying` although the target is recorded.
`resume()` therefore decides the phase from the recorded store as well as from the record: in phase `switched`, or in
phase `copying` while `credentials.store` names the target, it marks the record `switched`, finishes the deletion from
the old store and ends the record, and deletes or copies nothing in the recorded target; in phase `copying` with the
old store recorded it deletes the copies from the target and runs the move again from the first entry, the old store
holding every entry; without a record it does nothing. A stop never deletes the only copy of an entry. It returns the
record as found.
The start calls it through `CredentialStoreMoveResume` of `runtime.start`
(link:runtime-start.adoc#_store_move_resume[Store Move Resume]).

The audit record is built directly as an `AuditEvent` with the category `operator`; `pm-core` gained no factory for
it.

== Pitfalls

_Requirements:_ link:{req}/07-credentials.adoc#PM-CRED-2[PM-CRED-2], link:{req}/07-credentials.adoc#PM-CRED-4[PM-CRED-4]

1. **Never a file write in place of an unavailable OS store**: an unavailable recorded store fails the operation; it
   is never a reason to use the other store.
2. **Write `credentials.store` only through `CredentialStoreChoice.record`**, with a writer that owns it; never write
   `machine-config.json` around it.
3. **The key moves last**: after every Token Lane entry, and the sidecars are verified under the key read back from
   the target, never under the key held in memory, before the store is switched.
4. **Switch before marking the record**: the record says `switched` only once the target is recorded, so a resume
   never deletes from the old store what the target does not hold; a record in phase `copying` with the target
   recorded is a switched move, and the recorded store is never cleaned up.
5. **No secret in a message**: no log record, exception message, check line or audit record names a secret.
