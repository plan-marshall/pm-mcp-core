= ADR 005: The Integrity Key Is Read Through a Supplier of the Active Store
:nofooter:

== Status

Accepted

== Date

2026-10-17

== Context

`EnrolmentKey` held one `SecretStore`, fixed at construction: the keyring, or the fallback file store on a host
without one. With the recorded credential store, the key lives before the choice where the runtime finds a store and
afterwards in the recorded store, and a move between the stores carries it like every other entry. A key holder fixed
to one store would read the key from the old store after a move (question q3 of the work package).

== Decision

* `EnrolmentKey(Supplier<SecretStore> activeStore, Path stateDirectory, String user, SecureRandom random)` asks the
  supplier for the store on every read, create, write and delete. The supplier meant for it is
  `CredentialStoreChoice::integrityKeyStore`: the recorded store, or before the choice the OS store where one is
  available, else the file store, whose key is the key file `state/enrolment-hmac.key`.
* The store before the choice is found once, at the first call, and kept for the lifetime of the
  `CredentialStoreChoice`, as the former selector chose once per process. A supplier that probed the OS store on every
  call would answer the file store during a transient outage, and the next create would write a second key into the
  key file, under which sidecars signed with the first key fail as `enrolment_tampered`.
* The constructor with one `SecretStore` stays and delegates with a supplier of that store.
* Nothing is re-signed: after the first recording, which carries the key into the recorded store
  (link:../runtime-credentials/006-the-first-recording-carries-the-integrity-key.adoc[`runtime-credentials` ADR 006]),
  and after a move the key is read from the store now recorded, and every sidecar verifies under it.

Rationale not recorded.

== Alternatives Considered

Alternatives not recorded.

== Consequences

* A switch of `credentials.store` takes effect for the key at the next read, without rebuilding the key holder.
* No caller keeps the store of the key; the move reaches the key in a store that is not recorded through the
  constructor with one store.
