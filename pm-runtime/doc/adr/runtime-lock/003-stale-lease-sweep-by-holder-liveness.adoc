= ADR 003: The Stale Lease Sweep Judges a Lease by the Liveness of Its Holder
:nofooter:

== Status

Accepted

== Date

2026-10-10

== Context

Leases are plain records that survive a restart, so a lease of a holder that crashed stays in its store until
something removes it. The work package asks for a stale lease sweep that removes a lease of a dead holder and keeps a
live one. Per-project crash recovery, added later by the work package `runtime-lifecycle`, needs the sweep for a single
project.

== Decision

* `HolderLiveness` judges a holder by its PID and its start instant, as the specification fixes them.
* `StaleLeaseSweep` removes or orphans a lease of a dead holder, per the specification, and keeps a lease of a live holder.
* The sweep is not called from startup; that belongs to `runtime-lifecycle`.
* With `runtime-lifecycle` (pull request #29), `StaleLeaseSweep` gains a project-selecting overload, which the recovery step `LeaseRecoveryStep` uses for orphan marking.

Because leases are records, a sweep can remove those of a dead holder while keeping those of a live one.

== Alternatives Considered

Alternatives not recorded.

== Consequences

* A test proves that the sweep removes a lease of a dead holder and keeps a live one.
* Lease cleanup can target a single project and leaves the leases of other projects unchanged.
* The sweep finishing is logged as INFO 050 `STALE_LEASE_SWEEP_FINISHED`, an orphaned lease as WARN 151 `LEASE_ORPHANED` of `PmMcpLogMessages`.
