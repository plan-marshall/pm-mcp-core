= ADR 012: The Credential-Store Check Never Overwrites an Entry
:nofooter:

== Status

Accepted

== Date

2026-11-10

== Context

The check of the OS store before it is recorded (PM-CRED-2) writes, reads back and deletes one test entry under the fixed
global account `credential-store-check`. `CredentialStoreCheck.check(SecretStore)` called `put` without reading the
account first. An OS store that already held an entry under that account — an earlier run that stopped between the write
and the delete, or an operator's own entry — lost its value: the check overwrote it, compared its own value, and deleted
the entry afterwards. Two alternatives existed: restore the original value after the check, or refuse to write while the
account is occupied.

Restoring the original value can lose it: a crash between the overwrite and the restore leaves the check's value in
place, and the original is gone. The store offers no compare-and-swap, so the check cannot write atomically over an
occupied entry.

== Decision

* `CredentialStoreCheck.check(SecretStore)` reads the account before it writes.
* An occupied account fails the write step with the line `credential_store_check.write.occupied`; nothing is written and
  nothing is deleted, so the original value is still there.
* A read that fails is the write step's failure (`credential_store_check.write.failed`) with the store's own answer;
  nothing is written then either.
* The three steps of a free account stay write, read back and delete, each as one check line.
* The read-then-write pair is not atomic, and needs no compare-and-swap: one runtime owns the OS store for the machine
  (the runtime singleton lock), so no second writer interleaves between the read and the write.

== Alternatives Considered

1. *Restore the original value after the check.* _Not taken_: a stop between the overwrite and the restore loses the
   original, and the check exists to prove the store works, not to risk an entry.
2. *Use another account name per run.* _Not taken_: the fixed account is the contract of the check and of the operator's
   consent; a per-run name would leave test entries behind under unknown names.

== Consequences

* An occupied account is reported to the operator as a failed check with its own message key, and the entry is kept.
* `CredentialStoreCheckTest` holds the occupied case (nothing written, nothing deleted, the original value still there),
  the failed-read case, and the three steps of a free account.
* The credential-store aspect reaches `store.unavailable` with the check's line, as for any other failed step.
