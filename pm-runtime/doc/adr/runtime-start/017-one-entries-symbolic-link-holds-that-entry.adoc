= ADR 017: One Entry's Symbolic Link Holds That Entry, Never the Sweep
:nofooter:

== Status

Accepted

== Date

2026-11-22

== Context

The pending-entry step of the periodic sweep re-judges every candidate under the workspace lock with
`PendingEntryStore.verify`, which compares the entry's four stores against the workspace's digest sidecar. That
verification refuses a store path that passes through a symbolic link below the path base with an
`IllegalArgumentException` (Store Digest Verification: a link below the path base names no store of the scope). The step
caught `UncheckedIOException`, `IllegalStateException`, `InternalFaultException` and `StoreRefusal`, so the
`IllegalArgumentException` escaped: one entry whose directory carried a link aborted the step for the whole project,
including the residue that had nothing to do with it, and the run reported the whole project as not swept. The catch
that fixed that (`PLAN-V2-167`) took every `IllegalArgumentException` for a link, so a refusal of the recovery or of the
sidecar code was reported as a held entry and made the step fail on every hourly pass.

== Decision

`JournalScope.resolveWithoutLinks` refuses a linked store path with its own type, `JournalScope.SymbolicLinkRefusal`, an
`IllegalArgumentException`. The sweep verifies each candidate under the lock in one step of its own and holds the entry
for that refusal alone: it is kept and named in the report as `(held: …)`, and the other candidates are removed as
usual. Any other `IllegalArgumentException` of the verification is a fault, not a held entry: it is not read as one, and
the per-entry step rethrows it to the catch at the level of the whole project, which reports the project as not
swept. A refusal of one entry's path is still no reason to leave the project's other residue in place.

== Alternatives Considered

1. *Catch `IllegalArgumentException` around the whole run.*
   _Rejected_: it reports the project as not swept and removes no residue, so one link blocks every other entry.
2. *Follow the link and verify its target.*
   _Rejected_: a store reached through a link is no store of the scope (Store Digest Verification), and following it
   would let a directory outside the path base decide what the sweep removes.
3. *Keep the entry silently.*
   _Rejected_: the operator would never learn which entry holds a link, and the sweep's report is the only place the
   hold is visible until the entry-level hold exists.

== Consequences

* The step's report names a held entry with the verification's reason, after the readable residue was removed; its
  outcome is `Failed` because a directory stays behind.
* The entry stays where it is until the operator removes the link or abandons the entry; the sweep never removes it.
* A second cause of an `IllegalArgumentException` is no held entry: the refusal of the link has its own type, and a
  refusal of another cause leaves the step as the failure it is instead of holding an entry on every pass.
* `PendingEntryRecordsSweepTest` proves that the held entry is kept, the other residue is still removed, and only the
  link refusal holds an entry.
