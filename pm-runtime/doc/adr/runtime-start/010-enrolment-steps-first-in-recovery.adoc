= ADR 010: The Enrolment Check and the Owed-Audit Replay Are Recovery Steps 1 and 2
:nofooter:

== Status

Accepted

== Date

2026-10-12

== Context

Enrolment integrity is verified in recovery, and every enrolment write owes its audit record before the mutation, so a
stopped runtime can leave owed audit records behind. Per-project recovery (`ProjectRecovery`) already existed with its
constructors and callers when the work package `enrolment-store` added these two steps.

== Decision

* `ProjectRecovery.withEnrolment(...)` builds a recovery whose step 1 is the enrolment integrity check (`EnrolmentIntegrityStep`, `ENROLMENT_INTEGRITY`) and whose step 2 is the replay of owed enrolment audit records (`OwedEnrolmentAuditStep`, `OWED_ENROLMENT_AUDIT`).
* The older constructors fill those two slots with a no-op step.

The no-op slots keep the existing callers working.

== Alternatives Considered

Alternatives not recorded.

== Consequences

* `StartupSequence` does not run per-project recovery yet. Whoever wires it must build `ProjectRecovery.withEnrolment(...)` so that the enrolment check and the owed-audit replay run.
* The owed-audit replay is at-least-once; the audit sink must drop a repeated `transaction_id`.
