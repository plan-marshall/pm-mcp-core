## Objective

The derived facts store of a project (`<PM_MCP_BASE>/projects/<project_id>/derived-facts.json`, Store Schemas § Derived Facts Store, owner class *cache*) has no record type, no file format, no reader and no writer at HEAD: only its lock key (`LockKey.derivedFacts`, level `LockLevel.DERIVED_FACTS`) exists, and no work package of the index builds the rest (the plans `module-discovery` (PLAN-142) and `architecture-queries` (PLAN-130) both name the store as an open gap; operator decision 12 of 18, 2026-10-29: cut a package ordered before its consumers). This is the first of two plans. It cuts the package `derived-facts-store` and builds the data side: the entry records, the strict codec of the file, the parity test that pins both to the schema block of the specification, and the registry through which a consumer registers a fact kind (its value schema, its class, its inputs) WITHOUT this plan registering any concrete kind. The store with the input-digest recompute rule, the stale and failed semantics, the gate-evaluation helper and the exclusion of the operator-only fact is the second plan (`derived-facts-store-operations`).

**The build timings store is NOT part of this work.** Store Schemas 09 holds the Build Timings Store in the same file, but `BuildTimings`, `BuildTimingsCodec` and `BuildTimingsStore` already exist in `pm-core` `core.store` (not `pm-runtime`) with `BuildTimingsStoreTest`; they have no caller in any `src/main` yet (that is `adaptive-timeout-learning`, PLAN-128). Touch none of them.

2. **The record types.** In `pm-core` package `core.store`, new files with the prefix `DerivedFact`: `DerivedFactKind` (the closed enumeration of the sixteen kinds of the schema's `kind` enum, each with its wire name, `fromWireName`, and the flag `operatorOnly`, true for `AGENT_IDENTITY` alone, Store Schemas 09 § Operator-Only Facts); `DerivedFactKey` (a kind and an optional qualifier; the grammar of the schema's `propertyNames` pattern `^[a-z][a-z0-9_]{0,47}(:[A-Za-z0-9_.-]{1,128})?$`; the wire form `<kind>` or `<kind>:<qualifier>`; a key whose kind part is not a `DerivedFactKind` is refused); `DerivedFact` (kind, `value` as `de.planmarshall.core.role.corpus.JsonValue` or `null`, `source` with `derivation` and `class` (`local` or `network`), `inputDigest` (64 lower-case hex), `derivedAt`, `state` (`current`, `stale`, `failed`), `failure` with `reason` (at most 500 code points) and `at`); `DerivedFacts` (the document: the entries by key in document order, `FORMAT_VERSION = 1`, `empty()`, `fact(key)`). The compact constructors state the invariants the specification text states: `state` `current` carries a value and no failure; `stale` carries the last value and a failure; `failed` carries no value (`null` only with `failed`) and a failure; the key's kind equals the entry's `kind`. Done when: `DerivedFactKindTest` (the completeness test derives the expected set from the enum at run time, R15 (4) as a pattern), `DerivedFactKeyTest` and `DerivedFactTest` cover every invariant with one refusing case each.
3. **The strict codec.** `DerivedFactsCodec` reads and writes `derived-facts.json` on `StrictJson` as `BuildTimingsCodec` does: only the current format version (R13), only the declared members, each at most once, every required member (`format_version`, `facts`; per entry `kind`, `value`, `source`, `input_digest`, `derived_at`, `state`), instants only in the shape `Instant.toString` writes, and a refusal that names the file as a `StoreRefusal` (never an empty store). `value` is read with the public `JsonValue.read(JsonParser)` and written by a private generator over the `JsonValue` tree (member order kept, a number written with the digits it was read). The writer emits `"failure": null` for a `current` entry; the reader accepts the member absent or `null` there (the schema does not require it). The codec publishes its member lists as package-private constants for the parity test (the pattern of `JobRecordCodec.MEMBERS`). Done when: `DerivedFactsCodecTest` shows `read(write(x))` equal to `x`, `write(read(b))` byte-identical to `b` for canonical bytes, and one refusing case per rule (another format version, unknown member, duplicate member, missing required member, key grammar, key kind unlike entry kind, a bad digest, a failure reason of 501 code points, an offset-spelled instant, content after the document).
4. **Schema parity with the specification.** `DerivedFactsSchemaParityTest` in `pm-core/src/test/java/de/planmarshall/core/store/` reads the first `[source,json]` block after the line starting `== Derived Facts Store` of `store-schemas/09-derived-facts-and-build-timings.adoc` with `SpecificationDocument.jsonBlockAfter` (the pattern of `JobRecordSchemaParityTest`) and asserts, against the codec and the records: the title `DerivedFactsStore`; the members of the root and of the entry, of `source` and of `failure`, in schema order, and their `required` sets; the values of the `kind` enumeration against `DerivedFactKind`, of `source.class` and of `state`; the `propertyNames` pattern against the key grammar, the `input_digest` and `source.derivation` patterns, the `failure.reason` `maxLength`, `format_version` const against `FORMAT_VERSION`. Done when: the test passes at the head and fails when a member, an enumeration value or a bound of the schema block is changed without the code (shown once on a scratch copy, stated in the pull request body). **From here on the store schema block is test input (R10):** every plan that edits `store-schemas/09-derived-facts-and-build-timings.adoc` keeps that block byte-stable or changes it together with the codec; `skip-on-docs-only: false` in `.github/project.yml` makes the build run for a specification-only pull request.
