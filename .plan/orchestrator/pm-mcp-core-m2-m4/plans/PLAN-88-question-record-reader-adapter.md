## Objective

PLAN-14 (#93, `3323ce7`) delivered the question store in `pm-core` (`QuestionLog`, `QuestionRecord`, the `questions.jsonl` of each scope) and the engine port `QuestionRecordReader` in `pm-core` `core.spi`, and states that the adapter is not part of it. The Javadoc of the port says "An adapter of `pm-runtime` is to implement this port over it; no class of `pm-core` implements the port (PM-IMPL-5)", and ADR `pm-core/doc/adr/core-store/032-question-store-in-core-store-read-through-a-runtime-adapter.adoc` records the decision. No class of `pm-runtime` implements it and no file of `doc/plans/` names `QuestionRecordReader` (the Open Defect of the epic, found by the landing of PLAN-14 on 2026-10-18). The engine's `question` state waits on a persisted record; without the adapter the daemon has nothing to hand the engine. This plan builds the adapter and its tests.

## Deliverables

1. **The adapter** in `pm-runtime`, in a package the plan names (a new package or an existing one that fits; ask at refine if two readings differ in the files they create): implements `QuestionRecordReader` over `QuestionLog` for the scope of the `ReadRequest`, and returns the tri-state `QuestionRead` — `Open`, `Resolved` with its closed resolution outcome, or `Unreadable`. It maps an absent log, an unparseable line, a record of another class and a log the store refuses to a result of `Unreadable`, never to `Open` (ADR 032 and the port's Javadoc).
2. **The read is a read.** The adapter takes no lock that blocks an append, writes nothing, and reads through the confinement of the project paths the other `pm-runtime` readers use (`WorkspaceConfinement`, settled design below); a refused path is a value, not an exception.
3. **Tests** on the JVM without Quarkus: one per outcome (open, resolved with each outcome of the closed set, unreadable for each cause above), a fixture log with a refused line (ADR `core-store/039`: an append is refused while the log holds a refused line, and the read must say `Unreadable` for the same log), and a test that a broken store is never reported open. Fixtures come from `TestBases` of the `pm-runtime` test JAR.
4. **Documents.** The developer file of the package, one ADR for each design choice taken, `package-info.java`, the `Implementation:` and `Verified by:` lines of `PM-ARCH-4` (bullets 4 and 5) in `doc/Traceability.adoc`, and the deletion of the covered specification passage if the plan finds one.

The wiring of the adapter as a CDI producer in the Quarkus assembly belongs to `pm-mcp-server` in `plan-marshall-mcp`, not to this repository: list it in the pull request body as **Owed outside this repository**.

**Done when:** a `question` state resolved against a fixture log reads `Open` for an open record, `Resolved` with the recorded outcome for a resolved one, and `Unreadable` for every broken case of Deliverable 3; the adapter is the only implementation of the port in the product code; `verify`, `verify -Ppre-commit`, `verify -Pcoverage` and `verify -Pintegration-tests -pl pm-runtime -am` are green.
