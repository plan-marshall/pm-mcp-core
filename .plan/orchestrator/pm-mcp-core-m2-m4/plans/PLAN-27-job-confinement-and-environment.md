## Deliverables

The bullets of `doc/plans/job-confinement-and-environment.adoc` § What, in its words (regenerated at 710da61, after the specification moved into this repository).

1. The daemon composes the write and read sets of each job and records the confinement level and the Landlock ABI that `pm-exec` reports.
2. The job environment table built from scratch per job type, the rows of the CLI variant included; the `enrolment` rows come from the project's `build_environment`, which the terminal client captured from the operator's login environment and sent with the onboarding or `pm-operator enrol`, and no row is taken from the runtime's own environment.
3. The per-project build daemon store, so that no build daemon serves jobs of two write sets.
4. The enrolment opt-in `container_engine: docker`, set at the project's enrolment (its onboarding or `pm-operator enrol --container-engine docker`); without it the engine's sockets are withheld and the failure envelope names the opt-in.
5. Probe jobs: the working directory (the checkout root, or `cwd/` of the probe's job-private directory); the read set of every job plus its own job-private directory, read-only; the write set of the system temporary directory and device nodes, for a harness probe also its `headless.writable_paths` and data home, for a checkout's script the build write set of that checkout; the environment of the all-job rows, the `enrolment` rows from the login environment the terminal client sent, and `PATH` limited to the directories of the probed executable and its interpreter; no job token, MCP connection, credential variable, or session bus.
6. No session bus for any job; the runtime socket as an own read rule of every worker.

**Done when** (the package's own acceptance): Linux tests under Landlock: a write outside the write set and a read of `<PM_MCP_BASE>` are refused; a confined Gradle build proves the registry option; the Docker socket is unreachable without the opt-in; the job record carries level and ABI; a probe job cannot read `<PM_MCP_BASE>` beyond its own job-private directory, writes nothing outside its write set, and receives no job token, no credential variable, and no bus variable, its `PATH` holding only the probed executable's directories. The macOS run records `unavailable`.

**Trace starting set** (the requirements, use cases and roadmap live in `../plan-marshall-documentation`; the specifications and watch documents of the engine in this repository, `doc/specification/` and `doc/implementation-watch/`):

- **Checklist for durable multi-step protocols in `pm-runtime` and `core.store` (found by PLAN-74, 2026-10-18; four review rounds each found another unguarded transition of the credential-store move).** (1) A resume decides from the pair (record phase, state actually recorded), never from the phase alone, and a guard added to one phase branch gets its symmetric guard on every other branch; enumerate (phase x recorded state x writer) with a test per cell before the first review. (2) While a durable in-progress record exists, every other writer of the state it switches is refused under the same lock, and an authorization is verified against durable state, never asserted by the caller. (3) The record that drives recovery is deleted last, after every side effect (audit event, clean-up after a failure) is durable. (4) A decision with side effects (which store, which key) is decided once and persisted, never re-derived per call from a probe that can flap. (5) A copy-then-switch move has a test with a pre-populated target (an overlapping key and a target-only key) and a failure injected after the copy; the pre-existing-target hazard is checked for every kind of object the protocol copies (entries, integrity key, sidecars) in the same task. (6) A store's temp-file namespace is disjoint from its legal entry-name namespace. (7) A fix of a state-machine transition lists the specification section, the ADR, the Javadoc and the test that state it among its affected files and updates them in the same commit; ADR and test are checked against the specification text, not against the code they document. (8) The invariants of a multi-write protocol are stated per crash window, not per phase. (9) A test that asserts a file location derives the expected path from the production layout independently, never from the object under test. (10) A native binding is loaded once; only what can change at runtime (a lock state) is probed per operation.
