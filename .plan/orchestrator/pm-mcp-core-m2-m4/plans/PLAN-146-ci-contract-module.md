## Objective

Re-create the module `pm-provider-ci` as the contract module of the CI provider operations, as the Module Structure Specification already lists it (`doc/specification/module-structure.adoc` of `plan-marshall-documentation`, module tree line 117, row lines 168 to 170, Dependency Rules line 586), and build into it the part of the contract that has a stated shape and a staged consumer: `ci.whoami`, `ci.issue-view`, `ci.issue-comment`, the URL grammar that resolves a source's URL to its forge, repository and issue number, and the explicit provider registry; implement all of it natively in `pm-provider-github` and `pm-provider-gitlab`. The operator decided on 2026-10-29 (decision 2 of 18) that the contract is a module and not a port in `pm-core`; this plan implements that decision and does not reopen it.

Why now: #156 (PLAN-86, `landings/PLAN-86.md`) moved the shared HTTP base into `pm-provider-http` and removed the then-empty `pm-provider-ci`; the contract was never built. `ci.whoami` and `ci.issue-view` have no implementing class (the only mention of `ci.whoami` in code is a Javadoc sentence of `GitLabClient`); the package `forgejo-provider` is `blocked` on "the CI contract of `pm-provider-ci` (no work package)", and the staged plans for the project and machine onboarding (`setup.verify-credentials`, the provider verification) and for the sources of a start (`source-issue`) need operations that exist nowhere. The module is the unit of work all of them wait for; the pull-request read (`ci.pr-view`) is cut into the plan PLAN-147 (`ci-contract-pull-request-view`), which depends on this one.

2. **The contract.** Package `de.planmarshall.provider.ci` (a pure contract: no `cui-http` type, no forge name beyond the provider ids). `CiProvider`: `id()` (the provider id, `github`, `gitlab` or `forgejo`, equal to the value of the derived fact `ci_provider` and to the credential key); `whoami(Optional<RepositoryRef>)`, `issueView(IssueRef)`, `issueComment(IssueRef, String body)`, each returning the closed `de.planmarshall.provider.http.Result` (the operations' closed result, in which a refusal of the operation itself is `REJECTED` with the provider's reason, kept apart from `AUTH_FAILED` and `PERMISSION_DENIED`, `NOT_FOUND`, `RATE_LIMITED` with its `resetAt`, and `FAILED`; Module Structure row 170, Job Runtime § Outcome Derivation). Value types as records: `Identity` (login, user id, `TokenKind`, for a GitHub App the login of the operator whose user access token authors the writes beside the bot identity, the permissions the credential has on the named repository, the scopes the provider reports, the expiry the provider reports), `TokenKind` (the closed list of `token_kind` in `doc/specification/store-schemas/12-machine-stores.adoc` line 495 plus the App), `Issue` (title and body as text; labels, milestone, assignees, state and URL as structured fields), `IssueRef`/`RepositoryRef` (forge id, origin, owner-or-path, name, number), `IssueComment` (the comment id and URL). `ForgeUrl`: the URL grammar of each forge (GitHub and Forgejo `/<owner>/<repo>/issues/<n>`, GitLab `/<group>/…/<project>/-/issues/<n>`) resolving a URL, with a host-to-forge table the caller passes (built in: `github.com`, `gitlab.com`, `codeberg.org` as `forgejo`), to forge, repository and number, and a URL on an unknown host to the outcome `unknown_forge` as a value, never an exception; a pull-request URL is recognised and returned as such (the read of it is the follow-up plan). `CiProviders`: the explicit registry of a runtime, the members passed to the constructor, found by id, no classpath discovery, immutable, an id that is not registered answered as empty (the pattern of `CodeAnalysisProviderRegistry` in `pm-core`), plus the selection by the forge of a `ForgeUrl`. A provider is bound to one origin and one credential; an `IssueRef` on another origin is `REJECTED` before anything is sent (the origin pinning of `pm-provider-http`). **Done when:** unit tests without HTTP for the URL grammar (every forge, a trailing slash, query and fragment, a URL on an unknown host, a pull-request URL, a hostile URL: userinfo, a path with `..`, an over-long path), the registry (duplicate id, unknown id, selection by URL) and the value types' invariants; no abstract contract test class and no test JAR is added (see Standing Constraints).
3. **GitHub.** `GitHubCiProvider` in `de.planmarshall.provider.github`, native variant only, on `GitHubClient` and `HttpClient` (R03). `whoami`: for a personal access token `GET /user` with the repository's `permissions` from `GET /repos/{owner}/{repo}` and the kind (fine-grained or classic) and expiry the provider reports; for a GitHub App the App's bot identity from `GET /app` signed with `GitHubAppJwt` and the operator's login from `GET /user` with the user access token, both in one `Identity`. `issueView`: `GET /repos/{owner}/{repo}/issues/{n}` (a pull request answered by that endpoint is `REJECTED` "is a pull request"), the fields of the contract, labels, milestone and assignees as the provider names them, with a token narrowed by a new `GitHubOperation.ISSUE_READ` (`issues: read`; a public issue of another repository is read without a credential). `issueComment`: `GitHubClient.postComment` (exists, `GitHubClient.java` line 182) on the issue number of the project's own repository. The two client methods and the one operation constant that are missing are added to `GitHubClient` and `GitHubOperation` with their tests. **Done when:** `GitHubCiProviderTest` on `cui-test-mockwebserver-junit5` (R04) covers each operation against recorded-shape responses: a personal access token, an App (both identities), a private issue without a credential (`NOT_FOUND`/`AUTH_FAILED` as the provider answers, see the Verify-first clause), a pull request number, a rate limit with its reset instant, a `403`, a `404`, a malformed body (`FAILED`, never a thrown exception), an issue on another origin.
