## Public API changes (the assembly `plan-marshall-mcp` follows)

New `public final class CommitPathRefusals` (`isRefusedText(String)`, `isRefusedLocation(Path, String)`, `refusedTrackedTrees(Path, Collection<String>)`, never throws, empty when the repository or index is unreadable). `StagingSets.derive(ScopeType, Path, Collection, boolean)` keeps its signature but reads index and `HEAD` of the worktree: more names go to `outside` (any real directory such as a modified submodule, a tracked directory replaced by a file); a non-repository worktree switches the tree rule off silently. `GitOperations.commit` / `CommitInput` keep their signatures; new `FAILED` detail "the index of <path> holds unresolved conflict entries" (any conflict for an empty list: a direct caller that used `add .` with a conflict now gets `FAILED`); an empty list restores the whole index on `NOTHING_TO_COMMIT`; `PATH_REFUSED` detail is the first tracked-tree name in sort order. `commit_failed.detail`: `ABSOLUTE_PATH` semantics changed (see M3). `CommitSite.dirtyPaths`: a modified submodule by its name without a slash, an embedded repository `newdir/`, a rename by both sides, read with `-z` (`PM-WATCH-DSL-48`); `Params.message` null binding unchanged (`PM-WATCH-DSL-47`). `local-config.schema.json` `$defs/settings.commit_identity` patterns equal the `commit_trailer` ones: a stored value that now fails the schema is a name with a C0 or C1 control, TAB, U+2028 or U+2029, an e-mail with a C0 or C1 control, U+0085 or a non-ASCII White_Space character; the def is shared, so `machine-config` `project_defaults.commit_identity` is covered too; nothing in this repository validates at run time (`PM-WATCH-STORE-62`), a client or the assembly that validates against the schema would refuse such values.
