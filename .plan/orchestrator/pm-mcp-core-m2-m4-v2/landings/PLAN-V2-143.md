### Layer 3 — Correct
No crash found on the new paths. Findings by weight (the ordering behind 1 re-read at `SecretRedactor.java:344-368`: URL, quoted, unclosed, then PEM last):
1. **A PEM key given as the value of a labelled assignment leaks its body** (pre-existing, kept by the new ordering): `PRIVATE_KEY="-----BEGIN RSA PRIVATE KEY-----\nMIIE…\n-----END …-----"` — the label pass masks the rest of line 1 including the `BEGIN` marker, the PEM scan then finds none, the body and the `END` line stay readable; the same for `secret: -----BEGIN …`. By reading, not run; the ADR names the cross-line quoted residue, not this consequence.
2. **D3 widened the exposure of the documented quadratic URL pattern** (analysis, not measured): `URL_USER_INFORMATION` scans back from every scheme start on a line like `x://y:x://y:…` with no `@` (about n²/6 on an 8192-character line); `DiagnosticCollector.stored` now runs it on every classified line and the `Diagnostic` constructor on `stackTrace` (unbounded line count); input is capped at 16 MiB and 8192 per line, so an attacker-controlled `[ERROR]` flood costs seconds to minutes of CPU by estimate. No cost test covers the `stored` path.
3. `RewriteFinding.message`, `.path` and `Diagnostic.file` are stored unredacted.
4. `INVISIBLE` is removed from every text the redactor sees, including U+200C/U+200D and the bidi controls that are semantic in Persian, Indic and RTL text and emoji sequences; the ADR claim "removing one costs no evidence" is false for those (the operator chose the widening and the false-positive cost is recorded).
5. ADR 009 and the `TapOutputParser` Javadoc overclaim the point shape: a prose line `ok then proceed` is still counted; the Javadoc says `ok <number>`.
6. The `MAX_DETAIL_LENGTH` Javadoc of `CoverageRefusals` says "this many characters plus the kind"; the code bounds the whole detail to 256.
7. `Diagnostic.stackTrace` is redacted but not cut to 500, so a credentialed URL with a closing `@` beyond the 8192 line cut leaves up to ~8192 characters of partial password per line (needs a password over 8000 characters).
8. The escaped-JSON secret `{\"password\":\"hunter2\"}` matches no pattern (pre-existing; not in the ADR).
