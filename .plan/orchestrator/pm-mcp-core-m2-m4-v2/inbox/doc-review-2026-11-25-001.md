## The principle behind the decisions
A mechanism that predicts, infers or pre-declares something the process later observes as a fact is replaced by the observation, also where code exists. This round:
- the merge sync rebases when the provider reports the branch behind or the base changed a path of the realized footprint, instead of a cached forge fact;
- the Q-Gate submits findings only, without predicting which components the change touches;
- a removed dependency is a sanity-check item read from the build, instead of a self-review conflict over undeclared removals;
- the fix proof finds the red run in the change ledger, instead of a `pm_build` declaration;
- the pull-request author writes the title from the diff, instead of a staleness flag set by planning events;
- an ambiguous domain detection over-provides, instead of asking the operator;
- the credential files of builds are proposed from the locations that exist, read by the recording build, instead of parsed configuration.

Kept on purpose (no change): the outline Q-Gate consumer sweep and tier check, the learned worker budget, the review-bot `trigger_events` fail-fast.
