# Doc review 2026-11-24: engine code that the merged specifications no longer describe

This comes from the doc-review session of `plan-marshall-documentation` (round 2026-11-24, "observe facts instead of predicting them"). The operator decided the points and the documents are merged: core #607 (`50773c49`, this repository's `doc/specification`, watch and Traceability), docs #201, clients #570, plan-marshall-mcp #130. The code was not touched. The operator asked for the implementation to be done in the repository that owns it, through this epic. Nothing in this epic was edited. The epic decides how to cut and order the work. All line numbers are on `origin/main` at `f8299fa5`.

## The principle behind the decisions
A mechanism that predicts, infers or pre-declares something the process later observes as a fact is replaced by the observation, also where code exists. Examples:
- the lane is routed on the request's facts and the light outline is gated on its real affected files, instead of a scope estimate;
- prunes and widening read the realized change instead of the declared footprint;
- the worker's write set is confined instead of its writes being attributed afterwards;
- the freshness gate derives build-neutrality since the build `HEAD` instead of a reconcile stamp;
- the review bot's own refusal is acted on instead of structural caps;
- dependencies are read from the build in the new phase `sanity-check` instead of an outline section.
