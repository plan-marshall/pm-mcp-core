# Doc review 2026-11-25: the merge path and the epic queue observe the facts they copied (fourth round, code and plan follow-ups)

This comes from the doc-review session of `plan-marshall-documentation`, fourth round of "observe facts instead of predicting them". The operator decided the points; the documents are merged: core #628 (`d961c9df`, the engine specifications and watch), clients #592 (the design of the clients), docs #204 (requirements, roadmap, use cases). The code was not touched. Almost none of the new mechanisms is built (the merge path, `ci.pr-observe`, `epic.next-work`, the findings triage seam, the git probes: grep of `pm-*/src/main` found none), so most of this is for the packages that build them; §1 lists what is built and now disagrees. The epic decides how to cut and order the work. Line numbers are those of `origin/main` at `88680dd7` and may have moved.

## The principle behind the decisions
A mechanism that predicts, infers or pre-declares at an early point something the process observes as a fact at a later point it passes anyway is replaced by one observation where the fact exists. The merge path observed the pull request once (at adoption or push) and acted on that copy; the epic queue held `handed_back` rows that nothing observed again; the barrier read a base observation made at the merge base; `rejected` rested on a model-set label.

## The decisions (target text is in the merged specifications)
- **The merge gate observes the pull request.** `ci.pr-observe` reports `base_branch`; `merge.gate-entry` follows a base other than the plan's as `finalize.adopt-pr` does (write `base_branch`, a decision-log record naming both values, re-stamp `main_sha`, the next sync rebases). `closed` hands back (gap `cause: pr_closed`; the pull request is left closed, never reopened, `merge_outcome` `declined`). `merged` takes the observed-merged route when the merged `head_sha` is the plan's `HEAD`; otherwise outcome `pr_merged_unlanded` enters `finalize.hand-back` (gap `cause: pr_merged`, the unlanded commits named, branch refs kept, the pull request left as observed, `merge_outcome` `handed_back`, `merge_state` `not_applicable`; a new row of the Merge Outcome Mapping). The `not_mergeable` reasons gain `closed` and `merged`; `finalize.open-pr` gets a `merged` case routed to `finalize.merge-gate`.
- **`head_moved` is bounded.** It is charged to the server-rule retry budget (counter key `merge_head_moved`); spent, the plan hands back (`cause: exhausted`, `budget: server_rule_retry`). `merge.sync-base` compares the pull request's `head_sha` with the local `HEAD`: a remote head that is neither `HEAD`, nor `branch_pushed_at.head_sha`, nor an ancestor of `HEAD` ends the sync `foreign_head`, which calls `remediation.merge-conflict` (server rebase onto the observed head, as for `rejected_lease`). The sync pushes whenever the local `HEAD` differs from the last recorded push or from the remote head `ci.pr-observe` reports (a remote reset to an ancestor included). The lease of a push after a server rebase is the rejection's `remote_sha` or the re-read remote head, each only when it is the last recorded push or an ancestor of `HEAD`; any other head returns to `git.sync-required` (WD/06 Explicit push lease, SC/05 `git.push-with-lease`). The states of `git.branch-sync-state` are listed once (WD/06 Stage 6); `behind` and `diverged` give `sync_required` and `git.sync-required` instead of `push_state_unknown`.
- **A `checks_pending` refusal is free once.** The first at a `HEAD` enters the evidence wait; a repeat at the same `HEAD` after `all_green` is a `merge-refused` re-entry charged to the server-rule budget (counter `merge_refused_re_enter`); spent, hand-back with a gap naming the checks the provider called pending and stating that every observed check was complete.
- **The barrier re-reads the base.** Before `baseline_red_required` ends, it reads the provider's result for every failing check at the current base head (JR/03 Baseline Separation): all green at a base head `HEAD` does not contain gives `baseline_cleared` (facts name the base commit; the lease is released; the gate is re-entered; the next sync rebases onto that commit; it counts with `indeterminate` against `merge_barrier_indeterminate`); all green at a base head `HEAD` already contains gives `ci_failed`; still red, absent or unreadable stays `baseline_red_required` and the gap names the base commit read.
- **The epic queue observes `handed_back` rows.** `epic.next-work` observes every `handed_back` row with a pull request through `ci.pr-observe`, in the pass that reconciles shipped rows: merged with the head of the plan's last recorded push (`branch_pushed_at`) makes the row `merged` (landing facts as for a shipped row) and retires the plan's lesson `applied` in that step, provided the lesson is unclaimed or still claimed by that plan; merged with another head, closed, and no pull request (`local_only`, `no_pr`, a `landing.files` plan that wrote its changes) make it `abandoned`. A pass that wrote a row ends with the new outcome `reconciled`, routed to `epic.commit-ledger`. The epic watch settles on a new event `pull_request_settled`. A plan outside an epic has no coordination that observes its pull request: its lesson stays `active`. A handed-back plan's lesson claim is released and the lesson stays `active` until then. PM-WATCH-STORE-54 is deleted (id gap).
- **`decision.blocks` is derived on read**, from the scope's current runnable work, never stored; a server-raised class keeps its declared value.
- **`rejected` rests on a server-resolved fact.** `claim_refuted`, the only reason resolving `rejected`, needs `evidence.ref` to be a job id of this plan executed at or after the finding's `raised_at_head`; a `file:line` or URL ref resolves `suppressed`. `ext-point-verify`, `verification_profile` and `evidence.class: verifier` are removed. `duplicate` is refused (`invalid_link_args`) unless the finding named in `evidence.ref` has the same `file_path`, the same `line` or the same `rule_id`, and is not itself a duplicate. A `FIX` reply stays model-authored; it is transmitted and its thread resolved only when the finding resolves `fixed`, otherwise `transmit_outcome: not_sent`, `transmit_reason: nothing_to_transmit`. The `triage-groups` entry and the per-finding exception carry `evidence_ref`.
- **A changed setting or credential is met at the act.** A dispatch refused `method_not_allowed` hands back; `agent_identity` is refreshed at a plan's start and by the setup reconcile (nothing built, text only).
