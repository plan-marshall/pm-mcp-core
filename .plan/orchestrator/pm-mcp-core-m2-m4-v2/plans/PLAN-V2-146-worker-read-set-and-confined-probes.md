## Objective

The package `job-confinement-and-environment` composes the write set and the job environment since PLAN-V2-27 (#161, `7903bf23`) and enforces nothing; its read set for a worker is still *enumerated* (the base and the sockets are denied, nothing is listed), `headless.readable_paths` is in the schema file and in no Java code (`HarnessProfileSchemaParityTest` pins it as an unimplemented deviation owned by this package, `:49`), there is no socket-list concept, and the confined probe jobs (`SubprocessJobRunner.startProbe`, `:649`) have no production caller and several empty inputs. The verification stage runner (the plans staged behind this one) needs a worker that reads only what is listed, a profile that can say which paths it reads, and probe jobs that are composed completely. This plan builds those pure parts of the composition: the listed read set, the profile rules with the credential-location refusal, the socket list and the probe residue. **All enforcement is `pm-exec` in `pm-mcp-clients`** (its README rows `exec-listed-read-set`, `exec-socket-list` and `exec-hardening` are `open`; `Command.java` accepts only `--write`, `--read` and `--deny-read` today): this plan composes the launcher arguments and proves them at the argument level with the fixture launcher; **no claim is made that a kernel enforced anything** (Done-when).
