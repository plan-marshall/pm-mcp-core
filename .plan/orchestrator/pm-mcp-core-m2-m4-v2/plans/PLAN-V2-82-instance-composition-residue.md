## Objective

A plan instance is a set of files (the plan unit and one composed file per reached phase sub-workflow). Three things in the composition still read it as one tree:

- the **position rule** compares bare state ids against one merged set of all units, so a state pruned from its own sub-workflow passes when another reached unit declares the same id (`completed`, `handed_back`, `returned` and `finalize.hand-back` are declared by several units of the default plan by design), and a version is written that strands the plan;
- two **guards** are missing: a kept call whose callee the request does not supply is skipped silently, and a prune rule can remove a state a unit's entry binds to (a composed file then keeps a dangling entry; composed files are not verified standalone, ADR `workflow-plan/020`);
- the **policy calls** of the header and the `ceilings_changed` of the diff summary are collected from the plan unit alone, while the remediation calls live in the composed phase files (`outline`, `refine`, `execute`, `phase-4-plan`), so a raised retry or fix budget never reaches the header and the diff, and header and composed body disagree.

**Decisions this spec takes (each becomes an ADR, R06):**

1. *The position is a pair `(unit, state)`.* `InstancePosition` carries the unit of the current state and, per frame of the call stack, the calling unit and the calling state — the data `CallFrame` already holds (`callerWorkflowId`, `callerStateId`; the current unit is the top frame's `subWorkflowId`, or the plan unit when the stack is empty). The version must contain each pair, per unit. This is the composer-side sibling of the verifier-side defect PLAN-V2-69 folds in (`CallGraphExpansion` keys by bare id); the two share no class.
2. *The guards of `852e58d3` are the source of the change* (it is a local, unpushed commit of the branch `fix/instance-composition-guards`, one ahead of `13a1236c`, no pull request): a kept call with no sub-unit in the request is refused `invariant_failed` ("the call of '%s' names no sub-unit of the request"), and `InstancePruner` never removes a state a template's entries bind to (the prune is not applied and not listed in the header, so the header stays a true record). The plan cherry-picks it (it applies cleanly: it touches `InstancePruner`, `PlanInstanceComposer` and `PlanInstanceComposerTest`, none of which PLAN-46 changed) or re-implements it; either way it keeps the commit's three new tests.
3. *A policy call of a composed file is listed in the header with the unit that holds it.* `policy_calls[].in_unit` (optional; absent: the plan unit) and, for symmetry, `ceilings_changed[].in_unit`; the ceiling diff keys a call site by `(in_unit, call_site)`. Calls of the plan unit first, then those of the composed units in the order of the request's sub-units.
4. *The history is read whole until it is long: a Watch, not a tail-read primitive.* `PlanHistory.nextSeq()` decodes the whole `mcp/history.jsonl` on every history-bearing advance (flagged twice by review, answered "not changed"). The cost is one linear read per advance of a file of tens of lines per phase; the lead says `ActivityJournal` keeps a seek primitive privately — it does not (it reads the whole journal and bounds it by compaction, `ActivityJournal.java` lines 195 to 215), so a primitive would be new code in `core.store`, a bounded backwards read that must still treat a torn tail and a refused line. Not worth a deliverable now; the Watch states the measure that makes it one.
