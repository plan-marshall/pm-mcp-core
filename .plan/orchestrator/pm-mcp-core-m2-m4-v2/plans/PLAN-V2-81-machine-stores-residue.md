**Decisions this spec takes (each becomes an ADR, R06):**

1. *The verification result is a member of the provider's default.* `providers.<name>.verification` is `{passed, at, checks[{check, ok}]}`: the last result with its time, as `credentials-and-enrolment/01` § Provider Verification already says ("kept with the machine's provider defaults"). It carries the check names and their `ok` flags and NOT the provider's answers, so nothing a provider said is ever stored. A default recorded `available: true` must carry a passed result; a default recorded `false` carries a failed result or none (the operator's word). This is what "recorded available only after its checks passed" means in code; today `ProviderDefault.of(true, …)` builds it from nothing.
2. *A provider's answer is redacted before a check line carries it.* The specification says the line carries "the provider's own answer verbatim"; the statement is corrected to "after the redaction of anything credential-shaped" and `ProviderVerification` applies the existing `core.queue.SecretRedactor.redactText` to every `Answer.detail` it puts into a `CheckLine` (the arguments and the answer). The real probe of PLAN-V2-12 then needs no redaction of its own and cannot forget it.
3. *The credential-store check never overwrites an entry.* The account `credential-store-check` is read first; an occupied one fails the write step with the line `credential_store_check.write.occupied` and nothing is written or deleted (the alternative, restoring the original value, can lose it on a crash between the write and the restore).
4. *A provider with a `cli` variant records its variant.* For `git`, `github` and `gitlab` an omitted `variant` is refused (the default of "a project that sets none" would be undefined, and the verification skips the CLI checks for an empty variant); `forgejo` and `sonar` have no `cli` variant and omit it.
