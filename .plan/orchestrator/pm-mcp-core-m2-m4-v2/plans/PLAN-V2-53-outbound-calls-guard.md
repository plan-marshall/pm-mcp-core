## Objective

Credentials & Enrolment § Closed List of Outbound Calls (`doc/specification/credentials-and-enrolment/03-audit-and-outbound-https.adoc`, line 41, anchor `closed-outbound-list`, added by #188) says that "local, no telemetry" (`PM-ARCH-2`) is held by two tests of `PM-TEST-5` and not by review: a static architecture rule and an integration test behind a recording test network. Neither exists; PLAN-98 left both "owed to the milestone exit". The operator decided on 2026-10-29 (decision 5 of 18):

- **(A1)** The static rule is an **ArchUnit rule in `pm-runtime`**, and the operator's word is given for the one new test dependency of `pm-runtime` that this needs (`archunit-junit5`, as `pm-core` declares it). No other dependency and no plugin is added.
- **(B1)** **Hugging Face (the corpus fetch, `HuggingFaceSourceRepository`) is added to the closed list**, and the specification is amended to match the code: what `EndpointClient` and `LfsBatchClient` legitimately need is stated in it too.

This plan builds the rule so that the list is *closed in the code*: a class of `pm-runtime` or `pm-core` may open a connection only through `cui-http`, and only the classes named in an allow-list (one entry per destination class of the list) may use the `cui-http` client at all, so a new outbound call is a failing test until its class is added to the allow-list and its destination to the specification. Each rule has a negative control. The recording-test-network integration test of the same section stays owed (it needs the assembly and the update check, which exist in neither repository's code yet; see Dependencies and Sequencing and the operator question there) and the section says so after this plan.

## Deliverables

1. **Controls first, then the dependency and the connection rule (rule A).**
   (a) `pm-runtime/pom.xml` gains `com.tngtech.archunit:archunit-junit5` in test scope, with no version (the version `1.5.1` is managed by `cui-java-bom` through the parent, exactly as `pm-core/pom.xml` lines 61 to 65 declare it); nothing else is added to the POM.
   (b) `OutboundCallsArchTest` (new, `pm-runtime/src/test/java/de/planmarshall/runtime/guard/`), in the pattern of `pm-core`'s `AnalysisBoundaryArchTest`: it imports the main classes of `de.planmarshall.runtime` and `de.planmarshall.core` (`ImportOption.Predefined.DO_NOT_INCLUDE_TESTS`; the classes of `pm-core` come from the test classpath of `pm-runtime`) and fails when a class depends on a *connection-opening* type or calls a *connection-opening* method. The set, written out in the class Javadoc with the hazard: the HTTP client and web-socket of the JDK (`java.net.http.HttpClient`, `java.net.http.WebSocket`); the client sockets (`java.net.Socket`, `DatagramSocket`, `MulticastSocket`); the URL connections (`java.net.URLConnection` and its subtypes `HttpURLConnection`, `JarURLConnection`, `javax.net.ssl.HttpsURLConnection`, and the calls `URL.openConnection` and `URL.openStream`); the socket factories (`javax.net.SocketFactory` and its SSL subtype); the client channels of NIO (`SocketChannel`, `DatagramChannel`, `AsynchronousSocketChannel`). Listening types (`ServerSocket`, `ServerSocketChannel`, `AsynchronousServerSocketChannel`, `com.sun.net.httpserver.HttpServer`) accept connections and open none; they are not in the set (the operator is asked to confirm this reading of "opens a socket", see the questions in the pull request body). `java.net.http.HttpRequest`, `HttpResponse` and `HttpTimeoutException` are data types of `cui-http`'s API and are not in the set.
   (c) The exemptions are a named, closed map from class to reason, each entry one top-level class (nested and anonymous classes of it included), none by package: `de.planmarshall.runtime.job.WorkerEgressProxy` (opens `Socket` to the destination of a model job; "A model job's own traffic is the egress proxy's (`PM-SEC-5`) and is not part of this list"); `de.planmarshall.runtime.credentials.dbus.DbusConnection` (`SocketChannel` on a Unix-domain socket, the session bus of the Secret Service, local IPC that leaves no machine); `de.planmarshall.core.role.ShippedRoles` and `de.planmarshall.core.profile.ShippedProfiles` (`JarURLConnection` from `URL.openConnection()` on a `jar:` classpath resource, read from the JAR, never a network). The entries are the ones the sweep of the 2026-10-29 head finds (see Claim Labels); the plan re-runs the sweep and corrects the map.
   (d) **No dead entry, no unlisted violator.** A test evaluates rule A *without* its exemptions over the same import and asserts that the set of violating top-level classes equals the key set of the map: an entry that no longer violates fails (stale), and a class that violates without an entry fails (the rule). The import is asserted non-vacuous (it contains `HuggingFaceSourceRepository`, `WorkerEgressProxy` and `ShippedRoles`, so a changed import path cannot make the rule pass on nothing).

Rule B does not look at `pm-core`: the build already forbids `cui-http` there.
