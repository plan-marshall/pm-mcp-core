## Objective

PLAN-V2-106 (#355) was to replace the hand-written fakes and recorders by EasyMock doubles (operator decision 2026-10-30, "replace the fakes"). It converted 9 classes and kept 29, because its deliverable 1 let any "real in-memory implementation that many tests share" stay with a stated reason, and the Done-when scan was satisfiable with any stated reason. The analysis of the landing read the kept classes: about half are pure or scripted recorders of the kind the pull request itself converted (a list of appended records, a numbered answer, a captured argument), and its pull request body states reasons that the code refutes (Grounding corrections below). This plan (1) closes the keep vocabulary into an explicit list of sound keeps and one non-double class, (2) converts every other class the scan finds and every fixture-resident double the scan missed, and (3) makes the Done-when a scan whose result is the closed list and nothing else, so it cannot be met without converting.

The change is test code only. No production code, POM, plugin or dependency changes (EasyMock is allowed, CLAUDE.md "Dependencies and Versions"). No `@Test`, `@ParameterizedTest`, `@RepeatedTest` or `@Nested` line is added or removed.

## Deliverables

Seven small deliverables, grouped by module, each with an order. The test order of every conversion deliverable is `none`: this is a refactor, the guard is the unchanged tests, the test count and the assertion intent do not change, and no fail-first run is claimed. Each deliverable is one commit.

What a hand-written double is, for every deliverable and for the Done-when: a class, record, enum, anonymous class or lambda that implements a production interface or abstract class by hand and keeps state or records calls. A static factory that returns an EasyMock mock is not (`AuditSinkDoubles` of `core.store` is the precedent). Rules for the conversions: `createNiceMock` where the old double ignored a call; `createMock` where it threw or where the test asserted "no call"; `verify` where the old assertion was that nothing was called; `CaptureType.ALL` for a list of arguments; a double touched from more than one thread is read only after the threads are joined (H3). A converted assertion keeps its intent and carries a message of 20 to 60 characters; no AAA phase comment; no `Random`, no `UUID.randomUUID()`; a generated value replaces a literal where the literal is not the contract.

## Standing Constraints

Plan-specific constraints (the epic-wide rules are in `standing-rules.md`):

- **The keep vocabulary is closed.** A class not in K1-K9 or F1-F3 is converted; the lane adds no entry. An entry the outline wants to add (K10 is the only one the spec anticipates, for `StubProcess` if H1 is refuted) is reported in the first progress note with the measured failure before the code is written, and in the ADR.
- **No new hand-written double, not even a shared one.** A helper class may build EasyMock expectations; it may not implement a production interface by hand (CLAUDE.md Code Standards).
- **The guard is the unchanged tests.** The method count of each module equals the base; every converted assertion keeps its intent; no assertion is weakened to fit a mock (an `anyObject()` where the old test compared a value is a defect). Where a test asserted "nothing was called", the conversion asserts it by `verify` or an unexpected call; a double that cannot fail is not a conversion.
- **Thread safety.** A recorder that was a `CopyOnWriteArrayList` (the audit sinks, `SupervisorTestFixture` lists) was read while another thread could still write; a `Capture` is not. Each such site is proved at the outline (join first, or the read happens after `verify`) and named in the landing.
- **Not here:** the assertion messages of untouched assertions (PLAN-V2-101 to 105), the generators and draws of untouched lines (PLAN-V2-125, 126), the hand-made log handler `LoggedWatch` (PLAN-V2-126), deleting `JudgmentEndpointTest`, `JudgmentEndpointRemoteTest` and `SecretRegistry` (PLAN-V2-129: this plan does not touch the endpoint package; they were converted by PLAN-V2-106), sharing one in-memory lock manager across the five copies (not publishable under the artifact rule), and the unscanned population in Carried Open Items.
- **Where the project analyses its pull requests with Sonar** (read it over plain HTTP: `pullRequest=N`, never `branch=<feature>`): an open Sonar issue is fixed in a pushed commit, or dismissed with a stated reason recorded as `{issue-key}: {reason}` and transmitted through `plan-marshall:workflow-integration-sonar:sonar_rest transition --issue-key {key} --transition {falsepositive|wontfix}`. A dismissal the run cannot transmit is a blocker. The merge gate reads the open-issue count at the head (`0` confirmed, or every remaining issue dismissed); an `undecidable` read blocks.
