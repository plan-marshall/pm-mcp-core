## Standing Constraints

Plan-specific constraints (the epic-wide rules are in `standing-rules.md`, named in the First Instruction above):

- **Substance, not form.** The Done-when of PLAN-V2-85 to 88 was met by "a controller plus one `Generators` call or a one-line statement", and every analysis then found the weakness. A conversion here is accepted when a scratch mutation of the thing the test names fails it. The pull request body carries the per-class table (Deliverable 4), the counts before and after with their counting commands, and one failing mutation run per restored test.
- **A boundary keeps its edge.** A test that pins the value just beyond a limit (the first revision above current, the one-behind write, the first value over a bound) keeps that literal or a draw pinned to `limit + 1`. A test that pins an order keeps data that is unsorted by construction. A round trip keeps the characters the form escapes. A repeated generated expression goes into the module's artifact, not into a private method per class. A pair of values the test must tell apart is drawn so that it cannot be equal.
- **Assertion messages belong to PLAN-V2-101, 102 and 103.** This plan does not re-open them. A line it touches for another reason carries a message of 20 to 60 characters that says what is checked and keeps the diagnostic the old message carried (`result.detail()`, the drawn value).
