## Objective

Since the schema blocks became files (PLAN-V2-116 to 118), the file of a record is the one text the code, the specification and the parity tests share, and the landings of the three moves found that the code and the file part in three places while the parity tests either pin the difference or do not read the file at all. This plan makes them agree and removes the pins:

1. The intent record: the file (and the specification) says `choices`, `repairs` and the decider `role`; the code writes `decisions`, has no `repairs` and the decider `model`. `IntentSchemaParityTest` pins exactly these three items (lines 113 to 120 and 152 to 174). The specification is the true side (Phase Workflows § The Intent Record names `repairs` at line 462 and `choices[]` with the decider kind `role` at line 465; the work package `decision-log-renames` states that the code built follows the old names and is to follow the specification), so the code is corrected and the pin removed.
2. The plan-instance header and the composition record: the file lists 15 prune reasons and 10 fallback causes, the types have 13 and 9, and the Javadoc and the developer guide say the sets are equal. The files carry the specification (`no_code_delta`, `no_production_delta` and the gap cause `operator_path` are named by Phase Workflows and by the watch item PM-WATCH-PHASE-129), so the types are brought to the files, and the tests that hold a hand-copied list of the old values read the files instead.
3. 16 of the 27 schema files moved by PLAN-V2-116 and the two `pm-workflow` files have no reader at all; the tests that exist for the others cannot all fail where their landings said they could (no negative control in `ProjectConfigurationSchemaParityTest`, no rejecting case in the six classes of PLAN-V2-117, an outcome pattern probed with capitals only).

Findings that already have an owner are not here and stay where they are: `EpicIntent` bounds against `epic-intent-v1.schema.json` (PLAN-V2-03 D2, staged); `non_goals` lane dependence, `verified_by` and `capability` of the intent criteria, and the metrics member `attempt_end` with its pin in `MetricsSchemaParityTest` (PLAN-V2-129 `deferred-code-removal`, the staged plan of the work package `z3-deferred-code-removal`, see Dependencies); the `SpecificationDocument` helper, the property `pm.specification.root` and the comment of `pm-core/pom.xml` line 22 (PLAN-V2-122); the generated listings (PLAN-V2-121); the three `@Disabled` order checks (until their packages land); the lock specification (PLAN-V2-124). All line numbers are those of `origin/main` at `d1fb719f`; this plan re-reads them at the head.
