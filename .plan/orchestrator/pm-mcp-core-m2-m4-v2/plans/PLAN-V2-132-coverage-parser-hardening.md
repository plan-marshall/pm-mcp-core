## Objective

PLAN-V2-18 (#336) shipped native parsers for JaCoCo, Cobertura, LCOV and Istanbul coverage reports. Its XML reader keeps `XMLInputFactory.SUPPORT_DTD` **on** and refuses an internal DTD subset by scanning the document text (`CoverageXmlReader.refuseInternalSubset`), although the plan's own specification asked for DTD processing to be off and ADR `core-build/005` records that the DTD-off variant "was not measured". The text scan is defeated by a `>` inside a quoted system literal, and by UTF-16 or UTF-32 input without a byte-order mark; an external subset (`SYSTEM "http://…"`) passes it and no test covers that. The analysis also found four small result-honesty defects (`0/0` reported as a measured `0.0`, rounding before the threshold comparison, a Cobertura `branch-rate="0"` reported as measured, Istanbul duplicate keys last-wins) and a spec/ADR wording that understates what the code does. The reports are produced by the operator's own build, so the exposure is a hostile or malformed report, not a remote attacker; the plan makes the parser, not a text scan, the defence, proves it with probes that can fail, and makes each result say what was measured.

## Deliverables

1. **DTD processing is off in the parser, and the text prefilter is gone.** `CoverageXmlReader.factory()` (`CoverageXmlReader.java:194`) sets `SUPPORT_DTD` to `FALSE`; `refuseInternalSubset`, `doctypeIndex` and `decode` (`:114-154`) are deleted, together with both calls (`parse(String)` at `:75` and `parse(byte[])` at `:94`); the bytes already go to the parser through an `InputStream` (`open(byte[])`, `:188-190`), which detects the document's own encoding, while the `String` path reads through a `StringReader` and has none. The contract after the change: a `DOCTYPE` declaration is **tolerated, never resolved or fetched** (the real `jacoco-high.xml` and `jacoco-low.xml` carry one with the relative `report.dtd` and must still be read); a report that references an entity is **refused, never expanded** (the `ENTITY_REFERENCE` backstop stays); the factory keeps `IS_SUPPORTING_EXTERNAL_ENTITIES` false and the empty-stream resolver as depth. The refusal that disappears with the text scan is **an internal subset that declares an entity and references none**: with DTD processing off it is skipped like any `DOCTYPE`, which is harmless, and only a reference is refused. The tests that pin the old behaviour and reason are rewritten to the new contract, not dropped: `JacocoReportParserTest.refusesAnInternalSubsetBehindAComment` (`:233-248`, an internal subset with no reference, asserts the reason contains `internal subset`), the assertions of `JacocoReportParserTest:157-158` and `CoberturaReportParserTest:79-80` (the reason names the refused internal subset; the new reason names the entity reference). **Done when:** the ported fixtures `jacoco-high.xml`, `jacoco-low.xml`, `cobertura-high.xml` and `cobertura-low.xml` read as before, `deliberate-cobertura-external-entity.xml` is still refused, the three tests above state the new contract, and the HYPOTHESIS below is settled by a run (it is the evidence ADR `core-build/005` lacked).
2. **The hostile prologs are probed, each with a case that fails on the old code.** A probe class (`CoverageXmlHardeningTest`, name the outline's) drives every shape through `CoverageXmlReader` and the four format parsers: (a) `<!DOCTYPE r SYSTEM "a>b" [<!ENTITY x "y">]>` followed by a reference to `x` (the quoted-`>` case, L3-1); (b) the same document encoded UTF-16LE, UTF-16BE and UTF-32 **without** a byte-order mark; (c) an external subset, `<!DOCTYPE report SYSTEM "http://host/x.dtd">` and a `file:///` system id, with a counting `XMLResolver` or an equivalent probe that asserts **no resolution call and no network access** (L3-2); (d) an internal subset that declares a parameter entity; (e) an entity reference in an attribute value; (f) a comment or a CDATA section that mentions `DOCTYPE`. **Done when:** cases (a) to (e) fail on the code of `f97bc7f2` (the failing run is reported; a case that cannot fail is dropped from the deliverable and named in the landing) and pass after Deliverable 1; case (f) passes before and after and is the negative control; no case relies on a literal where the literal is not the contract (R20: the system ids and entity names are the contract and the display name says so).
3. **A counter that measured nothing is absent, not `0.0`.** `CoveragePercentages` (`:35`) turns a `0/0` into a measured `0.0`: a file with no lines enters the low-coverage list, and an LCOV file with `BRF:0` sets the branch metric to `0.0` where ADR `core-build/005` Alternative 4 rejects exactly that conflation. The change: a zero denominator yields **absent** in the percentage, the item list and the verdict for all four formats (JaCoCo `LINE`/`BRANCH` 0/0, LCOV `LF`/`BRF`/`FNF` 0, Istanbul, whose parser today reads only `pct` of each metric and skips `total` and `covered` (`IstanbulSummaryParser.java:106-131, 146`), so the zero rule needs the parser to read `total` (HYPOTHESIS below), Cobertura `lines-valid`/`branches-valid` 0). A Cobertura `branch-rate="0"` is read as **absent** when the report says branch measurement was off (`branches-valid="0"` or no `branches-valid`), and as a measured `0.0` otherwise; `Double.valueOf` is replaced by a decimal-only parse (it accepts `1d` and hexadecimal floats, `CoberturaReportParser.java:142`). **Done when:** one parameterised test per format shows `0/0` absent, one shows a measured `0/N` still `0.0`, and the Cobertura pair `branch-rate="0"` with and without `branches-valid` is pinned; the existing parser tests pass unchanged except where they asserted `0.0` for a `0/0` (each such change is named in the landing).
4. **The result is compared on the exact ratio, and the readers refuse what they cannot bound.** Today the percentage is rounded half-up to **two** decimals (`CoveragePercentages.round2`, `:58-59`, `Math.round(value * 100.0) / 100.0`) before the threshold comparison (`CoverageReport.java:52-56`), so a true 79.996 % becomes 80.0 and passes a threshold of 80. The threshold is compared on the unrounded ratio and the rounded value is the display only; the rule and its tie behaviour are stated (the original rounds half-even; the port is half-up). `IstanbulSummaryParser` refuses a duplicate member of `total` or of a file entry (`JsonFactory` `STRICT_DUPLICATE_DETECTION`, set on the factory at `IstanbulSummaryParser.java:46`; the duplicate keys are read at `:88-91`) instead of taking the last. The four readers take the report through one read with a **size cap** taken from a limits data file read with `LimitProperties.read` (the pattern of PLAN-V2-120; a literal is not allowed), an over-cap report is a `Refused` whose reason names the file **name**, not the absolute path (`JacocoReportParser.java:85` and the `Refused` reason of a missing file). **Done when:** a test pins 79.996 against a threshold of 80 (refused) and 80.0 (met); a duplicate `total` key and a duplicate file key are refused; a report one byte over the cap is refused with a reason that carries no directory, and one at the cap is read.
5. **The statements say what the code does.** `doc/specification/job-runtime/03-parsers-and-gates.adoc:48`, `pm-core/doc/developer/core-build.adoc:303-305`, ADR `core-build/005` (lines 43-44, the Alternatives 3 and 4, and the Consequences at `:83-86`) and `pm-core/src/test/resources/ported/coverage/PROVENANCE.adoc:60` say the parser "declares and uses an external entity" in a way that understates the code; they state the contract of Deliverable 1 instead (DTD processing off; a `DOCTYPE` tolerated and never resolved; an entity reference refused), in the condensed form R05 allows, with every block a test reads byte-stable (R10). `core-build.adoc:268` uses Javadoc markup in an AsciiDoc file and is corrected. One new ADR in `core-build/` (the next free number at `origin/main`) records the choice of the parser setting over the text scan, the measured DTD-off result, and the absent-not-zero rule; ADR 005 gets a Status note "superseded in part by ADR NNN" and its bullets are not edited in place (the pattern of ADR 009/010 of `provider-ci`). **Done when:** a search of the tree for the old wording returns none, and the links check of R17 reports `BROKEN LINKS 0`.

**Done when (plan):** Deliverables 1 to 5; no parser result changes for a report below the cap that carries a measured counter. **Sonar:** the SonarCloud search of the pull request (`pullRequest=<N>&resolved=false`) lists no open issue other than one dismissed with its reason, and its quality gate is green, before the pull request is reported ready. **Build:** `verify -Ppre-commit` (its rewrites reviewed and committed, in their own commit where they touch files outside the plan's scope), then targeted `-Dtest` runs of the `core.build` coverage classes and `CoverageXmlHardeningTest`; a full verify exceeds the host's budget (use per-module runs with `--timeout`). **Links:** the R17 check reports `BROKEN LINKS 0`.
