## Deliverables

Two deliverables, one commit each, in this order.

1. **The Harness Icon Store and its sanitising accept step (Task 3 of `doc/plans/machine-onboarding-unit.adoc`; Harness Profiles § Harness Icons; Store Schemas 12 § Harness Icon Store).** A store in `pm-runtime` at `<PM_MCP_BASE>/icons/`: one file per harness `icons/<harness_id>.<ext>` with `svg` or `png`, mode `0600`, and `icons/index.json` with its `format_version` and entries, written under a lock (`locks/icons.lock`) with an atomic write (write a temporary file in the same directory, then move) and an index update; and the sanitising accept step that takes a candidate icon as bytes from a caller: **at most 256 KiB**, SVG or PNG only (decided by the bytes, never by the file name), an SVG stripped of scripts, event attributes and external references, refusals with their reasons. Design rules, decided by the outline with an ADR: the sanitiser is an **allow-list** (the SVG elements and attributes it keeps are listed; everything else is dropped or the icon refused), not a deny-list; it uses no entity expansion and no external DTD (a document with a DOCTYPE is refused), refuses `<script>`, `<foreignObject>`, `<use>` and `<image>` with an external or `data:` reference, every `on*` attribute, every `href` or `xlink:href` that is not a fragment of the same document, `style` with `url(` or `@import`, and a PNG is checked by its signature and its chunk structure (a PNG that carries text chunks or a size above the bound is refused or stripped); the `harness_id` that names the file is checked with `HarnessId.matches` (PLAN-V2-06) before it touches a path, so no separator, dot segment or symlink can leave the directory, and the written file is opened without following links; an existing icon of the same harness is replaced atomically. **Deferred, behind a profile that declares the `source` form (later-improvements L-21; no shipped profile does):** the outbound fetch itself through the runtime's HTTPS client and the `proxy` setting on the consent `fetch_icons`; this plan builds no fetch and opens no connection (`OutboundCallsArchTest` stays as it is and its exception map is not touched). The monograms stay the icon of every harness until then.

## Standing Constraints

- **No connection is opened and the exception map of the outbound-call guard is not touched**; the store takes bytes from a caller.
- **No new hand-written double**; no dependency or plugin is added (an XML or image library is a decision for the operator: the sanitiser uses the JDK's StAX and `javax.imageio`-free PNG chunk reading, or the outline stops and asks).
