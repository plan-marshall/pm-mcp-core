## Objective

The second plan of the package `derived-facts-store` (the first, PLAN-V2-02 (`derived-facts-records-and-kinds`), built the entry records, the strict codec, the parity test and the kind registry; read its landing and the head of `main`). It builds the store of `derived-facts.json` and the rules of Store Schemas § Derived Facts Store that act on an entry: a local fact is recomputed whenever its `input_digest` changes; a network fact holds for 86400 seconds since `derived_at` (Timeouts & Budgets § Derived Facts) and is refreshed besides on request; a failed derivation keeps the last value with `state: stale` (or `failed` when no value was ever derived) and records the failure; a gate that depends on a stale or failed fact evaluates `COULD_NOT_EVALUATE`, never pass; and the operator-only fact `agent_identity` appears in no model-facing view. It registers no concrete kind and derives nothing: the derivation is a function the consumer passes in. It closes the package (R01: row and file leave in its commits).

**What is built here and what is the assembly's.** Here (`pm-core`): the store, the `DerivedFactReading` with its `couldNotEvaluate()`, and the projection `modelFacing()` that leaves out every operator-only kind. NOT here, and owed outside this repository (list in the pull request body as **Owed outside this repository**): the mapping of `couldNotEvaluate()` to `GuardResult.CouldNotEvaluate` and the guard that reads a fact (`pm-workflow` consumer plans; `pm-core` cannot reach `pm-workflow`); the `pm://project/config` resource, every representation and tool result, and the `ModelFacingFieldAuditTest` registry of the assembly in `plan-marshall-mcp`, which must serve only `modelFacing()`; the operator's local API representation of `agent_identity` for `pm-operator` and the web app.

## Deliverables

1. **The store and its reads.** `DerivedFactStore` in `pm-core` `core.store`: constructor `(AtomicStoreFile, LockManager, DerivedFactKinds)` refusing a store file whose key is not a `LockLevel.DERIVED_FACTS` lock (as `BuildTimingsStore` does); `snapshot()` reads the file without a lock (`StoreSnapshot.read`), the empty `DerivedFacts` if the file does not exist, a `StoreRefusal` naming the file if it is unreadable or of another format version (decision: strict, like every store, the operator deletes the cache file to force re-derivation; recorded in an ADR); `fact(DerivedFactKey)`; `store()`. `DerivedFactReading` (sealed): `Value(fact)` for a `current` entry still inside its validity, `Indeterminate(reason)` for a `stale` or `failed` entry (the reason is the stored failure reason with the kind), `Expired` for a `current` network entry older than the validity period at the instant passed, `Absent`; and `Optional<String> couldNotEvaluate()` present for every variant but `Value` (fail closed: a missing or expired fact is never a pass). `reading(key, now)` returns it. The directory of the file exists before the first write and the store does not create it (the pattern of `BuildTimingsStore`). Done when: `DerivedFactStoreTest` covers the empty store, each reading variant with the instant passed in (a clock fixture, no wall clock), the unreadable file and the other-format-version file as `StoreRefusal`, and the refused lock level.
2. **The recompute rule.** `refresh(key, inputDigest, derivation, now)` where `derivation` is a functional interface `Derivation` returning the sealed `DerivationOutcome` (`Derived(value, derivationId, sourceClass)` or `Failed(reason)`; no exception is the contract of a failed derivation). The decision is a table, each cell a test: the entry is absent → derive; its `input_digest` differs from the digest passed → derive (local and network kinds alike); its `source.class` is `network` and `now` is not before `derived_at` plus 86400 seconds → derive; its `state` is `stale` or `failed` → derive (a failed derivation is retried by the next call that needs the fact; no back-off is invented); otherwise the stored entry is returned and the derivation is NOT called. The derivation runs outside the lock (a network derivation is a provider call; the lock is held for the read and the write only), so a refresh that the caller makes inside a scope transaction takes the lock after the scope lock (the total order). A derived value is validated against the schema registered for the kind (`DerivedFactKinds.validate`); a value that violates it, a kind not registered, a qualifier on a kind that admits none, and a `source.class` the kind does not admit are treated as a failed derivation with that reason, never written as `current`. The result is the `DerivedFactReading` after the attempt. The validity period is the constant of the specification (`Duration.ofSeconds(86400)`), not a setting (the specification says "fixed"). Done when: `DerivedFactRefreshTest` has one case per cell of the table, shows the derivation is not called on a cache hit, shows a local fact never expires by time and a network fact does at exactly `derived_at + 86400 s` (one second before, at, one second after), and shows a value that violates its registered schema is `failed`/`stale` and not `current`.
3. **Stale and failed.** The write rules of the failure: a `Failed` outcome for a key that has an entry with a value rewrites the entry as `state: stale`, keeps `value`, `source`, `input_digest` and `derived_at` of the last good derivation (so the next call still sees the digest mismatch and retries) and sets `failure` to `{reason, at: now}` with the reason cut to 500 code points; for a key with no entry or only a `failed` one it writes `state: failed`, `value: null`, the digest that was attempted, `derived_at` of the attempt, and the failure. A later `Derived` outcome rewrites the entry `current` with `failure` null. A failed refresh of one key changes no other entry. The failure of a network derivation that the credential is not permitted to perform carries the missing permission in its reason (the consumer's text; the store only carries it). Done when: `DerivedFactFailureTest` has a case per transition (current→stale, stale→stale with a new failure, failed→failed, failed→current, stale→current, absent→failed), a reason of 600 code points stored as 500, the digest and value of the last good derivation kept on `stale`, and an unrelated entry byte-identical before and after.
4. **One lock, no lost update (PM-WATCH-STORE-43).** Every write is one short transaction on `LockKey.derivedFacts(base, projectId)`: acquire, re-read the file under the lock, change the one entry, write through `AtomicStoreFile`; when the stored entry was replaced meanwhile by an entry with the same digest and a later `derived_at`, keep it and return it (two refreshers of the same fact do not overwrite a newer result with an older one). Tests: in `pm-core`, `DerivedFactStoreConcurrencyTest` with a serializing test lock manager (the one in `RecordingLockManager` takes no operating-system lock): two threads refresh two different keys, and two refresh the same key; no entry is lost; and `LockOrder.check` accepts the derived-facts key after a held `plan` key and a held `workspace` key and refuses a plan key requested while it is held (the total order, `LockOrderTest` is the model). In `pm-runtime`, one new test class `DerivedFactStoreLockTest` in `pm-runtime/src/test/java/de/planmarshall/runtime/lock/` uses the real `FileLockManager`: a transaction holding a plan lock refreshes a fact (permitted), and two threads refresh two keys at once without a lost update (the guard of PM-WATCH-STORE-43, "the lock-order checker rejects any acquisition outside the total order; no update is lost"). Done when: the three test classes pass, and the watch item PM-WATCH-STORE-43 is deleted in the same pull request because these tests cover its guard (R05: a watch item is deleted only when a named test covers its guard; the pull request body names the tests).
5. **The operator-only fact.** `DerivedFactStore.modelFacing()` returns the facts without every key whose kind is `operatorOnly` (`AGENT_IDENTITY`, Store Schemas 09 § Operator-Only Facts), and `operatorFacts()` returns the whole set; both are projections of `snapshot()`, the first is the only collection a model-facing representation may be built from. The exclusion does not depend on a registration: `agent_identity` is excluded whether or not a consumer registered it, and a qualified key of it (`agent_identity:<qualifier>`) too. `reading(key, now)` and `refresh` serve the store's own server-side users (committer identity, setup checks) and are not model-facing. Done when: `DerivedFactModelFacingTest` has a store holding `agent_identity`, `agent_identity:app` and `push_remote`; `modelFacing()` holds only `push_remote`, `operatorFacts()` all three; the completeness test over `DerivedFactKind.values()` derives the expected operator-only set from the enum at run time and finds exactly `AGENT_IDENTITY`; and a registry that never registered `agent_identity` still excludes it. The Javadoc of `modelFacing()` names the assembly's duty (Objective).
