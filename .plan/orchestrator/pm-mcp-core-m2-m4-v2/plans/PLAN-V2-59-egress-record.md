## Objective

Close the **specification gaps** of the worker egress, and build **no enforcement** (operator decision 2026-10-29, decision 14 of 18, option 3). The work package `job-confinement-and-environment` (PLAN-27, #161) is open because the enforcement half lives in `pm-exec` of `pm-mcp-clients` and cannot be built here; what this repository can close is the record of it. The specification requires two things that the code and the pinned schemas do not have: (1) "every job record then states `egress: unenforced`" / "Both record `egress: enforced` in the job record" (`job-runtime/02-confinement-and-environment.adoc` § Worker Egress Proxy, bullets Enforcement and Where it cannot be enforced) — the job record has no `egress` member; (2) "Every refused destination is an activity entry of the worker" (same section, bullet The proxy) — the activity journal has no kind for it, and the kinds are a closed list. This plan adds the member and the kind to the specification, to the two pinned schema blocks, and to the typed code that the two parity tests force, and records the honest value: `unenforced`, because no platform in this repository or in the shipped `pm-exec` makes the proxy the worker's only route out. It does NOT build the Landlock/Seatbelt network rule, the worker network namespace, the egress tunnel, the launch report member, the admission gate, the acceptance act, the runtime status line, or the production start of `WorkerEgressProxy`: each is listed in the specification as "Remaining" and in Dependencies and Sequencing below.

## Remaining and Decisions (stated in the specification and the package file by D1 and D5; not built here)

Each is stated as the specification states it; where the specification is silent the item is marked *unstated*.

1. **Enforcement (external)**: the Landlock/Seatbelt network rule, the worker network namespace, the tunnel to the runtime's proxy, and the member of the launch report that states `enforced` — `pm-exec`, `pm-mcp-clients`, with the Linux child-subreaper package the epic already owes there.
2. **Production start of `WorkerEgressProxy` and the producer of the `egress` entries**: `WorkerSupervisor.java:309` passes `Optional.empty()`; a started proxy without a platform that forces the route is "configured, not enforced", which the specification forbids as the only protection ("never only configured"). *Decision for the operator:* wire the proxy before or only together with the platform enforcement and the admission gate?
3. **The operator's acceptance of unenforced egress**: stated at `job-runtime/02:141` (an operator act of both clients, recorded in the audit log, shown in the runtime status while it holds) and consumed at `client-profiles/01:995,1001`. *Unstated:* where the acceptance is stored, the name and fields of its audit record (`AuditEvent` has `egress_refused` only), the command of each client, how it is withdrawn. Both clients are outside this repository.
4. **The admission gate**: "no worker is admitted there unless the operator accepted" — no code checks it (`WorkerSupervisor` starts a worker whatever the platform); depends on 3. From this plan on, every worker record states the honest `unenforced` without the gate existing.
5. **The runtime status line**: stated at `job-runtime/02:141`; the member list of the runtime status (`runtime-lifecycle/01:67`) holds none. *Unstated:* its name and shape.
6. **Growth of the journal**: "every refused destination is an activity entry" with "a server entry is never cut" (`store-schemas/16`, Bounded per task) lets a worker that keeps asking for a refused host grow the journal without bound. *Decision for the operator:* one entry per distinct destination per attempt (with the count in the audit record, as the specification already counts per generation), or per request? **Decided 2026-10-29 (operator walk, decision 28, option 1): one `egress` entry per distinct refused destination per attempt** ("every refused destination" is read as every distinct one); the ADR records the reading, and no producer exists in this plan.
