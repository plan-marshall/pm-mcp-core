## Objective

Today a primitive can say how it failed only by being a different outcome, so every failure is a named constant that every calling state must route (Rule 2) and that the state catalogue must list: the catalogue has about 711 outcome edges. The specification already applies the opposite rule one level up — a sub-workflow's exits are "small and control-only … domain outcomes … only where callers genuinely continue differently" (`doc/specification/workflow-dsl/01-grammar.adoc` line 246) — and the staged `PLAN-V2-20` applies it to one primitive (its Decision 5: `failed` plus a closed `reason`). The SPI has no place for a reason, so a reason today would be an untyped string in `updatedFacts` that nothing checks. The operator decided on 2026-10-29 (option B1): **the design rule is that a name is an outcome only where the graph continues differently; every other failure, skip or indeterminacy is one outcome of its class plus a reason carried as data.** This plan gives the rule its typed home in the SPI of `pm-core`, additively, and changes no outcome of any existing primitive:

- `OutcomeReason`: the small interface of a reason, implemented by a closed enum: a wire name and the (optional) engine condition the reason maps to;
- `PrimitiveOutcome.reasonType()`: a default method (empty) by which one outcome of a primitive declares the closed enum of its reasons;
- `PrimitiveResult.reason`: a fourth, optional component; the three-component form every existing call site uses stays;
- the registry-time checks that make the declarations safe (a closed enum, grammar, uniqueness, the class admits a reason, the reason-to-condition table is total).

**Reasons are DATA ONLY** (decided): no DSL construct reads or routes on a reason. `PM-WATCH-DSL-22` (one target per outcome, branching through a router) and `PM-WATCH-DSL-15` (result guards) stay as they are; a reason that a unit must route on is promoted to a named outcome by the primitive's author — that is the rule, not an exception to it. What the engine does with a reason (the mapping to a condition, the data it records) is `PLAN-V2-19`; this plan declares and checks.

**Decisions this spec takes (each becomes an ADR, R06):**

1. *The design rule: a name is an outcome only where the graph continues differently; every other failure is a reason carried as data.* Recorded in `05-primitives.adoc`, in the developer guide and as the first ADR. It is a rule for primitive authors, checked where it can be checked (the declarations) and not where it cannot (whether two failures "continue differently" is a judgement of the author, reviewed with the catalogue).
2. *The reason is a closed enum behind a small interface, `OutcomeReason`* (`String wireName()`; `default Optional<String> conditionKind()`, empty), not a string fact and not a sealed type: the same idiom as `PrimitiveOutcome`, the set is closed by the enum, and a wire name lets a later log, a diagnostic and a diagram print it. The interface is named `OutcomeReason` because `Reason` is already the name of eight nested enums of the repository (for example `PrimitiveRegistrationException.Reason`, `InternalFaultException.Reason`).
3. *`reasonType()` belongs to the OUTCOME, not to the primitive:* `default Optional<Class<? extends OutcomeReason>> reasonType()` on `PrimitiveOutcome`, empty by default. `git.stage-and-commit`'s `failed` has reasons and its `hook_failed` has none; a per-primitive declaration could not say which. Additive: the 59 fixture enums that implement `PrimitiveOutcome` are untouched.
4. *`PrimitiveResult` gains `Optional<OutcomeReason> reason` as a FOURTH component and keeps the three-argument constructor* (`outcome`, `updatedFacts`, `spawnedJobId`, reason empty), so the 23 `new PrimitiveResult(` sites stay valid. This is the short form of a record with an optional component, not a compatibility shim for an older caller. The record enforces the pairing: a reason is present exactly when the outcome declares a `reasonType()`, and it is an instance of that type; a violation is an `IllegalArgumentException` at construction (a programming error of the primitive, as the existing `NullPointerException` checks are).
5. *Which classes admit a reason:* `FAILURE`, `INDETERMINATE` and `SKIP` — the three that explain "why not". `SUCCESS` has nothing to explain, `UNSETTLED` and `STEPPED_OUT` are engine control (`05-primitives.adoc` lines 145, 146). An outcome of another class that declares a `reasonType()` is refused at registration.
6. *The reason-to-condition table is total and closed:* every constant of a reason enum answers `conditionKind()` (empty is an answer), and a present answer is one of `footprint_violation` and `precondition_unmet` — the two conditions a primitive can originate. `guard_indeterminate`, `job_incomplete` and `config_drift` arise from the engine's own guard evaluation, task attempts and re-composition, and `integrity_breach` names its breached store, so none of them is mappable (`EngineStep.ConditionRaised.raise` refuses `integrity_breach` for the same reason). The set is a public constant of `OutcomeReason`; widening it is a one-line change with a test, and `PLAN-V2-19` does the mapping.
7. *Reasons are data only (B1), not routable by guard (B2).* B2 would grow `result_guard` from boolean/optional to enum equality and amend `PM-WATCH-DSL-15` and `-22`; it is taken only when a concrete unit needs it, as its own plan.
8. *A SKIP outcome with an optional input is `skipped` plus a reason* instead of a `skipped_<reason>` constant per cause (`05-primitives.adoc` line 143). Specification change only: no production primitive exists, and the one fixture constant of that name (`pm-core/src/test/.../spi/TestPrimitives.java` line 39, `skipped_no_input`) is untouched. The step record the line describes is not built (`PLAN-V2-19` states what it does and does not persist).

## Standing Constraints

- **Log messages: none expected.** A malformed reason declaration is a `PrimitiveRegistrationException`, as every other refusal of the registry.
- **Additive only.** No `Primitive`, `PrimitiveOutcome` or `PrimitiveResult` shape that a current caller uses changes: the three-component constructor, `outcome()`, `updatedFacts()`, `spawnedJobId()` and every existing default method stay. The name `Primitive` is kept (decided). Pre-1.0 does not license a rename here: it would touch 15 test files, 8 specification parts and the catalogue's ids for no gain.
- **No generic `Exception`** is caught or thrown in production code (the invariant throws `IllegalArgumentException`, a specific type).
- **Add no dependency and no plugin** (CLAUDE.md). `pm-core` depends on `pm-api` alone among the modules of the product.
- **The 59 fixture enums, the 12 fixture primitives and the 23 `new PrimitiveResult(` sites are not edited.** If one must be, stop and say why in the first progress note (R07): it means the shape is not additive.
- **Nothing routes on a reason.** No grammar production, no `GuardEvaluator` branch, no verifier rule reads a reason in this plan; `PLAN-V2-19` states the same for the engine and the verifier.
