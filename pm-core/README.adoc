= `pm-core`
:nofooter:

`pm-core` is the foundation of the engine. It holds the service interfaces, the state stores, the primitive SPI, the
provider-neutral contracts, the log message registry and the TOON encoder. The other modules of this repository build
on it. What the module may depend on is stated in the
https://github.com/plan-marshall/plan-marshall-documentation/blob/main/doc/specification/module-structure.adoc[Module Structure Specification].

== Packages

All packages lie below `de.planmarshall.core`. Each line is the first sentence of the package's `package-info.java`.

* `analysis`: the provider-neutral code-analysis contract, implemented by the provider modules.
* `architecture`: the merges over the contributions of the domain extensions: edge derivation and path ownership.
* `build`: the build output parsers, the evaluation of a gate, and the compiled artifact pattern table.
* `config`: the configuration: its split into team, local and machine files, the derived facts, and the keys of job budgets and retention.
* `discovery`: the discovery of the modules of a project and of their facts.
* `domain`: the domain extensions: the four axes of a domain and the descriptors that declare them.
* `findings`: the provider-neutral findings contract, implemented by the provider modules.
* `id`: the identifier types and their validation.
* `log`: the log messages of the module, `CoreLogMessages` with the prefix `PM_CORE`; the one holder of another module that a module may log through.
* `profile`: the client profiles: the loader of the profile documents of `pm-api`, their validation, the placeholders and the vocabulary translation.
* `queue`: the task queue store of a project below `projects/<project_id>/queue/`.
* `recipe`: the recipes and the extension points a domain contributes to.
* `role`: the role sets: the schema of a role artifact, the shipped, machine and project sets with their override and validation against the client profiles, and the qualification records.
* `role.corpus`: the corpus sources of the model verification corpus: the formats of its own part, the fetch of public datasets at their pinned commits, the generation of the imported items and the validation of the corpus.
* `service`: the service interfaces the foundation declares and `pm-runtime` implements: the job runner, the secret source and plan locking.
* `spi`: the primitive SPI and the engine ports: the interface every deterministic server operation implements, and the interfaces through which the workflow engine causes and observes what lies outside the status store.
* `spi.validation`: the content validators: the checks a text passes before the server stores it.
* `store`: the JSON and JSONL state stores: how a store is read, written, recovered and verified, the store layout of workspace, project and machine, and the global lock order.
* `toon`: the deterministic, reflection-free TOON encoder of PM-MCP.

== Build and Test

Run from the root of the repository:

* Tests: `python3 .plan/execute-script.py plan-marshall:build-maven:maven run --command-args "test -pl pm-core -am"`
* Integration tests: `python3 .plan/execute-script.py plan-marshall:build-maven:maven run --command-args "verify -Pintegration-tests -pl pm-core -am"`

The integration tests include `BuildGuardsIT`, which proves the dependency rules of the build with the fixture
projects below `src/guard-controls`. The commands for the whole repository are in `CLAUDE.md`.

The schema tests read the specification of this repository (`doc/specification`), whose root the Maven property
`pm.specification.root` names (default: the root of the build); a missing schema fails them. `ProductCorpusValidationTest`,
which validates the corpus of plan-marshall-mcp, reads a sibling checkout named by `pm.product.root` (default
`../plan-marshall-mcp`); both properties are passed to Surefire as system properties of the same name. A test whose
checkout is absent is skipped with the path named. In a worktree whose defaults do not
resolve, pass the checkout, for example `-Dpm.product.root=/path/to/plan-marshall-mcp`.
