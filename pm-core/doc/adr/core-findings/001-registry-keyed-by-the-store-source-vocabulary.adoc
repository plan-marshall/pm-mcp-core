= ADR 001: The Findings Registry Is Keyed by the Store's Own `source` Vocabulary
:nofooter:

== Status

Accepted

== Date

2026-10-11

== Context

The foundation declared `FindingSource` and `FindingResponder` as generic, unkeyed interfaces. The implementation
watch item PM-WATCH-MOD-8 left open which key a findings registry uses, so a finding could be fetched under a different
key than the one it is stored under.

== Decision

* The findings registry (`FindingRegistry` in `de.planmarshall.core.findings`) is keyed by `FindingSourceKey(kind, provider)`, the store's own `source` vocabulary, with `provider` set exactly when the kind is `analysis`, mirroring the store invariant.
* `FindingSource` and `FindingResponder` lose their type parameters; they are keyed by `FindingSourceKey` and are no longer functional interfaces.

The key is the store's vocabulary, so a finding is fetched under the key it is stored under. The decision settles
PM-WATCH-MOD-8.

== Alternatives Considered

Alternatives not recorded.

== Consequences

* The change to `FindingSource` and `FindingResponder` is breaking. Users of the deployed `SNAPSHOT` in `plan-marshall-mcp` could not be searched from this repository and were left for the reviewer to confirm.
* The Module Structure Specification records the decided key, and PM-WATCH-MOD-8 is removed from the implementation watch by the companion documentation pull request.
