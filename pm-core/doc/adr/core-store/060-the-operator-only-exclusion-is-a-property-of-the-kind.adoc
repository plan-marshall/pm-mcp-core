= ADR 060: The Operator-Only Exclusion Is a Property of the Kind
:nofooter:

== Status

Accepted

== Date

2026-11-01

== Context

`agent_identity` is operator-only: it is shown to the operator in both clients and used server-side for the committer
identity and the setup checks, and it never appears in a model-facing representation, resource (including
`pm://project/config`) or tool result. The value schemas of the kinds are registered by the consumers, and a consumer
may forget to register a kind, register it late, or register only some of the kinds it uses.

== Decision

The exclusion is a property of the `DerivedFactKind` enumeration (`operatorOnly`), and `DerivedFactStore.modelFacing()`
filters the snapshot by it. `agent_identity` is excluded whether a consumer registered it or not, and a qualified key of
the kind (`agent_identity:<qualifier>`) is excluded with it. `operatorFacts()` returns the whole set for the operator's
own clients.

== Alternatives Considered

* Deriving the excluded set from the registry: a consumer that never registered `agent_identity` would receive it in a
  model-facing view, and the exclusion would depend on a registration the assembly does not control. A registration is
  what a consumer does; the exclusion is what the specification requires of every consumer.

== Consequences

* A new operator-only kind is a change to the enumeration and the specification, and every model-facing view follows
  without a registration.
* The assembly owes the other half: every representation, resource and tool result it builds, and its
  `ModelFacingFieldAuditTest` registry, serves only `modelFacing()`; the operator's local API and the web app serve
  `operatorFacts()`.
* `DerivedFactModelFacingTest` derives the operator-only set from the enumeration at run time and states the
  exclusion without a registration.
