= ADR 046: The machine scope keeps its state in `machine/mcp/status.json`
:nofooter:

== Status

Accepted.

== Date

2026-10-26

== Context

The machine is the fourth top-level scope beside a plan, an epic and a project's workspace
(link:../../../../doc/specification/workflow-dsl/01-grammar.adoc#machine-scope[Workflow DSL § Machine Scope]). The status
store of the other scopes lies in the per-project machine store; the machine scope belongs to no project and exists
before any project is enrolled. Its workflow state has to live somewhere the runtime can address without a project, and
the store, its journal and its digest sidecar have to be guarded by a lock that stands in the one total lock order.

== Decision

`JournalScopeType` gains the constant `MACHINE` with the wire name `machine` and no scope id. `JournalScope.machine(base)`
is the scope with the path base `<PM_MCP_BASE>/machine/`, the journal `machine/mcp/transaction-journal.json`, the
sidecar `machine/mcp/digests.json` and the lock `LockKey.machineScope(base)` at `machine/locks/machine.lock`, which
stands at the level of the workspace lock. `WorkflowStatusStore` writes `mcp/status.json` for it, and
`WorkflowStatus.PHASES` carries the phase `machine`. The change ledger, the metrics store and the question log carry an
arm for the type and write directly below `machine/`.

== Alternatives Considered

A status inside a synthetic per-project store was refused: the machine scope precedes every project and a project's
release must not end the machine's onboarding. A store beside the machine stores (`machine-config.json` and its
neighbours) was refused: those are operator files outside the transaction journal, and the status is engine-owned state
that must move in journaled transactions.

== Consequences

The machine scope has the same transactional guarantees as the other scopes, including digest coverage and crash
recovery. Every exhaustive switch over `JournalScopeType` needs an arm, which the compiler enforces. A second machine
state store must not be added; components read this one.
