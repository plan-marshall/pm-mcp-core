= ADR 059: An Unreadable Store File Is a Refusal
:nofooter:

== Status

Accepted

== Date

2026-11-01

== Context

`derived-facts.json` is a cache: deleting it only forces a re-derivation. A reader of it can therefore be tempted to
answer an empty store for a file it cannot read, because the next refresh would rebuild the cache. The same store
document is read by the setup checks and by the gates of a plan, and a silent rebuild hides a truncated write, a file
of another format version or a foreign edit.

== Decision

An unreadable store file and a file of another `format_version` are a `StoreRefusal` naming the file, the version found
and the current one, exactly as every other store of `core.store` refuses them. The store never falls back to an empty
document for a file that exists and cannot be read; only an absent file answers the empty document.

The operator deletes the cache file to force a re-derivation. The refusal names the file, so the next step is the
operator's.

== Alternatives Considered

* Rebuilding an empty store on an unreadable file: a store that repairs itself would hide the corruption from every
  later reader and would overwrite the evidence on the first refresh. The refusal is what every other store of the
  package does, and one shared refusal is the pattern of PM-IMPL-2.

== Consequences

* A corrupt cache stops the reads that depend on it until the operator deletes it; a fresh file is written by the next
  refresh.
* The refusal is the same outcome a codec refusal carries, so a caller handles one type.
* `DerivedFactStoreTest` states the unreadable file and the other format version.
