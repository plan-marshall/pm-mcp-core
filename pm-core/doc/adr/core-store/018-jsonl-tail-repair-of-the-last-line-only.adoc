= ADR 018: JSONL Appends Under the Store's Lock, Only a Torn Last Line Is Repaired
:nofooter:

== Status

Accepted

== Date

2026-10-11

== Context

JSONL stores had no append discipline. The work package asks for the JSONL append discipline with tail repair under
the store's lock.

== Decision

`JsonlStoreFile` appends under the store's lock with a single `APPEND` write followed by `force`; every record is
newline-terminated. Only a torn last line is repaired; a malformed complete line is reported `unreadable` with its line
number, never repaired.

Rationale not recorded.

== Alternatives Considered

Alternatives not recorded.

== Consequences

* A torn last JSONL line is repaired at the tail only; a crash-point test proves it.
* `AuditEvent` of `core.service` gains the `jsonl_tail_repaired` event.
* Appends on file-locked stores (audit log, plan mailbox) are not yet safe against lock loss: closing a channel on a
  POSIX file releases the process's OS locks on that file. The fix belongs in the lock manager and must land before
  the audit-trail or mailbox packages use `JsonlStoreFile`.
