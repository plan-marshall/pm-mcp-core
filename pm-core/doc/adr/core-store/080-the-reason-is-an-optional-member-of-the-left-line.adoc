= ADR 080: The Reason Is an Optional Member of the Left Line
:nofooter:

== Status

Accepted

== Date

2026-11-20

== Context

The plan's history `mcp/history.jsonl` records where a plan has been and with which outcome
(link:051-the-plan-history-in-core-store.adoc[ADR 051]). Once the engine reads the reason of a result
(link:../../../../pm-workflow/doc/adr/workflow-engine/019-a-reason-with-a-condition-raises-it-instead-of-the-transition.adoc[ADR workflow-engine/019]),
the cause of a routed `failed` or `skipped` would be lost with the advance unless a store records it. The line is a
closed schema in format version 1, read by `PlanHistoryCodec`, which refuses an unknown member.

== Decision

* `PlanHistoryLine` gains the `@Nullable` component `reason` after `outcome`, read through `reasonValue()`; the schema
  `history-line.schema.json` gains the optional property `reason` of the outcome pattern, not required, and an `allOf`
  of two `if`/`then` clauses that admit it on a `left` line only and only beside an outcome that is not `null`, so the
  schema states the same invariants as the record.
* The record refuses a reason on a line whose event is not `left`, a reason without an outcome, and a reason outside the
  pattern. The codec writes the member after `outcome` only when it is present and reads it as an optional member.
* `FORMAT_VERSION` stays `1`, and `PlanHistoryLine.of(...)` keeps its eight parameters and builds a line without a reason.

== Alternatives Considered

* *A format version 2 of the line.* Not taken: a line without a reason is byte for byte the line it was, so every line
  written before stays readable, and the repository keeps no compatibility shims before 1.0.
* *Always write the member, `null` when absent.* Not taken: it would change every existing line's bytes and their digests
  for no information.
* *Record the reason in the status document.* Not taken: the status records where the plan is, the history where it has
  been (ADR 051).

== Consequences

* The engine writes the reason on the `left` line of a routed result and on no other line; a raise writes no `left` line.
* The canonical constructor of `PlanHistoryLine` gains a component, a breaking change before 1.0; the engine builds a
  line through the builder, and the tests that called the constructor were rewritten with it.
* `PlanHistoryTest` and `PlanHistorySchemaParityTest` pin the member, its omission, its `left`-only rule and its refusal
  without an outcome.
