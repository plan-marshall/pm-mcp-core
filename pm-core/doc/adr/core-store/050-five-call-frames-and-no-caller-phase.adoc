= ADR 050: Five Call Frames and No Caller Phase in the Status
:nofooter:

== Status

Accepted

== Date

2026-10-28

== Context

The workflow status stores the call stack, whose frames carried the caller's phase and a compiled maximum depth of
four. The phase is now derived from the phase unit on the stack (ADR workflow-ast 003, ADR workflow-engine 014), and the
phase level adds one frame to every call path, so the stored limit is one too small and the stored caller phase is a
derived fact that could disagree with the stack.

== Decision

* `WorkflowStatus.MAX_CALL_DEPTH` is five; `WorkflowStatusCodec` accepts five frames and refuses a sixth.
* `WorkflowStatus.CallFrame` carries no `caller_phase`; the JSON schema block of Store Schemas 02 and its parity test
  drop the member, the call-depth bounds admit five and refuse six.
* The phase of a scope is stored as the phase unit's wire name and is derived by the engine, never asserted by a
  caller.

== Alternatives Considered

1. *Keep `caller_phase` as a hint.* Rejected: a stored derived fact is a second source that can disagree with the
   stack, and the engine derives the phase deterministically.

== Consequences

A status document written by a build that stored `caller_phase` is not readable by this codec; nothing is released and
the format stays 1 (R13), so the member is replaced in place. The parity test keeps the schema block and the codec in
step.
