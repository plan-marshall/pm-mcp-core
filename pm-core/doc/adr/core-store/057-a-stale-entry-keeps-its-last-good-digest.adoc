= ADR 057: A Stale Entry Keeps Its Last Good Digest
:nofooter:

== Status

Accepted

== Date

2026-11-01

== Context

The failure rule of the specification keeps the last value with `state: stale` and records the failure. The next read
that needs the fact refreshes it. The decision table decides a refresh on the `input_digest` of the entry and on the
state, and the entry that keeps the last value has to say which digest it was derived from.

== Decision

A `Failed` outcome for a key whose entry carries a value rewrites the entry as `state: stale`, keeps its `value`,
`source`, `input_digest` and `derived_at` of the last good derivation, and sets `failure` to the reason and the instant
of the attempt. The digest of the last good derivation stays, not the digest that was attempted. The state rule
(`stale` or `failed` derives again) retries on the very next call even when the caller passes the same digest again.

A `Failed` outcome for a key with no entry, or with only a `failed` one, writes `state: failed` with the digest that was
attempted, because there is no last good digest to keep.

== Alternatives Considered

* Recording the attempted digest on `stale`: the next call with the same inputs would find a matching digest and a
  `current`-looking entry, and the stale value would be served without a retry. The retry would then depend on the
  caller changing its inputs rather than on the fact being stale.

== Consequences

* A stale entry retries automatically on the next call that needs the fact, with no back-off and no timer.
* The last good digest and instant are the pair a consumer reads to know what the kept value was derived from.
* `DerivedFactFailureTest` states the transitions and the kept digest, value and instant.
