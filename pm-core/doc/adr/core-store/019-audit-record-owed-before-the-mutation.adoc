= ADR 019: Every Enrolment Write Owes Its Audit Record Before the Mutation
:nofooter:

== Status

Accepted

== Date

2026-10-12

== Context

A tampered enrolment, a sidecar without its file and a file without its sidecar must each be refused and audited, and
the operator writes `enrol`, `unenrol` and `rebaseline` change the enrolment store. The rule for the audit record of an
enrolment write was settled in the review rounds of the pull request.

== Decision

* Every enrolment write owes its audit record durably before the mutation, recorded as `failed`/`not_confirmed`, and confirms it as `succeeded` only after the mutation. Each succeeded record carries its `transaction_id`.
* The durable audit intent is `AuditIntentFile` in `core.store`, extracted from `JsonlStoreFile` and shared with it.
* `replayOwedAudit` delivers owed records and continues past a project whose intent file cannot be read.
* A failing audit sink never hides a refusal: its failure is attached as suppressed.

Rationale not recorded.

== Alternatives Considered

Alternatives not recorded.

== Consequences

* Owed-audit replay is at-least-once; the audit sink must drop a repeated `transaction_id`.
* The owed-audit replay runs as recovery step 2 (`OWED_ENROLMENT_AUDIT`), built by `ProjectRecovery.withEnrolment(...)` in `pm-runtime`.
