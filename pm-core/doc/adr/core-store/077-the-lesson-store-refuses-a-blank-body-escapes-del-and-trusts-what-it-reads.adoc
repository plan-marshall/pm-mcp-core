= ADR 077: The Lesson Store Refuses a Blank Body, Escapes DEL and Trusts Only What It Can Read
:nofooter:

== Status

Accepted

== Date

2026-11-19

== Context

Pull request #512 (the landing of PLAN-V2-114, merged as `3b566897`) took three decisions about what the lesson store
refuses at write time without recording any of them: `create` and `revise` refuse a body without a non-whitespace
character, `LessonFrontMatter` refuses U+007F (DEL) in a `title`, and `LessonStore.isUntrusted(LessonResolution)` marks a
revision untrusted when a cited lesson is in any state but `found` or `empty_shell` — `absent`, `present_unreadable`,
`store_tampered`, `deleted_out_of_band` and `untracked` among them.

The third decision contradicted the specification, which says a revision is marked when a lesson among its `sources[]` or
`merged_from[]` "is `true`" (Store Schemas § Lesson Record, Derived from Untrusted Text), and the item was ask-at-refine
(standing rule R07) with no question asked. The second decision covered one member only: `component`, `tool_version`,
`rule`, the remedy statement and check, a source `ref`, a promotion `ref`, `merged_from[].by` and the retirement members
still wrote DEL literally, and the YAML reader refused the file, so each of them read back as `present_unreadable`.

== Decision

Three write-time contracts of the lesson store, in one place each:

* A write through the store (`create`, `revise`) refuses a body without a non-whitespace character. The state
  `empty_shell` therefore arises only from a file written outside the store; it is never a state a store write produces.
* `LessonCodec` escapes U+007F beside the non-ASCII characters it already escaped. DEL is the one code point below
  U+0080 that the YAML reader refuses in a scalar, so escaping it makes every front-matter string round-trip; the
  title-only refusal of #512 is removed, because the central rule covers a title too.
* A revision is marked `derived_from_untrusted` when a cited lesson of the kind `lesson` is marked, when its bytes do
  not decode, or when its trust cannot be established: it is `present_unreadable`, `store_tampered`,
  `deleted_out_of_band` or `untracked`, or it is deleted in the same transaction (the evidence the citation refers to is
  gone before the commit). A cited lesson that resolves `absent` reads nothing and marks nothing. A source of the kind
  `lesson` whose `ref` is no lesson id is refused with an `IllegalArgumentException`.

== Alternatives Considered

* **Treat an absent citation as untrusted as well** (the code of #512): an absent lesson was never read, so there is no
  untrusted text to inherit, and marking it would report a derivation the revision does not have. The operator chose the
  unreadable and integrity states alone.
* **Apply the specification's literal "is `true`"** (revert the widening): a citation of a lesson whose trust cannot be
  read would count as trusted, which is fail-open on the one path the mark exists for. The operator rejected it for that
  reason, and the specification sentence was corrected instead.
* **Refuse DEL centrally in every front-matter string** instead of escaping it: the schema bounds a `ref` by
  `minLength: 1` and nothing else, so a refusal would narrow the format without the schema stating it, and the schema
  block of `store-schemas/10` must stay byte-stable (standing rule R10). Escaping keeps the format as it is and makes the
  round trip the contract.
* **Leave the title-only refusal in place** beside the escaped writer: it would be a second rule for one member, with no
  property that the other members do not share.

== Consequences

* A front-matter string of any member may carry DEL and reads back unchanged; a file written by an older release that
  carried one reads as `present_unreadable`, because the escaping changes only what is written from now on.
* The untrusted mark is monotonic and fail-closed on a citation whose trust cannot be read, and it stays out of a
  citation of a lesson that does not exist.
* `LessonResolution.Absent` is the one state `LessonStore.isUntrusted` maps to `false` beyond `found` and `empty_shell`;
  the switch has no `default` arm, so a new variant of the sealed type fails to compile until its arm is stated.
* A revision whose `sources[]` names a malformed lesson id is refused before anything is written, so the store never
  records a citation it cannot read.
