= ADR 003: A Missed Source Is Partial, a Hash Mismatch Fails the Run
:nofooter:

== Status

Accepted

== Date

2026-10-14

== Context

An import of the corpus sources depends on public repositories and LFS endpoints the product does not control. One of
them may not answer, may no longer have the pinned commit or object, or may deliver content that is not what the
manifest pins. A role qualification graded on the corpus must say on what it was graded. The operator stated that a
source that cannot be fetched is reported by name with its items left out, and that any hash mismatch is a failure,
not a partial run.

== Decision

`ImportResult` reports every covered source with its item count and every missed source with its `Reason`
(`unreachable`, `pin_missing`, `hash_mismatch`, `malformed`), the file it concerns and the detail. A missed source
contributes no item; the other sources are imported all the same. The verdict is:

* `FAILED` when any source is missed for `hash_mismatch` or `malformed`: the items of the other sources are still
  generated, but no role is qualified on a failed run;
* otherwise `PARTIAL` when a source is missed for `unreachable` or `pin_missing`, with the missed sources named;
* otherwise `COMPLETE`.

A hash mismatch is any file, pointer oid or LFS object whose SHA-256 is not the one the manifest pins. Bytes an LFS
endpoint delivers count as delivered, whatever they are: `LfsBatchClient` of `pm-runtime` returns them as `FETCHED`
and `CorpusImport` checks them, so delivered bytes that are not the object fail the run. The client reads a download
up to one byte beyond the pointer's size and stops there; a longer body therefore yields bytes of the wrong size,
which is a mismatch, not an unavailable object. Only an object the endpoint cannot deliver (an error status, no
answer, a timeout, a malformed or refusing batch answer) is `unreachable` or `pin_missing`.

`malformed` is a fourth reason the outline did not name: a manifest, overlay or source file that does not yield the
selected items is a defect of the corpus. Its source is missed like any other (named with the reason, its items left
out, WARN `PM_CORE-102`), and, like a mismatch, it fails the run.

A corpus with no sources is not a corpus that could not be read. A corpus root that exists without a `sources/`
directory, or whose `sources/` holds no source, is `COMPLETE` with no source: the corpus of the product has none yet.
A corpus root that does not exist, is no directory or cannot be read, and a `sources/` that is no directory or cannot
be listed, refuse the whole import with an `UncheckedIOException`, the refusal `run` already declares for an I/O
failure: there is no source to name a missed entry after, and an empty result would be `COMPLETE`. The sources are
listed before the items of an earlier import are removed, so a refused import leaves them in place.

The import deletes and writes below the cache root (`<cache root>/items/` and the cache repositories), so the two
roots must not overlap. A cache root below the corpus root, a corpus root below the cache root (inside `items/` or the
cache repositories included) and two roots that are one refuse the run with an `IllegalArgumentException` before
anything is fetched, deleted or written. The roots are compared as normalized absolute paths and again with their
links resolved (the real path of the nearest existing ancestor, the rest of the path below it), so a link cannot hide
an overlap; a link that cannot be resolved refuses the run with an `UncheckedIOException` rather than assume no
overlap.

== Alternatives Considered

1. *A mismatching source missed like an unreachable one*, making the run `PARTIAL`. Not taken: changed content at a
   pinned commit means the pin no longer holds, which a partial qualification would hide.
2. *Aborting the import at the first mismatch.* Not taken: the report would name only the first broken source.
3. *The LFS client refusing mismatching bytes as `pin_missing`.* Not taken for the same reason as the first
   alternative: it would turn a failed run into a partial one.
4. *Refusing an oversized download as unavailable.* Not taken: the endpoint did deliver, and what it delivered is not
   the object.
5. *An unreadable corpus as a `FAILED` result with a synthetic missed entry.* Not taken: a missed entry names a
   source, and an unread corpus has none to name; the typed refusal reaches the caller without a result that could be
   mistaken for an import.
6. *A missing corpus root as an empty `COMPLETE` result.* Not taken: a mistyped path or a missing checkout would
   qualify a role on a corpus nothing was imported from.

== Consequences

* A caller qualifies only on `COMPLETE` or `PARTIAL`; a qualification on `PARTIAL` is recorded as partial with the
  missed sources named (`role-qualification`).
* Every missed source is logged: WARN `PM_CORE-102` `CORPUS_SOURCE_MISSED`, and for a mismatch ERROR `PM_CORE-200`
  `CORPUS_SOURCE_HASH_MISMATCH`. An LFS object the endpoint does not deliver is also logged by the client as WARN
  `PM_RUNTIME-126` `CORPUS_LFS_OBJECT_UNAVAILABLE`.
* A caller that gets the `UncheckedIOException` of an unreadable corpus qualifies nothing; the items of the earlier
  import stay below the cache root.
* An implementation of `SourceRepository` or `LfsObjectSource` returns what it fetched and leaves the hash check to
  `CorpusImport`.
