== Purpose
_Requirements: link:{docs}/Requirements.adoc#PM-IMPL-2[PM-IMPL-2]_

Package `de.planmarshall.core.toon` of `pm-core` holds the deterministic, reflection-free encoder of TOON, the
token-oriented text form in which PM-MCP hands structured answers to a model. The encoder implements the official TOON
specification, version `4.1` (release `v4.1.3`, `ToonEncoder.SPEC_VERSION` / `SPEC_RELEASE`), in its canonical options
only.

The output depends on the value alone: no locale, platform line separator or default charset is consulted, so the bytes
are identical on every platform, under a JVM and under native image. Nothing is reflected over: the encoder walks an
explicitly built value tree.

== Main Types

|Type |What it does

|link:{src}/ToonValue.java[`ToonValue`]
|The immutable value tree of the JSON data model: `ToonString`, `ToonNumber` (`BigDecimal`), `ToonBoolean`,
`ToonNull`, `ToonArray` and `ToonObject`. A sealed interface with the six variants, so a switch over it needs no
`default`.

|link:{src}/ToonEncoder.java[`ToonEncoder`]
|`encode(ToonValue)` returns the document as a string without trailing newline; `encodeUtf8(ToonValue)` returns its

|link:{src}/ToonEncodingException.java[`ToonEncodingException`]
|The refusal of a value that TOON cannot represent, with its `Reason`.
|===

`ToonValue.java` holds the builder of an object: `ToonObject.builder().add(key, value)` keeps the fields in the order
they are added, and a `null` or an empty `Optional` value is not added. An explicit JSON `null` is `ToonNull`. PM-MCP
maps its records onto the tree in their declared component order, which is what makes a record's TOON form stable.

== The Encoder

The form of a value follows from its shape and position (§ 1.4 of the specification):

* objects (§ 8), including an empty object as `key:`;
* inline primitive arrays `key[N]: v1,v2` and empty arrays `key: []` (§ 9.1);
* tabular arrays of uniform objects `key[N]{a,b{c,d}}:`, with nested field groups for nested-uniform columns (§ 9.3);
* list form for arrays of arrays and for mixed or non-uniform arrays, with objects as list items (§ 9.2, § 9.4, § 10);
* keyed tabular form `key[N:]{a,b}:` for an object of uniform objects (§ 9.5);
* primitives with canonical numbers (§ 2) and minimal quoting with the official escapes (§ 7.1 to § 7.3).

The canonical options are fixed: the comma document delimiter, two spaces per indentation level (§ 13), LF line
separators, no trailing spaces and no trailing newline (§ 12). A number is written in its canonical form; a string is
quoted only where the specification requires it, and a root string that starts with U+FEFF is quoted so that a reader
cannot take it for a byte-order mark.

`encode` answers one of two refusals as a `ToonEncodingException`, and never produces a partial document:

* `UNPAIRED_SURROGATE`: a string holds an unpaired surrogate, which TOON cannot represent (§ 3);
* `DUPLICATE_KEY`: an object holds two fields with the same key.

== Invariants and Failure Modes

* *Deterministic bytes.* Same value, same bytes, everywhere. A change of the output for an unchanged value is a defect,
  not a formatting preference: persisted TOON and its digests would drift.
* *Reflection-free.* The tree is built by the caller. Adding a type means adding a `ToonValue` variant, a switch arm in
  the encoder and its conformance case; it does not mean reflecting over a record.
* *Declaration order.* An object's fields stay in insertion order, which is the order of the record's components. The
  map-based factory sorts its keys, so code that builds a tree from a `Map` gets a sorted object, not a declared-order
  one.
* *No trailing newline.* A caller that writes a document adds its own line break. A caller that appends documents to a
  JSONL-style file writes one newline per document.

== Extending the Encoder

. Add the variant to `ToonValue` and its `of(…)` factory where a convenience is wanted.
. Add its arm to every switch of `ToonEncoder`; the sealed interface makes a missing arm a compile error.
. Add a case to `ToonEncoderTest` and, where the specification defines a form for it, a conformance case.
4. Prove the refusal case too: a value the form cannot represent is a `ToonEncodingException`, never a silently altered
   document.

== Pitfalls

* *Do not sort a declared-order object.* The encoder writes fields in the order of the tree; a `TreeMap`-based
  convenience factory sorts them. Records that are compared byte for byte must be built in declared order.
* *Do not encode a `Float` or a `Double`.* A number is a `BigDecimal`; a floating-point value is converted once, at the
  boundary, and the canonical form is what is written.
* *Do not rely on a platform charset.* `encodeUtf8` is the only byte entry point, and it writes UTF-8 without a
  byte-order mark.
* *Do not add a trailing newline in the encoder.* A second writer would add a second one; the caller owns the line
  break.
